## Organize the support team

Use **Agent Management** to maintain agent accounts, roles and quick replies. Assign roles based on the modules and actions each person actually needs. Keep account credentials personal rather than sharing one administrator login across the team.

After changing a role, verify it with the affected account: visible menus, conversation monitoring, content editing and settings access can differ. Account state, session ownership and field-level checks still apply beyond the presence of a menu.

<span data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP inherits the same identity

An MCP connection is bound to the authorizing tenant and agent account. AI does not receive a separate administrator role. The service reevaluates account permissions on calls; an unavailable tool cannot be enabled by guessing its name or supplying another tenant ID.

Manage connected applications in **System Settings → MCP Connection**. Revoke connections that are no longer needed. Logging out of the browser does not itself revoke an external AI application's authorization.

Role and agent-account changes through MCP require confirmation. When creating an agent through MCP, the initial password is entered by the user on the backend confirmation page rather than returned to the AI.


<span data-sixmm-canonical-anchor="understand-the-three-management-areas" aria-hidden="true"></span>

## Understand the three management areas

| Area | What to maintain |
| --- | --- |
| Agent accounts | Names, login emails, roles, enabled state and the reception controls exposed by the page. |
| Role management | The permitted modules and actions for a group of agents. Review the effect on existing members before saving changes. |
| Quick replies | Reusable response titles, content, order and enabled state. Review translations where the feature is available. |

<span data-sixmm-canonical-anchor="prepare-an-agent-for-their-first-shift" aria-hidden="true"></span>

### Prepare an agent for their first shift

1. Confirm the login email and intended role. Do not treat account availability, login state and working status as the same thing.
2. Review monitoring access, reception priority and maximum concurrent sessions where configured. These controls complement role permissions.
3. Ask the agent to sign in and verify the menus and handling actions needed for their work.
4. Prepare quick replies for common questions, then check that they contain current links and no visitor-specific information.

**Handover routine:** review open responsibilities before changing an agent's access. After a role or account change, verify the effective permissions rather than relying only on the role name.

## Common questions

<AccordionGroup>

<Accordion title="Does an administrator-authorized AI act as an ordinary agent?">
No. An MCP connection uses the account that authorized it. Connect with the account whose access is appropriate for the intended work.
</Accordion>

<Accordion title="Does signing out disconnect the external AI?">
Signing out of the console is separate from revoking an MCP connection. Use System settings → MCP connection to revoke an application.
</Accordion>

</AccordionGroup>
