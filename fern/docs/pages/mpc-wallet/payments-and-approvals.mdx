Enterprise payments can involve people with different roles. The operator prepares the transfer, an authorized reviewer handles approval where required, and the signing participants produce the transaction signature.

<span data-sixmm-canonical-anchor="prepare-the-payment" aria-hidden="true"></span>

## Prepare the payment

Select the source wallet, network and asset. Enter the recipient address, amount and any required destination memo. Review the preview and fees. If the selected workflow checks the destination against an allowlist, resolve any restriction using the authorized address management process.

<span data-sixmm-canonical-anchor="review-and-track-progress" aria-hidden="true"></span>

## Review and track progress

When approval is required, a reviewer can check the payment details in the enterprise task list and act within their permissions. Requests that require platform risk review may wait there before signing. After approval, check the payment record for signing, broadcast and chain confirmation.

| What you see | How to interpret it |
| --- | --- |
| Waiting for approval or review | A review step is still open. Check the assigned process. |
| Approved or waiting for signing | The request can move along the signing workflow. Follow the existing record. |
| Broadcast or waiting for confirmation | The chain outcome is still in progress. Use the transaction reference when available. |
| Result under verification | Keep monitoring the same request until the outcome is known. |
| Confirmed | The record has a chain outcome that can be reconciled. |

If a result is delayed, check the original request before taking another action. Cancellation eligibility depends on the actual signing stage. For system integration, see [transactions and retries](/mpc-wallet/transactions).
