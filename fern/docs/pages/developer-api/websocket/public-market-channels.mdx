Use public market channels when an application needs continuously updated prices, trades, candlesticks, or order-book depth without repeatedly polling REST endpoints. These streams can support trading screens, price displays, alerts, and market monitoring.

<span data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Connection URL

```
wss://ws.6mm.com/ws
```

Public WebSocket does not require authentication.

For connection lifecycle, unsubscribe, ping, and reconnect behavior, see [Connection, Subscription & Heartbeat](/developer-api/websocket/connection-subscription-and-heartbeat).

<span data-sixmm-canonical-anchor="common-channels" aria-hidden="true"></span>

## Common Channels

| Channel                            | Description                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Order book depth. Sends a snapshot first, then incremental updates |
| `market.trade.{symbol}`            | Latest trades                                                      |
| `market.kline.{symbol}.{interval}` | Klines                                                             |
| `market.ticker.{symbol}`           | Single-symbol ticker summary                                       |
| `market.tickers`                   | All-symbol ticker summary                                          |

<span data-sixmm-canonical-anchor="choose-a-channel" aria-hidden="true"></span>

## Choose a channel

| Application need | Channel |
| --- | --- |
| Build or maintain an order book | `market.depth.{symbol}` |
| Display a live trade feed | `market.trade.{symbol}` |
| Draw a candlestick chart | `market.kline.{symbol}.{interval}` |
| Display one market summary | `market.ticker.{symbol}` |
| Maintain a market overview | `market.tickers` |

<span data-sixmm-canonical-anchor="subscription-example" aria-hidden="true"></span>

## Subscription Example

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<span data-sixmm-canonical-anchor="push-message-wrapper" aria-hidden="true"></span>

## Push Message Wrapper

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

Use `topic` to route each message to the correct handler and `ts` to observe delivery timing. The `data` object contains the payload for the subscribed channel.

<span data-sixmm-canonical-anchor="order-book-handling" aria-hidden="true"></span>

## Order-book handling

The depth channel sends a snapshot first and then incremental updates. Initialize the local book from the snapshot before applying updates. After reconnecting, create a new session, subscribe again, and rebuild the local book from the next snapshot instead of continuing from stale in-memory state.

<span data-sixmm-canonical-anchor="production-recommendations" aria-hidden="true"></span>

## Production recommendations

- Generate a unique `id` for every subscribe, unsubscribe, and ping request.
- Confirm subscription acknowledgements before treating a channel as active.
- Resubscribe to every required topic after reconnecting.
- Keep network reads separate from slower database or UI processing.
- Monitor disconnect frequency, message-processing lag, and malformed payloads.
- Use [Private User Channel](/developer-api/websocket/private-user-channel) for authenticated account and order updates.
