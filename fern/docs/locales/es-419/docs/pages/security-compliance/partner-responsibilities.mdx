Un modelo claro de responsabilidad reduce el riesgo operativo y ayuda a los equipos de apoyo a responder más rápido.

<h2 id="responsibility-split">División de responsabilidades</h2>

| Área | 6MM | Socio |
| --- | --- | --- |
| Infraestructura comercial | Capacidades de emparejamiento, riesgo, motor de trading, API y SDK | Integración correcta y monitoreo de producción |
| Relación con el usuario final | No hay relación directa con el cliente a menos que se acuerde por separado | Incorporación de usuarios, soporte, divulgaciones y ciclo de vida de la cuenta |
| Secretos y credenciales | Proporciona modelo de credenciales y requisitos de firma | Almacena secretos de forma segura y restringe el acceso interno |
| Webhooks | Envía eventos de ciclo de vida firmados | Verifica firmas y procesa eventos de manera idempotente |
| Operaciones de cumplimiento | Proporciona tecnología orientada al cumplimiento y materiales de soporte | Confirma las obligaciones locales y los requisitos de atención al usuario |
| Versiones de integración | Mantiene capacidades documentadas de plataforma e integración | Prueba el código del socio, la configuración y los recorridos del usuario antes del lanzamiento |
| Manejo de incidentes | Investiga la infraestructura 6MM relevante y proporciona canales de soporte a socios | Detecta el impacto directo al usuario, preserva evidencia, contiene sistemas asociados y escala |

<h2 id="responsibilities-by-lifecycle">Responsabilidades por ciclo de vida</h2>

| Escenario | Acción en pareja |
| --- | --- |
| Diseño | Define propiedad del usuario, flujo de activos, flujo de datos, modelo de soporte y jurisdicciones objetivo. |
| Construcción | Guarda secretos en el backend, implementa autenticación soportada y preserva los identificadores de negocio. |
| Prueba | Escenarios de tiempo límite, reintento, duplicado-webhook, token expirado y fallas. |
| Lanzamiento | Revisión completa de la preparación, establecimiento de monitoreo y documentación de apoyo a la escalada. |
| Operación | Revisa alertas, reconcilia operaciones anormales, rota credenciales y mantén evidencia de auditoría. |
| Incidente | Contener sistemas controlados por socios, proteger las credenciales, preservar UTC plazos y contactar al canal de 6MM correcto. |

<h2 id="handoff-checklist">Lista de verificación de transferencia operativa</h2>

- Nombrar al propietario para la integración, salud, seguridad, cumplimiento y soporte al usuario final.
- Documentar URLs de base de producción, propietarios de credenciales y procedimientos de rotación.
- Confirmar paneles y alertas para fallas de autenticación, pedido, transferencia y webhook.
- Almacenar IDs de solicitudes, números de pedido de socios e IDs de eventos en registros buscables.
- Definir qué eventos requieren escalada inmediata.
- Mantener la [Plantilla de Solicitud de Soporte](/es-419/resources/support-request-template) disponible para el equipo de operaciones.
