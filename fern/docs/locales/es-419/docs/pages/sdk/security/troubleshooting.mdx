Comienza con el entorno, la marca de tiempo y el identificador de negocio de la operación fallida. Una verificación estructurada usualmente separa los problemas de configuración de autenticación, red y procesamiento asincrónico.

<h2 id="diagnostic-order">Orden diagnóstico recomendado</h2>

1. Confirmar el ambiente y la base afectados URL.
2. Registrar el rango de tiempo UTC y la primera solicitud que falle.
3. Identificar el módulo: Trading Widget, Agent SDK, REST API, WebSocket, o webhook.
4. Captura el ID de solicitud, ID de usuario del socio, `agentOrderNo`, ID de pedido o ID de evento webhook.
5. Revisa códigos recientes, credenciales, lista blanca de IP o cambios en el despliegue.
6. Reproduce con el caso de prueba más pequeño y seguro.

<h2 id="trading-widget-issues">Trading Widget problemas</h2>

| Síntoma | Causa probable | Arreglar |
| --- | --- | --- |
| iframe solicita dominio local del socio | baseUrl falta | Pásame baseUrl: 'https://app.6mm.com'. |
| El iframe es invisible o muy bajo | El contenedor padre no tiene altura | Establece la altura del contenedor o la altura de pasar. |
| token_provider_missing | El modo partner-token no tiene proveedor | Agrega autorizacióntokenProvider. |
| auth_exchange_failed | Token de embed inválido, expirado o no coincidente | Revisa la respuesta del token backend y channelId. |

<h2 id="agent-sdk-issues">Agent SDK problemas</h2>

| Síntoma | Causa probable | Arreglar |
| --- | --- | --- |
| Firma rechazada | Secreto incorrecto, deriva de reloj o campos de signos cambiados manualmente | Deja SDK generar campos de firma y sincronizar el tiempo del servidor. |
| Riesgo de movimiento de fondos duplicados | Nuevo número de orden usado después del tiempo fuera | Consulta por agentOrderNo original primero. |
| PROCESSING tratado como fracaso | Estado pendiente malinterpretado | Espera el webhook o llama a queryOrder. |
| Webhook procesado varias veces | Comportamiento de reintento sin idempotencia | Agrega la clave de idempotencia y las verificaciones de estado final. |

<h2 id="evidence-to-capture">Evidencia a capturar</h2>

| Integración | Evidencia útil |
| --- | --- |
| Trading Widget | Página URL, SDK ruta de versión, consola del navegador, solicitudes fallidas de red, carga útil `onError` y dimensiones del contenedor. |
| Agent SDK | SDK idioma/versión, URLbase, UTC marca de tiempo, ID de solicitud, `agentOrderNo`, código de respuesta y registros sanitizados. |
| Webhook | Tiempo de entrega, clave de evento o negocio, resultado de validación de firmas, estado de procesamiento y hash de cuerpo crudo sanitizado. |
| REST API | Método, ruta, entorno, ID de solicitud, código de respuesta y parámetros sanitizados. |

Nunca incluyas contraseñas, tokens de acceso, API secretos, firmas completas, claves privadas o datos personales no redactados en diagnósticos.

<h2 id="before-escalating">Antes de escalar</h2>

- Reintentar solo cuando la operación esté documentada como segura para reintentar.
- Después de un tiempo fuera, consulta el identificador original del negocio en lugar de crear uno nuevo.
- Confirmar el reloj del sistema y el entorno de credenciales para detectar errores de firma.
- Preservar el primer fracaso y cualquier resultado posterior de reintentos.
- Usar la [Plantilla de Solicitud de Soporte](/es-419/resources/support-request-template) para enviar un reporte completo y redactado.
