6MM soporte está diseñado para socios autorizados, integraciones activas y operaciones de producción. El soporte para usuarios finales sigue siendo responsabilidad de la plataforma asociada a menos que se acuerde por separado.

<h2 id="choose-the-right-path">Elige el camino correcto</h2>

| Situación | Ruta recomendada | Incluir |
| --- | --- | --- |
| Nueva asociación o evaluación de soluciones | Camino de incorporación de socios | Tipo de producto, región objetivo, cronología de lanzamiento, modelo de integración esperado. |
| SDK, API, webhook o pregunta sobre el entorno | Camino de soporte técnico | Endpoint, SDK versión, ID de solicitud, pasos de reproducción, registros. |
| Incidente de producción o flujo comercial degradado | Ruta de escalada de incidentes | Alcance del impacto, hora de inicio, usuarios afectados, IDs de pedidos, mitigación actual. |
| Cambio de activo, copia o material de lanzamiento | Ruta de soporte a operaciones | Página, idioma, cambio solicitado, fecha de lanzamiento, propietario de la aprobación. |
| Vulnerabilidad o sospecha de abuso | Ruta de reporte de seguridad | Detalles técnicos, punto final afectado, evidencia, urgencia, si el problema está activo. |

<h2 id="severity-guide">Guía de severidad</h2>

| Gravedad | Ejemplo |
| --- | --- |
| Crítica | No están disponibles el comercio de producción, autenticación, emisión de tokens o flujos relacionados con fondos. |
| Alto | Un flujo importante de socios se degrada, pero existe una solución alternativa. |
| Normal | Pregunta de integración, solicitud de configuración, problema de documentación o soporte de lanzamiento planeado. |

<h2 id="before-contacting-support">Antes de contactar al soporte</h2>

- Confirmar el área de producto y el entorno afectados.
- Recopilar IDs de solicitudes, IDs de pedido, marcas de tiempo, IDs de mapeo de usuarios, IDs de eventos de webhook y registros.
- Usar la plantilla de solicitud de soporte para problemas de producción.
