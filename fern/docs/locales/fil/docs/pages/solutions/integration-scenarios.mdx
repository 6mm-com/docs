Karaniwang ipinapakilala ang embedded trading sa isang umiiral na produkto, hindi inilulunsad bilang isang hiwalay na destinasyon. Ang pinakamahusay na landas ng integrasyon ay nakadepende kung saan na gumugugol ng oras ang mga gumagamit at kung aling sistema ang may-ari ng pagkakakilanlan, pondo, at operasyon.

<h2 id="common-scenarios">Karaniwang mga senaryo</h2>

| Senaryo | Pinakamagandang panimulang punto | Mga Tala |
| --- | --- | --- |
| Gusto ng app o wallet ng trading entry | Trading Widget SDK | Gumamit ng native o H5 entry point at buksan ang embedded trading experience pagkatapos ng user authorization. |
| Nais ng broker o channel platform ang access sa derivatives | Agent SDK + Trading Widget SDK | Panatilihin ang customer relationship at backend validation sa partner system. |
| Nais ng platform ng gabay na daloy ng kalakalan | API + piling SDK modules | Gamitin ang backend APIs para sa account, transfer, at order workflows habang inilalantad lamang ang kinakailangang frontend entry. |
| Nais ng umiiral na palitan ng karagdagang mga merkado | Integrasyon ng likwididad + API | Pagsamahin ang lalim ng merkado, mga workflow ng account, at operational monitoring. |

<h2 id="product-decisions-before-integration">Mga desisyon sa produkto bago ang integrasyon</h2>

- Magpasya kung ang mga user ay pumapasok mula sa homepage card, asset page, campaign page, o account center.
- Tukuyin kung aling sistema ang may-ari ng login state, eligibility ng user, at availability ng bansa o rehiyon.
- Magpasya kung paano ipapakita ang mga transfer, settlement records, at customer support tickets sa mga user.
- Magpasya kung aling mga event ang dapat i-forward sa internal analytics, CRM, o risk operations.
