Agent SDK so'rovlar hamkor maxfiy API orqali autentifikatsiya qilinadi. Bu sirni ishonchli backend xizmatida saqlang va imkon qadar SDK imzo maydonlarini yaratishga imkon bering.

> **Ikki imzo protokoli**
>
> Agent SDK imzolash tartiblangan so'rov maydonlari, soniyalar asosidagi vaqt tamg'asi va nonce dan foydalanadi. To'g'ridan-to'g'ri Developer API so'rovlari [Request Signing](/uz/developer-api/request-signing) da tasvirlangan alohida jarayondan foydalanadi. Ikkinchisiga bir yuk formatini qayta ishlatmang.

<h2 id="signing-rule">Imzolash qoidasi</h2>

Agent SDK so'rovlar uchun:

1. `sign` maydonini chiqarib tashlang.
2. Bo'sh qiymatli maydonlarni chiqarib tashlang.
3. Qolgan maydon nomlarini ASCII tartibda tartiblang.
4. Maydonlarni `k=v&k2=v2`sifatida birlashtiring.
5. HMAC-SHA256 o'n oltilik imzoni hisoblang `apiSecret`.

SDK bu qiymatni o'zi yuborgan ma'lumotlardan yaratishi kerak. Imzo yaratilgandan so'ng imzolangan maydonni o'zgartirish verifikatsiyaning muvaffaqiyatsiz bo'lishiga olib keladi.

<h2 id="sdk-managed-fields">SDK- boshqariladigan maydonlar</h2>

| Maydon | Manba | Tavsif |
| --- | --- | --- |
| agentCode | SDK konfiguratsiyasi | Hamkor agent kodi. |
| Vaqt tamg'asi | Joriy server vaqti | Unix vaqt tamg'asi soniyalarda. |
| nonce | Xavfsiz tasodifiy qiymat | Qayta ko'rishdan himoya tasodifiy ketma-ketlik. |
| Belgi | HMAC-SHA256 | Imzo so'rayman. |
| Valyuta | Standart valyuta | Valyutani o'tkazma/hisob APIs ishlatilganda ishlatiladi. |

<h2 id="secret-storage">Maxfiy saqlash</h2>

- Backend maxfiy menejeri yoki himoyalangan ish vaqti konfiguratsiyasidan `apiSecret` yuklash.
- Hech qachon sirni frontend to'plamlari, mobil ilovalar, ish stoli mijozlari, skrinshotlar yoki qo'llab-quvvatlash chiptalariga joylashtirmang.
- Ishlab chiqish, sahnalashtirish va ishlab chiqarish uchun sertifikatlarni alohida saqlash.
- Talab qiladigan xizmatlar va operatorlarga kirishni cheklash.
- Loglardan so'rov imzolari, avtorizatsiya qiymatlari va sirlarni yashirish.
- Ta'sir gumon qilinsa, ma'lumotlarni bekor qilish va almashtirish.

<h2 id="clock-and-replay-protection">Soat va qayta ko'rsatish himoyasi</h2>

SDK qayta ijro xavfini kamaytirish uchun `timestamp` va `nonce` o'z ichiga oladi. Orqa tizim soatlarini sinxronlashtiring va qo'lda tuzilgan nonce'ni qayta ishlatmang. Agar imzoni tekshirish muvaffaqiyatsiz bo'lsa, qayta urinishdan oldin sozlangan maxfiylik, server vaqti, ketma-ket maydonlar va muhitni tasdiqlang.

<h2 id="integration-checklist">Integratsiya tekshiruv ro'yxati</h2>

| Tekshirildi | Kutilayotgan natija |
| --- | --- |
| Maxfiy joylashuv | Faqat orqa tomonga mo'ljallangan maxfiy saqlash. |
| Atrof-muhit | Asosiy URL va credential bir muhitga tegishli. |
| Maydonni boshqarish | SDK `timestamp`, `nonce`va `sign`hosil qiladi. |
| Log' kesish | Biznes identifikatorlari ko'rinadi, credentiallar esa yashiriladi. |
| Rotatsiya | Credential egasi va almashtirish jarayoni hujjatlashtirilgan. |
