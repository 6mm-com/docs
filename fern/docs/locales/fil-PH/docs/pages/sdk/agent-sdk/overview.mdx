Ang 6MM Agent SDK ay para sa partner backend services na kailangang tumawag ng privileged Agent APIs nang hindi nagpapatupad ng signing at request handling mula sa simula. Hindi ito dapat tumakbo sa browser, mobile, o public desktop code dahil gumagamit ang integration ng partner API secret.

<h2 id="when-to-use-the-agent-sdk">Kailan gagamitin ang Agent SDK</h2>

Gumamit ng Agent SDK kapag kailangan ng iyong backend na i-bind ang partner user, ilipat ang mga asset sa aprubadong workflow, mag-query ng trading records, gumawa ng embedded trading entry URL, o mag-verify ng webhook notifications. Gamitin ang [Trading Widget SDK](/fil/sdk/trading-widget/overview) nang hiwalay kapag kailangang ipakita ng partner frontend ang trading interface.

<h2 id="common-configuration">Karaniwang konfigurasyon</h2>

| Susi | Halimbawa | Paglalarawan |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API service URL nang walang trailing slash. |
| agentCode | AGENT001 | Code ng partner agent. |
| apiSecret | iyong lihim na api | API lihim ng pagpirma na nakaimbak lamang sa backend. |
| defaultCurrency | USDT | Default na pera para sa transfer at account APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Partner endpoint para sa 6MM webhook notifications. |

<h2 id="typical-integration-flow">Karaniwang daloy ng integrasyon</h2>

1. Ang partner frontend ay nag-authenticate sa user sa pamamagitan ng sariling account system ng partner.
2. Ang partner backend ay nagma-map sa user sa isang stable partner-side identifier.
3. Ang backend ang tumatawag sa Agent SDK na may `agentCode` at protektadong API secret.
4. Pipirmahan at ipinapadala ng SDK ang kahilingan API Ahente.
5. Ang backend ay nag-iimbak ng ibinalik na business identifier at pinoproseso ang mga webhook nang pare-pareho.
6. Ang frontend ay tumatanggap lamang ng panandaliang resulta o entry credential na kailangan nito.

<h2 id="production-checklist">Listahan ng produksyon</h2>

- I-load ang `apiSecret` mula sa backend secret manager, hindi mula sa source code.
- Panatilihing hiwalay ang development, staging, at production credentials.
- Gumamit ng matatag na partner user mapping at natatanging business order identifiers.
- Panatilihin ang orihinal na identifier kapag sinusuri ang status ng timed-out request.
- Beripikahin ang mga webhook signature at itago ang mga naprosesong event ID.
- I-redact ang mga sikreto at pirma mula sa mga log habang pinananatili ang mga request ID para sa suporta.
