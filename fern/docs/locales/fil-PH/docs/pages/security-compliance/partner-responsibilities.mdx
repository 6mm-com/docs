Ang malinaw na modelo ng responsibilidad ay nagpapababa ng operational risk at tumutulong sa mga support team na mas mabilis tumugon.

<h2 id="responsibility-split">Hati ng Responsibilidad</h2>

| Lugar | 6MM | Kasosyo |
| --- | --- | --- |
| Imprastraktura ng kalakalan | Mga kakayahan sa pagtutugma, panganib, trading engine, API at SDK | Tamang integrasyon at pagmamanman ng produksyon |
| Relasyon ng end-user | Walang direktang relasyon sa customer maliban kung hiwalay na napagkasunduan | Onboarding ng user, suporta, pagsisiwalat, at lifecycle ng account |
| Mga lihim at kredensyal | Nagbibigay ng modelo ng kredensyal at mga kinakailangan sa pagpirma | Ligtas na nag-iimbak ng mga lihim at nililimitahan ang internal na access |
| Webhooks | Nagpapadala ng signed lifecycle events | Sinusuri ang mga pirma at pinoproseso ang mga kaganapan nang idempotensyal |
| Mga operasyon sa pagsunod | Nagbibigay ng teknolohiyang nakatuon sa pagsunod at mga materyales sa suporta | Kinukumpirma ang mga lokal na obligasyon at mga pangangailangan na nakatuon sa gumagamit |
| Mga Integration Release | Pinapanatili ang dokumentadong mga kakayahan sa platform at integrasyon | Sinusubukan ang code ng partner, configuration, at mga paglalakbay ng user bago ilabas |
| Paghawak ng insidente | Iniimbestigahan ang kaugnay na 6MM infrastructure at nagbibigay ng mga channel ng suporta sa partner | Natutukoy ang epekto na nakaharap sa user, pinapanatili ang ebidensya, naglalaman ng partner systems, at nag-eescalate |

<h2 id="responsibilities-by-lifecycle">Mga Responsibilidad ayon sa lifecycle</h2>

| Entablado | Aksyon ng Partner |
| --- | --- |
| Disenyo | Tukuyin ang pagmamay-ari ng user, daloy ng asset, daloy ng datos, modelo ng suporta, at target na hurisdiksyon. |
| Build | Panatilihin ang mga lihim sa backend, ipatupad ang suportadong authentication, at panatilihin ang mga business identifier. |
| Pagsubok | Mag-ehersisyo ng timeout, retry, duplicate-webhook, expired-token, at mga senaryo ng pagkabigo. |
| Paglulunsad | Kumpletong pagsusuri ng kahandaan, pagtatatag ng monitoring, at pag-escalate ng suporta sa dokumento. |
| Patakbuhin | Suriin ang mga alerto, ayusin ang mga abnormal na operasyon, i-rotate ang mga kredensyal, at panatilihin ang ebidensya ng audit. |
| Insidente | Magkaroon ng mga sistemang kontrolado ng partner, protektahan ang mga kredensyal, panatilihin ang UTC timeline, at makipag-ugnayan sa tamang 6MM channel. |

<h2 id="handoff-checklist">Checklist ng operasyonal na handoff</h2>

- Tukuyin ang may-ari para sa integration health, security, compliance, at end-user support.
- Idokumento ang production base URLs, mga may-ari ng kredensyal, at mga proseso ng rotation.
- Kumpirmahin ang mga dashboard at alerto para sa authentication, order, transfer, at webhook failures.
- I-store ang request IDs, partner order numbers, at event IDs sa searchable logs.
- Tukuyin kung aling mga pangyayari ang nangangailangan ng agarang pag-escalate.
- Panatilihing available ang [Support Request Template](/fil/resources/support-request-template) sa operations team.
