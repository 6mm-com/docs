Un exchange white label requiere más que un shell frontend. La experiencia del usuario depende de módulos centrales fiables detrás de la operación, cuentas, riesgo y liquidación.

<h2 id="core-modules">Módulos principales</h2>

| Módulo | Función |
| --- | --- |
| Coincidencia y ciclo de vida de pedidos | Se encarga de la presentación de pedidos, estado coincidente, cancelación y registros de ejecución. |
| Sistema de cuentas y posiciones | Mantiene saldos, estado de márgenes, posiciones y disponibilidad de operaciones. |
| Controles de riesgos | Coordina apalancamiento, margen, liquidación y comportamiento anormal del mercado. |
| Datos de mercado | Distribuye precios, profundidad, operaciones y datos gráficos a las interfaces de trading. |
| Asentamiento y registros | Mantiene alineado el historial de operaciones, los cambios de saldo y los registros operativos. |

<h2 id="implementation-questions">Preguntas sobre la implementación</h2>

- ¿Qué tipos de orden y condición-orden están expuestos a los usuarios?
- ¿Qué servicio posee las reglas de símbolos, la validación de precisión y la disponibilidad de negociación?
- ¿Cómo se concilian los registros de órdenes, comercio, posición, saldo y liquidación?
- ¿Qué identificadores permanecen estables a lo largo de REST respuestas, eventos WebSocket y registros de socios?
- ¿Qué ruta de monitorización y retroceso se aplica cuando la coincidencia, el riesgo o los datos de mercado no están disponibles?

Responde a estas preguntas antes del desarrollo frontend para que el comportamiento del producto, la gestión API , las operaciones y el soporte usen el mismo modelo de trading.
