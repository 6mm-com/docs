<h2 id="recommended-combination">Combinación recomendada</h2>

| Objetivo de pareja | Frontend | Backend | Por qué es importante |
| --- | --- | --- | --- |
| Añadir un terminal de trading integrado | Trading Widget SDK | Agent SDK | El widget gestiona la interfaz de trading mientras el backend asociado emite tokens y mantiene los secretos privados. |
| Crea un punto de entrada nativo para la aplicación | Entrada nativa o H5 | Agent SDK | La app abre una URL de entrada 6MM después de que el socio valide la sesión de usuario. |
| Crea un flujo de trading personalizado | Interfaz de usuario asociada | Revelador API + flujos de SDK seleccionados | Utiliza APIs para datos de cuenta, pedidos, posición y mercado mientras mantienes los controles operativos en el lado del servidor. |

<h2 id="reference-architecture">Arquitectura de referencia</h2>

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Guarda secretos en el servidor**
>
> El código del navegador solo debería llamar a los endpoints propiedad del socio. El secreto del Agente API nunca debe enviarse al código frontend.

<h2 id="production-checklist">Lista de verificación de producción</h2>

- Almacenar apiSecret solo en infraestructura backend.
- Utilizar HTTPS para solicitudes de API de agente y URLs de webhook.
- Persistir agentUserId, platformUserId, y agentOrderNo mapeos.
- Representar cantidades monetarias como cadenas decimales en lugar de valores en coma flotante.
- Tratar PROCESSING como pendientes, no como éxito o fracaso.
- Procesar webhooks idempotentes porque se esperan reintentos.
