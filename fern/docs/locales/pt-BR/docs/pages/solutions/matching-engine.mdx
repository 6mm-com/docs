Uma exchange white label requer mais do que um shell frontend. A experiência do usuário depende de módulos centrais confiáveis por trás de negociação, contas, risco e liquidação.

<h2 id="core-modules">Módulos centrais</h2>

| Módulo | Função |
| --- | --- |
| Correspondência e ciclo de vida dos pedidos | Gerencia o envio de pedidos, estado correspondente, cancelamento e registros de execução. |
| Sistema de contas e posições | Mantém saldos, estado de margem, posições e disponibilidade de negociação. |
| Controles de risco | Coordena alavancagem, margem, liquidação e comportamento anormal de mercado. |
| Dados de mercado | Distribui preços, profundidade, operações e dados gráficos para interfaces de negociação. |
| Assentamento e registros | Mantém o histórico de negociação, mudanças de saldo e registros operacionais alinhados. |

<h2 id="implementation-questions">Perguntas sobre implementação</h2>

- Quais tipos de ordem e condição-ordem são expostos aos usuários?
- Qual serviço possui regras de símbolos, validação de precisão e disponibilidade de negociação?
- Como são conciliados os registros de ordens, comércio, posição, saldo e liquidação?
- Quais identificadores permanecem estáveis em respostas REST , eventos WebSocket e registros de parceiros?
- Qual caminho de monitoramento e rollback se aplica quando dados de correspondência, risco ou mercado deixam de estar disponíveis?

Responda a essas perguntas antes do desenvolvimento frontend para que o comportamento do produto, API o manuseio, operações e suporte usem o mesmo modelo de negociação.
