Embedded trading jest zazwyczaj wprowadzany do istniejącego produktu, a nie uruchamiany jako samodzielny cel. Najlepsza ścieżka integracji zależy od tego, gdzie użytkownicy już spędzają czas oraz który system posiada tożsamość, fundusze i operacje.

<span id="common-scenarios" data-sixmm-canonical-anchor="common-scenarios" aria-hidden="true"></span>

## Typowe scenariusze

| Scenariusz | Najlepszy punkt wyjścia | Przypisy |
| --- | --- | --- |
| Aplikacja lub portfel wymaga wpisu handlowego | Trading Widget SDK | Użyj natywnego lub H5 punktu wejścia i otwórz wbudowane doświadczenie handlowe po autoryzacji użytkownika. |
| Broker lub platforma kanałowa chce dostępu do instrumentów pochodnych | Agent SDK + Trading Widget SDK | Utrzymuj relacje z klientem i weryfikację backendu w systemie partnerskim. |
| Platforma potrzebuje prowadzonego przepływu handlu | API + wybranych SDK modułów | Używaj API backendu do obsługi kont, transferów i zamówień, udostępniając tylko niezbędne wpisy frontendowe. |
| Istniejąca giełda chce dodatkowych rynków | Płynność + integracja API | Połącz głębokość rynku, workflow konta oraz monitorowanie operacyjne. |

<span id="product-decisions-before-integration" data-sixmm-canonical-anchor="product-decisions-before-integration" aria-hidden="true"></span>

## Decyzje produktowe przed integracją

- Decydować, czy użytkownicy wchodzą z karty strony głównej, strony zasobów, strony kampanii lub centrum konta.
- Decydować, który system jest właścicielem stanu logowania, uprawnienia użytkownika oraz dostępności w kraju lub regionie.
- Decydować, jak przekazy transferów, zapisy rozliczeń i zgłoszenia do obsługi klienta są wyświetlane użytkownikom.
- Decydować, które zdarzenia muszą zostać przekazane do analityki wewnętrznej, CRMlub operacji ryzyka.
