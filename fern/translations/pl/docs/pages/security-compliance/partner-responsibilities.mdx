Jasny model odpowiedzialności zmniejsza ryzyko operacyjne i pomaga zespołom wsparcia szybciej reagować.

<span id="responsibility-split" data-sixmm-canonical-anchor="responsibility-split" aria-hidden="true"></span>

## Podział odpowiedzialności

| Obszar | 6MM | Partner |
| --- | --- | --- |
| Infrastruktura handlowa | Dopasowywanie ofert, ryzyko, silnik handlowy, API i SDK możliwości | Prawidłowa integracja i monitorowanie produkcji |
| Relacja użytkownika końcowego | Brak bezpośredniej relacji z klientem, chyba że osobno się zgadniemy | Onboarding użytkowników, wsparcie, ujawnienia i cykl życia konta |
| Sekrety i kwalifikacje | Dostarcza model uwierzytelniania oraz wymagania dotyczące podpisywania | Bezpiecznie przechowuje sekrety i ogranicza dostęp wewnętrzny |
| Webhooki | Wysyła podpisane zdarzenia cyklu życia | Weryfikuje sygnatury i przetwarza zdarzenia idempotentnie |
| Operacje zgodności | Dostarcza technologie i materiały wspierające zgodne z przepisami | Potwierdza lokalne zobowiązania i wymagania dotyczące kontaktu z użytkownikami |
| Wydania integracyjne | Utrzymuje udokumentowane możliwości platformy i integracji | Testuje kod partnera, konfigurację i ścieżki użytkownika przed wydaniem |
| Obsługa incydentów | Bada istotne 6MM infrastruktury i zapewnia kanały wsparcia partnerów | Wykrywa wpływ skierowany do użytkownika, zachowuje dowody, zawiera systemy partnerskie i eskaluje |

<span id="responsibilities-by-lifecycle" data-sixmm-canonical-anchor="responsibilities-by-lifecycle" aria-hidden="true"></span>

## Obowiązki według cyklu życia

| Scena | Działanie partnera |
| --- | --- |
| Konstrukcja | Zdefiniuj własność użytkowników, przepływ zasobów, przepływ danych, model wsparcia oraz jurysdykcje docelowe. |
| Buduj | Zachowaj tajemnice na zapleczu, wprowadź wspieraną autoryzację i zachowaj identyfikatory biznesowe. |
| Test | Ćwicz timeout, próbę ponowną, duplikowanie webhooka, wygasłego tokena i scenariusze niepowodzenia. |
| Start | Przeprowadz przegląd gotowości, ustalenie monitoringu i dokumentowanie eskalacji wsparcia. |
| Operuj | Przeglądaj alerty, uzgadniaj nieprawidłowe operacje, rotuj dane uwierzytelniające i utrzymuj dowody audytowe. |
| Incydent | Zawieraj systemy kontrolowane przez partnerów, chroń dane uwierzytelniające, zachowaj UTC terminy i kontaktuj się z odpowiednim kanałem 6MM . |

<span id="handoff-checklist" data-sixmm-canonical-anchor="handoff-checklist" aria-hidden="true"></span>

## Lista kontrolna operacyjnego przekazania

- Wskazywanie właściciela dla zdrowia integracji, bezpieczeństwa, zgodności i wsparcia użytkownika końcowego.
- Adresy URL do produkcji dokumentów, właściciele poświadczeń oraz procedury rotacji.
- Potwierdzaj pulpity i alerty dotyczące awarii uwierzytelniania, zamówienia, transferu i webhooków.
- Identyfikatory żądań pamięci, numery zamówień partnerów oraz identyfikatory zdarzeń w przeszukiwalnych logach.
- Określić, które zdarzenia wymagają natychmiastowej eskalacji.
- Utrzymywanie dostępności [szablonu żądania wsparcia](/pl/resources/support-request-template) dla zespołu operacyjnego.
