Przygotowanie do zabezpieczenia rozpoczyna się od wybranego ustalenia dotyczącego opieki. Ochrona konta, zatwierdzanie transakcji, MPC uczestnictwo i odzyskiwanie materiałów służą różnym celom.

<span id="assign-responsibilities" data-sixmm-canonical-anchor="assign-responsibilities" aria-hidden="true"></span>

## Przypisz obowiązki

Oddzielne rutynowe przeglądanie, inicjowanie transferu, zatwierdzanie, administrowanie członkami i zarządzanie referencjami programistów, jeśli produkt na to pozwala. Sprawdź uprawnienia w zamierzonym obszarze roboczym; dostęp do jednego obszaru roboczego nie ustanawia władzy nad innym.

W przypadku przepływów pracy w przedsiębiorstwie ustal, kto sprawdza zmiany miejsca docelowego i żądania wychodzące. Aby podpisać urządzenie, uczestnik powinien przed zaakceptowaniem sprawdzić wyświetlaną sieć, zasób, kwotę, miejsce docelowe i kontekst. Potwierdzenia urządzenia nie należy traktować jako ślepej prośby o zatwierdzenie.

## Zachowaj odrębność poświadczeń

| Tworzywo | Zamiar |
| --- | --- |
| Uwierzytelnianie konta | Uzyskaj dostęp do aplikacji użytkownika |
| API klucz i sekret | Uwierzytelnij żądania backendu API. |
| Klucz autoryzacyjny klienta | Autoryzuj treść wypłaty API, jeśli jest to wymagane |
| MPC udział klucza | Weź udział w rozproszonym procesie podpisywania portfela |
| Materiały do ​​tworzenia kopii zapasowych i odzyskiwania | Przywróć uczestnictwo lub wykonaj obsługiwaną procedurę odzyskiwania |

Przechowuj je zgodnie z własnymi obowiązkami. Klucz API nie jest udziałem MPC; resetowanie hasła do konta nie jest operacją odzyskiwania portfela. Przesyłaj klucze publiczne wyłącznie w ramach odpowiedniego procesu rejestracji, nigdy odpowiadające im klucze prywatne.

<span id="prepare-recovery-before-use" data-sixmm-canonical-anchor="prepare-recovery-before-use" aria-hidden="true"></span>

## Przygotuj regenerację przed użyciem

Zapisz wymaganych uczestników, właścicieli kopii zapasowych i kroki odzyskiwania podczas wdrażania. Przechowuj kopie zapasowe w oddzielnych, odpowiednich lokalizacjach i przetestuj obsługiwaną procedurę odzyskiwania w kontrolowanym środowisku. Weź pod uwagę zarówno zagubione urządzenie, jak i awarię usługi platformy.

Samodzielne przechowywanie kluczy nie pozwala platformie na odtworzenie brakujących udziałów klientów. Jeśli pozostanie zbyt mało użytecznych uczestników i kopii zapasowych, aby spełnić wymagania portfela, dostęp do zasobów może zostać utracony. Wspólne przechowywanie kluczy również wymaga udokumentowanej umowy o odzyskaniu opieki; nie zakładaj, że uczestnictwo w platformie gwarantuje odzyskanie sprawności.

<span id="handle-an-unavailable-participant" data-sixmm-canonical-anchor="handle-an-unavailable-participant" aria-hidden="true"></span>

## Obsługuj niedostępnego uczestnika

Najpierw rozróżnij tymczasowy problem z połączeniem, niedostępne urządzenie i utracony materiał do podpisu. Przejrzyj sesję i stan urządzenia, a następnie skorzystaj z obsługiwanego procesu odzyskiwania lub wymiany. Nie wymazuj urządzenia, nie zmieniaj jego tożsamości podpisywania aplikacji ani nie zakładaj, że udziały można przenieść przed sprawdzeniem wymagań dotyczących odzyskiwania.

Dostępność kopii zapasowej nie jest dowodem ukończenia testu odzyskiwania. Zanim zaczniesz na nich polegać, sprawdź, jakie procedury i narzędzia są zawarte w Twojej wersji.
