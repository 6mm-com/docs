## Zalecany tryb: token partnera

partner-token pozwala uniknąć umieszczania krótkich tokenów w adresach URL i przechowuje apiSecret na zapleczu partnera.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'partner-token',
    tokenProvider: async ({ channelId, symbol, reason }) => {
      const resp = await fetch('/api/trading/embed-token', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ channelId, symbol, reason }),
      })

      if (!resp.ok) {
        throw new Error('Failed to request embed token')
      }

      return resp.json()
    },
  },
})
```

<span id="backend-flow" data-sixmm-canonical-anchor="backend-flow" aria-hidden="true"></span>

## Przepływ backendu

```text
1. Partner frontend receives auth_request from the iframe.
2. SDK calls tokenProvider.
3. Partner frontend calls its own backend.
4. Partner backend validates the partner session.
5. Partner backend calls 6MM Agent API or Java SDK createEmbedToken.
6. SDK sends embedToken to the iframe through postMessage.
7. iframe exchanges embedToken for a 6MM access token.
8. iframe continues initialization and emits ready.
```

<span id="tokenprovider-contract" data-sixmm-canonical-anchor="tokenprovider-contract" aria-hidden="true"></span>

## tokenProvider umowa

| Pole | Kierunek | Opis |
| --- | --- | --- |
| channelId | SDK -> Zaplecze partnera | Unikalny identyfikator sesji widgetu. Backend powinien przekazać go do createEmbedToken. |
| symbol | SDK -> Zaplecze partnera | Aktualnie żądany symbol handlowy. Użyj go, aby w razie potrzeby określić zakres tokena. |
| powód | SDK -> Zaplecze partnera | Dlaczego SDK żąda tokena, takiego jak początkowe ładowanie lub odświeżenie. |
| embedToken | Zaplecze partnera -> SDK | Token krótkotrwały utworzony przez Agent SDK lub Agenta API. |
| expireAt | Zaplecze partnera -> SDK | Sygnatura czasowa wygaśnięcia tokena zwrócona przez 6MM. |

<span id="failure-handling" data-sixmm-canonical-anchor="failure-handling" aria-hidden="true"></span>

## Obsługa awarii

| Stan | Zalecana obsługa |
| --- | --- |
| Sesja partnera wygasła | Zwróć 401 z punktu końcowego partnera i poproś użytkownika o ponowne zalogowanie się. |
| Utworzenie tokena tymczasowo nie powiodło się | Zgłoś błąd w tokenProvider i pozwól widżetowi wyświetlić błąd uwierzytelnienia. |
| channelId niezgodność | Odrzuć żądanie i utwórz ponownie instancję widżetu. |
| Użytkownikowi nie wolno handlować | Zwróć błąd kontrolowany przez partnera i nie twórz tokena osadzania. |

## Tryb zgodności: agent-sso

agent-sso utrzymuje przepływ starszych biletów /agent-entry. Preferuj token partnera w przypadku nowych integracji.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'agent-sso',
    entryUrlProvider: async ({ redirectPath }) => {
      const resp = await fetch('/api/trading-entry', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ redirectPath }),
      })
      const data = await resp.json()
      return data.webUrl
    },
  },
})
```

## Handel sekundami i zasady ochrony środowiska

W przypadku stron sekundowych użyj tego samego uwierzytelniania `partner-token` z `page` i `tradingMode` skonfigurowanymi w Widgecie. Nie ma osobnego tokena przewidywania. Każde wywołanie tokenProvider musi uzyskać nowy jednorazowy token z Twojego backendu.

Zwróć `embedToken`, `expireAt` w uniksowych sekundach i oryginalny `channelId` jako obiekt najwyższego poziomu. Odpowiedź tokena Agent SDK nie zawiera `channelId`; Twój backend odzwierciedla bieżący kanał Widget. Jeśli Twój punkt końcowy zawija odpowiedzi w `data`, rozpakuj go przed powrotem z tokenProvider.
