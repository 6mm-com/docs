Zacznij od środowiska, sygnatury czasowej i identyfikatora biznesowego operacji, która nie powiodła się. Kontrola strukturalna zwykle oddziela problemy konfiguracyjne od problemów z uwierzytelnianiem, siecią i przetwarzaniem asynchronicznym.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Zalecana kolejność diagnostyki

1. Potwierdź dotknięte środowisko i bazę URL.
2. Zapisz zakres czasu UTC i pierwsze nieudane żądanie.
3. Zidentyfikuj moduł: Trading Widget, Agent SDK, REST API, WebSocket lub webhook.
4. Przechwyć identyfikator żądania, identyfikator użytkownika partnera, `agentOrderNo`, identyfikator zamówienia lub webhook identyfikator zdarzenia.
5. Sprawdź najnowszy kod, dane uwierzytelniające, białą listę IP lub zmiany we wdrożeniu.
6. Odtwórz za pomocą najmniejszego bezpiecznego przypadku testowego.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget problemy

| Objaw | Prawdopodobna przyczyna | Naprawić |
| --- | --- | --- |
| iframe żąda domeny lokalnej partnera | Brakuje baseUrl. | Przekaż baseUrl: „https://app.6mm.com”. |
| iframe jest niewidoczny lub bardzo krótki | Kontener nadrzędny nie ma wysokości | Ustaw wysokość kontenera lub wysokość przejścia. |
| token_provider_missing | tryb tokenu partnera nie ma dostawcy | Dodaj autoryzacjętokenProvider. |
| auth_exchange_failed | Nieprawidłowy, wygasły lub niezgodny token osadzania | Sprawdź odpowiedź tokena zaplecza i channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK problemy

| Objaw | Prawdopodobna przyczyna | Naprawić |
| --- | --- | --- |
| Podpis odrzucony | Zły sekret, przesunięcie zegara lub ręcznie zmienione podpisane pola | Pozwól SDK wygenerować pola podpisywania i zsynchronizować czas serwera. |
| Ryzyko duplikowania przepływu środków | Nowy numer zamówienia użyty po przekroczeniu limitu czasu | Najpierw zapytaj o oryginał agentOrderNo. |
| PROCESSING traktowane jako awaria | Stan oczekujący został źle zrozumiany | Poczekaj na webhook lub zadzwoń do queryOrder. |
| Webhook przetworzone wielokrotnie | Ponów próbę bez idempotencji | Dodaj klucz idempotencji i kontrole stanu końcowego. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Dowody do przechwycenia

| Integracja | Przydatne dowody |
| --- | --- |
| Trading Widget | Strona URL, SDK ścieżka wersji, konsola przeglądarki, nieudane żądania sieciowe, `onError` ładunek i wymiary kontenera. |
| Agent SDK | SDK język/wersja, baza URL, UTC sygnatura czasowa, identyfikator żądania, `agentOrderNo`, kod odpowiedzi i oczyszczone logi. |
| Webhook | Czas dostawy, zdarzenie lub klucz biznesowy, wynik weryfikacji podpisu, stan przetwarzania i oczyszczony skrót typu raw. |
| REST API | Metoda, ścieżka, środowisko, identyfikator żądania, kod odpowiedzi i oczyszczone parametry. |

Nigdy nie uwzględniaj w diagnostyce haseł, tokenów dostępu, API tajnych danych, pełnych podpisów, kluczy prywatnych ani niezmienionych danych osobowych.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Przed eskalacją

- Ponów próbę tylko wtedy, gdy operacja zostanie udokumentowana jako bezpieczna.
- Po upływie limitu czasu zamiast tworzyć nowy, prześlij zapytanie do pierwotnego identyfikatora firmy.
- Sprawdź, czy zegar systemowy i środowisko poświadczeń zawierają błędy podpisu.
- Zachowaj pierwsze niepowodzenie i wszelkie późniejsze wyniki ponowienia.
- Skorzystaj z [Szablon żądania wsparcia](/pl/resources/support-request-template) o przesłanie kompletnego, zredagowanego raportu.

## Java diagnostyka v0.3.0

| Objaw | Sprawdź i odzyskaj |
| --- | --- |
| Żądanie o finansowanie ma nieznany wynik | Zachowaj oryginał `agentOrderNo`; wywołaj `queryWalletTransfer` w oryginalnym środowisku. Nie używaj `queryOrder`. |
| Interfejs symulacji pokazuje nieoczekiwane środki | Sprawdź frontend `tradingMode` oddzielnie od backendu `environment`; konto `isSimulatedUser` nie kieruje żądań. |
| Błąd zapytania `6905` | Wycofaj się, korzystając z limitu partnera współdzielonego, a następnie spróbuj ponownie użyć tego samego kursora i przefiltrować SDK. |
| Błąd zapytania `6904` | Zmniejsz liczbę jednoczesnych zapytań i zawęź okno czasowe; skontaktuj się z pomocą techniczną, jeśli problem będzie się utrzymywać. |
| Nieprawidłowy lub wygasły kursor | Uruchom ponownie to samo stałe okno historii i usuń duplikaty zapisanych rekordów. |
| Brakuje nowej metody Java. | Sprawdź rozwiązany artefakt Mavena pod kątem tagu publicznego `v0.3.0`; usuń sprzeczne zależności zgodnie z zasadami dotyczącymi artefaktów. |
