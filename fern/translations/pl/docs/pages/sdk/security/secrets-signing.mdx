Żądania Agent SDK są uwierzytelniane przy użyciu sekretu partnera API. Zachowaj ten sekret w zaufanej usłudze zaplecza i pozwól SDK wygenerować pola do podpisu, jeśli to możliwe.

> **Dwa protokoły podpisywania**
>
> Podpisywanie Agent SDK wykorzystuje posortowane pola żądań, znacznik czasu oparty na sekundach i wartość jednorazową. Bezpośrednie żądania Developer API korzystają z osobnego procesu opisanego w [Poproś o podpisanie](/pl/developer-api/request-signing). Nie używaj ponownie jednego formatu ładunku dla drugiego.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## Zasada podpisywania

W przypadku żądań Agent SDK:

1. Wyklucz pole `sign`.
2. Pomiń pola z pustymi wartościami.
3. Posortuj pozostałe nazwy pól w kolejności ASCII.
4. Połącz pola jako `k=v&k2=v2`.
5. Oblicz HMAC-SHA256 podpis szesnastkowy za pomocą `apiSecret`.

Wartości tablicy są serializowane jako kompaktowe JSON przed dołączeniem do ładunku podpisującego. Na przykład `platformUserIds` znakuje jako `["1188041528"]`, podając `platformUserIds=["1188041528"]` w ładunku `k=v`. Zachowaj kolejność elementów tablicy, podwójne cudzysłowy i identyfikatory ciągów; nie wstawiaj spacji formatujących ani nie używaj Java `List.toString()` (np. `[1188041528]`). SDK automatycznie obsługuje tę serializację.

SDK powinien zbudować tę wartość na podstawie tych samych danych, które wysyła. Zmiana podpisanego pola po wygenerowaniu podpisu powoduje niepowodzenie weryfikacji.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## SDK-zarządzane pola

| Pole | Źródło | Opis |
| --- | --- | --- |
| agentCode | SDK konfiguracja | Kod agenta partnerskiego. |
| znacznik czasu | Aktualny czas serwera | Znacznik czasu Uniksa w sekundach. |
| chwilowo | Bezpieczna wartość losowa | Losowy ciąg znaków chroniący przed ponownym odtwarzaniem. |
| podpisać | HMAC-SHA256 | Poproś o podpis. |
| waluta | Domyślna waluta | Używane, gdy przelew/konto APIs pomija walutę. |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## Tajne przechowywanie

- Załaduj `apiSecret` z menedżera tajnych danych zaplecza lub konfiguracji chronionego środowiska wykonawczego.
- Nigdy nie umieszczaj sekretu w pakietach frontendowych, aplikacjach mobilnych, klientach stacjonarnych, zrzutach ekranu lub zgłoszeniach pomocy technicznej.
- Trzymaj oddzielnie dane uwierzytelniające do programowania, testowania i produkcji.
- Ogranicz dostęp do usług i operatorów, którzy tego wymagają.
- Redaguj podpisy żądań, wartości autoryzacji i wpisy tajne z dzienników.
- Jeśli istnieje podejrzenie narażenia, unieważnij i zastąp dane uwierzytelniające.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Ochrona zegara i odtwarzania

SDK obejmuje `timestamp` i `nonce`, aby zmniejszyć ryzyko powtórki. Synchronizuj zegary zaplecza i nie używaj ponownie ręcznie skonstruowanej wartości jednorazowej. Jeśli weryfikacja podpisu nie powiedzie się, przed ponowną próbą potwierdź skonfigurowany klucz tajny, czas serwera, pola serializowane i środowisko.

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## Lista kontrolna integracji

| Sprawdzać | Oczekiwany wynik |
| --- | --- |
| Tajna lokalizacja | Tajny magazyn przeznaczony wyłącznie dla zaplecza. |
| Środowisko | Baza URL i dane uwierzytelniające należą do tego samego środowiska. |
| Obsługa w terenie | SDK generuje `timestamp`, `nonce` i `sign`. |
| Wycięcie lasu | Identyfikatory firm pozostają widoczne, gdy dane uwierzytelniające zostaną usunięte. |
| Obrót | Właściciel danych uwierzytelniających i proces wymiany są udokumentowane. |
