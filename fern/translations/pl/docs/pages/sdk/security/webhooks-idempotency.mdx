Webhooks powiadom zaplecze partnera o asynchronicznych zmianach stanu biznesowego. Ponieważ można ponowić próbę dostarczenia, każdy odbiorca musi zweryfikować podpis przed przeanalizowaniem zaufanych danych i musi przetworzyć zdarzenie idempotentnie.

<span id="webhook-headers" data-sixmm-canonical-anchor="webhook-headers" aria-hidden="true"></span>

## Webhook nagłówki

| Chodnikowiec | Opis |
| --- | --- |
| Znacznik czasu X-Agent | Znacznik czasu Uniksa w sekundach. |
| X-Agent-Nonce | Nonce chroniący przed powtórzeniem. |
| Podpis X-Agenta | HMAC-SHA256 podpis. |

```text
timestamp + nonce + rawBody
```

Podczas rekonstruowania podpisanej wartości użyj dokładnej nieprzetworzonej treści żądania otrzymanej w ciągu HTTP. Analiza i ponowna serializacja JSON może najpierw zmienić białe znaki lub kolejność pól i wygenerować inny podpis.

<span id="verification-flow" data-sixmm-canonical-anchor="verification-flow" aria-hidden="true"></span>

## Przepływ weryfikacji

1. Przeczytaj znacznik czasu, wartość jednorazową i nagłówki podpisu.
2. Przechwyć niezmodyfikowaną surową treść żądania.
3. Zbuduj `timestamp + nonce + rawBody`.
4. Oblicz HMAC-SHA256 z partnerem API sekretem.
5. Porównaj obliczone i otrzymane podpisy, korzystając z porównania w czasie stałym.
6. Zastosuj zatwierdzone kontrole aktualności sygnatury czasowej i kontroli jednorazowego ponownego użycia.
7. Analizuj i przetwarzaj zdarzenie dopiero po pomyślnej weryfikacji.

Gdy dostępny jest oficjalny weryfikator Agent SDK, użyj go zamiast utrzymywać niezależny kod podpisujący.

<span id="order-idempotency" data-sixmm-canonical-anchor="order-idempotency" aria-hidden="true"></span>

## Zamów idempotencję

| Sprawa | Obsługiwanie |
| --- | --- |
| Wstępna prośba o przeniesienie | Utwórz jeden, unikalny na całym świecie agentOrderNo. |
| HTTP przekroczenie limitu czasu | Zapytaj o oryginał agentOrderNo przed utworzeniem nowego. |
| PROCESSING odpowiedź | Poczekaj na webhook lub zapytaj o status zamówienia. |
| Powtarzane webhook | Deduplikacja według klucza idempotencji i statusu końcowego. |

<span id="recommended-idempotency-record" data-sixmm-canonical-anchor="recommended-idempotency-record" aria-hidden="true"></span>

## Zalecany rekord idempotencji

Przechowuj wystarczającą ilość informacji, aby rozpoznać powtarzającą się dostawę i bezpiecznie odzyskać:

| Pole | Zamiar |
| --- | --- |
| Wydarzenie lub klucz biznesowy | Unikalnie identyfikuje powiadomienie lub operację. |
| Numer zamówienia partnera | Łączy wydarzenie z pierwotnym żądaniem. |
| Hash ładunku | Pomaga zidentyfikować sprzeczne, powtarzające się ładunki. |
| Bieżący stan przetwarzania | Rozróżnia pracę otrzymaną, przetworzoną, udaną i nieudaną. |
| Ostateczny status biznesowy | Zapobiega dwukrotnemu zastosowaniu akcji końcowej. |
| Przetworzony znacznik czasu | Obsługuje zasady dochodzenia i przechowywania. |

Jeśli to możliwe, zatwierdź zmiany biznesowe i rekord idempotencji w tej samej transakcji. Powtarzające się zdarzenie powinno zwrócić już znany wynik zamiast ponownego stosowania salda, kolejności lub zmiany użytkownika.

<span id="timeout-and-retry-rule" data-sixmm-canonical-anchor="timeout-and-retry-rule" aria-hidden="true"></span>

## Reguła limitu czasu i ponownej próby

Limit czasu HTTP nie oznacza, że ​​pierwotne żądanie nie powiodło się. Zapytaj o operację, używając oryginalnego `agentOrderNo` lub poczekaj na webhook, zanim podejmiesz decyzję, czy wymagane jest inne działanie. Utworzenie nowego numeru zamówienia biznesowego po każdym przekroczeniu limitu czasu może spowodować zdublowanie ruchów środków.

<span id="production-checklist" data-sixmm-canonical-anchor="production-checklist" aria-hidden="true"></span>

## Lista kontrolna produkcji

- Zweryfikuj podpis przed analizą JSON lub przetwarzaniem biznesowym.
- Zachowaj surową treść niezależnie od przeanalizowanego ładunku.
- Odrzucaj nieaktualne lub odtwarzane żądania zgodnie z zatwierdzoną polityką integracji.
- Zapewnij bezpieczeństwo przetwarzania zdarzeń w przypadku powtarzających się dostaw poza kolejnością.
- Rejestruj identyfikatory zdarzeń, numery zamówień partnerów, wyniki przetwarzania i czas żądania.
- Usuń sekrety i wartości podpisów z dzienników i załączników pomocy technicznej.

## Granice finansowania i środowiska

Pierwotny transfer umowy webhook i przepływ `queryOrder` nie mają automatycznego zastosowania do Finansowania. Potwierdź operacje finansowania przy użyciu `queryWalletTransfer` i oryginalnego środowiska zamówienia. Wykorzystanie środków finansowych `status`; oryginalne odpowiedzi na przeniesienie umowy używają `orderStatus`. Pomyślna odpowiedź HTTP lub `code=0` nie jest sama w sobie dowodem przesunięcia środków.

Jawne, symulowane powiadomienia o przeniesieniu kontraktu obejmują `environment=SIMULATED`. Najpierw zweryfikuj surową treść, a następnie sprawdź użytkownika, kwotę, tożsamość zamówienia i środowisko z zapisanym lokalnym zamówieniem biznesowym.
