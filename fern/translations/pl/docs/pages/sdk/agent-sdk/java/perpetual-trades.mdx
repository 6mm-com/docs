Ten przewodnik jest przeznaczony dla **Agent Java SDK `v0.3.0`**, Java 8+ i oznaczonych zamówień publicznych. Przykłady działają w zapleczu partnera po inicjalizacji `client` w [Szybki start](/pl/sdk/agent-sdk/java/quick-start).

## Przykładowe wymagania wstępne

Fragmenty Java dzielą ten import. Zainicjuj `client` za pomocą Szybki start i uzyskaj `platformUserId` z zapisanego powiązania. Przykładowe identyfikatory użytkowników/zamówień należy zastąpić własnymi, utrwalonymi wartościami.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

<span data-sixmm-canonical-anchor="listperpetualtrades" aria-hidden="true"></span>

## `listPerpetualTrades`

Zapytaj o model: `PerpetualTradesRequest`.

```java
import com.sixmm.agent.model.PerpetualTradesRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualTradesRequest request = new PerpetualTradesRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualTrades(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Pola żądania

| Pole | Java typ | Wymagany | Oznaczający |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Tak | Jawnie podaj 1–100 unikalnych identyfikatorów użytkowników platformy publicznej należących do bieżącego partnera; pominięcie i pusta tablica są nieprawidłowe. |
| `symbol` | `String` | NIE | Opcjonalny filtr par handlowych. |
| `orderId` | `String` | NIE | Zwykły identyfikator zamówienia; a nie numer zamówienia przeniesienia partnera. |
| `startTime` | `Long` | NIE | Włącznie z milisekundami Uniksa; użyj stałego okna historii UTC. |
| `endTime` | `Long` | NIE | Ekskluzywne milisekundy Uniksa. |
| `limit` | `Integer` | NIE | Domyślnie 500; 1–1000. |
| `cursor` | `String` | NIE | Użyj zwróconego nextCursor z niezmienionymi filtrami; przestań, gdy hasMore ma wartość fałszywą. |

Przykład czyta jedną stronę. Aby zapoznać się z wymaganymi polami, zakresem gracza, semantyką filtra, limitem, kursorem i ograniczonymi próbami, wykonaj następujące czynności [Przegląd zapytań](/pl/sdk/agent-sdk/java/perpetual-queries). Zachowaj wszystkie filtry niezmienione podczas stronicowania; nie interpretuj błędu jako pustego wyniku.

## Szczegóły wypełnienia transakcji

Interfejs: `trades`. Wymaga wyraźnego platformUserIds.

| Pole `data`. | typ | oznaczający |
| --- | --- | --- |
| `fillId` | string | Identyfikator szczegółów wypełnienia transakcji, odpowiadający temu rekordowi entityId |
| `tradeId` | string | Pasujący identyfikator transakcji powiązany z transakcją; nie zastępuje szczegółowego identyfikatora |
| `orderId` | string | Ogólny identyfikator zamówienia, do którego należy ten szczegół |
| `positionId` | string | Identyfikator powiązanego stanowiska |
| `symbol` | string | para handlowa |
| `side` | string | Kierunek kupna i sprzedaży tego gracza BUY / SELL |
| `roleType` | string | Znak transakcji tego gracza MAKER / TAKER |
| `positionSide` | string | Kierunek pozycji, objaśniony zgodnie z rzeczywistą wartością LONG / SHORT / BOTH itd. |
| `price` | string | Ta cena transakcyjna |
| `quantity` | string | Ilość tej transakcji nie jest całkowitą ilością pierwotnego zamówienia. |
| `tradeValue` | string | Wartość nominalna tej transakcji wynika z nominału transakcji |
| `handlingFee` | string | Opłata transakcyjna za tę transakcję zachowuje symbol źródłowy i dokładność i sama w sobie nie przyjmuje wartości bezwzględnej. |
| `realizedPnl` | string | Zrealizowane zyski i straty odpowiadające tej transakcji; a nie zmienny zysk i strata bieżącej pozycji w czasie rzeczywistym |
| `tradedAt` | integer | Czas transakcji, milisekundy; użyj tego pola do filtrowania czasu |

Zamówienie może mieć wiele wypełnień, które należy szczegółowo zapisać. Nie łącz rekordów różnych graczy/nie wypełniaj ról do tradeId, a następnie odrzucaj ich tożsamości rekordowe.
