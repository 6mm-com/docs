Ten przewodnik jest przeznaczony dla **Agent Java SDK `v0.3.0`**, Java 8+ i oznaczonych zamówień publicznych. Przykłady działają w zapleczu partnera po inicjalizacji `client` w [Szybki start](/pl/sdk/agent-sdk/java/quick-start).

<span id="example-prerequisites" data-sixmm-canonical-anchor="example-prerequisites" aria-hidden="true"></span>

## Przykładowe wymagania wstępne

Fragmenty Java dzielą ten import. Zainicjuj `client` za pomocą Szybki start i uzyskaj `platformUserId` z zapisanego powiązania. Przykładowe identyfikatory użytkowników/zamówień należy zastąpić własnymi, utrwalonymi wartościami.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

<span data-sixmm-canonical-anchor="listcurrentperpetualorders" aria-hidden="true"></span>

## `listCurrentPerpetualOrders`

Zapytaj o model: `CurrentPerpetualOrdersRequest`.

```java
import com.sixmm.agent.model.CurrentPerpetualOrdersRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

CurrentPerpetualOrdersRequest request = new CurrentPerpetualOrdersRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.orderCategory = "NORMAL";
request.symbol = "BTCUSDT";
PerpetualResponse response = client.listCurrentPerpetualOrders(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Pola żądania

| Pole | Java typ | Wymagany | Oznaczający |
| --- | --- | --- | --- |
| `orderCategory` | `String` | Tak | NORMAL lub CONDITIONAL; zapytania warunkowe wymagają jawnych użytkowników. |
| `platformUserIds` | `java.util.List<String>` | Warunkowy | 1–100 unikalnych identyfikatorów publicznych; wymagane w przypadku wypełnień i zamówień warunkowych. Pomiń obsługiwane zapytania w zakresie bezpośredniego gracza; [] jest nieprawidłowe. |
| `symbol` | `String` | NIE | Opcjonalny filtr par handlowych. |
| `limit` | `Integer` | NIE | Domyślnie 500; 1–1000. |
| `cursor` | `String` | NIE | Użyj zwróconego nextCursor z niezmienionymi filtrami; przestań, gdy hasMore ma wartość fałszywą. |

Przykład czyta jedną stronę. Aby zapoznać się z wymaganymi polami, zakresem gracza, semantyką filtra, limitem, kursorem i ograniczonymi próbami, wykonaj następujące czynności [Przegląd zapytań](/pl/sdk/agent-sdk/java/perpetual-queries). Zachowaj wszystkie filtry niezmienione podczas stronicowania; nie interpretuj błędu jako pustego wyniku.

## `listPerpetualOrderHistory`

Zapytaj o model: `PerpetualOrderHistoryRequest`.

```java
import com.sixmm.agent.model.PerpetualOrderHistoryRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualOrderHistoryRequest request = new PerpetualOrderHistoryRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.orderCategory = "NORMAL";
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualOrderHistory(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

### Pola żądania

| Pole | Java typ | Wymagany | Oznaczający |
| --- | --- | --- | --- |
| `orderCategory` | `String` | Tak | NORMAL lub CONDITIONAL; zapytania warunkowe wymagają jawnych użytkowników. |
| `platformUserIds` | `java.util.List<String>` | Warunkowy | 1–100 unikalnych identyfikatorów publicznych; wymagane w przypadku wypełnień i zamówień warunkowych. Pomiń obsługiwane zapytania w zakresie bezpośredniego gracza; [] jest nieprawidłowe. |
| `symbol` | `String` | NIE | Opcjonalny filtr par handlowych. |
| `orderId` | `String` | NIE | Zwykły identyfikator zamówienia; a nie numer zamówienia przeniesienia partnera. |
| `conditionId` | `String` | NIE | Warunkowy identyfikator zamówienia; nie mieszać z orderId. |
| `clientOrderId` | `String` | NIE | Numer referencyjny zlecenia klienta handlowego, a nie agentOrderNo. |
| `side` | `String` | NIE | BUY / SELL filtr. |
| `status` | `String` | NIE | Status specyficzny dla zasobu; zobacz odniesienie do statusu. |
| `startTime` | `Long` | NIE | Włącznie z milisekundami Uniksa; użyj stałego okna historii UTC. |
| `endTime` | `Long` | NIE | Ekskluzywne milisekundy Uniksa. |
| `limit` | `Integer` | NIE | Domyślnie 500; 1–1000. |
| `cursor` | `String` | NIE | Użyj zwróconego nextCursor z niezmienionymi filtrami; przestań, gdy hasMore ma wartość fałszywą. |

## Zlecenia zwykłe: aktualne i historyczne

Prąd: `orders/current` + `orderCategory=NORMAL`; Historia: `orders/history` + `orderCategory=NORMAL`.

| Pole `data`. | typ | Znaczenie i zakres zastosowania |
| --- | --- | --- |
| `symbol` | string | Para handlowa, taka jak BTCUSDT |
| `orderId` | string | Identyfikator zwykłego zamówienia platformy |
| `orderCategory` | string | Naprawiono NORMAL |
| `clientOrderId` | string | numer zamówienia klienta podany przez źródło zlecenia transakcji; nie to samo pole, co przelew środków sprzedawcy agentOrderNo |
| `orderType` | string | Typ delegata, taki jak LIMIT, MARKET; faktyczna wartość wyliczeniowa ma pierwszeństwo |
| `side` | string | Kierunek kupna i sprzedaży BUY / SELL |
| `status` | string | Zwykły status zamówienia, zobacz przegląd zapytań |
| `timeInForce` | string | Okres ważności/strategia realizacji transakcji, taka jak GTC, IOC, FOK; interpretowane zgodnie z wartościami rzeczywistymi |
| `price` | string | Powierzona cena; można ją pominąć w przypadku braku podania ceny, a rynkowa cena transakcyjna nie będzie samodzielnie uzupełniana. |
| `quantity` | string | Oryginalna ilość zamówienia |
| `filledQuantity` | string | Ilość transakcji |
| `remainingQuantity` | string | Nieprzeprowadzona ilość; aktualne zapytanie przyjmuje ilość - filledQuantity, a zapytanie historyczne przyjmuje wartość rekordu historycznego |
| `avgFilledPrice` | string | Średnia cena transakcyjna zrealizowanej części; nieukończone może nie mieć żadnej wartości |
| `reduceOnly` | boolean | Czy tylko redukować pozycje |
| `closeOnly` | boolean | Czy jest używany tylko do zamykania pozycji |
| `makerOnly` | boolean | Określa, czy wykonać tylko jako Maker |
| `leverage` | integer | Wykorzystaj wiele; **Historyczny porządek zwyczajny** ma swoje źródło, a bieżący porządek zwyczajny tej wartości nie tworzy |
| `marginMode` | string | Tryb marginesu; **Historyczny porządek zwyczajny** obecnie zwraca numeryczny ciąg wyliczeniowy, taki jak „1”, „2”; aktualne zamówienie zwyczajne nie jest przewidziane |
| `createdAt` | integer | Czas utworzenia zamówienia, milisekundy; użyj tego pola do filtrowania historycznego czasu zamówienia |
| `updatedAt` | integer | Czas aktualizacji rekordu delegata, milisekundy |

Historia zamówień obejmuje zakończone zamówienia zwykłe. Żadnego rekordu nie można uznać za w pełni ukończony na podstawie samej nazwy interfejsu. Strona bieżącego zamówienia to zapytanie o bieżący status, a nie strumień zdarzeń dotyczących zamówienia.

## Zlecenia warunkowe: aktualne i historyczne

Prąd: `orders/current` + `orderCategory=CONDITIONAL`; Historia: `orders/history` + `orderCategory=CONDITIONAL`. Obydwa wymagają wyraźnego platformUserIds.

| Pole `data`. | typ | oznaczający |
| --- | --- | --- |
| `symbol` | string | para handlowa |
| `conditionId` | string | Identyfikator zleceń warunkowych, niezależny od zwykłego orderId |
| `orderCategory` | string | Naprawiono CONDITIONAL |
| `generatedOrderId` | string | Zwykły identyfikator zamówienia generowany po uruchomieniu; można pominąć, jeśli nie został wygenerowany |
| `clientOrderId` | string | Numer zamówienia klienta w przypadku zamówień warunkowych, wyprowadzany, jeśli istnieje |
| `side` | string | BUY / SELL |
| `orderType` | string | Typ zlecenia po uruchomieniu, interpretowany według wartości rzeczywistej |
| `triggerType` | string | Typ reguły wyzwalacza, wyjaśniony przez rzeczywiste wyliczenie źródła |
| `workingType` | string | Typ zadania/źródło ceny, które powoduje cenę, interpretowane jako rzeczywiste wyliczenie |
| `timeInForce` | string | Okres ważności/strategia realizacji zlecenia po uruchomieniu |
| `price` | string | Cena zamówienia po uruchomieniu jest generowana, gdy źródło ma wartość |
| `quantity` | string | Warunkowa wielkość zamówienia |
| `triggerPrice` | string | cena wywoławcza |
| `reduceOnly` | boolean | Czy tylko redukować pozycje |
| `closePosition` | boolean | Nie można mylić tego, czy używać semantyki zamykania pełnych pozycji, z closeOnly jako tym samym polem |
| `leverage` | integer | Wykorzystaj wielokrotność, wyjście, gdy jest niezerowe |
| `marginMode` | string | Ta klasa zwraca CROSS / ISOLATED, który jest ciągiem liczbowym różniącym się od zwykłych zleceń/pozycji historycznych |
| `status` | string | Warunkowy stan pojedynczego wyzwalacza, zobacz omówienie zapytań |
| `triggerStatus` | string | Bieżąca implementacja używa tej samej wartości statusu warunkowego co status |
| `createdAt` | integer | Czas utworzenia zamówienia warunkowego, milisekundy; Warunki historyczne są filtrowane przez ten czas |
| `updatedAt` | integer | Czas aktualizacji, wyjście, gdy istnieje wartość, milisekundy |
| `deletedAt` | integer | Usuń czas zaznaczenia, wyprowadź wartość, milisekundy; nie jest to ujednolicone pole czasu transakcji/anulowania |

Zlecenia warunkowe nie zapewniają filledQuantity, remainingQuantity, avgFilledPrice w przypadku zleceń zwykłych. Jeśli po uruchomieniu potrzebujesz statusu transakcji zwykłych zleceń/transakcji, zapytaj o zwykłe zamówienia/transakcje poprzez generatedOrderId i nie wnioskuj o wolumenie transakcji na podstawie statusu zamówienia warunkowego.
