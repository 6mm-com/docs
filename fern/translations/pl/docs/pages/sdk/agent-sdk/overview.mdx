6MM Agent SDK jest przeznaczony dla usług zaplecza partnerów, które muszą wywoływać uprzywilejowanego agenta APIs bez konieczności wdrażania podpisywania i obsługi żądań od zera. Nie może działać w kodzie przeglądarki, telefonu komórkowego ani publicznego komputera, ponieważ integracja wykorzystuje sekret partnera API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Kiedy używać Agent SDK

Użyj Agent SDK, gdy backend musi powiązać użytkownika partnera, przenosić aktywa w zatwierdzonym procesie, pobierać dane transakcyjne, utworzyć adres URL wejścia do handlu osadzonego lub zweryfikować powiadomienia webhook. Użyj [Trading Widget SDK](/pl/sdk/trading-widget/overview) osobno, gdy frontend partnera ma wyświetlać interfejs handlowy.

## Wspólna konfiguracja

| Klawisz | Przykład | Opis |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API usługa URL bez końcowego ukośnika. |
| agentCode | AGENT001 | Kod agenta partnerskiego. |
| apiSecret | Twój sekret API | API sekret podpisywania przechowywany tylko na backendzie. |
| defaultCurrency | USDT | Domyślna waluta przelewu i rachunku APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Punkt końcowy partnera do odbierania powiadomień webhook od 6MM. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Typowy przepływ integracyjny

1. Interfejs partnera uwierzytelnia użytkownika za pośrednictwem własnego systemu kont partnera.
2. Backend partnera mapuje użytkownika na stabilny identyfikator po stronie partnera.
3. Backend wywołuje Agent SDK z `agentCode` i chronionym sekretem API.
4. SDK podpisuje i wysyła do Agenta żądanie API.
5. Backend przechowuje zwrócony identyfikator biznesowy i przetwarza później webhooks idempotentnie.
6. Frontend otrzymuje tylko krótkotrwały wynik lub dane uwierzytelniające, których potrzebuje.

## Lista kontrolna produkcji

- Załaduj `apiSecret` z menedżera tajnych danych zaplecza, a nie z kodu źródłowego.
- Zachowaj oddzielne poświadczenia programistyczne, testowe i produkcyjne.
- Korzystaj ze stabilnego mapowania użytkowników partnerów i unikalnych identyfikatorów zamówień biznesowych.
- Zachowaj oryginalny identyfikator podczas sprawdzania statusu żądania, które przekroczyło limit czasu.
- Weryfikuj podpisy webhook i przechowuj przetworzone identyfikatory zdarzeń.
- Redaguj wpisy tajne i podpisy z dzienników, zachowując identyfikatory żądań pomocy technicznej.
