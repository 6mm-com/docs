## Rozkazy

| Enum                 | Wartości                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Strona porządkowa           | `BUY` / `SELL`                                                                                            |
| Strona pozycyjna        | `BOTH` / `LONG` / `SHORT`                                                                                 |
| Typ porządku normalnego    | `LIMIT` / `MARKET`                                                                                        |
| Typ porządku warunku | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| Czas obowiązywania        | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| Typ ceny wyzwalającej   | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| Status zamówienia         | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` oznacza, że zamówienie zostało zaakceptowane i zwrócone. `PENDING` oznacza, że zamówienie weszło w stan oczekujący lub otwarty rozkaz.

## Stanowiska

| Enum                      | Wartości                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Wartość żądania w trybie marginesu | `1` krzyż, `2` odizolowany                                     |
| Łańcuch trybu marginesowego        | `ISOLATED` / `CROSS`                                        |
| Tryb zamknięcia spustu        | `1` manualnie `2` realizować zysk, `3` stop loss `4` likwidację |

<span id="integration-rules" data-sixmm-canonical-anchor="integration-rules" aria-hidden="true"></span>

## Reguły całkowania

- Traktuj wartości enum jako wartości przewodów na wielka i wielką skalę.
- Zachowanie nieznanych wartości w logach i bezpieczne awarie zamiast bezgłośnego mapowania ich do znanego stanu.
- Nie wnioskuj, że każdy stan nieostatecznego porządku jest bezpieczny do ponownej próby. Zapytaj zamówienie lub pogodz je z prywatnym wydarzeniem WebSocket .
- Przechowywać zarówno oryginalną wartość API , jak i etykietę wyświetlania dla partnera, aby można było wspierać nowe wartości bez zmiany historycznych zapisów.

## Obsługa stanu zamówienia

| Grupa stanowa | Wartości | Zalecane prowadzenie |
| --- | --- | --- |
| Akceptowane lub otwarte | `NEW`, `PENDING`, `PARTIALLY_FILLED` | Utrzymuj zamówienie aktywne i dogaduj się z aktualizacjami WebSocket lub REST . |
| Ukończone | `FILLED` | Stosuj ostateczną ilość wypełnionych i dane realizacji. |
| Zamknięte bez pełnego wypełnienia | `CANCELED`, `REJECTED`, `PARTIALLY_FILLED_CANCELED` | Zatrzymaj aktywne przetwarzanie i zachowaj powód oraz ewentualną wykonaną ilość. |
