Korzystaj WebSocket strumieni do danych rynkowych oraz prywatnych aktualizacji stanów użytkowników, które muszą być aktualne bez konieczności ankietowania.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Połączenie URL

```text
wss://ws.6mm.com/ws
```

Prywatne strumienie wymagają kontekstu uwierzytelniania, takiego jak listenKey lub token dostępu, opisany w dokumentacji kanału prywatnego.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## Subskrybuj

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Pomyślne potwierdzenie subskrypcji:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## Zrezygnuj z subskrypcji

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

## Ping aplikacji

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<span id="message-envelope" data-sixmm-canonical-anchor="message-envelope" aria-hidden="true"></span>

## Koperta z wiadomością

Publiczne inicjatywy stosują spójną granicę:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## Zalecenia operacyjne

- Generowanie unikalnego `id` po stronie klienta dla każdego zgłoszenia, wypisania i pinga.
- Traktuj ponowne połączenie jako nową sesję i ponownie subskrybuj wymagane tematy.
- Sprawdź, czy zwrócony `topic` odpowiada kanałowi, którego oczekuje usługa.
- Utrzymanie idempotencji przetwarzania wiadomości, gdy w grę wchodzą zdarzenia prywatnego zamówienia lub konta.
- Rejestruj zmiany stanu połączenia, potwierdzenia subskrypcji oraz nieprawidłowe rozłączenia.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## Workflow Reconnect

1. Zamknąć lub odrzucić poprzednie gniazdo i utworzyć nowe połączenie.
2. Ponowne uwierzytelnienie prywatnych strumieni za pomocą ważnego listenKey lub tokena dostępu.
3. Ponownie subskrybuj każdy wymagany temat i czekaj na udane podziękowania.
4. Zastąpienie lokalnego stanu księgi zamówień nowym snapshotem przed wprowadzeniem aktualizacji przyrostowych.
5. Uzgadnianie otwartych zamówień, pozycji i bilansów poprzez REST jeśli mogły przegapić prywatne wydarzenia.

Używaj ograniczonego wykładniczego cofania z jitterem do prób ponownego połączenia. Ciągłe ponowne łączenie klienta powinno ostrzegać operatorów, zamiast próbować w nieskończoność bez widoczności.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## Bicie serca i przestarzałe połączenia

- Śledzenie najnowszej wiadomości przychodzącej i pomyślnego potwierdzenia pingu.
- Używanie interwału serca i progu bezczynności zatwierdzonych dla środowiska produkcyjnego.
- Traktuj połączenie jako przestarzałe, gdy przekroczony jest skonfigurowany próg, nawet jeśli gniazdo TCP nadal wydaje się otwarte.
- Nie używaj ponownie subskrypcji ze starego gniazda; Ponownie subskrybuj wyraźnie po każdym ponownym połączeniu.
