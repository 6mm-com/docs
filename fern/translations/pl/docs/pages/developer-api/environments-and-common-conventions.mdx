<span id="time-and-numeric-values" data-sixmm-canonical-anchor="time-and-numeric-values" aria-hidden="true"></span>

## Czas i wartości numeryczne

* O ile nie zaznaczono inaczej, pola czasowe to znaczniki czasowe milisekund Unix.
* Statystyki dzienne, przeglądy salda i statystyki wolumenu handlu domyślnie wykorzystują granice UTC dni.
* Pola wrażliwe na precyzję, takie jak ilość, cena, ilość i szybkość, są przesyłane jako ciągi znaków.
* Duże identyfikatory całkowitoliczbowe, takie jak `orderId`, `conditionId`i `strategyId` , zwracane są jako ciągi znaków w JSON.

<span id="response-format" data-sixmm-canonical-anchor="response-format" aria-hidden="true"></span>

## Format odpowiedzi

Udana odpowiedź:

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-12345678"
}
```

Odpowiedź błędna:

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Notatki:

* Błędy biznesowe zazwyczaj nadal zwracają zunifikowaną strukturę JSON . Integratorzy powinni najpierw `code` sprawdzić.
* Niepowodzenia uwierzytelniania mogą zwracać HTTP `401`; ograniczenie szybkości może zwracać HTTP `429`.
* Możesz wysłać `X-Request-ID` w nagłówku żądania. Serwer zwróci je tak, jak `requestId` w odpowiedzi.
