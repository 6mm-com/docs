> **Planowane — jeszcze nie uruchomione**
> AI Hub to planowana funkcja. Możliwości, punkty końcowe, polecenia i konfiguracje klienta na tej stronie opisują proponowany projekt i nie są obecnie dostępne. Ostateczna dostępność i instrukcje konfiguracji zostaną ogłoszone w momencie premiery.


Wybierz konfigurację na podstawie dwóch pytań:

1. Którego klienta AI chcesz używać?
2. Czy potrzebujesz tylko danych publicznych, dostępu do konta prywatnego lub przepływów pracy w handlu?

Jeśli nie masz pewności, zacznij od Hosted MCP w przypadku danych publicznych lub Lokalny MCP w przypadku przepływów pracy na kontach prywatnych.

## Wybierz według przypadku użycia

<CardGroup cols={2}>
<Card title="Potrzebuję jedynie danych z rynku publicznego" icon="fa-duotone fa-cloud" href="/pl/ai-hub/hosted-mcp">
Użyj hosta MCP. Bez instalacji lokalnej, bez klucza użytkownika API i bez dostępu do konta prywatnego.

<Card title="Chcę, żeby mój klient AI czytał moje konto" icon="fa-duotone fa-computer" href="/pl/ai-hub/local-mcp">
Użyj lokalnego MCP z poświadczeniami tylko do odczytu. Uruchom w trybie sieci testowej lub tylko do odczytu.
</Card>
<Card title="Mój agent może uruchamiać polecenia terminala" icon="fa-duotone fa-terminal" href="/pl/ai-hub/cli">

</Card>
<Card title="Mój zespół potrzebuje zarządzanego punktu końcowego" icon="fa-duotone fa-server" href="/pl/ai-hub/remote-mcp">
Użyj pilota MCP. Wdróż serwer w infrastrukturze kontrolowanej przez Twój zespół.
</Card>
</CardGroup>

## Szybka tabela decyzyjna

| Bramka | Zalecana konfiguracja | Dlaczego |
| --- | --- | --- |
| Poproś klienta AI o publiczne dane rynkowe | Hostowane MCP | Nie jest wymagana żadna instalacja lokalna ani klucz API. |
| Pozwól Claude Desktop, Cursor lub ChatGPT Desktop wywoływać narzędzia 6MM | Lokalny MCP | AI wywołuje narzędzia za pośrednictwem lokalnego serwera kontrolowanego przez użytkownika. |
| Niech Codex, Claude Code, Gemini CLI lub skrypty wywołają 6MM | CLI | Dane wyjściowe polecenia mogą mieć postać JSON i być łatwe do przeanalizowania przez agentów. |
| Podaj punkt końcowy MCP zarządzany przez firmę | Zdalny MCP | Instytucja kontroluje hosting, dane uwierzytelniające, dostęp i dzienniki. |
| Standaryzuj powtarzalne analizy lub przepływy pracy związane z ryzykiem | Umiejętności agenta | Szablony definiują użycie narzędzia, poręcze i format wyjściowy. |

## Wybierz według ścieżki konfiguracji

| Organizować coś | Instalacja | API kluczowa lokalizacja | Najlepszy zakres początkowy | Konto i zakres handlu |
| --- | --- | --- | --- | --- |
| Hostowane MCP | Nic | Brak klucza użytkownika API do danych publicznych | Dane rynku publicznego | Niezalecane do pierwszego wydania |
| Lokalny MCP | Użytkownik instaluje pakiet | Maszyna użytkownika | Dane publiczne i odczyt konta | Zalecana ścieżka dla przyszłego handlu |
| CLI | Użytkownik instaluje pakiet | Maszyna użytkownika | Dane publiczne i skrypty | Przydatne do podglądu i automatyzacji |
| Zdalny MCP | Użytkownik wdraża serwer | Chmura użytkownika lub chmura instytucji | Dane publiczne lub odczyt konta | Możliwe, gdy użytkownik kontroluje wdrożenie |
| Umiejętności | Dokumenty lub szablony do zainstalowania | Zależy od podstawowych narzędzi | Przepływy pracy analizy | Należy przestrzegać uprawnień narzędzia |

<span id="security-rule-of-thumb" data-sixmm-canonical-anchor="security-rule-of-thumb" aria-hidden="true"></span>

## Praktyczna zasada bezpieczeństwa

Użyj konfiguracji o najniższym ryzyku, która obsługuje zadanie:

- Dane dotyczące rynku publicznego: Hostowane MCP wystarczą.
- Dane konta prywatnego: Lokalne MCP lub zarządzane przez użytkownika Zdalne MCP.
- Podgląd transakcji: Lokalny MCP lub CLI, najlepiej najpierw testnet.
- Prawdziwy handel: tylko po wyraźnym pozwoleniu, podglądzie, potwierdzeniu, limitach i dziennikach audytu.
