Οι ενσωματωμένες συναλλαγές συνήθως εισάγονται σε ένα υπάρχον προϊόν και δεν κυκλοφορούν ως αυτόνομος προορισμός. Η καλύτερη διαδρομή ενοποίησης εξαρτάται από το πού περνούν ήδη χρόνο οι χρήστες και σε ποιο σύστημα ανήκει η ταυτότητα, τα κεφάλαια και οι λειτουργίες.

<h2 id="common-scenarios">Κοινά σενάρια</h2>

| Σενάριο | Το καλύτερο σημείο εκκίνησης | Σημειώσεις |
| --- | --- | --- |
| Η εφαρμογή ή το πορτοφόλι θέλει μια καταχώριση συναλλαγών | Trading Widget SDK | Χρησιμοποιήστε ένα εγγενές σημείο εισόδου ή ένα σημείο εισόδου H5 και ανοίξτε την ενσωματωμένη εμπειρία συναλλαγών μετά την εξουσιοδότηση του χρήστη. |
| Ο μεσίτης ή η πλατφόρμα καναλιού θέλει πρόσβαση σε παράγωγα | Agent SDK + Trading Widget SDK | Διατηρήστε τη σχέση με τους πελάτες και την επικύρωση του backend στο σύστημα συνεργατών. |
| Η πλατφόρμα θέλει μια καθοδηγούμενη ροή συναλλαγών | API + επιλεγμένες SDK ενότητες | Χρησιμοποιήστε APIs backend για ροές εργασίας λογαριασμού, μεταφοράς και παραγγελίας, ενώ εκθέτετε μόνο την απαραίτητη καταχώρηση στο frontend. |
| Το υπάρχον χρηματιστήριο θέλει επιπλέον αγορές | Ρευστότητα + ενσωμάτωση API | Συνδυάστε το βάθος της αγοράς, τις ροές εργασίας λογαριασμού και τη λειτουργική παρακολούθηση. |

<h2 id="product-decisions-before-integration">Αποφάσεις προϊόντων πριν από την ενσωμάτωση</h2>

- Αποφασίστε αν οι χρήστες θα συμμετέχουν από μια κάρτα αρχικής σελίδας, μια σελίδα στοιχείων, μια σελίδα καμπάνιας ή ένα κέντρο λογαριασμού.
- Αποφασίστε σε ποιο σύστημα ανήκει η κατάσταση σύνδεσης, η καταλληλότητα χρήστη και η διαθεσιμότητα χώρας ή περιοχής.
- Αποφασίστε πώς εμφανίζονται στους χρήστες οι μεταφορές, τα αρχεία διακανονισμού και τα εισιτήρια υποστήριξης πελατών.
- Αποφασίστε ποια συμβάντα πρέπει να προωθηθούν σε λειτουργίες εσωτερικής ανάλυσης, CRMή κινδύνου.
