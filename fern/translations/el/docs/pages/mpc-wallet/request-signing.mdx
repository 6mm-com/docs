Υπάρχουν τρία ξεχωριστά ζητήματα υπογραφής: έλεγχος ταυτότητας του αιτήματος HTTP, εξουσιοδότηση συγκεκριμένης απόσυρσης και παραγωγή της υπογραφής blockchain με MPC συμμετέχοντες. Η επιτυχία του πρώτου ελέγχου δεν αντικαθιστά τους άλλους δύο.

## Πραγματοποιήστε έλεγχο ταυτότητας ενός αιτήματος API

Το τρέχον API χρησιμοποιεί HMAC-SHA256 με API αναγνωριστικό κλειδιού και μυστικό. Το κανονικό αίτημά του περιέχει πέντε γραμμές, που χωρίζονται από μια νέα γραμμή, χωρίς νέα νέα γραμμή:

```text
METHOD
PATH
SORTED_QUERY
BODY_SHA256_HEX
UNIX_TIMESTAMP_SECONDS
```

Χρησιμοποιήστε τη μέθοδο κεφαλαίων HTTP και διαδρομή αιτήματος χωρίς τον κεντρικό υπολογιστή. Ταξινομήστε τα κλειδιά ερωτήματος, διατηρήστε τη σειρά των επαναλαμβανόμενων τιμών και εφαρμόστε την κωδικοποίηση φόρμας URL, συμπεριλαμβανομένου του `+` για τα κενά. Η γραμμή ερωτήματος είναι κενή όταν δεν υπάρχει ερώτημα. Κατακερματίστε τα ακριβή byte σώματος χρησιμοποιώντας SHA-256, συμπεριλαμβανομένου του κενού σώματος για αίτημα χωρίς σώμα.

Υπολογίστε HMAC-SHA256 χρησιμοποιώντας το παρεχόμενο μυστικό ως UTF-8 byte. μην το αποκωδικοποιήσετε με δεκαεξαδικό απλώς και μόνο επειδή φαίνεται δεκαεξαδικό. Κωδικοποιήστε το αποτέλεσμα ως πεζό εξάγωνο. Τα πεδία κεφαλίδας χωρίζονται με κενό:

```text
Authorization: HMAC-SHA256 keyId=<KEY_ID> signature=<HEX_SIGNATURE> timestamp=<UNIX_SECONDS>
```

## Παράδειγμα υπογραφής μόνο για ανάγνωση

Αυτός ο βοηθός τυπικής βιβλιοθήκης δημιουργεί κεφαλίδες για ένα ερώτημα κατάθεσης. δεν στέλνει αίτημα. Φορτώστε τα διαπιστευτήρια με ασφάλεια στην εφαρμογή σας και στείλτε τη διαδρομή που επιστρέφεται αμετάβλητη στη βάση URL που παρέχεται για το περιβάλλον σας.

```python
import hashlib
import hmac
import time
from urllib.parse import urlencode


def signed_read_headers(key_id, secret, timestamp=None):
    method = "GET"
    path = "/api/v1/deposits"
    query = urlencode(sorted([("page", "1"), ("page_size", "20")]))
    body = b""
    ts = str(int(time.time()) if timestamp is None else timestamp)
    canonical = "\n".join([
        method, path, query, hashlib.sha256(body).hexdigest(), ts
    ])
    signature = hmac.new(
        secret.encode("utf-8"), canonical.encode("utf-8"), hashlib.sha256
    ).hexdigest()
    return path + "?" + query, {
        "Authorization": (
            f"HMAC-SHA256 keyId={key_id} signature={signature} timestamp={ts}"
        )
    }
```

Διατηρήστε τα ρολόγια συγχρονισμένα. Ένας διακομιστής μεσολάβησης που αλλάζει τη διαδρομή, το ερώτημα ή το σώμα μετά την υπογραφή μπορεί να ακυρώσει τον έλεγχο ταυτότητας. Για αποτυχίες ελέγχου ταυτότητας, επιθεωρήστε την αιτία απόκρισης και το αναγνωριστικό αιτήματος πριν προσπαθήσετε ξανά. μην καταγράφετε ποτέ την κεφαλίδα μυστικής ή πλήρους εξουσιοδότησης.

## Εξουσιοδοτήστε μια API απόσυρση

Η τρέχουσα ροή απόσυρσης επιχείρησης API απαιτεί επίσης εξουσιοδότηση πελάτη Ed25519 στο `client_authorization`. Δεσμεύει το πλαίσιο της προβλεπόμενης συναλλαγής, συμπεριλαμβανομένου του αναγνωριστικού αιτήματος, του προορισμού, του περιουσιακού στοιχείου και του ποσού. Η καταχώρισή του με δημόσιο κλειδί ή η διαμόρφωση του καταπιστεύματος εξαρτάται από τη συμφωνία φύλαξης.

Χρησιμοποιήστε το αντίστοιχο πακέτο ενοποίησης για να δημιουργήσετε το κανονικό ωφέλιμο φορτίο, την υπογραφή και το δημόσιο κλειδί. Αυτό το κλειδί εξουσιοδότησης είναι ξεχωριστό από τα κοινόχρηστα στοιχεία HMAC μυστικό και MPC. Διατηρήστε το ιδιωτικό του κλειδί υπό τον έλεγχο του πελάτη. Επιβεβαιώστε την έκδοση ωφέλιμου φορτίου και τους κανόνες εγκυρότητας κατά την ενσωμάτωση αντί να δημιουργήσετε μια προσαρμοσμένη μορφή από αυτήν την επισκόπηση.

Μετά την αποδοχή του αιτήματος, εξακολουθούν να ισχύουν επιχειρηματικοί έλεγχοι και εγκρίσεις, ακολουθούμενες από MPC υπογραφή και επιβεβαίωση αλυσίδας. Βλέπω [συναλλαγές και επαναλήψεις](/el/mpc-wallet/transactions).
