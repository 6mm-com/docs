Η απόσυρση είναι μια ασύγχρονη επιχειρηματική λειτουργία. Μια επιτυχημένη απόκριση HTTP σημαίνει ότι το αίτημα διεκπεραιώθηκε. δεν αποδεικνύει ότι τα κεφάλαια έφθασαν στην αλυσίδα.

<span id="persist-one-business-identifier" data-sixmm-canonical-anchor="persist-one-business-identifier" aria-hidden="true"></span>

## Διατήρηση ενός αναγνωριστικού επιχείρησης

Δημιουργήστε και αποθηκεύστε το `client_request_id` πριν στείλετε μια ανάληψη. Χρησιμοποιήστε το ξανά για επαναλήψεις της ίδιας προβλεπόμενης λειτουργίας, ακόμη και μετά από επανεκκίνηση της διαδικασίας. Διατηρήστε τα πεδία της συναλλαγής συνεπή. η τρέχουσα υλοποίηση απορρίπτει ένα επαναλαμβανόμενο αναγνωριστικό με αντικρουόμενες επιχειρηματικές παραμέτρους.

Μην βασίζεστε μόνο σε μια κεφαλίδα `Idempotency-Key`. Το παρεχόμενο SDK μπορεί να προσθέσει αυτήν την κεφαλίδα, αλλά η τρέχουσα σύμβαση αφαίρεσης διπλότυπων ανάληψης βασίζεται στο πεδίο σώματος `client_request_id`.

<span id="understand-request-data" data-sixmm-canonical-anchor="understand-request-data" aria-hidden="true"></span>

## Κατανόηση δεδομένων αιτήματος

| Πεδίο | Εννοια |
| --- | --- |
| `chain_id`, `asset_id` | Αναγνωριστικά στο συμφωνημένο περιβάλλον |
| `to_address`, `amount` | Προορισμός και ένα θετικό δεκαδικό ποσό που αντιπροσωπεύεται ως συμβολοσειρά |
| `client_request_id` | Σταθερό αναγνωριστικό επιχειρηματικού αιτήματος |
| `dest_memo_type`, `dest_memo` | Λεπτομέρειες σημειώματος προορισμού όπου τις απαιτεί το δίκτυο |
| `client_authorization` | Εξουσιοδότηση συναλλαγής πελάτη για αναλήψεις που ξεκινούν με API κλειδί |
| `end_user_id` | Προαιρετικό αναγνωριστικό επιχειρηματικού χρήστη στη ροή της επιχείρησης API |

Αυτός ο πίνακας επισημαίνει τα βασικά πεδία, όχι ένα πλήρες σχήμα αιτήματος. Επιβεβαιώστε τις απαιτήσεις προεπισκόπησης, επιβεβαίωσης τελών και φύλαξης σε σχέση με την έκδοση ενσωμάτωσης. Αποφύγετε δυαδικά ποσά κινητής υποδιαστολής και μην αντιγράψετε παραδείγματα αλυσίδων ή αριθμών στοιχείων μεταξύ περιβαλλόντων.

## Ακολουθήστε το αποτέλεσμα

| Δηλώστε παραδείγματα | Ερμηνεία |
| --- | --- |
| `pending_approval`, `pending_platform_review` | Η έγκριση ή ο έλεγχος της επιχείρησης εκκρεμεί |
| `approved`, `pending_sign` | Η έγκριση και η υπογραφή είναι ξεχωριστά στάδια |
| `broadcasting`, `pending_chain` | Η μετάδοση ή η επιβεβαίωση της αλυσίδας είναι σε εξέλιξη |
| `broadcast_unverified`, `recovering` | Το αποτέλεσμα είναι ακόμα αβέβαιο. μην δημιουργήσετε άλλη μεταφορά |
| `awaiting_reauthorization` | Μπορεί να απαιτείται νέα εξουσιοδότηση πελάτη για το ίδιο αίτημα |
| `confirmed` | Το σύστημα έχει καταγράψει την επιβεβαίωση της αλυσίδας |

Η λίστα είναι ενδεικτική και μπορεί να εξελιχθεί. Διατηρήστε άγνωστες καταστάσεις για διερεύνηση αντί να τις αντιστοιχίσετε σε επιτυχία ή αποτυχία. Μια αποτυχημένη ή απορριφθείσα ετικέτα από μόνη της δεν είναι επαρκής απόδειξη ότι τίποτα δεν υπογράφηκε ή μεταδόθηκε.

## Ανάρρωση μετά από ένα τάιμ άουτ

Ερώτημα `GET /api/v1/withdrawals/by-request` χρησιμοποιώντας την αρχική παράμετρο ερωτήματος `client_request_id`. Συνεχίστε να κάνετε ψηφοφορία ή να εναρμονίζετε την αρχική λειτουργία όσο το αποτέλεσμά της είναι αβέβαιο. Εάν απαιτείται ανανέωση εξουσιοδότησης, χρησιμοποιήστε το ίδιο αναγνωριστικό και τη συμφωνημένη διαδικασία ανανέωσης.

Η ακύρωση εξαρτάται από το πραγματικό στάδιο υπογραφής και τους ελέγχους του διακομιστή. Ξεκινήστε μια επιχειρηματική δραστηριότητα αντικατάστασης μόνο αφού διαπιστωθεί ότι το πρωτότυπο δεν μεταβιβάστηκε και δεν είναι δυνατό να μεταφερθεί. Λήψη συμβάντων μέσω [webhooks](/el/mpc-wallet/webhooks-and-sdks), και διατηρήστε τα API ερωτήματα ως διαδρομή συμφωνίας.
