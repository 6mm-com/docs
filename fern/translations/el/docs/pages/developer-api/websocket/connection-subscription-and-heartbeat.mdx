Χρησιμοποιήστε ροές WebSocket για δεδομένα αγοράς και ιδιωτικές ενημερώσεις κατάστασης χρήστη που πρέπει να παραμένουν ενημερωμένες χωρίς δημοσκόπηση.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Σύνδεση URL

```text
wss://ws.6mm.com/ws
```

Οι ιδιωτικές ροές απαιτούν περιβάλλον ελέγχου ταυτότητας, όπως listenKey ή διακριτικό πρόσβασης, όπως περιγράφεται στην τεκμηρίωση του ιδιωτικού καναλιού.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## Εγγραφείτε

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Επιτυχής επιβεβαίωση συνδρομής:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## Κατάργηση εγγραφής

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

## Εφαρμογή ping

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<span id="message-envelope" data-sixmm-canonical-anchor="message-envelope" aria-hidden="true"></span>

## Φάκελος μηνύματος

Οι δημόσιες ωθήσεις χρησιμοποιούν έναν σταθερό φάκελο:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## Επιχειρησιακές συστάσεις

- Δημιουργήστε ένα μοναδικό `id` από την πλευρά του πελάτη για κάθε αίτημα εγγραφής, διαγραφής και ping.
- Αντιμετωπίστε την επανασύνδεση ως νέα συνεδρία και εγγραφείτε ξανά στα απαιτούμενα θέματα.
- Επαληθεύστε ότι η `topic` που επιστράφηκε αντιστοιχεί στο κανάλι που αναμένει η υπηρεσία σας.
- Διατηρήστε την επεξεργασία μηνυμάτων ανίκανη όταν εμπλέκονται ιδιωτικές παραγγελίες ή συμβάντα λογαριασμού.
- Καταγράψτε τις αλλαγές κατάστασης σύνδεσης, τις επιβεβαιώσεις συνδρομής και τις μη φυσιολογικές αποσυνδέσεις.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## Επανασύνδεση ροής εργασιών

1. Κλείστε ή απορρίψτε την προηγούμενη πρίζα και δημιουργήστε μια νέα σύνδεση.
2. Επαναλάβετε τον έλεγχο ταυτότητας ιδιωτικών ροών με έγκυρο listenKey ή διακριτικό πρόσβασης.
3. Εγγραφείτε ξανά σε κάθε απαιτούμενο θέμα και περιμένετε επιτυχείς αναγνωρίσεις.
4. Αντικαταστήστε την κατάσταση του τοπικού βιβλίου παραγγελιών με ένα νέο στιγμιότυπο πριν εφαρμόσετε σταδιακές ενημερώσεις.
5. Συμβιβάστε ανοιχτές εντολές, θέσεις και υπόλοιπα μέσω REST εάν μπορεί να έχουν χαθεί ιδιωτικές εκδηλώσεις.

Χρησιμοποιήστε οριοθετημένη εκθετική οπισθοδρόμηση με διακύμανση καθυστέρησης για προσπάθειες επανασύνδεσης. Ένας πελάτης που επανασυνδέεται συνεχώς θα πρέπει να ειδοποιεί τους χειριστές αντί να προσπαθεί επ' αόριστον χωρίς ορατότητα.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## Καρδιακός παλμός και μπαγιάτικες συνδέσεις

- Παρακολουθήστε το πιο πρόσφατο εισερχόμενο μήνυμα και την επιτυχή επιβεβαίωση ping.
- Χρησιμοποιήστε το διάστημα παλμών και το όριο αδράνειας που έχουν εγκριθεί για το περιβάλλον παραγωγής.
- Αντιμετωπίστε μια σύνδεση ως μπαγιάτικη όταν ξεπεραστεί το διαμορφωμένο όριο, ακόμα και αν η υποδοχή TCP εξακολουθεί να εμφανίζεται ανοιχτή.
- Μην επαναχρησιμοποιείτε συνδρομές από παλιά πρίζα. Εγγραφείτε ξανά ρητά μετά από κάθε επανασύνδεση.
