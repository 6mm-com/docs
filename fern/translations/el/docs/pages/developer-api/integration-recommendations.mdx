Χρησιμοποιήστε αυτές τις συστάσεις ως βάση για την ετοιμότητα παραγωγής. Συμπληρώνουν την αναφορά τελικού σημείου και βοηθούν τις ενοποιήσεις να ανακτηθούν με ασφάλεια από χρονικά όρια, επανασυνδέσεις, διπλότυπες αιτήσεις και περιστατικά διαπιστευτηρίων.

<span id="authentication-and-secrets" data-sixmm-canonical-anchor="authentication-and-secrets" aria-hidden="true"></span>

## Έλεγχος ταυτότητας και μυστικά

- Προτιμώ [API Key υπογραφή](/el/developer-api/authentication) για προγράμματα συναλλαγών από την πλευρά του διακομιστή και JWT για ενέργειες frontend που βασίζονται στον χρήστη.
- Διατηρήστε `apiSecret` στη μυστική διαχείριση backend. Εμφανίζεται μόνο μία φορά και δεν πρέπει ποτέ να αποστέλλεται σε πρόγραμμα περιήγησης ή πρόγραμμα-πελάτη για κινητά.
- Εφαρμόστε τα ελάχιστα απαιτούμενα δικαιώματα API Key και περιορίστε τις IP προέλευσης όταν το περιβάλλον ενοποίησης υποστηρίζει σταθερές διευθύνσεις εξόδου.
- Απενεργοποιήστε ή διαγράψτε αμέσως ένα κλειδί που διέρρευσε και, στη συνέχεια, ελέγξτε τα αρχεία καταγραφής αιτημάτων πριν εκδώσετε μια αντικατάσταση.

<span id="request-validation-and-idempotency" data-sixmm-canonical-anchor="request-validation-and-idempotency" aria-hidden="true"></span>

## Αίτηση επικύρωσης και ανικανότητας

- Πριν κάνετε παραγγελίες, ζητήστε `/v1/public/market/symbols` και επικυρώστε `tickSize`, `stepSize`, ελάχιστη ονομαστική αξία και μέγιστη ποσότητα τοπικά.
- Δημιουργήστε μια μοναδική `clientOrderId` για κάθε εγγραφή παραγγελίας, ώστε τα αιτήματα να μπορούν να συμβιβαστούν μετά από μια αποσύνδεση.
- Διατηρήστε το αρχικό αναγνωριστικό όταν ένα HTTP αποτέλεσμα είναι αβέβαιο. Υποβάλετε ερώτημα για την υπάρχουσα παραγγελία πριν δημιουργήσετε μια αίτηση αντικατάστασης.
- Αντιμετωπίστε τα δεκαδικά ποσά και τις τιμές ως συμβολοσειρές ή δεκαδικούς τύπους, όχι δυαδικές τιμές κινητής υποδιαστολής.

<span id="order-and-websocket-state" data-sixmm-canonical-anchor="order-and-websocket-state" aria-hidden="true"></span>

## Τάξη και WebSocket κατάσταση

- Προσδιορίστε την τελική κατάσταση μετά την ακύρωση, την ακύρωση όλων ή την τροποποίηση λειτουργιών από [Ιδιωτικές εκδηλώσεις WebSocket](/el/developer-api/websocket/private-user-channel) ή ένα ερώτημα REST .
- Αντιμετωπίστε κάθε επανασύνδεση ως νέα περίοδο λειτουργίας WebSocket και επαναφέρετε όλες τις απαιτούμενες συνδρομές.
- Ελέγξτε τη συνέχεια του βιβλίου παραγγελιών με `endVersion`. Εάν εμφανιστεί κενό έκδοσης, απορρίψτε το τοπικό βιβλίο και εγγραφείτε ξανά για ένα νέο στιγμιότυπο.
- Καταργήστε τα διπλότυπα συμβάντα ιδιωτικών παραγγελιών και λογαριασμών πριν τα εφαρμόσετε σε υπόλοιπα, θέσεις ή αρχεία συνεργατών.

<span id="logging-monitoring-and-retries" data-sixmm-canonical-anchor="logging-monitoring-and-retries" aria-hidden="true"></span>

## Καταγραφή, παρακολούθηση και επαναλήψεις

- Καταγράψτε το αναγνωριστικό αιτήματος, το αναγνωριστικό παραγγελίας πελάτη, την κατάσταση HTTP , τον κωδικό API επιχείρησης, τον λανθάνοντα χρόνο και τον αριθμό επανάληψης χωρίς καταγραφή μυστικών ή πλήρων διακριτικών.
- Δοκιμάστε ξανά μόνο λειτουργίες που έχουν τεκμηριωθεί ως ασφαλείς, χρησιμοποιώντας οριοθετημένη εκθετική οπισθοδρόμηση και διακύμανση καθυστέρησης.
- Ειδοποίηση για αποτυχίες ελέγχου ταυτότητας, σφάλματα υπογραφής, αποκρίσεις ορίου ρυθμού, βρόχους επανασύνδεσης WebSocket , κενά ακολουθίας και διαφορές συμφωνίας παραγγελιών.
- Διατηρήστε τα ρολόγια διακομιστή συγχρονισμένα, επειδή ο έλεγχος ταυτότητας και η υπογραφή εξαρτώνται από τις χρονικές σημάνσεις.

## Πριν από την παραγωγή

- Λήξη χρονικού ορίου άσκησης, διπλότυπο αίτημα, επανασύνδεση, εναλλαγή πλήκτρων και webhook σενάρια επανάληψης σε μη παραγωγικό περιβάλλον.
- Εκχωρήστε κατόχους για εναλλαγή διαπιστευτηρίων, περιστατικά συναλλαγών, αποτυχίες webhook και συμφωνία.
- Συμπληρώστε το [Λίστα ελέγχου έναρξης παραγωγής](/el/resources/production-launch-checklist) και χρησιμοποιήστε το [Πρότυπο αιτήματος υποστήριξης](/el/resources/support-request-template) όταν απαιτείται κλιμάκωση.
