Ξεκινήστε με το περιβάλλον, τη χρονική σήμανση και το αναγνωριστικό επιχείρησης για την αποτυχημένη λειτουργία. Ένας δομημένος έλεγχος συνήθως διαχωρίζει τα προβλήματα ρύθμισης παραμέτρων από τα ζητήματα ελέγχου ταυτότητας, δικτύου και ασύγχρονης επεξεργασίας.

<h2 id="diagnostic-order">Συνιστώμενη διαγνωστική σειρά</h2>

1. Επιβεβαιώστε το επηρεαζόμενο περιβάλλον και URL βάσης.
2. Καταγράψτε το UTC χρονικό εύρος και το πρώτο αίτημα αποτυχίας.
3. Προσδιορίστε τη μονάδα: Trading Widget, Agent SDK, REST API, WebSocketή webhook.
4. Καταγράψτε το αναγνωριστικό αιτήματος, το αναγνωριστικό χρήστη συνεργάτη, το `agentOrderNo`, το αναγνωριστικό παραγγελίας ή το αναγνωριστικό συμβάντος webhook .
5. Ελέγξτε τον πρόσφατο κώδικα, τα διαπιστευτήρια, τη λίστα επιτρεπόμενων IP ή τις αλλαγές ανάπτυξης.
6. Αναπαραγωγή με τη μικρότερη ασφαλή δοκιμαστική θήκη.

<h2 id="trading-widget-issues">Trading Widget θέματα</h2>

| Σύμπτωμα | Πιθανή αιτία | Διόρθωση |
| --- | --- | --- |
| Το iframe ζητά τοπικό τομέα συνεργάτη | baseUrl λείπει | Πάσο baseUrl: «https://app.6mm.com». |
| Το iframe είναι αόρατο ή πολύ κοντό | Το γονικό κοντέινερ δεν έχει ύψος | Ορίστε το ύψος του περιέκτη ή το ύψος διέλευσης. |
| token_provider_missing | Η λειτουργία partner-token δεν έχει πάροχο | Προσθήκη auth.tokenProvider. |
| auth_exchange_failed | Μη έγκυρο, ληγμένο ή αναντιστοιχισμένο διακριτικό ενσωμάτωσης | Ελέγξτε την απόκριση του διακριτικού υποστήριξης και channelId. |

<h2 id="agent-sdk-issues">Agent SDK θέματα</h2>

| Σύμπτωμα | Πιθανή αιτία | Διόρθωση |
| --- | --- | --- |
| Η υπογραφή απορρίφθηκε | Λανθασμένο μυστικό, μετατόπιση ρολογιού ή μη αυτόματα αλλαγμένα υπογεγραμμένα πεδία | Αφήστε SDK να δημιουργήσετε πεδία υπογραφής και να συγχρονίσετε την ώρα του διακομιστή. |
| Διπλός κίνδυνος κίνησης κεφαλαίων | Νέος αριθμός παραγγελίας που χρησιμοποιείται μετά το χρονικό όριο | Ερώτημα από το αρχικό agentOrderNo πρώτα. |
| PROCESSING αντιμετωπίζονται ως αποτυχία | Η κατάσταση σε εκκρεμότητα παρεξηγήθηκε | Περιμένετε webhook ή καλέστε queryOrder. |
| Webhook υποβληθεί σε επεξεργασία πολλές φορές | Δοκιμάστε ξανά τη συμπεριφορά χωρίς ανικανότητα | Προσθέστε το κλειδί idempotency και τους ελέγχους τελικής κατάστασης. |

<h2 id="evidence-to-capture">Στοιχεία προς σύλληψη</h2>

| Ενσωμάτωση | Χρήσιμα στοιχεία |
| --- | --- |
| Trading Widget | Σελίδα URL, SDK διαδρομή έκδοσης, κονσόλα προγράμματος περιήγησης, αποτυχημένες αιτήσεις δικτύου, ωφέλιμο φορτίο `onError` και διαστάσεις κοντέινερ. |
| Agent SDK | SDK γλώσσα/έκδοση, βασική URL, UTC χρονική σήμανση, αναγνωριστικό αιτήματος, `agentOrderNo`, κωδικός απόκρισης και αποστειρωμένα αρχεία καταγραφής. |
| Webhook | Χρόνος παράδοσης, συμβάν ή επιχειρηματικό κλειδί, αποτέλεσμα επικύρωσης υπογραφής, κατάσταση επεξεργασίας και απολυμασμένος κατακερματισμός ακατέργαστου σώματος. |
| REST API | Μέθοδος, διαδρομή, περιβάλλον, αναγνωριστικό αιτήματος, κωδικός απόκρισης και απολυμασμένες παράμετροι. |

Ποτέ μην συμπεριλαμβάνετε κωδικούς πρόσβασης, διακριτικά πρόσβασης, API μυστικά, πλήρεις υπογραφές, ιδιωτικά κλειδιά ή προσωπικά δεδομένα που δεν έχουν διορθωθεί στα διαγνωστικά.

<h2 id="before-escalating">Πριν από την κλιμάκωση</h2>

- Επαναλάβετε μόνο όταν η λειτουργία τεκμηριωθεί ως ασφαλής για επανάληψη.
- Μετά από ένα χρονικό όριο, υποβάλετε ερώτημα για το αρχικό αναγνωριστικό επιχείρησης αντί να δημιουργήσετε ένα νέο.
- Επιβεβαιώστε το ρολόι του συστήματος και το περιβάλλον διαπιστευτηρίων για σφάλματα υπογραφής.
- Διατηρήστε την πρώτη αποτυχία και τυχόν μεταγενέστερα αποτελέσματα επανάληψης.
- Χρησιμοποιήστε το [Πρότυπο αιτήματος υποστήριξης](/el/resources/support-request-template) για να στείλετε μια πλήρη αναφορά.
