Τα αιτήματα Agent SDK επαληθεύονται με μυστικό συνεργάτη API. Κρατήστε αυτό το μυστικό σε μια αξιόπιστη υπηρεσία υποστήριξης και αφήστε το SDK να δημιουργήσει πεδία υπογραφής όποτε είναι δυνατόν.

> **Δύο πρωτόκολλα υπογραφής**
>
> Η υπογραφή Agent SDK χρησιμοποιεί ταξινομημένα πεδία αιτημάτων, μια χρονική σήμανση που βασίζεται σε δευτερόλεπτα και ένα nonce. Άμεσα αιτήματα Developer API χρησιμοποιούν την ξεχωριστή διαδικασία που περιγράφεται στο [Υπογραφή αιτήματος](/el/developer-api/request-signing). Μην επαναχρησιμοποιείτε τη μία μορφή ωφέλιμου φορτίου για την άλλη.

## Κανόνας υπογραφής

Για Agent SDK αιτήματα:

1. Εξαιρέστε το πεδίο `sign`.
2. Παράλειψη πεδίων με κενές τιμές.
3. Ταξινομήστε τα υπόλοιπα ονόματα πεδίων με τη σειρά ASCII.
4. Ενώστε τα πεδία ως `k=v&k2=v2`.
5. Υπολογίστε την HMAC-SHA256 δεκαεξαδική υπογραφή με `apiSecret`.

Οι τιμές του πίνακα σειριοποιούνται ως συμπαγείς JSON πριν από την ένταξη στο ωφέλιμο φορτίο υπογραφής. Για παράδειγμα, το `platformUserIds` υπογράφει ως `["1188041528"]`, δίνοντας `platformUserIds=["1188041528"]` στο `k=v` ωφέλιμο φορτίο. Διατηρήστε τη σειρά στοιχείων του πίνακα, τα διπλά εισαγωγικά και τα αναγνωριστικά συμβολοσειρών. Μην εισάγετε κενά μορφοποίησης και μην χρησιμοποιείτε Java `List.toString()` (όπως `[1188041528]`). Το SDK χειρίζεται αυτόματα αυτήν τη σειριοποίηση.

Το SDK θα πρέπει να δημιουργήσει αυτήν την τιμή από τα ίδια δεδομένα που στέλνει. Η αλλαγή ενός υπογεγραμμένου πεδίου μετά τη δημιουργία υπογραφής προκαλεί την αποτυχία της επαλήθευσης.

## SDK-διαχειριζόμενα πεδία

| Πεδίο | Πηγή | Περιγραφή |
| --- | --- | --- |
| agentCode | SDK διαμόρφωση | Κωδικός αντιπροσώπου συνεργάτη. |
| χρονική σφραγίδα | Τρέχουσα ώρα διακομιστή | Unix timestamp σε δευτερόλεπτα. |
| καμία φορά | Ασφαλής τυχαία τιμή | Τυχαία συμβολοσειρά προστασίας αναπαραγωγής. |
| σημείο | HMAC-SHA256 | Υπογραφή αιτήματος. |
| νόμισμα | Προεπιλεγμένο νόμισμα | Χρησιμοποιείται όταν η μεταφορά/λογαριασμός APIs παραλείπει το νόμισμα. |

## Μυστική αποθήκευση

- Φόρτωση `apiSecret` από έναν διαχειριστή μυστικών υποστήριξης ή μια προστατευμένη διαμόρφωση χρόνου εκτέλεσης.
- Μην τοποθετείτε ποτέ το μυστικό σε πακέτα frontend, εφαρμογές για κινητά, υπολογιστές-πελάτες για υπολογιστές, στιγμιότυπα οθόνης ή εισιτήρια υποστήριξης.
- Διατηρήστε χωριστά τα διαπιστευτήρια για ανάπτυξη, σκηνοθεσία και παραγωγή.
- Περιορίστε την πρόσβαση στις υπηρεσίες και τους φορείς εκμετάλλευσης που το απαιτούν.
- Διορθώστε υπογραφές αιτημάτων, τιμές εξουσιοδότησης και μυστικά από αρχεία καταγραφής.
- Ανάκληση και αντικατάσταση διαπιστευτηρίων όταν υπάρχει υποψία έκθεσης.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Προστασία ρολογιού και επανάληψης

Το SDK περιλαμβάνει τα `timestamp` και `nonce` για μείωση του κινδύνου επανάληψης. Διατηρήστε συγχρονισμένα τα ρολόγια του backend και μην επαναχρησιμοποιείτε ένα μη αυτόματο κατασκευασμένο μη αυτόματο. Εάν η επικύρωση υπογραφής αποτύχει, επιβεβαιώστε το διαμορφωμένο μυστικό, τον χρόνο διακομιστή, τα σειριακά πεδία και το περιβάλλον πριν προσπαθήσετε ξανά.

## Λίστα ελέγχου ενσωμάτωσης

| Ελεγχος | Αναμενόμενο αποτέλεσμα |
| --- | --- |
| Μυστική τοποθεσία | Μυστικός χώρος αποθήκευσης μόνο backend. |
| Περιβάλλο | Η βάση URL και το διαπιστευτήριο ανήκουν στο ίδιο περιβάλλον. |
| Χειρισμός πεδίου | Το SDK δημιουργεί τα `timestamp`, `nonce` και `sign`. |
| Ξύλευση | Τα αναγνωριστικά επιχείρησης παραμένουν ορατά ενώ τα διαπιστευτήρια διαγράφονται. |
| Περιστροφή | Ο ιδιοκτήτης διαπιστευτηρίων και η διαδικασία αντικατάστασης τεκμηριώνονται. |
