Αυτός ο οδηγός στοχεύει **Agent Java SDK `v0.3.0`** και Java 8+.

<span id="choose-both-the-frontend-mode-and-the-funds-environment" data-sixmm-canonical-anchor="choose-both-the-frontend-mode-and-the-funds-environment" aria-hidden="true"></span>

## Επιλέξτε τόσο τη λειτουργία frontend όσο και το περιβάλλον κεφαλαίων

Διαμορφώστε το περιβάλλον κεφαλαίων του backend του συνεργάτη ξεχωριστά από τη λειτουργία συναλλαγών frontend. Τα δεσμευτικά και τα διαπιστευτήρια εισόδου κοινοποιούνται. Η έκδοση εισιτηρίου ή κουπόνι δεν επιλέγει πορτοφόλι ή μετακινεί χρήματα.

| Διαμόρφωση | Παραγωγή | Προσομοίωση |
| --- | --- | --- |
| Δέσμευση και έλεγχος ταυτότητας | Κοινόχρηστες δεσμεύσεις χρήστη και διαπιστευτήρια μιας χρήσης | Ίδια ταυτότητα και έλεγχος ταυτότητας |
| Νέες μεταφορές και υπόλοιπα χρηστών | Παραλείψτε το `environment` ή χρησιμοποιήστε το `PRODUCTION` | Χρησιμοποιήστε ρητά `SIMULATED` |
| Χρηματοδότηση ανάκτησης αρχικής παραγγελίας | Χρησιμοποιήστε το αποθηκευμένο αρχικό περιβάλλον | Χρησιμοποιήστε το αποθηκευμένο αρχικό περιβάλλον |
| Λειτουργία συναλλαγών widget | `tradingMode=real` | `tradingMode=demo` |
| Frontend HTTP/Στόχος WS | Στόχος παραγωγής που παρέχεται από 6MM | Ο προσομοιωμένος στόχος παρέχεται από 6MM |
| Έξι ερωτήματα διαρκούς δεδομένων | Στοιχεία παραγωγής | Χωρίς επιλογέα περιβάλλοντος. Αυτές οι μέθοδοι δεν υποβάλλουν ερωτήματα σε προσομοιωμένα δεδομένα |

Για το `wallet-transfer-status`, η παράλειψη του `environment` χρησιμοποιεί το αποθηκευμένο περιβάλλον της αρχικής παραγγελίας, συμπεριλαμβανομένης μιας προσομοιωμένης παραγγελίας. Ένα ρητά αντικρουόμενο περιβάλλον απορρίπτεται. Προτιμήστε να αποθηκεύετε το περιβάλλον και να το περνάτε ρητά κατά την ανάκτηση μιας επέμβασης.

Το `isSimulatedUser` περιγράφει τον λογαριασμό. Δεν δρομολογεί νέα αιτήματα σε ένα προσομοιωμένο πορτοφόλι. Η παράλειψη του `environment` σε ένα αίτημα νέων χρημάτων εξακολουθεί να επιλέγει την παραγωγή, ακόμη και όταν η σημαία λογαριασμού είναι αληθής.

## Υποστηριζόμενα μοντέλα αιτήματος Java

Αυτά τα αιτήματα υποστηρίζουν `withEnvironment(ExecutionEnvironment.SIMULATED)`:

- `TransferRequest`, `TransferAllOutRequest`, `ReverseOrderRequest`.
- `QueryOrderRequest`, `ListOrdersRequest`.
- `QueryUserAssetsRequest`.
- `WalletTransferRequest`, `WalletTransferQueryRequest`.

`bind`, `queryAccount`, `createEntryUrl`, `createEmbedToken`, και τα έξι μοντέλα διαρκούς αιτήματος ερωτήματος δεν επιλέγουν περιβάλλον κεφαλαίων.

```java
import com.sixmm.agent.model.ExecutionEnvironment;
import com.sixmm.agent.model.QueryUserAssetsRequest;
import com.sixmm.agent.model.QueryUserAssetsResponse;

QueryUserAssetsResponse assets = client.queryUserAssets(
        QueryUserAssetsRequest.of("1188041528")
                .withFunding()
                .withEnvironment(ExecutionEnvironment.SIMULATED));
```

Αρχικοποιήστε το `client` χρησιμοποιώντας [Γρήγορη εκκίνηση](/el/sdk/agent-sdk/java/quick-start) και χρησιμοποιήστε το δημόσιο αναγνωριστικό χρήστη από την αποθηκευμένη βιβλιοδεσία σας.

## Διατηρήστε το αρχικό περιβάλλον

Διατηρήστε τον τύπο διεπαφής, `agentOrderNo`, την ταυτότητα χρήστη και το περιβάλλον πριν στείλετε ένα αίτημα χρημάτων. Διατηρήστε αυτό το περιβάλλον κατά τη διάρκεια των ερωτημάτων κατάστασης, της ανάκτησης, της συμφωνίας και της επεξεργασίας webhook. Μετά από ένα χρονικό όριο, μην επαναλάβετε ποτέ παραλείποντας το αρχικό περιβάλλον ή χρησιμοποιώντας έναν νέο αριθμό παραγγελίας.

Οι μεταφορές χρηματοδότησης/συμβολαίου παραμένουν σε ένα περιβάλλον. Τα προσομοιωμένα κεφάλαια δεν μπορούν να γίνουν κεφάλαια παραγωγής. Χρησιμοποιήστε ξεχωριστά προσομοιωμένα λογιστικά από την πλευρά του συνεργάτη και αναγνωρίσιμα προθέματα παραγγελιών, όπως `SIM-`.

## Προσομοιωμένη ακολουθία ολοκλήρωσης

1. Δέστε τον χρήστη και αποθηκεύστε το αναγνωριστικό χρήστη της δημόσιας πλατφόρμας.
2. Υποβάλετε ερωτήματα με ρητά `SIMULATED` και περιλαμβάνουν Χρηματοδότηση όταν χρειάζεται.
3. Δημιουργήστε μια μικρή προσομοιωμένη μεταφορά χρηματοδότησης και διατηρήστε την αρχική της επιχειρηματική παραγγελία.
4. Επιβεβαιώστε το τελικό αποτέλεσμα με το αποκλειστικό ερώτημα κατάστασης χρηματοδότησης.
5. Ανοίξτε ή ενσωματώστε τη σελίδα των δευτερολέπτων προορισμού σε λειτουργία `demo`.
6. Ζητήστε τα ίδια προσομοιωμένα πορτοφόλια και συμβιβάστε το πραγματικό μεταφερόμενο ποσό.
7. Για να ελέγξετε τη διαρκή διαπραγμάτευση, μεταφέρετε προσομοιωμένη Χρηματοδότηση σε προσομοιωμένο Συμβόλαιο και χρησιμοποιήστε την προσομοίωση προθεσμιακών συμβάσεων. Τα έξι διαρκή ερωτήματα συνεργατών δεν μπορούν να επικυρώσουν το προσομοιωμένο ιστορικό συναλλαγών.

## Λίστα ελέγχου αποδοχής

| Σενάριο | Αποδεικτικά στοιχεία προς επαλήθευση |
| --- | --- |
| Ταυτότητα | Η αντιστοίχιση δεσμευμένου χρήστη αποθηκεύεται. Δεν είναι δυνατή η υποβολή ερωτημάτων στους χρήστες άλλου συνεργάτη. |
| Πιστοποίηση | Οι ροές ανακατεύθυνσης και ενσωμάτωσης χρησιμοποιούν νέα διαπιστευτήρια. Η υπογραφή δεν δημιουργεί εντολές κεφαλαίων. |
| Χρήματα | Και οι δύο πλευρές συμφωνούν για το πραγματικό ποσό και την τελική κατάσταση. |
| Άγνωστο αποτέλεσμα | Η ανάκτηση χρησιμοποιεί την αρχική παραγγελία χωρίς να δημιουργήσει δεύτερη μεταφορά. |
| Περιβαλλοντική απομόνωση | Οι προσομοιωμένοι στόχοι backend και frontend συμφωνούν. τα ισοζύγια παραγωγής δεν επηρεάζονται. |
| Ερωτήματα | Χειρίζονται τα απαιτούμενα φίλτρα χρήστη/κατηγορίας, παράθυρα χιλιοστών του δευτερολέπτου, κενές σελίδες και δρομείς. |
| Όρια ποσοστών | Όλοι οι καλούντες ερωτήματος μοιράζονται τον περιορισμό και δοκιμάστε ξανά την αρχική αποτυχημένη σελίδα. |
| Αποθήκευση | Τα ποσά και τα αναγνωριστικά παραμένουν σειρές. Οι εγγραφές οντοτήτων αποθηκεύονται ανεπαρκώς. |

Πριν μεταβείτε στην παραγωγή, αλλάξτε τόσο τον στόχο κεφαλαίων υποστήριξης όσο και τη λειτουργία frontend. Οι εκκρεμείς παραγγελίες συνεχίζουν να ανακάμπτουν στο αρχικό τους περιβάλλον.
