6MM Agent SDK предназначен для партнерских серверных служб, которым необходимо вызывать привилегированный агент APIs без реализации подписи и обработки запросов с нуля. Его нельзя запускать в коде браузера, мобильного устройства или общедоступного настольного компьютера, поскольку при интеграции используется секрет партнера API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Когда использовать Agent SDK

Используйте Agent SDK, когда вашему бэкенду необходимо связать пользователя партнёра, перемещать активы в рамках утверждённого рабочего процесса, запрашивать торговые записи, создавать URL для входа во встроенную торговлю или проверять уведомления Webhook. Используйте [Trading Widget SDK](/ru/sdk/trading-widget/overview) отдельно, когда партнёрский фронтенд должен отображать торговый интерфейс.

## Общая конфигурация

| Ключ | Пример | Описание |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Служба агента API URL без косой черты в конце. |
| agentCode | AGENT001 | Код агента-партнера. |
| apiSecret | ваш-api-секрет | API секрет подписи хранится только на серверной стороне. |
| defaultCurrency | USDT | Валюта по умолчанию для перевода и счета APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Конечная точка партнера для уведомлений 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Типичный процесс интеграции

1. Партнерский интерфейс аутентифицирует пользователя через собственную систему учетных записей партнера.
2. Серверная часть партнера сопоставляет пользователя со стабильным идентификатором на стороне партнера.
3. Серверная часть вызывает Agent SDK с `agentCode` и защищенным секретом API.
4. SDK подписывает и отправляет агенту запрос API.
5. Серверная часть сохраняет возвращенный бизнес-идентификатор и позже обрабатывает webhooks идемпотентно.
6. Интерфейсный интерфейс получает только кратковременный результат или необходимые ему входные данные.

## Контрольный список производства

- Загрузите `apiSecret` из внутреннего диспетчера секретов, а не из исходного кода.
- Храните учетные данные разработки, подготовки и производства отдельно.
- Используйте стабильное сопоставление пользователей-партнеров и уникальные идентификаторы бизнес-заказов.
- Сохраняйте исходный идентификатор при проверке статуса запроса с истекшим временем ожидания.
- Проверьте подписи webhook и сохраните идентификаторы обработанных событий.
- Удаляйте секреты и подписи из журналов, сохраняя при этом идентификаторы запросов на поддержку.
