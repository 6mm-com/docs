## SDK вызов

Создайте встраиваемые токены с вашего бэкенда после проверки сессии партнера. Браузер должен вызывать вашу конечную точку, а ваша кончатая точка — 6MM через Agent SDK.

```java
CreateEmbedTokenResponse resp = client.createEmbedToken(
        CreateEmbedTokenRequest.of("agent-user-001", "tw_abc123")
                .withSymbol("ETHUSDT"));

System.out.println(resp.embedToken);
System.out.println(resp.expireAt);
```

> **Одноразовая квалификация**
>
> embedToken кратковременный и одноразовый. Не помещайте его в строку URL запроса.

<span id="backend-endpoint-example" data-sixmm-canonical-anchor="backend-endpoint-example" aria-hidden="true"></span>

## Пример бэкенд-эндпоинта

```java
@PostMapping("/api/trading/embed-token")
public EmbedTokenView createEmbedToken(@RequestBody EmbedTokenRequest request,
                                       PartnerSession session) {
    String agentUserId = session.getAgentUserId();
    CreateEmbedTokenResponse resp = agentClient.createEmbedToken(
            CreateEmbedTokenRequest.of(agentUserId, request.getChannelId())
                    .withSymbol(request.getSymbol()));

    return new EmbedTokenView(resp.embedToken, resp.expireAt, request.getChannelId());
}
```

Возвращайте только поля, необходимые поставщику Trading Widget токенов. Не возвращайте apiSecret, сырые поля подписи или внутреннюю конфигурацию сервиса.

## Обработка отказов

| Состояние | Рекомендуемое обращение |
| --- | --- |
| Пользовательская сессия отсутствует или истекает | Верните 401 с партнёрской конечной точки и попросите пользователя войти снова. |
| Пользователь агента не связан | Сначала привяжите пользователя, затем попробуйте создать токен. |
| 6MM возвращает временную ошибку | Верните повторяемую ошибку на фронтенд и запишите requestId для поддержки. |
| channelId не совпадает с экземпляром виджета | Отклоните запрос и создайте сессию виджета заново. |
