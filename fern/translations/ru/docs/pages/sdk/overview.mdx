## Рекомендуемая комбинация

| Партнёрская цель | Фронтенд | Бэкенд | Почему это важно |
| --- | --- | --- | --- |
| Добавьте встроенный торговый терминал | Trading Widget SDK | Agent SDK | Виджет управляет торговым интерфейсом, а партнёрский бэкенд выпускает токены и хранит секреты в тайне. |
| Создайте нативную точку входа в приложение | Нативная или H5-запись | Agent SDK | Приложение открывает 6MM запись URL после того, как партнёр подтвердит пользовательскую сессию. |
| Постройте индивидуальный торговый поток | Партнёрский интерфейс | Разработчик API + выбрал SDK потоки | Используйте API для данных о счетах, заказах, позициях и рынке, при этом операционные контроли остаются на серверной стороне. |

## Эталонная архитектура

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Хранить секреты на стороне сервера**
>
> Код браузера должен вызывать только конечные устройства, принадлежащие партнёрам. Агент API секрет никогда не должен отправляться в фронтенд-код.

## Чек-лист производства

- Хранить apiSecret только в бэкенд-инфраструктуре.
- Используйте HTTPS для запросов API агентов и URL вебхуков.
- Сохранять agentUserId, platformUserIdи agentOrderNo отображения.
- Представлять денежные суммы в виде десятичных строк вместо значений с плавающей точкой.
- Рассматривать PROCESSING как ожидающее, а не как успех или неудачу.
- Обрабатывать вебхуки идемпотентно, потому что ожидаются повторные попытки.
