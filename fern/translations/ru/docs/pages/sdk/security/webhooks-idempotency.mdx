Webhooks уведомляет серверную часть партнера об асинхронных изменениях бизнес-состояния. Поскольку доставка может быть повторена, каждый получатель должен проверить подпись перед анализом доверенных данных и должен обработать событие идемпотентно.

<span id="webhook-headers" data-sixmm-canonical-anchor="webhook-headers" aria-hidden="true"></span>

## Webhook заголовки

| Заголовок | Описание |
| --- | --- |
| X-Agent-Timestamp | Временная метка Unix в секундах. |
| X-Агент-Nonce | Nonce защиты от повторного воспроизведения. |
| X-Агент-Подпись | HMAC-SHA256 подпись. |

```text
timestamp + nonce + rawBody
```

Используйте точное необработанное тело запроса, полученное через HTTP при восстановлении подписанного значения. Предварительный анализ и повторная сериализация JSON может изменить ордер пробелов или полей и создать другую подпись.

<span id="verification-flow" data-sixmm-canonical-anchor="verification-flow" aria-hidden="true"></span>

## Процесс проверки

1. Прочитайте заголовки метки времени, одноразового номера и подписи.
2. Запишите неизмененное необработанное тело запроса.
3. Постройте `timestamp + nonce + rawBody`.
4. Вычислите HMAC-SHA256 с секретом партнера API .
5. Сравните вычисленные и полученные подписи, используя сравнение в постоянное время.
6. Примените утвержденные проверки актуальности меток времени и повторного использования одноразовых номеров.
7. Анализируйте и обрабатывайте событие только после успешной проверки.

Если доступен официальный верификатор Agent SDK, используйте его вместо поддержки независимого кода подписи.

<span id="order-idempotency" data-sixmm-canonical-anchor="order-idempotency" aria-hidden="true"></span>

## Заказать идемпотентность

| Случай | Умение обращаться |
| --- | --- |
| Первоначальный запрос на перенос | Создайте один глобально уникальный agentOrderNo. |
| HTTP тайм-аут | Запросите исходный agentOrderNo перед созданием нового. |
| PROCESSING ответ | Дождитесь webhook или запросите статус заказа. |
| Повторяющийся webhook | Дедупликация по ключу идемпотентности и окончательному статусу. |

<span id="recommended-idempotency-record" data-sixmm-canonical-anchor="recommended-idempotency-record" aria-hidden="true"></span>

## Рекомендуемая запись идемпотентности

Сохраните достаточно информации, чтобы распознать повторную доставку и безопасно восстановить ее:

| Поле | Цель |
| --- | --- |
| Ключ события или бизнеса | Уникально идентифицирует уведомление или операцию. |
| Номер заказа партнера | Связывает событие с исходным запросом. |
| Хэш полезной нагрузки | Помогает выявить конфликтующие повторяющиеся полезные данные. |
| Текущее состояние обработки | Различает полученную, обработанную, успешную и неудавшуюся работу. |
| Окончательный статус бизнеса | Предотвращает применение терминального действия дважды. |
| Временная метка обработки | Поддерживает политики расследования и хранения. |

По возможности зафиксируйте бизнес-изменение и запись идемпотентности в одной транзакции. Повторяющееся событие должно возвращать уже известный результат вместо повторного применения баланса, заказа или изменения пользователя.

<span id="timeout-and-retry-rule" data-sixmm-canonical-anchor="timeout-and-retry-rule" aria-hidden="true"></span>

## Правило тайм-аута и повтора

Тайм-аут HTTP не доказывает, что исходный запрос не выполнен. Запросите операцию, используя исходный `agentOrderNo` или дождитесь его webhook, прежде чем решить, требуется ли другое действие. Создание нового номера бизнес-заказа после каждого тайм-аута может привести к дублированию движений средств.

<span id="production-checklist" data-sixmm-canonical-anchor="production-checklist" aria-hidden="true"></span>

## Контрольный список производства

- Проверьте подпись перед синтаксическим анализом или бизнес-обработкой JSON .
- Сохраняйте необработанное тело независимо от проанализированной полезной нагрузки.
- Отклоняйте устаревшие или воспроизведенные запросы в соответствии с утвержденной политикой интеграции.
- Обеспечьте безопасность обработки событий при повторной и внеочередной доставке.
- Регистрируйте идентификаторы событий, номера заказов партнеров, результат обработки и время запроса.
- Редактируйте секреты и значения подписей из журналов и вложений поддержки.

## Финансирование и границы окружающей среды

Исходный поток передачи Контракта webhook и `queryOrder` не применяется автоматически к Финансированию. Подтвердите операции финансирования, используя `queryWalletTransfer` и исходную среду заказа. Финансирование использует `status`; в исходных ответах на передачу контракта используется `orderStatus`. Успешный ответ HTTP или `code=0` сам по себе не доказывает, что средства были переведены.

Явные уведомления о передаче смоделированного контракта включают `environment=SIMULATED`. Сначала проверьте необработанное тело, затем сверьте пользователя, сумму, идентификатор заказа и среду с сохраненным локальным бизнес-заказом.
