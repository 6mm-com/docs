Начните со среды, отметки времени и бизнес-идентификатора неудачной операции. Структурированная проверка обычно отделяет проблемы конфигурации от проблем аутентификации, сети и асинхронной обработки.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Рекомендуемый порядок диагностики

1. Подтвердите затронутую среду и базу URL.
2. Запишите временной диапазон UTC и первый неудачный запрос.
3. Определите модуль: Trading Widget, Agent SDK, REST API, WebSocket или webhook.
4. Запишите идентификатор запроса, идентификатор пользователя-партнера, `agentOrderNo`, идентификатор заказа или идентификатор события webhook.
5. Проверьте последний код, учетные данные, белый список IP или изменения в развертывании.
6. Воспроизведите с помощью наименьшего безопасного тестового примера.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget проблемы

| Симптом | Вероятная причина | Исправить |
| --- | --- | --- |
| iframe запрашивает локальный домен партнера | baseUrl отсутствует | Передайте baseUrl: 'https://app.6mm.com'. |
| iframe невидим или очень короткий | Родительский контейнер не имеет высоты | Установите высоту контейнера или высоту прохода. |
| token_provider_missing | в режиме партнерского токена нет провайдера | Добавить авторизациюtokenProvider. |
| auth_exchange_failed | Недействительный, просроченный или несоответствующий токен внедрения. | Проверьте ответ токена серверной части и channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK проблемы

| Симптом | Вероятная причина | Исправить |
| --- | --- | --- |
| Подпись отклонена | Неправильный секретный код, отклонение тактового сигнала или подписанные поля, измененные вручную. | Пусть SDK сгенерирует поля подписи и синхронизирует время сервера. |
| Риск дублирования движения средств | Новый номер заказа используется после таймаута | Сначала запросите исходный agentOrderNo. |
| PROCESSING рассматривается как сбой | Состояние ожидания неправильно понято | Подождите webhook или вызовите по queryOrder. |
| Webhook обработано несколько раз | Повторить поведение без идемпотентности | Добавьте ключ идемпотентности и проверки конечного состояния. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Доказательства для захвата

| Интеграция | Полезные доказательства |
| --- | --- |
| Trading Widget | Страница URL, путь к версии SDK, консоль браузера, неудачные сетевые запросы, полезная нагрузка `onError` и размеры контейнера. |
| Agent SDK | SDK язык/версия, базовая URL, UTC временная метка, идентификатор запроса, `agentOrderNo`, код ответа и очищенные журналы. |
| Webhook | Время доставки, событие или бизнес-ключ, результат проверки подписи, состояние обработки и очищенный хэш необработанного тела. |
| REST API | Метод, путь, среда, идентификатор запроса, код ответа и очищенные параметры. |

Никогда не включайте в диагностику пароли, токены доступа, секреты API, полные подписи, закрытые ключи или неотредактированные личные данные.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Прежде чем перейти к эскалации

- Повторяйте попытку только тогда, когда операция задокументирована как безопасная для повторения.
- По истечении времени ожидания запросите исходный бизнес-идентификатор вместо создания нового.
- Проверьте системные часы и среду учетных данных на наличие ошибок подписи.
- Сохраните первую неудачную попытку и результаты последующих повторных попыток.
- Используйте [Шаблон запроса на поддержку](/ru/resources/support-request-template) отправить полный отредактированный отчет.

## Java v0.3.0 диагностика

| Симптом | Проверка и восстановление |
| --- | --- |
| Запрос на финансирование имеет неизвестный результат | Сохраните оригинал `agentOrderNo`; вызовите `queryWalletTransfer` с исходной средой. Не используйте `queryOrder`. |
| Пользовательский интерфейс моделирования показывает неожиданные средства | Проверьте внешний интерфейс `tradingMode` отдельно от внутреннего `environment`; учетная запись `isSimulatedUser` не маршрутизирует запросы. |
| Ошибка запроса `6905` | Откажитесь от использования общей квоты партнера, затем повторите попытку с тем же курсором и фильтрацией через SDK. |
| Ошибка запроса `6904` | Уменьшите количество одновременных запросов и сузьте временное окно; обратитесь в службу поддержки, если упорно. |
| Неверный или просроченный курсор | Перезапустите то же окно фиксированной истории и выполните дедупликацию сохраненных записей. |
| Отсутствует новый метод Java | Проверьте разрешенный артефакт Maven по общедоступному тегу `v0.3.0`; удалите конфликтующие зависимости в соответствии с вашей политикой артефактов. |
