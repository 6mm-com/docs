Начните с среды, временной метки и бизнес-идентификатора для неудачной операции. Структурированная проверка обычно отделяет проблемы конфигурации от аутентификации, сетевых и асинхронной обработки.

<h2 id="diagnostic-order">Рекомендуемый диагностический порядок</h2>

1. Подтвердить затронутую среду и базовую URL.
2. Запишите UTC временной диапазон и первый неудачный запрос.
3. Определите модуль: Trading Widget, Agent SDK, REST API, WebSocketили webhook.
4. Зафиксировать идентификатор запроса, идентификатор пользователя партнёра, `agentOrderNo`, ID заказа или идентификатор события вебхука.
5. Проверьте недавний код, учетные данные, IP белый список или изменения в развертывании.
6. Воспроизводите с помощью наименьшего безопасного тестового случая.

<h2 id="trading-widget-issues">Trading Widget проблемы</h2>

| Симптом | Вероятная причина | Исправление |
| --- | --- | --- |
| iframe запрашивает партнёра в локальном домене | baseUrl отсутствует | Pass baseUrl: 'https://app.6mm.com'. |
| iframe невидим или очень короткий | Родительский контейнер не имеет высоты | Установите высоту контейнера или высоту прохода. |
| token_provider_missing | Режим Partner-Token не имеет провайдера | Добавьте авторизациюtokenProvider. |
| auth_exchange_failed | Недействительный, истекший или несовпадающий встраиваемый токен | Проверьте отклик токена на бэкенде и channelId. |

<h2 id="agent-sdk-issues">Agent SDK проблемы</h2>

| Симптом | Вероятная причина | Исправление |
| --- | --- | --- |
| Подпись отклонена | Неправильный секрет, смещение часов или ручное изменение подписанных полей | Позвольте SDK генерировать поля подписи и синхронизировать время сервера. |
| Риск перемещения дублирующих средств | Новый номер заказа используется после тайм-аута | Сначала запросите по оригинальным agentOrderNo . |
| PROCESSING считали неудачей | Ожидающее государство неправильно понято | Подождите вебхук или вызовите queryOrder. |
| Webhook обрабатывается многократно | Повторяйте поведение без идемпотентности | Добавьте ключ идемпотентности и проверки конечного состояния. |

<h2 id="evidence-to-capture">Доказательства для захвата</h2>

| Интеграция | Полезные доказательства |
| --- | --- |
| Trading Widget | Страница URL, SDK путь версии, консоль браузера, неудачные сетевые запросы, `onError` полезная нагрузка и размеры контейнеров. |
| Agent SDK | SDK языке/версии, базовой URL, UTC временной меткой, идентификатором запроса, `agentOrderNo`, кодом ответа и очищенными журналами. |
| Вебхук | Время доставки, событие или бизнес-ключ, результат проверки подписи, состояние обработки и очищенный raw body hash. |
| REST API | Метод, путь, среда, идентификатор запроса, код ответа и очищенные параметры. |

Никогда не включайте в диагностику пароли, токены доступа, API секреты, полные подписи, приватные ключи или неотредактированные персональные данные.

<h2 id="before-escalating">Перед эскалацией</h2>

- Повторять только тогда, когда операция задокументирована как безопасная для повторного попробовки.
- После тайм-аута запросите исходный бизнес-идентификатор вместо создания нового.
- Подтверждение системного тактового сигнала и среды учетных данных на наличие ошибок подписи.
- Сохранить первую неудачу и все последующие повторные попытки.
- Используйте [Шаблон запроса поддержки](/ru/resources/support-request-template) для отправки полного, отредактированного отчёта.
