Запросы Agent SDK аутентифицируются с помощью секрета партнера API. Храните этот секрет в доверенной внутренней службе и позволяйте SDK генерировать поля подписи, когда это возможно.

> **Два протокола подписания**
>
> При подписании Agent SDK используются отсортированные поля запроса, временная метка в секундах и одноразовый номер. Прямые запросы Developer API используют отдельный процесс, описанный в разделе [Запрос на подписание](/ru/developer-api/request-signing). Не используйте повторно один формат полезной нагрузки для другого.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## Правило подписи

Для запросов Agent SDK:

1. Исключите поле `sign`.
2. Пропускать поля с пустыми значениями.
3. Отсортируйте оставшиеся имена полей в порядке ASCII.
4. Объедините поля как `k=v&k2=v2`.
5. Вычислите шестнадцатеричную подпись HMAC-SHA256 с помощью `apiSecret`.

Значения массива сериализуются как компактные JSON перед присоединением к подписывающим полезным данным. Например, `platformUserIds` обозначается как `["1188041528"]`, что дает `platformUserIds=["1188041528"]` в полезных данных `k=v` . Сохранять порядок элементов массива, двойные кавычки и идентификаторы строк; не вставляйте пробелы форматирования и не используйте Java `List.toString()` (например, `[1188041528]`). SDK автоматически обрабатывает эту сериализацию.

SDK должен построить это значение на основе тех же данных, которые он отправляет. Изменение подписанного поля после создания подписи приводит к сбою проверки.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## Поля, управляемые SDK

| Поле | Источник | Описание |
| --- | --- | --- |
| agentCode | SDK конфиг | Код агента-партнера. |
| временная метка | Текущее время сервера | Временная метка Unix в секундах. |
| одноразовый номер | Безопасное случайное значение | Случайная строка для защиты от повторного воспроизведения. |
| знак | HMAC-SHA256 | Запросить подпись. |
| валюта | Валюта по умолчанию | Используется, когда в переводе/счете APIs отсутствует валюта. |

## Секретное хранилище

- Загрузите `apiSecret` из внутреннего секретного менеджера или защищенной конфигурации среды выполнения.
- Никогда не размещайте секрет в пакетах внешнего интерфейса, мобильных приложениях, клиентах для настольных компьютеров, скриншотах или обращениях в службу поддержки.
- Храните учетные данные для разработки, подготовки и производства отдельно.
- Ограничьте доступ к сервисам и операторам, которые этого требуют.
- Редактировать подписи запросов, значения авторизации и секреты из журналов.
- Отозвать и заменить учетные данные при подозрении на заражение.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Защита часов и повторов

SDK включает `timestamp` и `nonce` для снижения риска повторного воспроизведения. Синхронизируйте внутренние часы и не используйте повторно созданный вручную одноразовый номер. Если проверка подписи не удалась, перед повторной попыткой подтвердите настроенный секрет, время сервера, сериализованные поля и среду.

## Контрольный список интеграции

| Проверять | Ожидаемый результат |
| --- | --- |
| Секретная локация | Секретное хранилище только для серверной части. |
| Среда | База URL и учетные данные принадлежат одной среде. |
| Обработка полей | SDK генерирует `timestamp`, `nonce` и `sign`. |
| Ведение журнала | Бизнес-идентификаторы остаются видимыми, пока учетные данные редактируются. |
| Вращение | Владелец учетных данных и процесс замены документированы. |
