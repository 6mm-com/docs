Встроенная торговля обычно внедряется в существующий продукт, а не запускается как самостоятельный путь назначения. Лучший путь интеграции зависит от того, где пользователи уже проводят время и какая система владеет идентичностью, фондами и операциями.

<h2 id="common-scenarios">Распространённые сценарии</h2>

| Сценарий | Лучший старт | Примечания |
| --- | --- | --- |
| Приложение или кошелёк хочет торговую запись | Trading Widget SDK | Используйте нативную или H5-точку входа и откройте встроенный торговый опыт после авторизации пользователя. |
| Брокер или платформа канала хочет получить доступ к деривативам | Agent SDK + Trading Widget SDK | Сохраняйте отношения с клиентами и валидацию бэкенда в партнерской системе. |
| Платформа требует направленного торгового потока | API + выбранные SDK модули | Используйте бэкенд- APIs для рабочих процессов с аккаунтами, переводом и заказами, при этом показывайте только необходимую фронтенд-запись. |
| Существующая биржа требует дополнительных рынков | Ликвидность + интеграция API | Объединяйте глубину рынка, рабочие процессы с клиентами и операционный мониторинг. |

<h2 id="product-decisions-before-integration">Решения о продукте до интеграции</h2>

- Определить, вводят ли пользователи с карточки главной страницы, страницы активов, страницы кампании или центра аккаунта.
- Определить, какая система владеет состоянием входа, правом пользователя и доступностью страны или региона.
- Решать, как перемещения, записи о расчетах и заявки службы поддержки показываются пользователям.
- Определить, какие события должны быть переадресованы во внутреннюю аналитику, CRMили операции по риску.
