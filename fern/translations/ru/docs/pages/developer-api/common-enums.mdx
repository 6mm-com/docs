## Заказы

| Энум                 | Ценности                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Сторона ордена           | `BUY` / `SELL`                                                                                            |
| Сторона позиции        | `BOTH` / `LONG` / `SHORT`                                                                                 |
| Нормальный тип ордера    | `LIMIT` / `MARKET`                                                                                        |
| Тип ордера условий | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| Время действия        | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| Тип триггерной цены   | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| Статус ордена         | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` означает, что запрос на заказ был принят и возвращён. `PENDING` означает, что приказ вошёл в состояние ожидания или открытого приказа.

## Должности

| Энум                      | Ценности                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Значение запроса в режиме margin | `1` крест `2` изолирован                                     |
| Строка режима поля        | `ISOLATED` / `CROSS`                                        |
| Режим закрытия спуска        | `1` инструкции `2` тейк-профит, `3` стоп-лосс `4` ликвидации |

<span id="integration-rules" data-sixmm-canonical-anchor="integration-rules" aria-hidden="true"></span>

## Правила интеграции

- Рассматривать значения enum как значения проводов с чувствительностью к регистру.
- Сохранять неизвестные значения в журналах и безопасно отказывать вместо тихого сопоставления их в известное состояние.
- Не делать выводов, что каждое состояние неконечного ордера безопасно для повторной попытки. Запросите заказ или согласуйте его с частным WebSocket событием.
- Сохранять как исходное значение API , так и отображённую на партнёра, чтобы новые значения можно было поддерживать без изменения исторических записей.

## Обработка состояния заказов

| Группа штатов | Ценности | Рекомендуемое обращение |
| --- | --- | --- |
| Принято или открыто | `NEW`, `PENDING`, `PARTIALLY_FILLED` | Держите ордер активным и примиряйте WebSocket или REST обновления. |
| Завершено | `FILLED` | Примените итоговые данные по заполненному количеству и записи исполнения. |
| Закрыт без полного заполнения | `CANCELED`, `REJECTED`, `PARTIALLY_FILLED_CANCELED` | Прекратите активную обработку и сохраните причину и любое выполненное количество. |
