<h2 id="service-endpoints">Конечные точки обслуживания</h2>

| Тип      | Конечная точка              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<h2 id="time-and-numeric-values">Время и числовые значения</h2>

* Если не указано иное, временные поля — это миллисекундные метки Unix.
* Ежедневная статистика, снимки баланса и статистика объёмов торгов по умолчанию используют UTC дневные границы.
* Точно-чувствительные поля, такие как количество, цена, количество и скорость, передаются в виде строк.
* Большие целочисленные идентификаторы, такие как `orderId`, `conditionId`, и `strategyId` , возвращаются в виде строк в JSON.

<h2 id="response-format">Формат ответа</h2>

Успешный ответ:

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-12345678"
}
```

Ответ на ошибку:

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Примечания:

* Ошибки бизнеса обычно всё равно возвращают унифицированную структуру JSON . Интеграторы должны сначала проверить `code` .
* Ошибки аутентификации могут вернуть HTTP `401`; ограничение скорости может вернуть HTTP `429`.
* Вы можете отправить `X-Request-ID` в заголовке запроса. Сервер вернёт его как `requestId` в ответе.
