Вывод средств — это асинхронная бизнес-операция. Успешный ответ HTTP означает, что запрос был обработан; он не устанавливает, что средства поступили в цепочку.

<span id="persist-one-business-identifier" data-sixmm-canonical-anchor="persist-one-business-identifier" aria-hidden="true"></span>

## Сохранение одного бизнес-идентификатора

Сгенерируйте и сохраните `client_request_id` перед отправкой вывода. Используйте его повторно для повторных попыток той же предполагаемой операции, в том числе после перезапуска процесса. Обеспечьте единообразие полей транздоли криптографического ключа; текущая реализация отклоняет повторяющийся идентификатор с конфликтующими бизнес-параметрами.

Не полагайтесь только на заголовок `Idempotency-Key`. Предоставленный SDK может добавить этот заголовок, но текущий контракт дедупликации вывода основан на поле тела `client_request_id`.

## Понимание данных запроса

| Поле | Значение |
| --- | --- |
| `chain_id`, `asset_id` | Идентификаторы в согласованной среде |
| `to_address`, `amount` | Назначение и положительная десятичная сумма, представленная в виде строки. |
| `client_request_id` | Стабильный идентификатор бизнес-запроса |
| `dest_memo_type`, `dest_memo` | Подробные сведения о пункте назначения, если их требует сеть. |
| `client_authorization` | Авторизация транздоли криптографического ключа клиента для вывода средств, инициированного ключом API |
| `end_user_id` | Необязательный идентификатор бизнес-пользователя в корпоративном потоке API |

В этой таблице выделены основные поля, а не полная схема запроса. Подтвердите предварительную версию, подтверждение оплаты и требования к хранению в отношении интеграционной версии. Избегайте двоичных сумм с плавающей запятой и не копируйте цепочки примеров или номера активов между средами.

## Следите за результатом

| Примеры штатов | Интерпретация |
| --- | --- |
| `pending_approval`, `pending_platform_review` | Одобрение или проверка бизнеса не завершены |
| `approved`, `pending_sign` | Согласование и подписание — отдельные этапы. |
| `broadcasting`, `pending_chain` | Выполняется трансляция или подтверждение цепочки |
| `broadcast_unverified`, `recovering` | Результат все еще неясен; не создавайте еще один перевод |
| `awaiting_reauthorization` | Для того же запроса может потребоваться новая авторизация клиента. |
| `confirmed` | Система зафиксировала подтверждение цепочки |

Список носит иллюстративный характер и может расширяться. Сохраняйте неизвестные состояния для исследования, а не сопоставляйте их с успехом или неудачей. Неудавшийся или отклоненный лейбл сам по себе не является достаточным доказательством того, что ничего не подписывалось и не транслировалось.

## Восстановление после таймаута

Запросите `GET /api/v1/withdrawals/by-request` с использованием исходного параметра запроса `client_request_id`. Продолжайте опрос или согласование исходной операции, пока ее результат неизвестен. Если требуется продление авторизации, используйте тот же идентификатор и согласованную процедуру продления.

Отмена зависит от фактического этапа подписания и проверок сервера. Начинайте бизнес-операцию по замене только после того, как будет установлено, что оригинал не передан и не может быть передан. Получайте события через [webhooks](/ru/mpc-wallet/webhooks-and-sdks)и сохраните запросы API в качестве пути сверки.
