В руководствах для разработчиков описывается текущая поверхность интеграции корпоративного кошелька. MPC Кошелек не запущен: примеры конечных точек — это ссылки на реализацию, а не обещание общедоступного сервиса или замороженный контракт API.

<span id="obtain-integration-information" data-sixmm-canonical-anchor="obtain-integration-information" aria-hidden="true"></span>

## Получить информацию об интеграции

Подтвердите тестовую базовую версию URL, API, удостоверение рабочей области, модель хранения, включенные сети и активы, разрешения API, требования к авторизации клиента и настройку webhook. Идентификаторы сети и активов берутся из согласованной среды; не думайте, что они равны идентификаторам общедоступной цепи.

Храните учетные данные для интеграции кошелька отдельно от торговых API учетных данных. Сайт общей документации не обеспечивает взаимозаменяемость услуг или моделей учетных записей.

<span id="connect-the-business-flow" data-sixmm-canonical-anchor="connect-the-business-flow" aria-hidden="true"></span>

## Подключите бизнес-поток

1. Создайте ключ API с наименьшими привилегиями для предполагаемой рабочей области предприятия и сохраните его в секрете на своем сервере.
2. Прежде чем выполнять передачу, проверьте подписанный запрос только для чтения и обработку ошибок.
3. Назначьте адрес получения для стабильного идентификатора бизнес-пользователя, затем проверьте возвращенный адрес и все примечания.
4. Получайте события депозита и согласовывайте их с запросами API и вашими собственными записями.
5. Добавьте авторизацию вывода средств, стабильные идентификаторы бизнес-запросов и отслеживание результатов.

<span id="core-api-areas" data-sixmm-canonical-anchor="core-api-areas" aria-hidden="true"></span>

## Основные API области

| Область | Текущие примеры маршрутов | Цель |
| --- | --- | --- |
| Получение адресов | `POST /api/v1/addresses`, `GET /api/v1/addresses` | Выделение и запрос адресов |
| Депозиты | `GET /api/v1/deposits`, `GET /api/v1/deposits/{id}` | Следите за входящими переводами |
| Вывод средств | `POST /api/v1/withdrawals`, `GET /api/v1/withdrawals/{id}` | Отправьте запрос и запросите его результат |
| Запросить поиск | `GET /api/v1/withdrawals/by-request` | Согласование запроса после неопределенного ответа |
| Балансы | `GET /api/v1/balances` | Запрос бизнес-балансов в авторизованной области |

Регистрация маршрута не означает, что каждый ключ API может вызывать любую операцию. Доступ к продукту, разрешения на рабочее пространство, режим хранения и инициализация — все это может повлиять на доступность. Интерфейсы административного и личного устройства находятся за пределами корпоративного процесса быстрого запуска.

## Подтвердить адреса получения

Поставляемая реализация SDK поддерживает подписанные подтверждения адреса. Настройте доверенных участников или доверенные материалы, указанные в пакете интеграции, и независимо предоставьте ожидаемую информацию о рабочей области, цепочке и группе ключей, где это необходимо. Не извлекайте все ожидания доверия из одного и того же ответа, который вы проверяете.

Для полностью управляемых адресов пула аттестация может идентифицировать адрес, принадлежащий платформе, в то время как его назначение клиенту остается оператором на стороне сервера. Не описывайте это задание как криптографическое доказательство владения клиентом.

Продолжить с [запросить подпись](/ru/mpc-wallet/request-signing), [транздоли криптографического ключа](/ru/mpc-wallet/transactions) и [webhooks и SDKs](/ru/mpc-wallet/webhooks-and-sdks).
