Существует три отдельных проблемы подписи: аутентификация запроса HTTP, авторизация конкретного вывода и создание подписи блокчейна с участием MPC участников. Прохождение первой проверки не заменяет две другие.

## Аутентификация запроса API

Текущий API использует HMAC-SHA256 с идентификатором ключа и секретом API . Его канонический запрос содержит пять строк, разделенных символом новой строки, без завершающего символа новой строки:

```text
METHOD
PATH
SORTED_QUERY
BODY_SHA256_HEX
UNIX_TIMESTAMP_SECONDS
```

Используйте метод HTTP в верхнем регистре и запросите путь без хоста. Сортируйте ключи запроса, сохраняйте порядок повторяющихся значений и применяйте кодировку формы URL, включая `+` для пробелов. Строка запроса пуста, если запрос не существует. Хешируйте точные байты тела, используя SHA-256, включая пустое тело для запроса без тела.

Вычислите HMAC-SHA256 с использованием предоставленного секрета в виде UTF-8 байтов; не декодируйте его в шестнадцатеричном формате только потому, что он выглядит шестнадцатеричным. Закодируйте результат в шестнадцатеричном виде строчными буквами. Поля заголовка разделены пробелами:

```text
Authorization: HMAC-SHA256 keyId=<KEY_ID> signature=<HEX_SIGNATURE> timestamp=<UNIX_SECONDS>
```

## Пример подписи только для чтения

Этот помощник стандартной библиотеки создает заголовки для запроса на депозит; он не отправляет запрос. Надежно загрузите учетные данные в свое приложение и отправьте возвращенный путь без изменений в базу URL, предоставленную для вашей среды.

```python
import hashlib
import hmac
import time
from urllib.parse import urlencode


def signed_read_headers(key_id, secret, timestamp=None):
    method = "GET"
    path = "/api/v1/deposits"
    query = urlencode(sorted([("page", "1"), ("page_size", "20")]))
    body = b""
    ts = str(int(time.time()) if timestamp is None else timestamp)
    canonical = "\n".join([
        method, path, query, hashlib.sha256(body).hexdigest(), ts
    ])
    signature = hmac.new(
        secret.encode("utf-8"), canonical.encode("utf-8"), hashlib.sha256
    ).hexdigest()
    return path + "?" + query, {
        "Authorization": (
            f"HMAC-SHA256 keyId={key_id} signature={signature} timestamp={ts}"
        )
    }
```

Следите за синхронизацией часов. Прокси-сервер, который меняет путь, запрос или тело после подписания, может сделать аутентификацию недействительной. В случае сбоев аутентификации перед повторной попыткой проверьте причину ответа и идентификатор запроса; никогда не регистрируйте секретный или полный заголовок авторизации.

## Разрешить вывод средств API

Текущий поток вывода средств предприятия API также требует авторизации клиента Ed25519 в `client_authorization`. Он связывает предполагаемый контекст транздоли криптографического ключа, включая идентификатор запроса, пункт назначения, актив и сумму. Его регистрация с открытым ключом или конфигурация доверия зависят от условий хранения.

Используйте соответствующий пакет интеграции для создания канонических полезных данных, подписи и открытого ключа. Этот ключ авторизации отделен от секрета HMAC и общих ресурсов MPC. Сохраните свой закрытый ключ под контролем клиента. Подтвердите версию полезных данных и правила действия во время интеграции вместо создания собственного формата из этого обзора.

После того как запрос будет принят, бизнес-проверки и утверждения все еще могут применяться, после чего следует подписание MPC и подтверждение цепочки. Видеть [транздоли криптографического ключа и повторы](/ru/mpc-wallet/transactions).
