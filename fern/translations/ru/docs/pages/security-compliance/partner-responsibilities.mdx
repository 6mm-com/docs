Чёткая модель ответственности снижает операционные риски и помогает командам поддержки быстрее реагировать.

<h2 id="responsibility-split">Разделение ответственности</h2>

| Площадь | 6MM | Партнёр |
| --- | --- | --- |
| Торговая инфраструктура | Возможности сопоставления, риски, торговые движки, API и SDK | Правильная интеграция и мониторинг производства |
| Отношения конечного пользователя | Нет прямых отношений с клиентом, если не согласовано отдельно | Адаптация пользователей, поддержка, раскрытие информации и жизненный цикл аккаунта |
| Секреты и квалификации | Предоставляет модель учетных данных и требования к подписанию | Хранит секреты надёжно и ограничивает внутренний доступ |
| Вебхуки | Отправляет подписанные события жизненного цикла | Проверяет сигнатуры и обрабатывает события идентично |
| Операции по соблюдению требований | Предоставляет технологии, ориентированные на соответствие требованиям, и вспомогательные материалы | Подтверждает местные обязательства и требования, ориентированные на пользователей |
| Интеграционные релизы | Поддерживает документированные возможности платформы и интеграции | Тестирует код, конфигурацию и пользовательский путь партнёров перед релизом |
| Управление инцидентами | Исследует релевантную 6MM инфраструктуру и предоставляет каналы поддержки партнёров | Обнаруживает воздействие, ориентированное на пользователя, сохраняет доказательства, содержит партнёрские системы и эскалирует ситуацию |

<h2 id="responsibilities-by-lifecycle">Обязанности по жизненному циклу</h2>

| Сцена | Партнёрские действия |
| --- | --- |
| Конструкция | Определите право собственности пользователя, поток активов, поток данных, модель поддержки и целевые юрисдикции. |
| Строительство | Храните секреты на сервере, внедряйте поддерживаемую аутентификацию и сохраняйте бизнес-идентификаторы. |
| Тест | Проверьте тайм-аут, повторную попытку, дубликат вебхука, истечённый токен и сценарии неудач. |
| Запуск | Завершить оценку готовности, организовать мониторинг и задокументировать эскалацию поддержки. |
| Эксплуатация | Проверяйте оповещения, сверяйте аномальные операции, меняйте учетные данные и сохраняйте доказательства аудита. |
| Инцидент | Содержать системы под управлением партнёров, защищать учетные данные, сохранять UTC сроки и связываться с нужным 6MM каналом. |

<h2 id="handoff-checklist">Чек-лист оперативной передачи</h2>

- Назначить владельца для поддержки интеграции, здоровья, безопасности, соответствия и конечных пользователей.
- Документировать базовые URL-адреса, владельцев учетных данных и процедуры ротации.
- Подтверждать дашборды и оповещения о сбоях аутентификации, заказа, передачи и вебхуков.
- Храните идентификаторы запросов, номера заказов партнёров и идентификаторы событий в поисковых логах.
- Определить, какие события требуют немедленной эскалации.
- Сохранять [шаблон запроса на поддержку](/ru/resources/support-request-template) для операционной команды.
