6MM документация по безопасности сосредоточена на готовности к производству партнёров. Цель — поддерживать стабильность торговой инфраструктуры, одновременно чётко обозначая границы ответственности.

<span id="security-layers" data-sixmm-canonical-anchor="security-layers" aria-hidden="true"></span>

## Уровни безопасности

| Слой | Фокус |
| --- | --- |
| Инфраструктура | Сетевая изоляция, зашифрованная связь с сервисами, мониторинг и резервное подключение. |
| Торговые системы | Детерминированное сопоставление, маржевые проверки, контроль рисков и предотвращение злоупотреблений. |
| Безопасность интеграции | API ключи, HMAC подписи, подписи вебхуков, защита от повторов и секреты только для бэкенда. |
| Партнёрская деятельность | Проверка пользовательских сессий, хранение активов, поддержка клиентов и локальный контроль соответствия. |

<span id="partner-responsibilities" data-sixmm-canonical-anchor="partner-responsibilities" aria-hidden="true"></span>

## Обязанности партнёра

- Хранить API секреты и ключи для входа в браузеры и мобильные приложения.
- Проверять сессии партнёров перед выдачей учетных данных для входа в торговлю.
- Реализовать проверку идемпотентности вебхука и состояния терминала.
- Вести операционные журналы для потоков счетов, заказов, переводов и вебхуков.

<span id="integration-trust-boundaries" data-sixmm-canonical-anchor="integration-trust-boundaries" aria-hidden="true"></span>

## Границы интеграционного доверия

| Граница | Требуемый контроль |
| --- | --- |
| Браузер или приложение для партнёра бэкенда | Проверьте сессию партнёра перед выдачей любых торговых учетных данных. |
| Партнёрский бэкенд на 6MM API | Используйте обмежённые данные данных, подписание запросов, синхронизацию времени и защищённое секретное хранилище. |
| 6MM webhook к партнерской конечной точке | Проверьте подпись по исходному телу запроса, отклоните устаревшие или недействительные сообщения и удалите повторные попытки. |
| Обмен данных от состояния к партнёру | Сверяйте приказы, позиции, балансы и передачи с помощью надёжных идентификаторов и проверок состояния терминала. |

<span id="production-verification" data-sixmm-canonical-anchor="production-verification" aria-hidden="true"></span>

## Проверка производства

- Тест истек, аннулирован и неправильно распределён обхват данных.
- Тестирование изменённых тел вебхуков, дублированных обратных вызовов, задерживаемых обратных вызовов и тайм-аутов конечных точек.
- Подтвердить, что логи редактируют секреты, токены доступа и полезные нагрузки для конфиденциальных запросов.
- Оповещение о повторяющихся сбоях сигнатур, аномальной активности порядка, различиях в сверке и нестабильности соединения.
- Задокументировать владельца и путь реагирования на предметы раскрытия учетных данных, сбоя вебхука и торговых инцидентов.
