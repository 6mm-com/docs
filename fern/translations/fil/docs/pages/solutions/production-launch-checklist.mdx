Gamitin ang checklist na ito bago ipakita ang mga trading flow na pinapagana ng 6MMsa mga gumagamit ng produksyon. Dinisenyo ito para sa mga koponan ng produkto, engineering, operasyon, panganib, at suporta na sabay-sabay na suriin.

<h2 id="launch-checklist">Launch checklist</h2>

| Lugar | Checklist |
| --- | --- |
| Produkto | Handa na ang mga entry point, user copy, risk prompts, language coverage, at support paths. |
| Backend | API credentials, signing, token issuance, webhooks, retries, at logging ang ipinatupad. |
| Kalakalan | Sinuri ang order, transfer, position, margin, fee, at liquidation behavior. |
| Seguridad | Inihahanda ang mga lihim, access roles, monitoring, incident response, at audit logs. |
| Mga Operasyon | Itinalaga ang mga support workflow, escalation paths, reconciliation, at araw-araw na monitoring. |

<h2 id="recommended-sequence">Inirerekomendang pagkakasunod-sunod</h2>

1. Kumpletong beripikasyon ng sandbox o internal environment.
2. Patakbuhin ang end-to-end user journeys para sa login, entry, transfer, trading, at suporta.
3. Kumpirmahin ang pagmamay-ari ng monitoring at incident response.
4. Aprubahan ang public copy, localized assets, at resource downloads.
5. Magsimula sa isang kontroladong launch window bago ang malawakang promosyon.

<h2 id="after-launch">Pagkatapos ng paglulunsad</h2>

Suriin ang aktibidad araw-araw sa unang panahon ng paglulunsad. Panoorin ang conversion ng entry, mga kabiguan sa pag-isyu ng token, mga error sa order, kalidad ng spread, pagkumpleto ng transfer, webhook retries, at mga support ticket nang sabay-sabay.
