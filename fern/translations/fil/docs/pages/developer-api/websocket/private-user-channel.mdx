Gumawa muna ng `listenKey` :

```http
POST /v1/private/user/listen-key
```

Halimbawa ng tugon:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "listenKey": "f57cb61ef604ce76be09e753a5dbdd8c",
    "expireAt": 1777539918867
  },
  "requestId": "req-listen-key"
}
```

`listenKey` ay valid sa loob ng 60 minuto bilang default. Inirerekomenda ang pag-renew tuwing 30 minuto.

<h2 id="renew">Mag-renew</h2>

```http
PUT /v1/private/user/listen-key
Content-Type: application/json
```

```json
{ "listenKey": "f57cb61ef604ce76be09e753a5dbdd8c" }
```

<h2 id="close">Isara</h2>

```http
DELETE /v1/private/user/listen-key
Content-Type: application/json
```

```json
{ "listenKey": "f57cb61ef604ce76be09e753a5dbdd8c" }
```

<h2 id="connect-to-private-websocket">Kumonekta sa pribadong WebSocket</h2>

```
wss://ws.6mm.com/ws?listenKey=YOUR_LISTEN_KEY
```

Compatible na paraan ng JWT connection:

```
wss://ws.6mm.com/ws?token=YOUR_ACCESS_TOKEN
```

Kapag nagtagumpay ang authentication, awtomatikong nag-subscribe ang server sa pribadong channel ng kasalukuyang user. Hindi na kailangan ng manual subscription.

Matagumpay na pagkilala sa authentication:

```json
{ "event": "auth", "success": true, "data": "1188041528" }
```

<h2 id="common-private-events">Karaniwang pribadong kaganapan</h2>

| Kaganapan                | Paglalarawan                                                                   |
| -------------------- | ----------------------------------------------------------------------------- |
| `ORDER_TRADE_UPDATE` | Mga pagbabago sa status ng order, kabilang ang bagong order, pagbabago, kalakalan, at pagkansela |
| `ACCOUNT_UPDATE`     | Balanse ng account at pagbabago sa posisyon                                          |

Pribadong push message wrapper:

```json
{
  "topic": "user.5794",
  "ts": 1771047000000,
  "data": {
    "eventType": "ORDER_TRADE_UPDATE"
  }
}
```

REST query endpoints at WebSocket private streams ay gumagamit ng magkahiwalay na schema. Dapat i-parse ng mga kliyente ang bawat schema nang hiwalay at huwag ipalagay na magkapareho ang mga pangalan ng field.

<h2 id="common-differences">Karaniwang pagkakaiba</h2>

| Domain         | REST larangan     | WebSocket larangan                                             |
| -------------- | -------------- | ----------------------------------------------------------- |
| Katayuan ng Order   | `status`       | `orderStatus`                                               |
| Frozen na balanse | `frozenMargin` | `frozenBalance`                                             |
| Margin mode    | `marginMode`   | `marginMode`, ibinalik bilang string sa mga posisyon at daloy |

<h2 id="recovery-and-reconciliation">Pagbangon at pagkakasundo</h2>

- I-renew ang listenKey bago mag-expire at gumawa ng bago kung mabigo ang renewal.
- I-reconnect, i-re-authenticate, at ituring ang bagong socket bilang bagong event session.
- I-deduplicate ang mga kaganapan bago baguhin ang balanse ng partner o order records.
- Kung maaaring may mga event na hindi napansin, i-query ang [orders](/fil/developer-api/rest-api/order), [positions](/fil/developer-api/rest-api/position), at [account state](/fil/developer-api/rest-api/user-and-account) sa pamamagitan ng REST.
- Sundin ang [connection and heartbeat guide](/fil/developer-api/websocket/connection-subscription-and-heartbeat) para sa retry at stale-connection handling.
