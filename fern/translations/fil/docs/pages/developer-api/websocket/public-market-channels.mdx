Gamitin ang mga pampublikong channel ng merkado kapag ang isang aplikasyon ay nangangailangan ng patuloy na ina-update na presyo, kalakalan, candlestick, o lalim ng order-book nang hindi paulit-ulit na sinusuri REST mga endpoint. Maaaring suportahan ng mga stream na ito ang mga trading screen, pagpapakita ng presyo, alerto, at pagmamanman ng merkado.

<h2 id="connection-url">Koneksyon URL</h2>

```
wss://ws.6mm.com/ws
```

Ang pampublikong WebSocket ay hindi nangangailangan ng authentication.

Para sa lifecycle ng koneksyon, pag-unsubscribe, pag-ping, at pag-reconnect na pag-uugali, tingnan ang [Connection, Subscription & Heartbeat](/fil/developer-api/websocket/connection-subscription-and-heartbeat).

<h2 id="common-channels">Karaniwang mga Channel</h2>

| Channel                            | Paglalarawan                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Mag-order ng lalim ng libro. Nagpapadala muna ng snapshot, pagkatapos ay incremental updates |
| `market.trade.{symbol}`            | Pinakabagong mga trade                                                      |
| `market.kline.{symbol}.{interval}` | Klines                                                             |
| `market.ticker.{symbol}`           | Buod ng ticker na may iisang simbolo                                       |
| `market.tickers`                   | Buod ng lahat ng simbolo ng ticker                                          |

<h2 id="choose-a-channel">Pumili ng channel</h2>

| Pangangailangan sa aplikasyon | Channel |
| --- | --- |
| Bumuo o magpanatili ng order book | `market.depth.{symbol}` |
| Ipakita ang live trade feed | `market.trade.{symbol}` |
| Gumuhit ng candlestick chart | `market.kline.{symbol}.{interval}` |
| Ipakita ang isang buod ng merkado | `market.ticker.{symbol}` |
| Panatilihin ang pangkalahatang-ideya ng merkado | `market.tickers` |

<h2 id="subscription-example">Halimbawa ng Subscription</h2>

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<h2 id="push-message-wrapper">Push Message Wrapper</h2>

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

Gamitin ang `topic` para i-route ang bawat mensahe sa tamang handler at `ts` para obserbahan ang timing ng delivery. Ang `data` object ay naglalaman ng payload para sa subscribed channel.

<h2 id="order-book-handling">Paghawak ng order-book</h2>

Ang depth channel ay nagpapadala muna ng snapshot at pagkatapos ay incremental updates. I-initialize ang lokal na libro mula sa snapshot bago mag-apply ng mga update. Pagkatapos muling kumonekta, gumawa ng bagong session, mag-subscribe muli, at muling buuin ang lokal na libro mula sa susunod na snapshot sa halip na magpatuloy mula sa luma na estado sa memorya.

<h2 id="production-recommendations">Mga rekomendasyon sa produksyon</h2>

- Gumawa ng natatanging `id` para sa bawat subscribe, unsubscribe, at ping request.
- Kumpirmahin ang subscription acknowledgements bago ituring na aktibo ang channel.
- Mag-resubscribe sa lahat ng kinakailangang paksa pagkatapos muling kumonekta.
- Panatilihing hiwalay ang network reads mula sa mas mabagal na database o UI processing.
- Subaybayan ang dalas ng pagdiskonekta, pagkaantala sa pagproseso ng mensahe, at mga maling payload.
- Gamitin ang [Private User Channel](/fil/developer-api/websocket/private-user-channel) para sa authenticated account at order updates.
