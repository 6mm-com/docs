<h2 id="service-endpoints">Mga Endpoint ng Serbisyo</h2>

| Uri      | Endpoint              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<h2 id="time-and-numeric-values">Oras at Numerikong Halaga</h2>

* Maliban kung may ibang tinukoy, ang mga time field ay Unix millisecond timestamps.
* Ang pang-araw-araw na estadistika, balance snapshots, at trading volume statistics ay gumagamit ng UTC day boundaries bilang default.
* Ang mga field na sensitibo sa precision tulad ng halaga, presyo, dami, at rate ay ipinapadala bilang mga string.
* Ang malalaking integer ID tulad ng `orderId`, `conditionId`, at `strategyId` ay ibinabalik bilang mga string sa JSON.

<h2 id="response-format">Format ng Tugon</h2>

Matagumpay na tugon:

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-12345678"
}
```

Tugon sa error:

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Mga Tala:

* Karaniwan, ang mga error sa negosyo ay nagbabalik pa rin ng unified JSON structure. Dapat munang suriin ng mga integrator `code` .
* Ang mga pagkabigo sa authentication ay maaaring magbalik ng HTTP `401`; ang rate limiting ay maaaring magbalik ng HTTP `429`.
* Maaari mong ipadala ang `X-Request-ID` sa request header. Ibabalik ito ng server bilang `requestId` sa tugon.
