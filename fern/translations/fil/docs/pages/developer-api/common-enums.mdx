<h2 id="orders">Mga Order</h2>

| enum                 | Mga Halaga                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Order side           | `BUY` / `SELL`                                                                                            |
| Panig ng posisyon        | `BOTH` / `LONG` / `SHORT`                                                                                 |
| Normal na uri ng order    | `LIMIT` / `MARKET`                                                                                        |
| Uri ng order ng kondisyon | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| Panahon na ipinatutupad        | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| Uri ng trigger price   | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| Katayuan ng Order         | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` nangangahulugang tinanggap at naibalik na ang order request. `PENDING` nangangahulugang pumasok na ang order sa pending o open-order na estado.

<h2 id="positions">Mga Posisyon</h2>

| enum                      | Mga Halaga                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Halaga ng kahilingan sa margin mode | `1` krus, `2` hiwalay                                     |
| Margin mode string        | `ISOLATED` / `CROSS`                                        |
| Isara ang trigger mode        | `1` manual, `2` take profit, `3` stop loss, `4` liquidation |

<h2 id="integration-rules">Mga patakaran sa integrasyon</h2>

- Ituring ang enum values bilang case-sensitive wire values.
- Panatilihin ang mga hindi kilalang halaga sa mga log at mabigo nang ligtas sa halip na tahimik na i-map ang mga ito sa isang kilalang estado.
- Huwag isipin na ang bawat estado ng hindi panghuling order ay ligtas subukang muli. I-query ang order o i-reconcile ito sa isang pribadong WebSocket event.
- I-store ang parehong orihinal na API value at ang partner-facing display label upang masuportahan ang mga bagong value nang hindi binabago ang historical records.

<h2 id="order-state-handling">Paghawak ng estado ng order</h2>

| Grupo ng Estado | Mga Halaga | Inirerekomendang paghawak |
| --- | --- | --- |
| Tinanggap o bukas | `NEW`, `PENDING`, `PARTIALLY_FILLED` | Panatilihing aktibo ang order at makipag-ayos sa mga update ng WebSocket o REST . |
| Natapos | `FILLED` | I-apply ang final filled quantity at execution records. |
| Sarado nang walang full fill | `CANCELED`, `REJECTED`, `PARTIALLY_FILLED_CANCELED` | Itigil ang aktibong pagproseso at panatilihin ang dahilan at anumang na-execute na dami. |
