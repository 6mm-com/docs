Utiliza canales de mercado público cuando una aplicación necesita precios actualizados continuamente, operaciones, velas o profundidad en el libro de órdenes sin consultar repetidamente REST endpoints. Estos flujos pueden soportar pantallas de trading, pantallas de precios, alertas y monitoreo de mercado.

<h2 id="connection-url">Conexión URL</h2>

```
wss://ws.6mm.com/ws
```

El WebSocket público no requiere autenticación.

Para el ciclo de vida de la conexión, darse de baja, hacer ping y reconectarse, consulta [Conexión, Suscripción y Latido](/es-419/developer-api/websocket/connection-subscription-and-heartbeat).

<h2 id="common-channels">Canales comunes</h2>

| Canal                            | Descripción                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Profundidad del libro de pedidos. Envía primero una instantánea, luego actualizaciones incrementales |
| `market.trade.{symbol}`            | Últimas operaciones                                                      |
| `market.kline.{symbol}.{interval}` | Klines                                                             |
| `market.ticker.{symbol}`           | Resumen del ticker de un solo símbolo                                       |
| `market.tickers`                   | Resumen del ticker de todos los símbolos                                          |

<h2 id="choose-a-channel">Elige un canal</h2>

| Necesidad de aplicación | Canal |
| --- | --- |
| Construye o mantén un libro de pedidos | `market.depth.{symbol}` |
| Muestra una transmisión de comercio en vivo | `market.trade.{symbol}` |
| Dibuja un gráfico de candelabros | `market.kline.{symbol}.{interval}` |
| Resumen del mercado Display one | `market.ticker.{symbol}` |
| Mantén una visión general del mercado | `market.tickers` |

<h2 id="subscription-example">Ejemplo de suscripción</h2>

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<h2 id="push-message-wrapper">Envoltorio de mensajes push</h2>

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

Usa `topic` para enrutar cada mensaje al manejador correcto y `ts` para observar el momento de entrega. El objeto `data` contiene la carga útil para el canal suscrito.

<h2 id="order-book-handling">Manejo de la libreta de pedidos</h2>

El canal de profundidad envía primero una instantánea y luego actualizaciones incrementales. Inicializa el libro local desde la instantánea antes de aplicar las actualizaciones. Después de reconectarte, crea una nueva sesión, suscríbete de nuevo y reconstruye el libro local desde la siguiente instantánea en lugar de continuar desde un estado obsoleto en memoria.

<h2 id="production-recommendations">Recomendaciones de producción</h2>

- Generar un `id` único para cada solicitud de suscripción, baja y ping.
- Confirmar los acuses de recibo de suscripción antes de tratar un canal como activo.
- Suscribirse de nuevo a todos los temas requeridos después de reconectarse.
- Mantener las lecturas de red separadas del procesamiento lento de bases de datos o UI.
- Frecuencia de desconexión del monitoreo, retraso en el procesamiento de mensajes y cargas útiles deformadas.
- Usar [Canal de Usuario Privado](/es-419/developer-api/websocket/private-user-channel) para actualizaciones autenticadas de cuentas y pedidos.
