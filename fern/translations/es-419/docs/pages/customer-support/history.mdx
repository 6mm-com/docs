Utilice el historial de conversaciones para recuperar el contexto, revisar la calidad del servicio e investigar una consulta específica. Comience con un número de conversación o un rango de tiempo limitado en lugar de explorar todos los registros.

<div className="sixmm-support-flow">

1. **Encuentra la sesión**: elige los filtros y la fecha correcta.
2. **Lea el contexto completo**: revise los mensajes y los detalles del agente y del visitante.
3. **Seguimiento**: mejora una respuesta o continúa el caso no resuelto.

</div>


<span id="find-an-earlier-conversation" data-sixmm-canonical-anchor="find-an-earlier-conversation" aria-hidden="true"></span>

## Encuentra una conversación anterior

Abra **Historial de conversaciones**. Utilice los filtros disponibles de búsqueda de usuario/sesión, tipo de conversación, calificación, agente, categoría, idioma y tiempo. Abra los detalles para leer los mensajes y la información de la sesión.

La columna de la lista de correo electrónico del usuario prefiere el correo electrónico de contacto y, en caso contrario, utiliza el correo electrónico del visitante. La vista detallada conserva ambos campos para que los agentes puedan distinguir sus fuentes. Un valor vacío significa que ese campo no fue recopilado; no prueba que un cliente no tenga una cuenta de correo electrónico.

<span id="review-service-quality" data-sixmm-canonical-anchor="review-service-quality" aria-hidden="true"></span>

## Revisar la calidad del servicio.

Utilice la conversación, el agente y la calificación juntos para comprender el caso. Una respuesta que se muestra como un mensaje de IA puede provenir de una respuesta configurada o de una etapa de coincidencia en lugar de una llamada de modelo grande. Compare el contenido con el conocimiento actual y utilice una prueba de flujo al investigar el comportamiento de respuesta.

La eliminación solo está disponible con los permisos pertinentes. Lea la confirmación antes de eliminar uno o varios registros. MCP las consultas del historial utilizan el alcance autorizado y la eliminación requiere confirmación; No asuma que el historial completo del inquilino está disponible para todos los agentes.


<span id="read-the-fields-without-mixing-identities" data-sixmm-canonical-anchor="read-the-fields-without-mixing-identities" aria-hidden="true"></span>

## Leer los campos sin mezclar identidades

| Campo | Interpretación |
| --- | --- |
| Número de conversación | Identifica la consulta que está revisando. Úselo para evitar confundir sesiones separadas. |
| Nombre del visitante | Una etiqueta visible legible, no prueba de una cuenta de intercambio verificada. |
| Tipo de entrada e ID de usuario | Ayude a distinguir el acceso anónimo de una identidad de inicio de sesión integrada. No se deben adivinar los datos de identidad que faltan. |
| Correo electrónico del usuario | Utiliza primero el correo electrónico de contacto y luego el correo electrónico del visitante; Los detalles mantienen las dos fuentes separadas. |
| Idioma y IP ubicación | Contexto útil para soporte, no prueba de la identidad del usuario o ubicación física exacta. |
| Clasificación | Comentarios que existen para esa sesión. No es lo mismo ninguna calificación que una calificación negativa. |

<span id="example-review-a-low-rated-consultation" data-sixmm-canonical-anchor="example-review-a-low-rated-consultation" aria-hidden="true"></span>

### Ejemplo: revisar una consulta de baja calificación

1. Filtre por fecha, agente y calificación según corresponda, luego abra el registro completo.
2. Lea lo que preguntó el visitante antes de evaluar la respuesta. Compruebe si un traspaso o un malentendido lingüístico afectó la conversación.
3. Si la respuesta estuvo incompleta, revise el contenido del conocimiento correspondiente y la configuración del bot. Un mal resultado no siempre significa que el modelo en sí fracasó.
4. Mantenga el número de sesión con su seguimiento interno para que el equipo pueda volver a la misma evidencia.

## Preguntas comunes

<AccordionGroup>

<Accordion title="¿Por qué el correo electrónico está en blanco?">
Es posible que la sesión no haya recopilado un correo electrónico de contacto o no haya recibido un correo electrónico de la integración de entrada. Revise ambos campos en detalle antes de concluir que faltan datos inesperadamente.
</Accordion>

<Accordion title="¿Por qué cambiar el filtro de fecha cambia los resultados?">
La página puede filtrar por hora de inicio o hora de cierre. Una conversación que comienza un día y termina en otro pertenece a resultados diferentes bajo esas dos opciones.
</Accordion>

</AccordionGroup>
