<h2 id="recommended-combination">Combinación recomendada</h2>

| Meta del compañero | Frontend | Backend | Por qué importa |
| --- | --- | --- | --- |
| Agrega un terminal de trading integrado | Trading Widget SDK | Agent SDK | El widget maneja la interfaz de trading mientras el backend asociado emite tokens y mantiene los secretos privados. |
| Crea un punto de entrada nativo para la app | Entrada nativa o H5 | Agent SDK | La app abre una 6MM URL de entrada después de que el socio valida la sesión de usuario. |
| Construye un flujo de trading personalizado | Interfaz de usuario asociada | Desarrollador API + flujos de SDK seleccionados | Usa APIs para datos de cuentas, órdenes, posición y mercado mientras mantienes los controles operativos del lado del servidor. |

<h2 id="reference-architecture">Arquitectura de referencia</h2>

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Guardar secretos del lado del servidor**
>
> El código del navegador solo debe llamar a los endpoints propiedad del socio. El Agente API secreto nunca debe enviarse al código frontend.

<h2 id="production-checklist">Lista de verificación de producción</h2>

- Almacenar apiSecret solo en infraestructura backend.
- Usar HTTPS para solicitudes de API de Agente y URLs de webhooks.
- Persistir agentUserId, platformUserId, y agentOrderNo aplicaciones.
- Representan los montos monetarios como cadenas decimales en lugar de valores de punto flotante.
- Manejar PROCESSING como pendientes, no como éxito o fracaso.
- Procesar los webhooks idempotente porque se esperan reintentos.
