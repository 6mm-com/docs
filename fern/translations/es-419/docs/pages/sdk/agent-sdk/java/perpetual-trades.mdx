## Requisitos previos de ejemplo

Los fragmentos Java comparten estas importaciones. Inicialice `client` usando el Inicio rápido y obtenga `platformUserId` del enlace guardado. Los ID de usuario/pedido de ejemplo deben reemplazarse con sus propios valores persistentes.

import com.sixmm.agent.*;

## `listPerpetualTrades`

Modelo de solicitud: `PerpetualTradesRequest`.

```java
import com.sixmm.agent.model.PerpetualTradesRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualTradesRequest request = new PerpetualTradesRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualTrades(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Campos de solicitud

| Campo | Java tipo | Requerido | Significado |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Sí | Proporcione explícitamente entre 1 y 100 ID de usuario únicos de la plataforma pública que pertenezcan al socio actual; la omisión y una matriz vacía no son válidas. |
| `symbol` | `String` | No | Filtro de pares comerciales opcional. |
| `orderId` | `String` | No | ID de pedido ordinario; no es un número de orden de transferencia de socio. |
| `startTime` | `Long` | No | Milisegundos Unix inclusivos; utilice una ventana de historial fija UTC. |
| `endTime` | `Long` | No | Milisegundos exclusivos de Unix. |
| `limit` | `Integer` | No | Predeterminado 500; 1–1000. |
| `cursor` | `String` | No | Utilice el nextCursor devuelto con filtros sin cambios; detenerse cuando hasMore sea falso. |

El ejemplo lee una página. Para campos obligatorios, alcance del reproductor, semántica de filtro, límite, cursor y reintentos limitados, siga [Resumen de consultas](/es-419/sdk/agent-sdk/java/perpetual-queries). Mantenga todos los filtros sin cambios mientras busca; no interprete un error como un resultado vacío.

## Detalles de llenado comercial

Interfaz: `trades`. Requiere platformUserIds explícito.

| `data` campo | tipo | significado |
| --- | --- | --- |
| `fillId` | string | ID de detalles de llenado comercial, correspondiente a este registro entityId |
| `tradeId` | string | El ID de transacción coincidente asociado con la transacción; no reemplaza la identificación detallada |
| `orderId` | string | El ID de pedido general al que pertenece este detalle. |
| `positionId` | string | ID de posición asociada |
| `symbol` | string | par comercial |
| `side` | string | Dirección de compra y venta de este jugador BUY / SELL |
| `roleType` | string | Carácter de transacción de este jugador MAKER / TAKER |
| `positionSide` | string | Dirección de posición, explicada según el valor real LONG / SHORT / BOTH etc. |
| `price` | string | Este precio de transacción |
| `quantity` | string | La cantidad de esta transacción no es la cantidad total del pedido original. |
| `tradeValue` | string | El valor nominal de esta transacción proviene del nocional de la transacción. |
| `handlingFee` | string | La tarifa de transacción para esta transacción conserva el símbolo fuente y la precisión, y no toma el valor absoluto por sí misma. |
| `realizedPnl` | string | Las ganancias y pérdidas realizadas correspondientes a esta transacción; no las ganancias y pérdidas flotantes en tiempo real de la posición actual |
| `tradedAt` | integer | Tiempo de transacción, milisegundos; Utilice este campo para filtrar el tiempo. |

Un pedido puede tener múltiples ejecuciones, las cuales deben guardarse en detalle. No combine registros de diferentes jugadores/cumple roles mediante tradeId y luego descarte sus identidades de registros.
