## Modo recomendado: token de socio

partner-token evita poner tokens cortos en las URL y mantiene apiSecret en el backend del socio.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'partner-token',
    tokenProvider: async ({ channelId, symbol, reason }) => {
      const resp = await fetch('/api/trading/embed-token', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ channelId, symbol, reason }),
      })

      if (!resp.ok) {
        throw new Error('Failed to request embed token')
      }

      return resp.json()
    },
  },
})
```

<span id="backend-flow" data-sixmm-canonical-anchor="backend-flow" aria-hidden="true"></span>

## Flujo de fondo

```text
1. Partner frontend receives auth_request from the iframe.
2. SDK calls tokenProvider.
3. Partner frontend calls its own backend.
4. Partner backend validates the partner session.
5. Partner backend calls 6MM Agent API or Java SDK createEmbedToken.
6. SDK sends embedToken to the iframe through postMessage.
7. iframe exchanges embedToken for a 6MM access token.
8. iframe continues initialization and emits ready.
```

<span id="tokenprovider-contract" data-sixmm-canonical-anchor="tokenprovider-contract" aria-hidden="true"></span>

## tokenProvider contrato

| Campo | Dirección | Descripción |
| --- | --- | --- |
| channelId | SDK -> Backend del socio | Identificador de sesión de widget único. El backend debería pasarlo a createEmbedToken. |
| símbolo | SDK -> Backend del socio | Símbolo comercial solicitado actual. Úselo para determinar el alcance del token cuando sea necesario. |
| razón | SDK -> Backend del socio | Por qué SDK solicita un token, como carga inicial o actualización. |
| embedToken | Backend del socio -> SDK | Token de corta duración creado por el Agent SDK o el Agente API. |
| expireAt | Backend del socio -> SDK | Marca de tiempo de vencimiento del token devuelta por 6MM. |

<span id="failure-handling" data-sixmm-canonical-anchor="failure-handling" aria-hidden="true"></span>

## Manejo de fallas

| Condición | Manejo recomendado |
| --- | --- |
| La sesión de socio expiró | Devuelva 401 desde el punto final del socio y solicite al usuario que inicie sesión nuevamente. |
| La creación del token falló temporalmente | Lanza un error en tokenProvider y permite que el widget muestre un error de autenticación. |
| channelId no coincide | Rechace la solicitud y vuelva a crear la instancia del widget. |
| El usuario no puede comerciar | Devuelve un error controlado por el socio y no crea un token de inserción. |

<span id="compatibility-mode-agent-sso" data-sixmm-canonical-anchor="compatibility-mode-agent-sso" aria-hidden="true"></span>

## Modo de compatibilidad: agente-sso

agent-sso mantiene el flujo de tickets de entrada de agente/antiguos. Prefiere token de socio para nuevas integraciones.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'agent-sso',
    entryUrlProvider: async ({ redirectPath }) => {
      const resp = await fetch('/api/trading-entry', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ redirectPath }),
      })
      const data = await resp.json()
      return data.webUrl
    },
  },
})
```

<span id="seconds-trading-and-environment-rules" data-sixmm-canonical-anchor="seconds-trading-and-environment-rules" aria-hidden="true"></span>

## Segundos reglas comerciales y ambientales.

Para páginas de segundos, use la misma autenticación `partner-token` con `page` y `tradingMode` configurados en el widget. No existe un token de predicción independiente. Cada tokenProvider llamada debe obtener un token nuevo y único de su backend.

Devuelve `embedToken`, `expireAt` en segundos de Unix y el `channelId` original como un objeto de nivel superior. La respuesta del token Agent SDK no contiene `channelId`; su backend hace eco del canal de widget actual. Si su punto final envuelve las respuestas en `data`, desempaquételo antes de regresar de tokenProvider.
