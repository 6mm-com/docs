Usa esta lista de verificación antes de exponer los flujos de trading impulsados por 6MMa los usuarios de producción. Está diseñado para que los equipos de producto, ingeniería, operaciones, riesgos y soporte los revisen juntos.

<span id="launch-checklist" data-sixmm-canonical-anchor="launch-checklist" aria-hidden="true"></span>

## Lista de verificación de lanzamiento

| Área | Lista de verificación |
| --- | --- |
| Producto | Los puntos de entrada, textos de usuario, indicaciones de riesgo, cobertura de idiomas y rutas de soporte están listos. |
| Backend | Se implementan API credenciales, firmas, emisión de tokens, webhooks, retries y registros. |
| Comercio | Se han revisado el comportamiento de pedidos, transferencias, posiciones, margen, comisiones y liquidación. |
| Seguridad | Se preparan registros de secretos, roles de acceso, monitoreo, respuesta a incidentes y auditoría. |
| Operaciones | Se asignan flujos de trabajo de soporte, rutas de escalada, conciliación y monitoreo diario. |

<span id="recommended-sequence" data-sixmm-canonical-anchor="recommended-sequence" aria-hidden="true"></span>

## Secuencia recomendada

1. Validación completa del entorno sandbox o del entorno interno.
2. Ejecutar recorridos de usuario de extremo a extremo para inicio de sesión, entrada, transferencia, comercio y soporte.
3. Confirmar la propiedad del monitoreo y la respuesta a incidentes.
4. Aprobar la copia pública, recursos localizados y descargas de recursos.
5. Comenzar con una ventana de lanzamiento controlada antes de una promoción amplia.

<span id="after-launch" data-sixmm-canonical-anchor="after-launch" aria-hidden="true"></span>

## Después del lanzamiento

Revisa la actividad diariamente durante el periodo inicial de lanzamiento. Observa la conversión de entrada, fallas en la emisión de tokens, errores de pedido, calidad de spread, finalización de transferencias, intentos de webhook y tickets de soporte juntos.
