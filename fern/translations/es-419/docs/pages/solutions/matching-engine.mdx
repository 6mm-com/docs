Un intercambio de marca blanca requiere más que un shell frontend. La experiencia del usuario depende de módulos centrales confiables detrás del trading, cuentas, riesgo y liquidación.

<span id="core-modules" data-sixmm-canonical-anchor="core-modules" aria-hidden="true"></span>

## Módulos centrales

| Módulo | Rol |
| --- | --- |
| Coincidencia y ciclo de vida del pedido | Maneja la presentación de órdenes, estado coincidente, cancelación y registros de ejecución. |
| Sistema de cuentas y posiciones | Mantiene los saldos, el estado del margen, las posiciones y la disponibilidad de operaciones. |
| Controles de riesgo | Coordina apalancamiento, margen, liquidación y comportamiento anormal del mercado. |
| Datos de mercado | Distribuye precios, profundidad, operaciones y datos gráficos a las interfaces de trading. |
| Asentamiento y registros | Mantiene alineado el historial de operaciones, cambios de saldo y registros operativos. |

## Preguntas sobre la implementación

- ¿Qué tipos de orden y condición-orden están expuestos a los usuarios?
- ¿Qué servicio posee las reglas de símbolos, la validación de precisión y la disponibilidad de operaciones?
- ¿Cómo se concilian los registros de órdenes, comercio, posición, saldo y liquidación?
- ¿Qué identificadores permanecen estables a través de REST respuestas, eventos de WebSocket y registros de socios?
- ¿Qué ruta de monitoreo y retroceso se aplica cuando los datos de emparejamiento, riesgo o mercado no están disponibles?

Responde estas preguntas antes del desarrollo frontend para que el comportamiento del producto, API manejo, operaciones y soporte usen el mismo modelo de trading.
