استخدم تدفقات WebSocket لبيانات السوق وتحديثات حالة المستخدم الخاصة التي يجب أن تبقى محدثة دون إجراء استطلاعات.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## URL الاتصال

```text
wss://ws.6mm.com/ws
```

تتطلب التدفقات الخاصة سياق مصادقة مثل listenKey أو رمز الوصول كما هو موضح في وثائق القناة الخاصة.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## اشترك

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

تأكيد الاشتراك الناجح:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## إلغاء الاشتراك

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

<span id="application-ping" data-sixmm-canonical-anchor="application-ping" aria-hidden="true"></span>

## تصغير التطبيق

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<span id="message-envelope" data-sixmm-canonical-anchor="message-envelope" aria-hidden="true"></span>

## ظرف الرسالة

الدفع العام يستخدم ظرفا ثابتا:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## التوصيات التشغيلية

- إنشاء `id` فريد على جانب العميل لكل طلب اشتراك، إلغاء اشتراك، وطلب ping.
- اعتبر إعادة الاتصال كجلسة جديدة وأعد الاشتراك في المواضيع المطلوبة.
- التحقق من أن `topic` المردود يطابق القناة التي تتوقعها خدمتك.
- الحفاظ على معالجة الرسائل ذات القدرة الذاتية عندما يتعلق الأمر بأوامر خاصة أو أحداث حساب.
- تسجيل تغييرات حالة الاتصال، تأكيدات الاشتراك، والانقطاعات غير الطبيعية.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## إعادة ربط سير العمل

1. أغلق أو تخلص من المقبس السابق وأنشئ اتصالا جديدا.
2. إعادة التحقق من صحة التدفقات الخاصة باستخدام listenKey أو رمز وصول صالح.
3. أعد الاشتراك في كل موضوع مطلوب وانتظر التقدير الناجح.
4. استبدال الولاية المحلية في دفتر الأوامر بصورة جديدة قبل تطبيق تحديثات تدريجية.
5. التوفيق بين الأوامر المفتوحة والمواقف والتوازنات من خلال REST إذا كان قد فاتت الأحداث الخاصة.

استخدم ارتداد أسي محدود مع التذبذب لمحاولات إعادة الاتصال. يجب على العميل الذي يعيد الاتصال بشكل مستمر تنبيه المشغلين بدلا من إعادة المحاولة إلى أجل غير مسمى دون رؤية واضحة.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## نبض القلب والروابط القديمة

- تتبع أحدث رسالة واردة وتأكيد ناجح للتنبيه.
- استخدم فترة نبض القلب وعتبة الخمول المعتمدة لبيئة الإنتاج.
- عامل الاتصال على أنه قديم عندما يتجاوز الحد المكون، حتى لو كان مقبس TCP لا يزال مفتوحا.
- لا تعيد استخدام الاشتراكات من مقبس قديم؛ أعد الاشتراك بشكل صريح بعد كل إعادة اتصال.
