استخدم هذه التوصيات كأساس جاهزية للإنتاج. تكمل هذه التوصيات مرجع نقطة النهاية وتساعد التكاملات على التعافي بأمان من انتهاء المهلات، وإعادة الاتصال، والطلبات المكررة، وحوادث بيانات الاعتماد.

<h2 id="authentication-and-secrets">المصادقة والأسرار</h2>

- يفضل [ توقيعAPI Key ](/ar/developer-api/authentication) لبرامج التداول على جانب الخادم و JWT لإجراءات الواجهة الأمامية التي يقودها المستخدم.
- الاحتفاظ `apiSecret` في إدارة السرية خلفية. يتم عرضه مرة واحدة فقط ولا يجب إرساله أبدا إلى متصفح أو عميل محمول.
- تطبيق الحد الأدنى من الأذونات المطلوبة API Key وتقييد عناوين IP المصدر عندما تدعم بيئة التكامل عناوين الخروج المستقرة.
- تعطيل أو حذف مفتاح مسروب فورا، ثم مراجعة سجلات الطلبات قبل إصدار بديل.

<h2 id="request-validation-and-idempotency">طلب التحقق والهوية الذاتية</h2>

- قبل تقديم الطلبات، `/v1/public/market/symbols` الاستعلام والتحقق من `tickSize`، `stepSize`، القيمة الاسمية الدنيا والكمية القصوى محليا.
- توليد `clientOrderId` فريد لكل كتابة أمر حتى يمكن التوفيق بين الطلبات بعد الانقطاع.
- الحفاظ على المعرف الأصلي عندما تكون نتيجة HTTP غير مؤكدة. استعلام الترتيب الحالي قبل إنشاء طلب بديل.
- التعامل مع المبالغ العشرية والأسعار كسلاسل أو أنواع عشرية، وليس كقيم ثنائية للفاصلة العائمة.

<h2 id="order-and-websocket-state">الترتيب والحالة WebSocket</h2>

- تحديد الحالة النهائية بعد إلغاء أو إلغاء كل أو تعديل العمليات من [أحداث WebSocket الخاصة] (/developer-api/websocket/private-user-channel) أو استعلام REST .
- تعامل كل إعادة اتصال كجلسة WebSocket جديدة واستعادة جميع الاشتراكات المطلوبة.
- تحقق من استمرارية دفتر الأوامر باستخدام `endVersion`. إذا ظهرت فجوة في الإصدار، تخلص من الكتاب المحلي وأعد الاشتراك للحصول على لقطة جديدة.
- إزالة تكرار أحداث الأوامر والحساب الخاصة قبل تطبيقها على الأرصدة أو المراكز أو سجلات الشركاء.

<h2 id="logging-monitoring-and-retries">تسجيل التسجيل، المراقبة، وإعادة المحاولات</h2>

- معرف طلب السجلات، معرف طلب العميل، حالة HTTP ، كود العمل API ، التأخير، وعدد إعادة المحاولة دون تسجيل أسرار أو رموز كاملة.
- إعادة المحاولة فقط للعمليات الموثقة كآمنة، باستخدام تراجع أسي محدود وتذبذب.
- تنبيه عن فشل المصادقة، أخطاء التواقيع، استجابات الحد السريع، حلقات إعادة الربط WebSocket ، فجوات التسلسل، وفروق التوافق بين الأومر.
- الحفاظ على مزامنة ساعات الخادم لأن المصادقة والتوقيع يعتمدان على الطوابع الزمنية.

<h2 id="before-production">قبل الإنتاج</h2>

- ممارسة مهلة الاستراحة، وتكرار الطلب، وإعادة الاتصال، وتدوير المفاتيح، وإعادة محاولة webhook في بيئة غير إنتاجية.
- تعيين المالكين لتدوير بيانات التوثيق، وحوادث التداول، وفشل الويبهوك، والمصالحة.
- إكمال [قائمة التحقق لإطلاق الإنتاج](/ar/resources/production-launch-checklist) واستخدام [قالب طلب الدعم](/ar/resources/support-request-template) عند الحاجة إلى التصعيد.
