ابدأ بالبيئة والطابع الزمني ومعرف العمل للعملية الفاشلة. يقوم الفحص المنظم عادةً بفصل مشكلات التكوين عن مشكلات المصادقة والشبكة والمعالجة غير المتزامنة.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## ترتيب التشخيص الموصى به

1. تأكد من البيئة والقاعدة المتأثرة URL.
2. سجل النطاق الزمني UTC وأول طلب فاشل.
3. حدد الوحدة: Trading Widget، Agent SDK، REST API، WebSocket، أو webhook.
4. التقط معرف الطلب، أو معرف المستخدم الشريك، `agentOrderNo`، أو معرف الطلب، أو معرف الحدث webhook.
5. تحقق من أحدث التعليمات البرمجية أو بيانات الاعتماد أو القائمة البيضاء IP أو تغييرات النشر.
6. قم بالتكاثر باستخدام أصغر حالة اختبار آمنة.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget مشاكل

| أعراض | السبب المحتمل | يصلح |
| --- | --- | --- |
| يطلب iframe المجال المحلي للشريك | baseUrl مفقود | تمرير baseUrl: 'https://app.6mm.com'. |
| iframe غير مرئي أو قصير جدًا | الحاوية الأصلية ليس لها ارتفاع | ضبط ارتفاع الحاوية أو ارتفاع التمرير. |
| token_provider_missing | لا يوجد لدى وضع الرمز المميز للشريك مزود | إضافة مصادقة.tokenProvider. |
| auth_exchange_failed | رمز التضمين غير صالح أو منتهي الصلاحية أو غير متطابق | تحقق من استجابة الرمز المميز للواجهة الخلفية وchannelId. |

## Agent SDK مشاكل

| أعراض | السبب المحتمل | يصلح |
| --- | --- | --- |
| تم رفض التوقيع | سر خاطئ، أو انحراف الساعة، أو تم تغيير الحقول الموقعة يدويًا | اسمح لـ SDK بإنشاء حقول التوقيع ومزامنة وقت الخادم. |
| مخاطر حركة الأموال المكررة | رقم الطلب الجديد المستخدم بعد انتهاء المهلة | الاستعلام عن طريق agentOrderNo الأصلي أولاً. |
| تم التعامل مع PROCESSING على أنها فاشلة | يساء فهم الحالة المعلقة | انتظر webhook أو اتصل بـ queryOrder. |
| تمت معالجة Webhook عدة مرات | أعد محاولة السلوك دون العجز | أضف مفتاح العجز وفحوصات الحالة النهائية. |

## أدلة لالتقاط

| اندماج | أدلة مفيدة |
| --- | --- |
| Trading Widget | مسار إصدار الصفحة URL، SDK، ووحدة تحكم المتصفح، وطلبات الشبكة الفاشلة، والحمولة الصافية `onError`، وأبعاد الحاوية. |
| Agent SDK | SDK اللغة/الإصدار، الأساسي URL، UTC الطابع الزمني، معرف الطلب، `agentOrderNo`، رمز الاستجابة، والسجلات المعقمة. |
| Webhook | وقت التسليم، ومفتاح الحدث أو العمل، ونتيجة التحقق من صحة التوقيع، وحالة المعالجة، وتجزئة الجسم الخام المعقمة. |
| REST API | الطريقة والمسار والبيئة ومعرف الطلب ورمز الاستجابة والمعلمات المعقمة. |

لا تقم أبدًا بتضمين كلمات المرور أو رموز الوصول أو أسرار API أو التوقيعات الكاملة أو المفاتيح الخاصة أو البيانات الشخصية غير المنقحة في التشخيص.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## قبل التصعيد

- أعد المحاولة فقط عندما يتم توثيق العملية على أنها آمنة لإعادة المحاولة.
- بعد انتهاء المهلة، استعلم عن معرف العمل الأصلي بدلاً من إنشاء معرف جديد.
- تأكد من ساعة النظام وبيئة الاعتماد بحثًا عن أخطاء التوقيع.
- احتفظ بالفشل الأول وأي نتائج إعادة محاولة لاحقة.
- استخدم [نموذج طلب الدعم](/ar/resources/support-request-template) لإرسال تقرير كامل ومنقح.

## Java تشخيص الإصدار 0.3.0

| أعراض | التحقق والانتعاش |
| --- | --- |
| طلب التمويل له نتيجة غير معروفة | احتفظ بالأصل `agentOrderNo`؛ اتصل بـ `queryWalletTransfer` بالبيئة الأصلية. لا تستخدم `queryOrder`. |
| تُظهر واجهة مستخدم المحاكاة الأموال غير المتوقعة | تحقق من الواجهة الأمامية `tradingMode` بشكل منفصل عن الواجهة الخلفية `environment`؛ الحساب `isSimulatedUser` لا يقوم بتوجيه الطلبات. |
| خطأ في الاستعلام `6905` | تراجع عن استخدام حصة الشريك المشتركة، ثم أعد المحاولة باستخدام نفس المؤشر وقم بالتصفية من خلال SDK. |
| خطأ في الاستعلام `6904` | تقليل الاستعلامات المتزامنة وتضييق النافذة الزمنية؛ اتصل بالدعم إذا كان مستمرًا. |
| المؤشر غير صالح أو منتهي الصلاحية | أعد تشغيل نفس نافذة السجل الثابت وقم بإلغاء تكرار السجلات المحفوظة. |
| طريقة Java الجديدة مفقودة | تحقق من قطعة Maven التي تم حلها مقابل العلامة العامة `v0.3.0`؛ قم بإزالة التبعيات المتعارضة وفقًا لسياسة العناصر الخاصة بك. |
