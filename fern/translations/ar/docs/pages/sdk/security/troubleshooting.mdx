ابدأ بالبيئة، والطابع الزمني، ومعرف الأعمال للعملية الفاشلة. عادة ما يفصل الفحص المنظم مشاكل التكوين عن مشاكل المصادقة، الشبكة، والمعالجة غير المتزامنة.

<h2 id="diagnostic-order">ترتيب التشخيص الموصى به</h2>

1. تأكد من البيئة المتأثرة والقاعدة URL.
2. تسجيل النطاق الزمني UTC وأول طلب فاشل.
3. حدد الوحدة: Trading Widget، Agent SDK، REST API، WebSocket، أو webhook.
4. التقاط معرف الطلب، معرف المستخدم الشريك، `agentOrderNo`، معرف الطلب، أو معرف حدث webhook.
5. تحقق من الشيفرة الأخيرة، وبيانات الاعتماد، والقائمة البيضاء IP ، أو تغييرات النشر.
6. التكاثر بأصغر حالة اختبار آمنة.

<h2 id="trading-widget-issues">Trading Widget القضايا</h2>

| عَرَض | السبب المحتمل | الإصلاح |
| --- | --- | --- |
| طلبات iframe شريك النطاق المحلي | baseUrl مفقود | تمرير baseUrl: 'https://app.6mm.com'. |
| iframe غير مرئي أو قصير جدا | الحاوية الأم لا تحتوي على ارتفاع | حدد ارتفاع الحاوية أو ارتفاع التمرير. |
| token_provider_missing | وضع الشريك-الرمز لا يحتوي على مزود | أضف التوثيق.tokenProvider. |
| auth_exchange_failed | رمز تضمين غير صالح، منتهية الصلاحية، أو غير متطابق | تحقق من استجابة الرموز الخلفية و channelId. |

<h2 id="agent-sdk-issues">Agent SDK القضايا</h2>

| عَرَض | السبب المحتمل | الإصلاح |
| --- | --- | --- |
| تم رفض التوقيع | سر خاطئ، انحراف الساعة، أو تغيير الحقول الموقعة يدويا | دع SDK تولد حقول التوقيع وتزامن وقت الخادم. |
| مخاطر حركة الأموال المكررة | رقم الطلب الجديد المستخدم بعد انتهاء المهلة | استعلام من agentOrderNo الأصلي أولا. |
| PROCESSING يعامل كفشل | سوء فهم الولاية المنتظر | انتظر webhook أو اتصل queryOrder. |
| تمت معالجة Webhook عدة مرات | إعادة المحاولة بدون القدر الجنسي | أضف مفتاح القدر والتحقق النهائي. |

<h2 id="evidence-to-capture">أدلة للقبض عليها</h2>

| التكامل | أدلة مفيدة |
| --- | --- |
| Trading Widget | URL الصفحة، مسار الإصدار SDK، وحدة تحكم المتصفح، طلبات الشبكة الفاشلة، حمولة `onError`، وأبعاد الحاويات. |
| Agent SDK | SDK اللغة/الإصدار، URL الأساسية، UTC الطابع الزمني، معرف الطلب، `agentOrderNo`، رمز الرد، والسجلات المنقحة. |
| ويب هوك | وقت التسليم، مفتاح الحدث أو العمل، نتيجة التحقق من التوقيع، حالة المعالجة، والتجزئة الخام المنقحة. |
| REST API | الطريقة، المسار، البيئة، معرف الطلب، رمز الرد، والمعلمات المنقحة. |

لا تدرج أبدا كلمات المرور أو رموز الوصول أو أسرار API أو التوقيعات الكاملة أو المفاتيح الخاصة أو البيانات الشخصية غير المحجوبة في التشخيصات.

<h2 id="before-escalating">قبل التصعيد</h2>

- إعادة المحاولة فقط عندما يتم توثيق العملية على أنها آمنة لإعادة المحاولة.
- بعد انتهاء المهلة، استعلام معرف الأعمال الأصلي بدلا من إنشاء معرف جديد.
- تأكيد ساعة النظام وبيئة بيانات الاعتماد للكشف عن أخطاء التوقيع.
- الحفاظ على الفشل الأول وأي نتائج إعادة محاولة لاحقة.
- استخدم [قالب طلب الدعم](/ar/resources/support-request-template) لإرسال تقرير كامل ومحذوف.
