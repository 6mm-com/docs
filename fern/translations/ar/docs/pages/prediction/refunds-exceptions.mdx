يمكن أن تتضمن الاستثناءات انقطاع الأسعار، أو أدلة الأسعار غير المتسقة، أو تناقضات الاحتمالات، أو فشل معالجة التسوية. يتطلب الاستثناء دقة مسجلة؛ إنها ليست نتيجة خاسرة تلقائيًا.

## المواقف الشائعة

| الموقف | ما يجب القيام به |
| --- | --- |
| تغذية الشبكة مفقودة أثناء النافذة الصالحة | التحقق من معالجة الاستثناء/استرداد الأموال؛ العينة الغائبة لا يمكن أن تثبت الخطأ |
| انتهت مهلة الاستجابة للطلب | ابحث عن الطلب الأصلي والحجز قبل الإرسال مرة أخرى |
| العرض والنتيجة المسجلة غير موافقين | قارن مصدر السعر والطوابع الزمنية والمصطلحات المقبولة وأدلة النتائج |
| يبدو أن التسوية متأخرة | تحقق من الحالة النهائية والمعاملة بشكل منفصل |
| السجل المسترد أو الملغى | قم بمراجعة السبب وحركة الأموال الفعلية والحجز المتبقي |

## الاسترداد والإلغاء مختلفان

يصف استرداد الأموال معاملة الصندوق. يصف الفراغ إبطال الأمر. لا تستنتج مبلغ الاسترداد الدقيق أو الموعد النهائي للمعالجة من الملصق وحده؛ استخدام القرار والمعاملات المسجلة.

يتم استبعاد الطلبات المستردة والملغاة من مبلغ الرهان المؤهل للاحتساب في الإبلاغ. لا ينبغي اعتبار المبالغ المستردة بمثابة عوائد فائزة عند تقييم أداء اللعب.

## دعم الأدلة

قم بتوفير رقم الطلب، والرقم الدائري إن أمكن، والرمز، والطوابع الزمنية ذات الصلة، ومضاعف الدفع المسجل، والنتيجة/الحالة، ورقم معاملة التسوية. بالنسبة للنزاعات المتعلقة بالشبكة، قم بتضمين الفاصل الزمني للسعر المقبول والنافذة الزمنية الصالحة. لا تقم مطلقًا بتضمين كلمات مرور أو أسرار API أو رموز الوصول الكامل.

يستخدم [دعم الشركاء](/ar/resources/contact/support) لمسار الدعم و [التحويلات والمعاملات](/ar/prediction/transfers-ledger) للمصالحة.
