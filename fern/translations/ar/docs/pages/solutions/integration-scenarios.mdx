عادة ما يتم إدخال التداول المدمج في منتج موجود، وليس كوجهة مستقلة. أفضل مسار تكامل يعتمد على المكان الذي يقضيه فيه المستخدمون بالفعل وأي نظام يملك الهوية والأموال والعمليات.

<span id="common-scenarios" data-sixmm-canonical-anchor="common-scenarios" aria-hidden="true"></span>

## السيناريوهات الشائعة

| السيناريو | أفضل نقطة بداية | ملاحظات |
| --- | --- | --- |
| التطبيق أو المحفظة تريد إدخال تداول | Trading Widget SDK | استخدم نقطة دخول أصلية أو H5 وافتح تجربة التداول المدمجة بعد تفويض المستخدم. |
| الوسيط أو منصة القناة تريد الوصول إلى المشتقات | Agent SDK + Trading Widget SDK | حافظ على التحقق من العلاقة مع العملاء والدعم الخلفي في نظام الشركاء. |
| المنصة تريد تدفق تداول موجه | API + وحدات SDK مختارة | استخدم API الخلفية لسير عمل الحساب، والنقل، والأوامر مع عرض إدخال الواجهة الأمامية المطلوبة فقط. |
| البورصة الحالية تريد أسواقا إضافية | السيولة + تكامل API | اجمع بين عمق السوق، وسير عمل الحسابات، والمراقبة التشغيلية. |

<span id="product-decisions-before-integration" data-sixmm-canonical-anchor="product-decisions-before-integration" aria-hidden="true"></span>

## قرارات المنتج قبل التكامل

- تحديد ما إذا كان المستخدمون يدخلون من بطاقة الصفحة الرئيسية، صفحة أصول، صفحة حملة، أو مركز حساب.
- تحديد النظام الذي يملك ولاية تسجيل الدخول، وأهلية المستخدم، وتوفر الدولة أو المنطقة.
- تحديد كيفية عرض التحويلات، سجلات التسوية، وتذاكر دعم العملاء للمستخدمين.
- تحديد الأحداث التي يجب تحويلها إلى عمليات التحليلات الداخلية أو CRMأو المخاطر.
