استخدم هذه القائمة قبل عرض قدرات التداول المدعومة 6MMللمستخدمين الحقيقيين.

<span id="integration-readiness" data-sixmm-canonical-anchor="integration-readiness" aria-hidden="true"></span>

## الجاهزية للتكامل

- يتم تأكيد مجالات الإنتاج ومسارات إعادة التوجيه.
- Trading Widget، Agent SDK، API، أو WebSocket تم اختبار التدفقات من البداية إلى النهاية.
- الواجهة الخلفية الشريكة تخزن جميع الأسرار على جانب الخادم.
- يتم تفعيل استقبال Webhook، والتحقق من التوقيع، وإعادة المحاولة، وميزة الهوية.
- تشمل السجلات معرفات الطلبات، معرفات تعيين المستخدمين، معرفات الطلبات، والطوابع الزمنية.

<span id="product-and-resource-readiness" data-sixmm-canonical-anchor="product-and-resource-readiness" aria-hidden="true"></span>

## جاهزية المنتج والموارد

- نقاط الدخول، اللافتات، وأصول البطاقات تستخدم النسخة المعتمدة من اللغة المعتمدة.
- الأصول ذات العلامة البيضاء تستخدم فقط عندما تسمح اتفاقية التعاون بذلك.
- يتم مراجعة تنبيهات المخاطر الموجهة للمستخدمين ونسخ إدخال التداول من قبل فريق الشريك.
- يتم تعيين مالكين للدعم والتصعيد.

<span id="operational-readiness" data-sixmm-canonical-anchor="operational-readiness" aria-hidden="true"></span>

## الجاهزية التشغيلية

- المراقبة تشمل API الأخطاء، إصدار الرموز، تهيئة الويدجت، فشل webhook، وأحداث دورة حياة الأومر.
- تم تأكيد مسارات الاتصال الطارئة.
- يتم إعداد خطة التراجع أو التعطيل المؤقت للمشاركة في التداول.

<span id="security-and-compliance-readiness" data-sixmm-canonical-anchor="security-and-compliance-readiness" aria-hidden="true"></span>

## جاهزية الأمن والامتثال

- تستخدم API المفاتيح أدنى صلاحيات وقيود IP معتمدة حيثما ينطبق.
- تم اختبار تدوير الشهادات وإلغاؤها.
- يتم التحقق من توقيعات Webhook مقابل هيئات الطلب الخام.
- إفصاحات المستخدمين، إشعارات المخاطر، حدود المسؤولية، ومراجعة السوق المستهدفة مكتملة.
- يمكن استرجاع أدلة الحوادث والمصالحة والدعم دون كشف الأسرار.
