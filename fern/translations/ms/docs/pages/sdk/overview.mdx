<h2 id="recommended-combination">Inirerekomendang kombinasyon</h2>

| Layunin ng Partner | Frontend | Backend | Bakit ito mahalaga |
| --- | --- | --- | --- |
| Magdagdag ng embedded trading terminal | Trading Widget SDK | Agent SDK | Ang widget ang humahawak sa trading UI habang ang partner backend ang naglalabas ng tokens at pinananatiling pribado. |
| Gumawa ng native app entry point | Native o H5 entry | Agent SDK | Nagbubukas ang app ng 6MM entry URL pagkatapos ma-validate ng partner ang user session. |
| Bumuo ng custom na daloy ng trading | Partner UI | Developer API + napiling SDK flows | Gamitin ang APIs para sa account, order, position, at market data habang pinananatili ang operational controls sa server-side. |

<h2 id="reference-architecture">Arkitektura ng Sanggunian</h2>

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Panatilihin ang mga lihim sa server-side**
>
> Browser code ay dapat tumawag lamang sa mga endpoint na pag-aari ng partner. Ang Agent API secret ay hindi dapat ipadala sa frontend code.

<h2 id="production-checklist">Listahan ng produksyon</h2>

- I-store apiSecret lamang sa backend infrastructure.
- Gamitin ang HTTPS para sa Agent API requests at webhook URLs.
- I-persist ang agentUserId, platformUserId, at agentOrderNo mappings.
- Ipakita ang mga monetary amount bilang decimal strings sa halip na floating-point values.
- Ituring ang PROCESSING bilang nakabinbin, hindi bilang tagumpay o kabiguan.
- Iproseso ang webhooks nang pareho dahil inaasahan ang mga retry.
