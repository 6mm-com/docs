Чітка модель відповідальності знижує операційні ризики та допомагає командам підтримки реагувати швидше.

<h2 id="responsibility-split">Розподіл відповідальності</h2>

| Площа | 6MM | Партнер |
| --- | --- | --- |
| Торгова інфраструктура | Можливості підбору, ризиків, торгових механізмів, API та SDK | Правильна інтеграція та моніторинг виробництва |
| Відносини кінцевого користувача | Жодних прямих відносин з клієнтами, якщо не узгоджені окремо | Адаптація користувачів, підтримка, розкриття інформації та життєвий цикл облікового запису |
| Таємниці та кваліфікації | Надає модель акредитації та вимоги до підписання | Надійно зберігає секрети та обмежує внутрішній доступ |
| Webhooks | Надсилає підписані події життєвого циклу | Перевіряє підписи та обробляє події ідемпотентно |
| Операції з дотримання вимог | Надає технології, орієнтовані на відповідність вимогам, та допоміжні матеріали | Підтверджує місцеві зобов'язання та вимоги, орієнтовані на користувача |
| Релізи інтеграції | Підтримує задокументовані можливості платформи та інтеграції | Тестує код партнера, конфігурацію та користувацькі шляхи перед релізом |
| Вирішення інцидентів | Досліджує релевантну інфраструктуру 6MM та надає канали підтримки партнерів | Виявляє вплив, орієнтований на користувача, зберігає докази, утримує партнерські системи та посилює ескалацію |

<h2 id="responsibilities-by-lifecycle">Обов'язки за життєвим циклом</h2>

| Сцена | Партнерські дії |
| --- | --- |
| Конструкція | Визначте право власності користувачів, потік активів, потік даних, модель підтримки та цільові юрисдикції. |
| Будівництво | Зберігайте секрети на бекенді, впроваджуйте підтримувану автентифікацію та зберігайте бізнес-ідентифікатори. |
| Тест | Виконуйте тайм-аут, повторну спробу, дублікат вебхука, прострочений токен і сценарії невдач. |
| Запуск | Завершити перевірку готовності, встановити моніторинг і задокументувати ескалацію підтримки. |
| Експлуатація | Перевіряйте сповіщення, узгоджуйте аномальні операції, змінюйте облікові дані та зберігайте докази аудиту. |
| Інцидент | Зберігайте системи під керуванням партнерів, захищайте облікові дані, зберігайте UTC терміни та зв'язуйтеся з відповідним 6MM каналом. |

<h2 id="handoff-checklist">Контрольний список операційної передачі</h2>

- Назвіть власника для підтримки інтеграції, здоров'я, безпеки, відповідності та кінцевих користувачів.
- Документувати URL-адреси базової продукції, власників облікових даних та процедури ротації.
- Підтверджувати дашборди та сповіщення про автентифікацію, замовлення, передачу та збоїв вебхуків.
- Зберігати ідентифікатори запитів, номери замовлень партнерів і ідентифікатори подій у пошукових журналах.
- Визначити, які події потребують негайної ескалації.
- Тримати [шаблон запиту на підтримку](/uk/resources/support-request-template) доступним для операційної команди.
