6MM надає технологічну інфраструктуру та підтримку, орієнтовану на відповідність, для уповноважених партнерів. Вимоги до відповідності відрізняються залежно від юрисдикції та бізнес-моделі, тому кожен запуск слід розглядати з урахуванням власних зобов'язань партнера.

<h2 id="what-this-section-covers">Що охоплює цей розділ</h2>

| Площа | Опис |
| --- | --- |
| Підтримка ліцензій | Рекомендації щодо підтримуваних ліцензійних шляхів та необхідних матеріалів для підготовки. |
| Партнерські обов'язки | Адаптація користувачів, розкриття інформації, місцевий контроль відповідності та управління відносинами з клієнтами. |
| Технічне керування | Підписання, ведення журналів, контроль доступу, верифікація вебхуків і моніторинг виробництва. |
| Огляд запуску | Підтвердження на основі чек-листів перед тим, як показувати торгову функціональність користувачам. |

<h2 id="important-boundary">Важлива межа</h2>

6MM документація допомагає партнерам підготувати технічні та операційні контролі. Вона не замінює юридичні консультації, перевірку відповідності юрисдикції чи власні регуляторні зобов'язання партнера.

<h2 id="information-to-prepare">Інформація для підготовки</h2>

Перед перевіркою відповідності або запуску задокументуйте:

- Цільові країни або регіони та типи користувачів, які отримають доступ.
- Обсяг продукту, включно з вбудованою торгівлею, доставкою за білою етикеткою, ліквідністю, гаманцем, зберіганням або брокерськими функціями.
- Суб'єкт, відповідальний за адаптацію користувачів, перевірку особи, розкриття інформації, зберігання, підтримку та комунікацію з інцидентами.
- Потоки даних між партнерським фронтендом, партнерським бекендом, 6MM API, SDK, вебхуками та операційними системами.
- Власники зберігання облікових даних, контроль доступу, ведення аудиту, моніторингу та ескалації.

<h2 id="recommended-review-path">Рекомендований шлях перегляду</h2>

1. Використовуйте [матрицю відповідальності партнера](/uk/security-compliance/partner-responsibilities) для призначення права власності.
2. Перегляд [ліцензійної підтримки](/uk/security-compliance/license-support) щодо цільової операційної моделі.
3. Підтвердіть керування [архітектурою безпеки](/uk/security-compliance/security-architecture) та API/Webhook.
4. Завершити [контрольний список запуску виробництва](/uk/resources/production-launch-checklist).

Юридичні та відповідні висновки мають бути затверджені кваліфікованими консультантами та відповідальним партнером. Ці сторінки описують підготовку до інтеграції та межі відповідальності, а не юридичну думку чи гарантію наявності конкретної ліцензії.
