<h2 id="service-endpoint">Кінцевий пункт обслуговування</h2>

```
wss://ws.6mm.com/ws
```

WebSocket канали поділяються на публічні та приватні канали:

| Тип             | Автентифікація              | Опис                                            |
| ---------------- | --------------------------- | ------------------------------------------------------ |
| Громадські канали  | Не обов'язково                | Ринкові дані, такі як глибина, угоди, Клайни та тікер |
| Приватні канали | `listenKey` чи JWT обов'язкові | Ордер користувачів, акаунти та потік позицій              |

<h2 id="public-channels">Громадські канали</h2>

Публічна WebSocket не потребує автентифікації. Після підключення надішліть `subscribe` запит на підписку на ринкові канали.

Поширені канали:

| Канал                            | Опис                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Глибина книги замовлень. Спочатку надсилає знімок, потім поступові оновлення |
| `market.trade.{symbol}`            | Останні обміни                                                      |
| `market.kline.{symbol}.{interval}` | Клайнс                                                             |
| `market.ticker.{symbol}`           | Односимволний тикер                                       |
| `market.tickers`                   | Огляд тикерів усіх символів                                          |

<h2 id="private-channels">Приватні канали</h2>

<h2 id="listenkey">listenKey</h2>
Для приватних WebSocket потоків спочатку створіть `listenKey` через REST API , а потім підключіться до:

```
wss://ws.6mm.com/ws?listenKey=YOUR_LISTEN_KEY
```

<h2 id="jwt">JWT</h2>
Сумісний JWT метод підключення:

```
wss://ws.6mm.com/ws?token=YOUR_ACCESS_TOKEN
```

Після успішної автентифікації сервер автоматично підписується на приватний канал поточного користувача. Ручна підписка не потрібна.
