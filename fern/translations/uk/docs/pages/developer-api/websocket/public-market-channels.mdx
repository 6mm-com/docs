Використовуйте канали публічного ринку, коли додаток потребує постійно оновлюваних цін, угод, свічок або глибини книги замовлень, не повторюючи опитування REST кінцевих точок. Ці потоки можуть підтримувати торгові екрани, відображення цін, сповіщення та моніторинг ринку.

<h2 id="connection-url">Зв'язок URL</h2>

```
wss://ws.6mm.com/ws
```

Публічна WebSocket не потребує автентифікації.

Для життєвого циклу підключення, відписки, пінгу та повторного підключення дивіться у розділі [Connection, Subscription & Heartbeat](/uk/developer-api/websocket/connection-subscription-and-heartbeat).

<h2 id="common-channels">Спільні канали</h2>

| Канал                            | Опис                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Глибина книги замовлень. Спочатку надсилає знімок, потім поступові оновлення |
| `market.trade.{symbol}`            | Останні обміни                                                      |
| `market.kline.{symbol}.{interval}` | Клайнс                                                             |
| `market.ticker.{symbol}`           | Односимволний тикер                                       |
| `market.tickers`                   | Огляд тикерів усіх символів                                          |

<h2 id="choose-a-channel">Виберіть канал</h2>

| Потреба у подачі заявки | Канал |
| --- | --- |
| Створення або підтримка книги замовлень | `market.depth.{symbol}` |
| Відобразити прямий трансляцію торгівлі | `market.trade.{symbol}` |
| Намалюйте діаграму свічки | `market.kline.{symbol}.{interval}` |
| Відобразити один огляд ринку | `market.ticker.{symbol}` |
| Підтримуйте огляд ринку | `market.tickers` |

<h2 id="subscription-example">Приклад підписки</h2>

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<h2 id="push-message-wrapper">Push-обгортка повідомлень</h2>

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

Використовуйте `topic` для маршрутизації кожного повідомлення до правильного обробника та `ts` для спостереження за часом доставки. Об'єкт `data` містить корисне навантаження для підписаного каналу.

<h2 id="order-book-handling">Обробка у книгі замовлень</h2>

Канал глибини спочатку надсилає знімок, а потім поступові оновлення. Ініціалізуйте локальну книгу з знімка перед застосуванням оновлень. Після повторного підключення створіть нову сесію, знову підпишіться і відновіть локальну книгу з наступного знімка замість того, щоб продовжувати з застарілого стану в пам'яті.

<h2 id="production-recommendations">Рекомендації щодо виробництва</h2>

- Генерувати унікальний `id` для кожного запиту на підписку, відписку та пінг.
- Підтверджуйте підтвердження підписки перед тим, як вважати канал активним.
- Повторно підписатися на всі необхідні теми після повторного підключення.
- Тримати мережеві читання окремо від повільнішої обробки бази даних або інтерфейсу.
- Моніторити частоту відключення, затримку обробки повідомлень і деформовані корисні навантаження.
- Використовуйте [Приватний канал користувача](/uk/developer-api/websocket/private-user-channel) для автентифікації акаунта та оновлень замовлень.
