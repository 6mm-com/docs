<h2 id="error-response-format">Формат відповіді на помилки</h2>

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Бізнес-помилки зазвичай все одно повертають уніфіковану структуру JSON . Інтегратори повинні спочатку перевірити `code` . Невдачі автентифікації можуть повернути HTTP `401`; обмеження швидкості може повернути HTTP `429`.

<h2 id="common-error-codes">Поширені коди помилок</h2>

| Код помилки      | Опис                                  |
| --------------- | -------------------------------------------- |
| `0`             | Успіх                                      |
| `1001`          | Не надано дійсної інформації про автентифікацію |
| `1002`          | Токен закінчився                                |
| `1003`          | Недійсний токен, API Keyабо підпис         |
| `1004`          | Жетон анульовано                                |
| `1006`          | Джерело IP невідповідність                           |
| `2001`          | Відсутній необхідний параметр                   |
| `2002`          | Недійсне значення параметра                      |
| `2003`          | Параметр поза зоною дії                       |
| `3001`          | Недостатній баланс                         |
| `3003`          | Порядок не знайдено                              |
| `3004`          | Дублікатний запит                            |
| `3005`          | Замовлення не можна скасувати                     |
| `3006`          | Дозвіл відмовлено                            |
| `3100` - `3112` | Помилка валідації параметра порядку стану   |
| `5001`          | Помилка внутрішнього сервера                        |
| `5002`          | Тимчасово недоступна послуга              |
| `5003`          | Спрацювано ліміт ставки                         |

<h2 id="troubleshooting">Усунення несправностей</h2>

| Проблема                                     | Рекомендація                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `1001` немає достовірної інформації про автентифікацію  | Перевірте, чи входить `Authorization: Bearer <accessToken>` чи `X-API-KEY` .                  |
| `1002` Токен закінчився                        | Оновіть токен або увійдіть ще раз перед повторною спробою.                                                   |
| `1003` недійсний токен, API Keyабо підпис | Перевірте API Key, корисне навантаження підпису, тіло запиту JSON рядок і порядок параметрів запиту.           |
| `1006` джерело IP невідповідність                   | Перевірте конфігурацію API Key IP білого списку.                                                    |
| `3004` дубльований запит                    | Не використовуйте один і той самий підпис для шляхів, пов'язаних із порядком. Регенеруйте `timestamp` і `signature`. |
| `5003` ліміт ставки активовано                 | Зменшуйте частоту запитів і використовуйте експоненціальний відкат при повторній спробі.                                |
| `Timestamp outside of tolerance window`     | Зателефонуйте `/v1/time` , щоб відкалібрувати зсув за часом, і знову підпишіть запит.                             |
