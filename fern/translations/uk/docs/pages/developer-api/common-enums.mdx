<h2 id="orders">Замовлення</h2>

| Enum                 | Цінності                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Сторона ордену           | `BUY` / `SELL`                                                                                            |
| Позиція        | `BOTH` / `LONG` / `SHORT`                                                                                 |
| Звичайний тип ордеру    | `LIMIT` / `MARKET`                                                                                        |
| Тип порядку стану | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| Час дії        | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| Тип тригерної ціни   | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| Статус ордену         | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` означає, що запит на замовлення було прийнято і повернуто. `PENDING` означає, що наказ перейшов у стан очікування або відкритого порядку.

<h2 id="positions">Посади</h2>

| Enum                      | Цінності                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Значення запиту в режимі margin | `1` схрестя, `2` ізольована                                     |
| Рядок режиму margin        | `ISOLATED` / `CROSS`                                        |
| Режим закриття тригера        | `1` посібнику, `2` тейк-прибуток `3` стоп-лос `4` ліквідацію |

<h2 id="integration-rules">Правила інтегрування</h2>

- Розглядати значення enum як значення дроту, чутливих до регістру.
- Зберігати невідомі значення в журналах і безпечно виходити з ладу замість тихого відображення їх у відомий стан.
- Не робіть висновків, що кожен нефінальний нарядний стан безпечно повторити спробу. Запитуйте ордер або узгодьте його з приватною WebSocket подією.
- Зберігати як оригінальне значення API , так і етикетку, орієнтовану на партнера, щоб нові значення можна було підтримувати без зміни історичних записів.

<h2 id="order-state-handling">Обробка стану замовлень</h2>

| Державна група | Цінності | Рекомендоване поводження |
| --- | --- | --- |
| Прийнято або відкрито | `NEW`, `PENDING`, `PARTIALLY_FILLED` | Підтримуйте ордер активним і узгоджуйте WebSocket або REST оновленнями. |
| Завершено | `FILLED` | Застосуйте остаточні заповнені номери та записи виконання. |
| Закрито без повного заповнення | `CANCELED`, `REJECTED`, `PARTIALLY_FILLED_CANCELED` | Припиніть активну обробку та збережіть причину та будь-яку виконану кількість. |
