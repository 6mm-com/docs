> REST Базова URL: `https://api.6mm.com`\
> WebSocket URL: `wss://ws.6mm.com/ws`

Ця документація призначена для зовнішніх систем, які інтегруються з сервісом 6MM API . Він охоплює вхід, автентифікацію JWT , управління API Key , підписання API Key HMAC , запити до акаунтів, замовлення, позиції, ринкові дані та WebSocket потоки.

Забезпечення рахунку та підготовка фінансування здійснюється через процеси на стороні платформи. Ця документація описує лише зовнішньо викликані API сервісні кінцеві точки.

## Кінцеві точки обслуговування

| Тип      | Кінцева точка              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<span id="integration-flow" data-sixmm-canonical-anchor="integration-flow" aria-hidden="true"></span>

## Потік інтеграції

Рекомендована послідовність інтеграції:

1. Увійдіть у акаунт, наданий платформою, і отримайте `accessToken`.
2. Для серверного програмного доступу створіть API Key з JWT спочатку та безпечно зберігайте одноразовий повернений `apiSecret`.
3. Приватні запити, а також кінцеві точки ордерів і позицій можна викликати за допомогою `Authorization: Bearer <accessToken>` або підпису API Key.
4. Для приватних WebSocket потоків спочатку створіть `listenKey` , потім підключіться до `wss://ws.6mm.com/ws?listenKey=...`.
5. Ринкові дані REST кінцевих точок і публічних WebSocket каналах не потребують автентифікації.

<span id="authentication-choice" data-sixmm-canonical-anchor="authentication-choice" aria-hidden="true"></span>

## Вибір автентифікації

| Сценарій                               | Рекомендований метод         |
| -------------------------------------- | -------------------------- |
| Дії користувачів фронтенду                  | JWT                        |
| Серверні програмні виклики         | API Key + HMAC підпис   |
| API Key створення, оновлення та видалення | JWT                        |
| Публічний ринок REST / публічний WebSocket  | Автентифікація не потрібна |
