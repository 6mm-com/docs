Використовуйте квитки, щоб стежити за роботою, яку неможливо виконати за одну бесіду. Зберігайте чіткі тип запису, відповідальну особу та поточний прогрес, щоб наступний агент міг продовжити.

<div className="sixmm-support-flow">

1. **Ідентифікуйте запис** — виберіть заявку агента, заявку користувача або відгук.
2. **Дослідити та призначити** — прочитайте опис і підтвердьте, хто ним займається.
3. **Оновити результат** — записувати прогрес і перевіряти збережений статус.

</div>


<span id="choose-the-correct-record" data-sixmm-canonical-anchor="choose-the-correct-record" aria-hidden="true"></span>

## Виберіть правильний запис

Відкрийте **Керування квитками** та виберіть відповідну вкладку.

| запис | призначення |
| --- | --- |
| Агентський квиток | Робота створена та підтримується командою підтримки |
| Квиток користувача | Запитання, надіслане відвідувачем для доопрацювання |
| Відгуки користувачів | Пропозиція або проблема, надіслана через запис відгуку |

<span id="handle-a-case" data-sixmm-canonical-anchor="handle-a-case" aria-hidden="true"></span>

## Займатися справою

Прочитайте опис, контактні дані, пов’язану розмову та вкладення, наявні в записі. Призначте його відповідному обробнику та оновлюйте статус у міру просування роботи. Використовуйте підтримувані елементи керування для квитків агентів; квитки користувачів і відгуки мають власні доступні дії.

Оновлення статусу саме по собі не доводить, що відвідувач отримав відповідь електронною поштою чи чатом. За потреби надішліть відповідь через доступний канал зв’язку та перевірте результат. Зберігайте особисту інформацію в рамках авторизованого робочого процесу орендаря.

<span id="use-mcp-for-triage" data-sixmm-canonical-anchor="use-mcp-for-triage" aria-hidden="true"></span>

## Використовуйте MCP для сортування

Попросіть підключений ШІ скласти список невирішених випадків, згрупувати їх за проблемами та підготувати запропоновану відповідь. Перегляньте призначення та зміни статусу, перш ніж застосовувати їх до реальних випадків. Створення квитка агента та подання квитка користувача є різними робочими процесами; інструмент для одного не означає, що він підтримує інший. Видалення квитка через MCP вимагає підтвердження.


<span id="use-status-and-priority-deliberately" data-sixmm-canonical-anchor="use-status-and-priority-deliberately" aria-hidden="true"></span>

## Свідомо використовуйте статус і пріоритет

Квитки агентів підтримують стани очікування, обробки, вирішені та закриті. Квитки користувачів і відгуки відкривають власні елементи керування статусом; не припускайте, що кожна вкладка має однакові дії.

| Деталь | Як це допомагає |
| --- | --- |
| Номер квитка | Знайдіть точний запис під час передачі роботи іншому агенту. |
| Опис і відповідний сеанс | Зрозумійте, що сталося і про що вже йшлося. |
| Правоодержувач або обробник | Визначте особу, відповідальну за наступні дії. |
| Пріоритет на квитки агента | Відокремте терміновість від статусу робочого процесу; заявка з високим пріоритетом не вирішується автоматично. |
| Створено та вирішено разів | Перегляньте часову шкалу за вибраною датою. |

<span id="example-an-issue-needs-technical-investigation" data-sixmm-canonical-anchor="example-an-issue-needs-technical-investigation" aria-hidden="true"></span>

### Приклад: проблема потребує технічного дослідження

1. Відкрийте оригінальний запис і зберіть час, постраждалу сторінку та відтворювані кроки з наданої інформації.
2. Перегляньте пов’язану бесіду, якщо вона доступна. Уникайте просити відвідувача повторити вже записану інформацію.
3. Призначте відповідного обробника та оновлюйте статус у міру просування роботи. Зберігайте внутрішні нотатки фактичними.
4. Коли проблему буде перевірено, оновіть результат і зв’яжіться з відвідувачем через доступний канал. Перевірте збережений запис перед тим, як покинути сторінку.

## Загальні запитання

<AccordionGroup>

<Accordion title="Чи автоматично сповіщає відвідувача розв’язання квитка?">
Зміна статусу сама по собі не доводить, що було надіслано повідомлення електронної пошти чи чату. Окремо перевірте канал зв’язку та результат доставки.
</Accordion>

<Accordion title="Чому я не можу знайти квиток?">
Перевірте вкладку запису, основу дати, діапазон дат, статус і фільтри правонаступників. Очистіть непотрібні фільтри перед повторним пошуком.
</Accordion>
