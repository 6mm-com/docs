Використовуйте журнали операцій, щоб відповісти, хто що змінив і коли. Поєднайте дію, ціль і джерело з бізнес-записом замість того, щоб читати опис журналу окремо.

<div className="sixmm-support-flow">

1. **Знайдіть подію** — фільтруйте за часом, ключовим словом і категорією.
2. **Прочитайте деталі** — перевірте актора, ціль, джерело та результат.
3. **Перевірте результат** — відкрийте відповідний запис перед повторною спробою.

</div>


<span id="trace-an-operation" data-sixmm-canonical-anchor="trace-an-operation" aria-hidden="true"></span>

## Відстеження операції

Відкрийте **Журнали операцій**. Фільтруйте за ключовим словом, категорією, дією, типом актора, типом цілі та датою за допомогою доступних елементів керування. Прочитайте деталі, щоб визначити, хто діяв, який запис змінився та результат.

Операції MCP відображаються разом із їх програмою/джерелом і статусом виконання. Залежно від операції можуть з’явитися як бізнес-зміна, так і запис її виконання MCP; два записи аудиту самі по собі не означають, що дію було виконано двічі.

<span id="distinguish-authorization-from-execution" data-sixmm-canonical-anchor="distinguish-authorization-from-execution" aria-hidden="true"></span>

## Відрізнити дозвіл від виконання

Підключення програми лише підтверджує авторизацію. Запропонований запис, очікування на схвалення та завершений запис є різними станами. Журнал не є повною розшифровкою всього, що було сказано зовнішньому штучному інтелекту, і запит лише для читання не слід припускати для створення бізнес-запису.

Під час дослідження невдалого виклику MCP збережіть ідентифікатор операції, час і повідомлення про помилку. Запитайте результат операції перед повторною спробою. Журнали операцій доступні лише для читання через MCP.

## Прочитайте один запис журналу

| Деталь | Чому це важливо |
| --- | --- |
| час | Розміщує дію в послідовності подій, які ви досліджуєте. |
| Категорія і дія | Розрізняйте оновлення вмісту, дію сеансу чи іншу підтримувану операцію. |
| Актор | Ідентифікує дію облікового запису або системи; це не обов'язково відвідувач у розмові. |
| Джерело | Допомагає відрізнити діяльність програми MCP від інших операцій. |
| Цільова | Ідентифікує бізнес-об’єкт або операцію MCP, на яку посилається запис. |
| Деталі та результат | Надайте доступне пояснення та стан виконання. Прочитайте помилку, перш ніж вирішити повторити спробу. |

### Приклад: зміна статті MCP не з’явилася

1. Звужте діапазон дат і знайдіть програму або пов’язану операцію.
2. Перевірте, чи операція очікує на підтвердження, помилка чи завершена. Авторизація сама по собі не означає внесення змін.
3. Відкрийте цільову статтю та порівняйте її поточний вміст. Якщо повідомляється про конфлікт версій, прочитайте останню версію та підготуйте новий запит, а не повторно використовуйте застарілий вміст.
4. Збережіть ідентифікатор операції та деталі помилки, якщо потрібне подальше дослідження. Пов’язаний запис бізнес-аудиту та запис виконання MCP можуть описувати ту саму зміну.

Корисна передача обслуговування містить час, ідентифікатор цілі, ідентифікатор операції, якщо він є, і спостережуваний результат. Він не повинен містити паролі облікових записів або API секрети.

## Загальні запитання
