Використовуйте цей чек-лист перед тим, як показувати 6MMторгові можливості реальним користувачам.

<h2 id="integration-readiness">Готовність до інтеграції</h2>

- Підтверджуються домени виробництва та шляхи перенаправлення.
- Trading Widget, Agent SDK, API, або WebSocket потоки були перевірені від початку до кінця.
- Партнерський бекенд зберігає всі секрети на стороні сервера.
- Увімкнено прийом вебхуків, верифікацію підписів, обробку повторних спроб та ідемпотентність.
- Журнали включають ідентифікатори запитів, ідентифікатори відображення користувачів, ідентифікатори замовлень і часові позначки.

<h2 id="product-and-resource-readiness">Готовність продукту та ресурсів</h2>

- Точки входу, банери та активи карток використовують затверджену мовну версію.
- Активи з білим лейблом використовуються лише тоді, коли це дозволяє угода про співпрацю.
- Підказки щодо ризику для користувача та тексти входу в торгівлю переглядаються партнерською командою.
- Призначаються власники підтримки та ескалації.

<h2 id="operational-readiness">Бойова готовність</h2>

- Моніторинг охоплює API помилки, випуск токенів, ініціалізацію віджетів, збоїв webhook та події життєвого циклу замовлення.
- Шляхи екстреного контакту підтверджені.
- Для входу в торгівлю готується план відкату або тимчасового відключення.

<h2 id="security-and-compliance-readiness">Безпека та готовність до відповідності</h2>

- API ключі використовують мінімальні дозволи та затверджені IP обмеження, де це застосовно.
- Ротація та анулювання кваліфікацій були протестовані.
- Підписи Webhook перевіряються за сирими запитами.
- Завершено розкриття інформації користувачів, повідомлення про ризики, межі відповідальності та огляд цільового ринку.
- Докази інциденту, примирення та підтвердження можуть бути отримані без розкриття секретів.
