Посібники для розробників описують поточну поверхню інтеграції корпоративного гаманця. MPC Wallet не запущено: приклади кінцевих точок є посиланнями на впровадження, а не обіцянкою загальнодоступної служби чи замороженим API контрактом.

<span id="obtain-integration-information" data-sixmm-canonical-anchor="obtain-integration-information" aria-hidden="true"></span>

## Отримати інформацію про інтеграцію

Підтвердьте тестову базу URL, версію API, ідентифікатор робочої області, модель зберігання, увімкнені мережі та активи, дозволи API, вимоги авторизації клієнта та налаштування webhook. Ідентифікатори мережі та активів надходять із узгодженого середовища; не припускайте, що вони дорівнюють публічним ідентифікаторам ланцюжка.

Зберігайте облікові дані для інтеграції гаманця окремо від облікових даних для торгівлі API. Спільний сайт документації не робить служби або моделі облікових записів взаємозамінними.

<span id="connect-the-business-flow" data-sixmm-canonical-anchor="connect-the-business-flow" aria-hidden="true"></span>

## Підключіть бізнес-потік

1. Створіть ключ із найменшими привілеями API для передбачуваної корпоративної робочої області та збережіть його таємницю на сервері.
2. Перевірте підписаний запит лише для читання та обробку помилок перед запровадженням передачі.
3. Призначте адресу отримання для стабільного ідентифікатора бізнес-користувача, а потім перевірте повернуту адресу та будь-яке повідомлення.
4. Отримуйте події депозитів і узгоджуйте їх із API запитами та своїми власними записами.
5. Додайте дозвіл на зняття коштів, стабільні ідентифікатори бізнес-запитів і відстеження результатів.

<span id="core-api-areas" data-sixmm-canonical-anchor="core-api-areas" aria-hidden="true"></span>

## Основні API області

| Площа | Актуальні приклади маршрутів | призначення |
| --- | --- | --- |
| Отримання адрес | `POST /api/v1/addresses`, `GET /api/v1/addresses` | Виділяти та запитувати адреси |
| Депозити | `GET /api/v1/deposits`, `GET /api/v1/deposits/{id}` | Слідкуйте за вхідними передачами |
| Зняття коштів | `POST /api/v1/withdrawals`, `GET /api/v1/withdrawals/{id}` | Надішліть запит і запитайте його результат |
| Запит на пошук | `GET /api/v1/withdrawals/by-request` | Узгодити запит після невизначеної відповіді |
| Залишки | `GET /api/v1/balances` | Запитувати бізнес-баланси в дозволеному діапазоні |

Реєстрація маршруту не означає, що кожна клавіша API може викликати кожну операцію. Доступ до продукту, дозволи робочої області, режим зберігання та ініціалізація можуть впливати на доступність. Адміністративні та персональні інтерфейси пристроїв знаходяться за межами цього корпоративного потоку швидкого запуску.

## Перевірте адреси отримання

Надана реалізація SDK підтримує атестації підписаної адреси. Налаштуйте довірених учасників або матеріал довіри, визначений пакетом інтеграції, і незалежно надайте очікувану робочу область, ланцюжок і інформацію про групу ключів, якщо потрібно. Не виводьте всі очікування довіри з тієї самої відповіді, яку ви перевіряєте.

Для повністю керованих адрес пулу атестація може ідентифікувати адресу, що належить платформі, тоді як її призначення клієнту залишається заявою на стороні сервера. Не описуйте це призначення як криптографічний доказ власності клієнта.

Продовжити з [підписання запиту](/uk/mpc-wallet/request-signing), [операції](/uk/mpc-wallet/transactions) і [webhooks і SDKs](/uk/mpc-wallet/webhooks-and-sdks).
