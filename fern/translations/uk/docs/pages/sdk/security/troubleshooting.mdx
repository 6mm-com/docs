Почніть із середовища, позначки часу та бізнес-ідентифікатора для невдалої операції. Структурована перевірка зазвичай відокремлює проблеми конфігурації від проблем автентифікації, мережі й асинхронної обробки.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Рекомендований порядок діагностики

1. Підтвердьте уражене середовище та базу URL.
2. Запишіть UTC діапазон часу та перший невдалий запит.
3. Визначте модуль: Trading Widget, Agent SDK, REST API, WebSocket або webhook.
4. Зберіть ідентифікатор запиту, ідентифікатор користувача партнера, `agentOrderNo`, ідентифікатор замовлення або ідентифікатор події webhook.
5. Перевірте останній код, облікові дані, білий список IP або зміни в розгортанні.
6. Відтворити з найменшим безпечним тестом.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget проблеми

| Симптом | Ймовірна причина | Виправити |
| --- | --- | --- |
| iframe запитує локальний домен партнера | baseUrl відсутній | Передайте baseUrl: 'https://app.6mm.com'. |
| iframe невидимий або дуже короткий | Батьківський контейнер не має висоти | Встановіть висоту контейнера або висоту проходу. |
| token_provider_missing | Режим маркера партнера не має постачальника | Додайте авторизацію.tokenProvider. |
| auth_exchange_failed | Недійсний, прострочений або невідповідний маркер вбудовування | Перевірте відповідь маркера серверної частини та channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK проблеми

| Симптом | Ймовірна причина | Виправити |
| --- | --- | --- |
| Підпис відхилено | Неправильний секрет, збій годинника або змінені вручну підписані поля | Нехай SDK генерує поля підпису та синхронізує час сервера. |
| Ризик дублювання руху коштів | Новий номер замовлення використано після тайм-ауту | Спочатку запитайте за оригінальним agentOrderNo. |
| PROCESSING розглядається як помилка | Стан очікування неправильно зрозумілий | Зачекайте webhook або зателефонуйте queryOrder. |
| Webhook оброблено кілька разів | Повторіть поведінку без ідемпотентності | Додайте ключ ідемпотентності та перевірку кінцевого стану. |

## Докази для захоплення

| Інтеграція | Корисні докази |
| --- | --- |
| Trading Widget | Сторінка URL, шлях до версії SDK, консоль браузера, невдалі мережеві запити, корисне навантаження `onError` і розміри контейнера. |
| Agent SDK | SDK мова/версія, базова URL, UTC позначка часу, ідентифікатор запиту, `agentOrderNo`, код відповіді та дезінфіковані журнали. |
| Webhook | Час доставки, подія чи бізнес-ключ, результат перевірки підпису, стан обробки та дезінфікований геш необробленого тіла. |
| REST API | Метод, шлях, середовище, ідентифікатор запиту, код відповіді та дезінфіковані параметри. |

Ніколи не включайте в діагностику паролі, маркери доступу, API секрети, повні підписи, закриті ключі або невідредаговані особисті дані.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Перед ескалацією

- Повторюйте лише тоді, коли операція задокументована як безпечна для повторної спроби.
- Після тайм-ауту запитайте вихідний бізнес-ідентифікатор замість створення нового.
- Перевірте системний годинник і середовище облікових даних на наявність помилок підпису.
- Збереження результатів першої помилки та будь-яких пізніших повторних спроб.
- Використовуйте [Шаблон запиту на підтримку](/uk/resources/support-request-template) щоб надіслати повний відредагований звіт.

## Діагностика Java v0.3.0

| Симптом | Перевірка і відновлення |
| --- | --- |
| Результат запиту на фінансування невідомий | Зберегти оригінал `agentOrderNo`; виклик `queryWalletTransfer` з вихідним середовищем. Не використовуйте `queryOrder`. |
| Інтерфейс моделювання показує несподівані кошти | Перевірте інтерфейс `tradingMode` окремо від бекенда `environment`; обліковий запис `isSimulatedUser` не направляє запити. |
| Помилка запиту `6905` | Відмовтеся від використання спільної партнерської квоти, а потім повторіть той самий курсор і фільтри через SDK. |
| Помилка запиту `6904` | Зменшити кількість одночасних запитів і звузити часове вікно; зв’яжіться зі службою підтримки, якщо це не зникне. |
| Недійсний або прострочений курсор | Перезапустіть те саме вікно фіксованої історії та видаліть дублікати збережених записів. |
| Відсутній новий метод Java. | Перевірте виправлений артефакт Maven на загальнодоступний тег `v0.3.0`; видаліть конфліктні залежності відповідно до вашої політики артефактів. |
