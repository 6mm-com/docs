Репозиторій Java SDK є джерелом істини для SDK вихідного коду, нотаток до релізів, прикладів використання та деталей реалізації:

[6mm-com/agent-java-sdk] (https://github.com/6mm-com/agent-java-sdk)

## Тривалість виконання

| Предмет | Вартість |
| --- | --- |
| Мінімальна версія Java | Java 8+ |
| Рекомендований інструмент для збірки | Maven 3.9+ |
| Група Maven | `com.sixmm.exchange.sdk` |
| Артефакт Maven | `agent` |
| Задокументований позначки джерела | `v0.1.1` |

Публічний репозиторій GitHub — це хостинг вихідного коду, а не репозиторій залежностей Maven. Створіть і встановіть позначений вихідний код локально або опублікуйте затверджений артефакт у приватному репозиторії Maven вашої організації перед тим, як використовувати його в командних збірках.

<span id="typical-backend-responsibilities" data-sixmm-canonical-anchor="typical-backend-responsibilities" aria-hidden="true"></span>

## Типові обов'язки бекенду

- Перевірити сесію партнера.
- Відвести партнера користувача на agentUserId.
- Зв'язування колів перед першою торгівлею або трансферними потоками.
- Зателефонуйте createEntryUrl для одноразового повного SSO.
- Зателефонуйте createEmbedToken для режиму Trading Widget партнера-токен.
- Перевірити вебхуки трансферу та обробити їх ідемпотентно.

<span id="security-and-operational-rules" data-sixmm-canonical-anchor="security-and-operational-rules" aria-hidden="true"></span>

## Правила безпеки та експлуатації

- Зберігати `apiSecret` лише у бекенд-менеджері секретів або захищеній змінній середовища.
- Зберігати синхронізацію часу сервера, оскільки підписані запити містять часові позначки.
- Розглядати `agentOrderNo` як міцний ключ ідемпотентності та зберігати його глобально унікальним.
- Зберігати `platformUserId` як рядок і зберігати його зв'язок із `agentUserId`.
- Запитати початкову передачу перед повторною спробою після тайм-ауту або невизначеного результату мережі.
