6MM Agent SDK призначений для партнерських серверних служб, які потребують виклику привілейованого агента APIs без впровадження підпису та обробки запитів з нуля. Його не можна запускати в коді веб-переглядача, мобільного або загальнодоступного настільного комп’ютера, оскільки інтеграція використовує секрет партнера API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Коли використовувати Agent SDK

Використовуйте Agent SDK, коли бекенду потрібно пов’язати користувача партнера, перемістити активи за затвердженим робочим процесом, отримати торгові записи, створити URL для входу у вбудовану торгівлю або перевірити сповіщення Webhook. Використовуйте [Trading Widget SDK](/uk/sdk/trading-widget/overview) окремо, коли партнерський фронтенд має відображати торговий інтерфейс.

## Загальна конфігурація

| ключ | приклад | опис |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Служба агента API URL без косої риски в кінці. |
| agentCode | AGENT001 | Код агента партнера. |
| apiSecret | your-api-secret | API секрет підпису зберігається лише на сервері. |
| defaultCurrency | USDT | Валюта за умовчанням для переказу та рахунку APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Кінцева точка партнера для сповіщень 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Типовий інтеграційний потік

1. Інтерфейс партнера автентифікує користувача через власну систему облікового запису партнера.
2. Сервер партнера відображає користувача на стабільний ідентифікатор на стороні партнера.
3. Сервер викликає Agent SDK із `agentCode` і захищеним секретом API.
4. SDK підписує та надсилає запит агента API.
5. Сервер зберігає повернутий бізнес-ідентифікатор і обробляє пізніше webhooks ідемпотентно.
6. Інтерфейс отримує лише короткочасний результат або необхідні облікові дані для входу.

## Контрольний лист виробництва

- Завантажте `apiSecret` із серверного секретного менеджера, а не вихідний код.
- Зберігайте облікові дані для розробки, постановки та виробництва окремо.
- Використовуйте стабільне зіставлення користувачів партнерів і унікальні ідентифікатори бізнес-замовлень.
- Зберігайте вихідний ідентифікатор під час перевірки статусу запиту, який минув.
- Перевірте підписи webhook і збережіть оброблені ідентифікатори подій.
- Видаляйте секрети та підписи з журналів, зберігаючи ідентифікатори запитів для підтримки.

## Можливості Java SDK v0.3.0

Java SDK тепер включає гаманці фінансування, явні середовища фінансування, шість безперервних запитів даних і довідкові ставки. PHP можливості необхідно перевірити на відповідність пакету, наданому партнером; Додавання Java не передбачає відповідності методів PHP.
