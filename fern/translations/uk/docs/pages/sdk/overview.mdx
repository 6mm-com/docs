<h2 id="recommended-combination">Рекомендована комбінація</h2>

| Партнерська мета | Фронтенд | Бекенд | Чому це важливо |
| --- | --- | --- | --- |
| Додайте вбудований торговий термінал | Trading Widget SDK | Agent SDK | Віджет керує торговим інтерфейсом, а партнерський бекенд випускає токени і зберігає секрети в таємниці. |
| Створіть нативну точку входу для додатку | Рідний або H5-запис | Agent SDK | Додаток відкриває запис 6MM URL після того, як партнер підтверджує користувацьку сесію. |
| Створіть власний торговий потік | Партнерський інтерфейс | Розробник API + вибрано SDK потоки | Використовуйте API для даних про рахунок, замовлення, позиції та ринку, залишаючи операційні контролі на сервері. |

<h2 id="reference-architecture">Еталонна архітектура</h2>

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Зберігайте секрети на стороні сервера**
>
> Код браузера повинен звертатися лише до кінцевих точок, що належать партнеру. Секрет агента API ніколи не повинен передаватися фронтенд-коду.

<h2 id="production-checklist">Чек-лист виробництва</h2>

- Зберігати apiSecret лише в бекенд-інфраструктурі.
- Використовуйте HTTPS для запитів API агента та URL вебхуків.
- Зберігати agentUserId, platformUserIdта agentOrderNo відображення.
- Представляти грошові суми як десяткові рядки замість значень з плаваючою комою.
- Розглядати PROCESSING як очікуване, а не як успіх чи невдачу.
- Обробляти вебхуки ідемпотентно, оскільки очікуються повторні спроби.
