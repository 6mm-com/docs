Вбудована торгівля зазвичай впроваджується в існуючий продукт, а не запускається як окремий призначення. Найкращий шлях інтеграції залежить від того, де користувачі вже витрачають час і яка система володіє ідентичністю, фондами та операціями.

<h2 id="common-scenarios">Поширені сценарії</h2>

| Сценарій | Найкраща відправна точка | Примітки |
| --- | --- | --- |
| Додаток або гаманець хоче запис для торгівлі | Trading Widget SDK | Використовуйте нативну або H5-точку входу і відкрийте вбудований торговий досвід після авторизації користувача. |
| Брокер або платформа каналу хоче отримати доступ до деривативів | Agent SDK + Trading Widget SDK | Зберігайте взаємовідносини з клієнтами та бекенд-валідацію в партнерській системі. |
| Платформа хоче керований торговий потік | API + вибрані SDK модулі | Використовуйте бекенд API для робочих процесів облікового запису, передачі та замовлень, при цьому відкриваючи лише необхідний фронтенд-запис. |
| Існуюча біржа хоче додаткових ринків | Ліквідність + інтеграція API | Поєднуйте глибину ринку, робочі процеси з обліком та операційний моніторинг. |

<h2 id="product-decisions-before-integration">Рішення щодо продукту до інтеграції</h2>

- Вирішувати, чи вводять користувачі з картки головної сторінки, сторінки активів, сторінки кампанії або центру облікових записів.
- Визначити, яка система володіє станом входу, відповідністю користувача та доступністю країни чи регіону.
- Визначити, як перекази, записи про розрахунки та заявки підтримки клієнтів відображаються користувачам.
- Визначити, які події мають бути передані у внутрішню аналітику, CRMабо операції з ризиком.
