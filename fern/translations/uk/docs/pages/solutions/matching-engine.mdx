White-label біржа вимагає більше, ніж фронтенд-оболонка. Користувацький досвід залежить від надійних основних модулів, що стоять за торгівлею, рахунками, ризиками та розрахунками.

<h2 id="core-modules">Основні модулі</h2>

| Модуль | Роль |
| --- | --- |
| Відповідність і життєвий цикл порядку | Обробляє записи подання наказів, співпадіння стану, скасування та виконання. |
| Система обліку та позицій | Підтримує баланси, стан маржі, позиції та доступність для торгівлі. |
| Контроль ризиків | Координує важільне плече, маржу, ліквідацію та аномальну поведінку ринку. |
| Ринкові дані | Розподіляє ціни, глибину, угоди та дані графіків до торгових інтерфейсів. |
| Поселення та записи | Підтримує узгодження історії торгівлі, змін балансу та операційних записів. |

<h2 id="implementation-questions">Питання щодо реалізації</h2>

- Які типи порядку та умов доступні користувачам?
- Який сервіс володіє правилами символів, точною валідацією та доступністю торгівлі?
- Як узгоджуються записи порядку, торгівлі, позиції, балансу та розрахунків?
- Які ідентифікатори залишаються стабільними у REST відповідях, WebSocket подіях та записах партнерів?
- Який моніторинг і шлях відкату застосовується, коли дані про відповідність, ризик або ринк стають недоступними?

Відповідайте на ці питання до розробки фронтенду, щоб поведінка продукту, API обробка, операції та підтримка використовували одну й ту ж модель торгівлі.
