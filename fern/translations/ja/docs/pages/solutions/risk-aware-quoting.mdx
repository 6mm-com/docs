マーケットメイキングは単に注文を出すだけではありません。生産的な取引環境では、見積もりはボラティリティ、ポジションのエクスポージャー、ヘッジ条件、運用限度に対応しなければなりません。

<h2 id="risk-aware-liquidity-goals">リスク認識型流動性目標</h2>

- 市場を取引可能に保ち、制御不能なエクスポージャーを生じさせる。
- ボラティリティ、深さ、ヘッジ条件が変化した際に、見積もりの行動を調整する。
- 流動性運用をマージン、清算、口座リスクのルールと調整すること。
- 大規模な内部マーケットメイキングチームを必要とせずにパートナーの成長を支援すること。

<h2 id="areas-to-align-before-launch">打ち上げ前に調整すべき分野</h2>

| 面積 | 判決 |
| --- | --- |
| 支援市場 | どのシンボルや決済資産を最初にリリースすべきか。 |
| ユーザープロフィール | 小売、機関、チャネル、または混合ユーザーフロー。 |
| モニタリング | どの深さ、スプレッド、充填、リスク指標を毎日見直すべきか。 |
| エスカレーション | 異常な変動性、遅延決済、またはユーザーに影響を及ぼすインシデントを扱うのは誰でしょうか。 |

<h2 id="signals-and-safeguards">信号と安全対策</h2>

リスク認識のある流動性運用は、在庫露出、市場の変動性、スプレッド、実行可能な深さ、価格フィードの健全性、拒否率、下流の注文フローを一斉に観察すべきです。管理は、承認された閾値を超えた場合に規模の縮小、スプレッド拡大、見積もりの一時停止、またはオペレーターのレビューを求めることがあります。

閾値やアクションは運用モデルに依存し、本番環境の前にテストされなければなりません。すべての自動化状態変更を記録し、リスク、運用、サポートチームが異常な実行条件を説明できるようにします。
