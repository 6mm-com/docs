コンプライアンス、ライセンス、トレーディングテクノロジーは、取引インフラと規制されたデジタル資産運用を準備するパートナーのためのコンプライアンス計画支援を組み合わせています。

<span id="who-this-is-for" data-sixmm-canonical-anchor="who-this-is-for" aria-hidden="true"></span>

## これは誰宛てですか

このガイドは、組み込み型取引やホワイトラベル取引所のローンチを評価する製品、コンプライアンス、セキュリティ、法務、エンジニアリングチーム向けです。これらのチームは、管轄区域ごとの専門的レビューに準備すべき技術的証拠や責任判断を特定するのに役立ちます。

<span id="what-this-covers" data-sixmm-canonical-anchor="what-this-covers" aria-hidden="true"></span>

## これが何をカバーしているか

- 適合した取引操作のための技術的アーキテクチャ
- API、 SDK、ホワイトラベル展開パス
- ライセンスおよび管轄計画支援
- セキュリティおよび鍵管理の要件
- インシデント対応およびユーザー保護のための運用プロセス

<span id="planning-questions" data-sixmm-canonical-anchor="planning-questions" aria-hidden="true"></span>

## 計画に関する質問

| 面積 | 解決すべき質問 |
| --- | --- |
| ターゲット市場 | どの管轄区域やユーザータイプが対象ですか? |
| 製品 | どのような取引、資産、保管、または証券会社の機能が提供されますか? |
| 運用モデル | 製品は組み込み取引、ホワイトラベルインターフェース、 API、あるいはその組み合わせを使うのか? |
| 責任 | オンボーディング、開示、サポート、監視、インシデントエスカレーションはどちらの側が所有しているのでしょうか? |
| データとセキュリティ | 認証情報、ユーザーデータ、ログ、運用証拠はどこに保存されているのでしょうか? |

<span id="recommended-workflow" data-sixmm-canonical-anchor="recommended-workflow" aria-hidden="true"></span>

## 推奨ワークフロー

1. ターゲット市場、ユーザータイプ、提案される製品範囲を定義する。
2. 技術アーキテクチャとデータフローを文書化すること。
3. 各運用プロセスに対してパートナーおよび 6MM の責任を割り当てる。
4. 認証情報の保存、リクエスト署名、ウェブフック、インシデント対応制御の確認。
5. 管轄区域ごとの法的およびコンプライアンスの完全な審査。
6. リリース前に証拠を集めるために生産開始チェックリストを活用すること。

<span id="important-note" data-sixmm-canonical-anchor="important-note" aria-hidden="true"></span>

## 重要な注意事項

6MM 文書は技術的要件、運用ワークフロー、統合責任について記述できます。法的、規制的、ライセンスに関する決定は、該当法域の資格を持つ専門家と確認する必要があります。
