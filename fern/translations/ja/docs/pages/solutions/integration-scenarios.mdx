組み込み取引は通常、既存の製品に導入され、独立した目的地としてリリースされるわけではありません。最適な統合経路は、ユーザーがすでにどこに時間を費やし、どのシステムがアイデンティティ、資金、運営を所有しているかによって異なります。

<h2 id="common-scenarios">一般的なシナリオ</h2>

| シナリオ | 最適な出発点 | 注記 |
| --- | --- | --- |
| アプリやウォレットは取引エントリーを求めています | Trading Widget SDK | ネイティブまたはH5のエントリーポイントを使い、ユーザー承認後に埋め込まれた取引体験を開きます。 |
| ブローカーやチャネルプラットフォームがデリバティブへのアクセスを求めている | Agent SDK + Trading Widget SDK | 顧客関係とバックエンドの検証はパートナーシステム内に留めてください。 |
| プラットフォームはガイド付きの取引フローを求めています | API +選択された SDK モジュール | バックエンド API はアカウント、移管、注文ワークフローに使い、必要なフロントエンドエントリだけを公開します。 |
| 既存の取引所は追加の市場を求めています | 流動性+ API 統合 | 市場の深み、アカウントワークフロー、運用管理を組み合わせましょう。 |

<h2 id="product-decisions-before-integration">統合前の製品決定</h2>

- ユーザーがホームページカード、アセットページ、キャンペーンページ、またはアカウントセンターから入力するかを決定します。
- どのシステムがログイン状態、ユーザーの資格、国や地域の利用可能かを決定します。
- 移管、決済記録、カスタマーサポートチケットの表示方法を決定します。
- どのイベントを内部分析、 CRM、またはリスク運用に転送すべきかを決定する。
