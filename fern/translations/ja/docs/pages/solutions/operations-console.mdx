ホワイトラベル取引所のローンチは、初日から運用上の可視性が必要です。チームは、エンジニアリングクエリだけに頼ることなく、ユーザー、資産、取引活動、リスクイベント、サポートケースを把握できるべきです。

<span id="operational-views" data-sixmm-canonical-anchor="operational-views" aria-hidden="true"></span>

## 運用上の視点

- ユーザーおよびアカウントの状態
- 資産移転および決済記録
- 注文、ポジション、取引活動
- 手数料、コミッション、事業報告
- リスクイベント、清算イベント、異常活動
- 顧客対応チームのサポートコンテキスト

<span id="team-workflows" data-sixmm-canonical-anchor="team-workflows" aria-hidden="true"></span>

## チームのワークフロー

| チーム | 典型的なワークフロー |
| --- | --- |
| 運用 | 取引活動、市場の状況、ユーザー対応のインシデントを監視しましょう。 |
| カスタマーサポート | ユーザーアカウント、送金、注文、ポジションのコンテキストを見つけてください。 |
| ファイナンス | 和解記録、手数料記録、事業報告書の照合。 |
| リスク | 異常な活動、マージン圧、清算の仕組みのレビュー。 |

<span id="launch-recommendation" data-sixmm-canonical-anchor="launch-recommendation" aria-hidden="true"></span>

## 打ち上げ推奨

公開前に必要な運用ダッシュボードを定義してください。技術的に完成した統合でも、サポート、財務、リスクチームがユーザーの質問に迅速に答えられないと未完成に感じられることがあります。
