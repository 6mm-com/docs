ホワイトラベル取引所は単なるフロントエンドシェル以上のものを必要とします。ユーザー体験は、取引、アカウント、リスク、決済の背後にある信頼できるコアモジュールに依存しています。

<h2 id="core-modules">コアモジュール</h2>

| モジュール | 役割 |
| --- | --- |
| マッチングと注文ライフサイクル | 注文の提出、マッチング状態、キャンセル、実行記録を処理します。 |
| アカウントおよびポジションシステム | 残高、マージン状態、ポジション、取引の可用性を管理します。 |
| リスク管理 | レバレッジ、マージン、清算、異常市場の動きを調整します。 |
| 市場データ | 価格、深さ、取引、チャートデータを取引インターフェースに配信します。 |
| 入植と記録 | 取引履歴、バランスの変化、運用記録を常に整合させます。 |

<h2 id="implementation-questions">実装に関する質問</h2>

- ユーザーに公開されている順序や条件順序の種類は?
- シンボルルール、精密検証、取引の可用性を所有するサービスは?
- 注文、取引、ポジション、残高、決済記録はどのように照合されますか?
- どの識別子が REST 応答、 WebSocket イベント、パートナーレコード間で安定しているか?
- マッチング、リスク、市場データが利用できなくなった場合、どのような監視およびロールバック経路が適用されるか?

これらの質問に答えてからフロントエンド開発を進め、製品振る舞い、 API ハンドリング、運用、サポートが同じ取引モデルを使えるようにしましょう。
