例外には、価格の中断、一貫性のない価格証拠、オッズの不一致、または決済処理の失敗が含まれる場合があります。例外には記録された解像度が必要です。自動的に負けという結果にはなりません。

<span id="common-situations" data-sixmm-canonical-anchor="common-situations" aria-hidden="true"></span>

## よくある状況

| 状況 | 何をするか |
| --- | --- |
| 有効期間中にグリッド フィードが欠落する | 例外/返金処理を確認します。サンプルが存在しないからといって、ミスを証明することはできません |
| 注文応答がタイムアウトしました | 再送信する前に元の注文と予約を確認してください |
| 表示結果と記録結果が一致しない | 価格ソース、タイムスタンプ、承認された条件、および結果の証拠を比較します |
| 決済が遅れているように見える | 最終ステータスとトランザクションを個別に確認する |
| 返金または無効化された記録 | 理由、実際の資金の動き、予約残高を確認する |

<span id="refund-and-void-are-distinct" data-sixmm-canonical-anchor="refund-and-void-are-distinct" aria-hidden="true"></span>

## 払い戻しと無効は別のものです

払い戻しには、基金の取り扱いが記載されています。 void は注文が無効であることを表します。ラベルだけから正確な返金金額や処理期限を推測しないでください。記録された解像度とトランザクションを使用します。

返金および無効化された注文は、レポートの有効な利害関係から除外されます。ゲームプレイのパフォーマンスを評価する際、払い戻しは勝利のリターンとしてカウントされるべきではありません。

<span id="support-evidence" data-sixmm-canonical-anchor="support-evidence" aria-hidden="true"></span>

## 証拠を裏付ける

注文番号、該当する場合はラウンド番号、シンボル、関連するタイムスタンプ、記録されたオッズ、結果/ステータス、および決済取引番号を提供します。グリッドに関する紛争の場合は、受け入れられた価格間隔と有効な時間枠を含めます。パスワード、API シークレット、フル アクセス トークンは決して含めないでください。

使用 [パートナーサポート](/ja/resources/contact/support) サポートパスと [転送と取引](/ja/prediction/transfers-ledger) 和解のために。
