結果の評価により、受け入れられた条件が満たされたかどうかが判断されます。決済には、最終的な財務上の処理が記録されます。スケジュールされた結果の評価時間または有効期限は、必ずしも関連するすべてのトランザクションが完了したときのタイムスタンプであるとは限りません。

<span id="ゲームごとの評価" data-sixmm-anchor-target="evaluation-by-game" aria-hidden="true"></span>
<h2 id="evaluation-by-game">ゲームごとの評価</h2>

| ゲーム | 評価 |
| --- | --- |
| 上下予測 | ラウンドの開始価格と決済価格を比較する |
| カスタム予測 | この注文の始値と満期の決済価格を比較します |
| 予測グリッド | 受け入れられたウィンドウ内で適格なタッチまたはクロスをチェックする |

指向性ゲームの同一価格と正確な価格/時間境界は、適用されるルールに従う必要があります。グリッドにヒットしただけでは、資金がすぐに利用可能になるわけではありません。決済処理を確認します。

<span id="和解の証拠" data-sixmm-anchor-target="settlement-evidence" aria-hidden="true"></span>
<h2 id="settlement-evidence">和解の証拠</h2>

注文番号、記録された条件、価格証拠、最終ステータス、実際の支払い、決済時間、取引番号を保持します。アップ/ダウンの場合、ラウンド記録には結果情報と賭け金/リターンの合計も含まれます。

<span id="結果を調整する" data-sixmm-anchor-target="reconcile-the-result" aria-hidden="true"></span>
<h2 id="reconcile-the-result">結果を調整する</h2>

1. レコードが予想される注文とアカウントに属していることを確認します。
2. 結果を正しい価格および時間条件と比較します。
3. 実際のペイアウトを、記録されたペイアウト乗数および適用される手数料/丸めルールと比較します。
4. 決済トランザクションを資金口座の動きと照合します。

<span id="遅延と例外" data-sixmm-anchor-target="delays-and-exceptions" aria-hidden="true"></span>
<h2 id="delays-and-exceptions">遅延と例外</h2>

結果が遅れても損失として扱うべきではありません。残高更新の前に結果が表示されても、重複したリクエストがトリガーされるべきではありません。注文と取引のステータスを確認し、矛盾が残る場合は証拠を添えてサポートに連絡してください。

見る [払い戻しと例外](/ja/prediction/refunds-exceptions) そして [支払いと損益](/ja/prediction/returns-pnl).
