> **計画中 – まだ開始されていません**
> AI Hub は計画中の機能です。このページの機能、エンドポイント、コマンド、およびクライアント構成は、提案された設計について説明したものであり、現在は利用できません。最終的な可用性とセットアップ手順は発売時に発表されます。


リモート MCP は、長期間実行される MCP エンドポイントを独自の制御下に置きたいユーザーまたは機関向けです。

ホスト型 MCP とは異なり、リモート MCP はユーザーの 6MM によって操作されません。 6MM はコード、画像、テンプレート、ドキュメントを提供します。ユーザーはホスティングと資格情報を制御します。

<h2 id="architecture">建築</h2>

```text
AI client
  -> user-managed MCP HTTP endpoint
  -> 6MM REST / WebSocket API
```

<h2 id="deployment-targets">導入対象</h2>

- Docker または Docker Compose。
- VPS リバース プロキシを使用します。
- 鉄道。
- 与える。
- フライアイオ。
- AWS ECS またはラムダ。
- 内部 Kubernetes。

<h2 id="required-files">必要なファイル</h2>

- ドッカーファイル。
- docker-compose.yml。
- .env.テンプレート。
- HTTP トランスポート モード。
- /mcp エンドポイント。
- /health エンドポイント。
- リバース プロキシと TLS のメモ。

<h2 id="credential-model">資格情報モデル</h2>

資格情報は、AI クライアント プロンプトではなく、ユーザー管理の環境に保存する必要があります。機関が管理する展開の場合は、承認されたクライアントとネットワークへのアクセスを制限します。

<h2 id="recommended-first-release">推奨される最初のリリース</h2>

まずは公開市場データから始めます。認証、キーのスコープ、ログ、およびアクセス制御が使用可能になった後に、読み取り専用のアカウントを追加します。管理された取引要件が満たされるまで、取引は無効のままにしておく必要があります。
