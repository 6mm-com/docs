## 前提条件の例

Java スニペットはこれらのインポートを共有します。クイック スタートを使用して `client` を初期化し、保存されたバインディングから `platformUserId` を取得します。ユーザー/オーダー ID の例は、独自の永続化された値に置き換える必要があります。

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

## `listCurrentPerpetualPositions`

リクエストモデル: `CurrentPerpetualPositionsRequest`。

```java
import com.sixmm.agent.model.CurrentPerpetualPositionsRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

CurrentPerpetualPositionsRequest request = new CurrentPerpetualPositionsRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
PerpetualResponse response = client.listCurrentPerpetualPositions(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### リクエストフィールド

| 分野 | Java タイプ | 必須 | 意味 |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | 条件付き | 1 ～ 100 個の一意のパブリック ID。約定および条件付き注文に必要です。ダイレクトプレイヤースコープでサポートされているクエリを省略します。 []は無効です。 |
| `symbol` | `String` | いいえ | オプションの取引ペアフィルター。 |
| `limit` | `Integer` | いいえ | デフォルトは 500。 1 ～ 1000。 |
| `cursor` | `String` | いいえ | 返された nextCursor をフィルターを変更せずに使用します。 hasMore が false の場合に停止します。 |

この例では 1 ページを読み取ります。必須フィールド、プレーヤーのスコープ、フィルター セマンティクス、制限、カーソル、制限された再試行については、次のとおりです。 [クエリの概要](/ja/sdk/agent-sdk/java/perpetual-queries)。ページング中はすべてのフィルターを変更しないでください。エラーを空の結果として解釈しないでください。

## `listPerpetualPositionHistory`

リクエストモデル: `PerpetualPositionHistoryRequest`。

```java
import com.sixmm.agent.model.PerpetualPositionHistoryRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualPositionHistoryRequest request = new PerpetualPositionHistoryRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualPositionHistory(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

## 役職: 現在および過去の役職

| `data` フィールド | タイプ | 現在位置 | 歴史的地位 | 意味 |
| --- | --- | --- | --- | --- |
| `positionId` | string | 供給 | 供給 | entityId に対応する位置 ID |
| `symbol` | string | 供給 | 供給 | 取引ペア |
| `positionSide` | string | 供給 | 供給 | LONG / SHORT / BOTH およびその他の位置方向 |
| `status` | string | 供給 | 供給 | 位置の数値ステータスを含む文字列。クエリの概要を参照してください。 |
| `leverage` | integer | 供給 | 供給 | 複数を活用する |
| `marginMode` | string | 供給 | 供給 | 数値列挙文字列 "1" は完全な位置、"2" は独立した位置の場合 |
| `quantity` | string | 供給 | 利用不可 | 現在位置数量 |
| `entryPrice` | string | 供給 | 供給 | 保存されたポジションの平均始値 |
| `margin` | string | 供給 | 利用不可 | ユーザーの契約ウォレット残高全体ではなく、現在のポジション証拠金の額 |
| `maxQuantity` | string | 利用不可 | 供給 | この履歴ポジションに記録されたポジションの最大数 |
| `closeQuantity` | string | 利用不可 | 供給 | 過去のポジションのライフサイクル中にクローズされたポジションの累積数 |
| `closePrice` | string | 利用不可 | 供給 | 保存された平均終値 |
| `pnl` | string | 利用不可 | 供給 | 過去のポジション損益。単に繰り返して蓄積するためにトランザクション realizedPnl と組み合わせないでください。 |
| `roe` | string | 利用不可 | 供給 | 過去のポジションリターンの比例値（100 倍ではない）。たとえば、`"0.043"` は `4.3%` を表し、`"-0.05"` は `-5%` を表します |
| `fundingFeeAccum` | string | 供給 | 供給 | 累積資金調達手数料、ソースシンボルと精度の保持 |
| `openedAt` | integer | 供給 | 供給 | ポジションオープン時間、ミリ秒 |
| `updatedAt` | integer | 供給 | 利用不可 | 現在位置更新時間、ミリ秒 |
| `closedAt` | integer | 利用不可 | 供給 | 終了時間、ミリ秒。このフィールドを使用して履歴位置時間をフィルタリングします |

履歴 `roe` の計算口径は `pnl / (entryPrice × maxQuantity / leverage)` であり、インターフェイスは保存された比率値を直接返します。パーセンテージを表示する場合は、10 進数演算を使用して 100 を掛け、`%` を加算します。分母には​​口座ウォレット残高ではなく、履歴ポジション記録の名目証拠金が使用されます。始値や最大ポジション数量が0、レバレッジが無効などで計算できない場合、ソースは0として保存されます。そのため、`roe=0`だけから損益が0であると推測することはできません。

現在のポジションには、リアルタイムのマーク価格、リアルタイムの変動損益、リアルタイム ROE、またはリアルタイムの清算価格がありません。これは保存されたポジションのステータスを反映しており、更新時間フィールドと証拠金フィールドを使用して現在のリアルタイムのリスク管理結果を主張することはできません。
