6MM Agent SDK は、署名と要求処理を最初から実装せずに特権エージェント APIs を呼び出す必要があるパートナー バックエンド サービス用です。統合ではパートナー API のシークレットが使用されるため、ブラウザー、モバイル、またはパブリック デスクトップ コードで実行しないでください。

## Agent SDK を使用する場合

バックエンドでパートナー ユーザーのバインド、承認されたワークフローによる資産の移動、取引記録のクエリ、埋め込み取引エントリ URL の作成、または webhook 通知の確認が必要な場合は、Agent SDK を使用します。を使用します。 [Trading Widget SDK](/ja/sdk/trading-widget/overview) パートナーのフロントエンドが取引インターフェイスを表示する必要がある場合は別途に。

## 共通構成

| 鍵 | 例 | 説明 |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM エージェント API サービス URL 末尾のスラッシュなし。 |
| agentCode | AGENT001 | パートナーエージェントコード。 |
| apiSecret | あなたの API シークレット | API 署名シークレットはバックエンドにのみ保存されます。 |
| defaultCurrency | USDT | 送金とアカウントのデフォルト通貨 APIs。 |
| webhookUrl | https://partner.example.com/6mm/webhook | 6MM webhook 通知のパートナー エンドポイント。 |

## 一般的な統合フロー

1. パートナー フロントエンドは、パートナー独自のアカウント システムを通じてユーザーを認証します。
2. パートナー バックエンドは、ユーザーを安定したパートナー側の識別子にマップします。
3. バックエンドは、`agentCode` と保護された API シークレットを使用して Agent SDK を呼び出します。
4. SDK はエージェント API リクエストに署名して送信します。
5. バックエンドは返されたビジネス識別子を保存し、後で webhooks 冪等に処理します。
6. フロントエンドは、必要な有効期間の短い結果またはエントリ資格情報のみを受け取ります。

## 製作チェックリスト

- ソース コードではなく、バックエンド シークレット マネージャーから `apiSecret` をロードします。
- 開発、ステージング、実稼働の認証情報を分離してください。
- 安定したパートナー ユーザー マッピングと一意の業務注文 ID を使用します。
- タイムアウトしたリクエストのステータスを確認するときに、元の識別子を保持します。
- webhook の署名を検証し、処理されたイベント ID を保存します。
- サポート用のリクエスト ID を保持しながら、ログからシークレットと署名を編集します。

## Java SDK v0.3.0 の機能

Java SDK には、ファンディング ウォレット、明示的な資金環境、6 つの永久データ クエリ、および法定基準レートが含まれるようになりました。 PHP の機能は、パートナーが提供するパッケージと比較してチェックする必要があります。 Java の追加は、PHP メソッドの一致を意味しません。
