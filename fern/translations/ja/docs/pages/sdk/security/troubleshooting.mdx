まず、失敗した操作の環境、タイムスタンプ、ビジネス識別子から始めます。構造化チェックでは通常、構成の問題を認証、ネットワーク、および非同期処理の問題から分離します。

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## 推奨される診断順序

1. 影響を受ける環境とベース URL を確認してください。
2. UTC の時間範囲と最初に失敗したリクエストを記録します。
3. モジュールを特定します: Trading Widget、Agent SDK、REST API、WebSocket、または webhook。
4. リクエスト ID、パートナー ユーザー ID、`agentOrderNo`、オーダー ID、または webhook イベント ID を取得します。
5. 最近のコード、認証情報、IP ホワイトリスト、または展開の変更を確認してください。
6. 最小の安全なテスト ケースで再現します。

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget の問題

| 症状 | 考えられる原因 | 修理 |
| --- | --- | --- |
| iframe はパートナーのローカル ドメインをリクエストします | baseUrl が見つかりません | baseUrl: 'https://app.6mm.com' を渡します。 |
| iframe が表示されないか、非常に短いです | 親コンテナには高さがありません | コンテナの高さまたはパスの高さを設定します。 |
| token_provider_missing | パートナートークンモードにはプロバイダーがありません | auth.tokenProviderを追加します。 |
| auth_exchange_failed | 無効、期限切れ、または不一致の埋め込みトークン | バックエンド トークンの応答と channelId を確認してください。 |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK の問題

| 症状 | 考えられる原因 | 修理 |
| --- | --- | --- |
| 署名が拒否されました | 間違ったシークレット、クロックのずれ、または手動で変更された署名付きフィールド | SDK で署名フィールドを生成し、サーバー時刻を同期させます。 |
| 資金移動の重複リスク | タイムアウト後に使用される新しい注文番号 | 最初に元の agentOrderNo でクエリを実行します。 |
| PROCESSING は失敗として扱われます | 保留状態の誤解 | webhook を待つか、queryOrder に電話してください。 |
| Webhook が複数回処理されました | 冪等性を持たない再試行動作 | 冪等性キーと最終状態チェックを追加します。 |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## 捕らえるべき証拠

| 統合 | 有用な証拠 |
| --- | --- |
| Trading Widget | ページ URL、SDK バージョン パス、ブラウザ コンソール、失敗したネットワーク リクエスト、`onError` ペイロード、およびコンテナーのディメンション。 |
| Agent SDK | SDK 言語/バージョン、ベース URL、UTC タイムスタンプ、リクエスト ID、`agentOrderNo`、応答コード、およびサニタイズされたログ。 |
| Webhook | 配信時間、イベントまたはビジネスキー、署名検証結果、処理状態、およびサニタイズされた生の本体ハッシュ。 |
| REST API | メソッド、パス、環境、リクエストID、レスポンスコード、サニタイズされたパラメータ。 |

診断には、パスワード、アクセス トークン、API シークレット、完全な署名、秘密キー、または編集されていない個人データを決して含めないでください。

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## エスカレートする前に

- 操作を再試行しても安全であることが文書化されている場合にのみ再試行してください。
- タイムアウト後は、新しいビジネス ID を作成するのではなく、元のビジネス ID をクエリします。
- システム クロックと認証情報環境に署名エラーがないか確認します。
- 最初の失敗とその後の再試行結果を保存します。
- を使用します。 [サポートリクエストのテンプレート](/ja/resources/support-request-template) 編集された完全なレポートを送信します。

## Java v0.3.0 診断

| 症状 | 確認と回復 |
| --- | --- |
| 資金調達リクエストの結果は不明です | 元の `agentOrderNo` を保持します。元の環境で `queryWalletTransfer` を呼び出します。 `queryOrder` は使用しないでください。 |
| シミュレーション UI に予期しない資金が表示される | フロントエンド `tradingMode` をバックエンド `environment` とは別にチェックします。アカウント `isSimulatedUser` はリクエストをルーティングしません。 |
| クエリエラー `6905` | 共有パートナー クォータの使用を中止し、同じカーソルを再試行し、SDK でフィルターします。 |
| クエリエラー `6904` | 同時クエリを減らし、時間枠を狭めます。解決しない場合はサポートにお問い合わせください。 |
| カーソルが無効または期限切れです | 同じ固定履歴ウィンドウを再起動し、保存されたレコードを重複排除します。 |
| 新しい Java メソッドがありません | 解決された Maven アーティファクトをパブリック タグ `v0.3.0` に対して確認します。アーティファクト ポリシーに従って、競合する依存関係を削除します。 |
