Agent SDK リクエストはパートナー API シークレットで認証されます。その秘密を信頼できるバックエンド サービス内に保管し、可能な限り SDK に署名フィールドを生成させます。

> **2 つの署名プロトコル**
>
> Agent SDK 署名では、並べ替えられたリクエスト フィールド、秒ベースのタイムスタンプ、およびナンスが使用されます。直接の Developer API リクエストは、で説明されている別のプロセスを使用します。 [署名のリクエスト](/ja/developer-api/request-signing)。あるペイロード形式を他のペイロード形式に再利用しないでください。

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## 署名ルール

Agent SDK リクエストの場合:

1. `sign` フィールドを除外します。
2. 値が空のフィールドを省略します。
3. 残りのフィールド名を ASCII の順に並べ替えます。
4. フィールドを `k=v&k2=v2` として結合します。
5. HMAC-SHA256 の 16 進署名を `apiSecret` で計算します。

配列値は、署名ペイロードに結合する前に、コンパクト JSON としてシリアル化されます。たとえば、`platformUserIds` は `["1188041528"]` として署名し、`k=v` ペイロードに `platformUserIds=["1188041528"]` を与えます。配列要素の順序、二重引用符、文字列 ID を保持します。書式設定スペースを挿入したり、Java `List.toString()` (`[1188041528]` など) を使用したりしないでください。 SDK はこのシリアル化を自動的に処理します。

SDK は、送信するのと同じデータからこの値を構築する必要があります。署名生成後に署名付きフィールドを変更すると、検証が失敗します。

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## SDK 管理フィールド

| 分野 | ソース | 説明 |
| --- | --- | --- |
| agentCode | SDK 構成 | パートナーエージェントコード。 |
| タイムスタンプ | 現在のサーバー時間 | 秒単位の Unix タイムスタンプ。 |
| ノンス | 安全なランダム値 | リプレイ保護のランダムな文字列。 |
| サイン | HMAC-SHA256 | 署名を要求します。 |
| 通貨 | デフォルトの通貨 | 送金/アカウント APIs が通貨を省略する場合に使用されます。 |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## 秘密の保管場所

- バックエンド シークレット マネージャーまたは保護されたランタイム構成から `apiSecret` を読み込みます。
- シークレットをフロントエンド バンドル、モバイル アプリ、デスクトップ クライアント、スクリーンショット、またはサポート チケットに決して置かないでください。
- 開発、ステージング、本番の認証情報を分けて保管してください。
- アクセスを必要とするサービスとオペレーターへのアクセスを制限します。
- ログからリクエストの署名、認証値、およびシークレットを編集します。
- 漏洩が疑われる場合は、認証情報を取り消して置き換えます。

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## クロックとリプレイの保護

SDK には、リプレイのリスクを軽減するために `timestamp` と `nonce` が含まれています。バックエンドクロックの同期を維持し、手動で構築したノンスを再利用しないでください。署名の検証が失敗した場合は、再試行する前に、構成されたシークレット、サーバー時間、シリアル化されたフィールド、および環境を確認してください。

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## 統合チェックリスト

| チェック | 期待される結果 |
| --- | --- |
| 秘密の場所 | バックエンド専用のシークレット ストレージ。 |
| 環境 | ベース URL と資格情報は同じ環境に属します。 |
| フィールドハンドリング | SDK は `timestamp`、`nonce`、および `sign` を生成します。 |
| ロギング | 認証情報が編集されていても、ビジネス ID は表示されたままになります。 |
| 回転 | 資格情報の所有者と置換プロセスが文書化されます。 |
