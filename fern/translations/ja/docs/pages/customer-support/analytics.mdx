会話、チケット、ナレッジアクティビティを、チームが行動できる質問に変えます。定義されたレポート期間から始めて、数値の変化の背後にある記録を調査します。

<div className="sixmm-support-flow">

1. **期間を設定します** — 日付とフィルターの一貫性を保ちます。
2. **指標を比較** — ボリューム、ハンドリング、フィードバックをまとめて確認します。
3. **記録を検査する** — 例を見つけて、具体的な改善点を選択します。

</div>


<span id="understand-support-activity" data-sixmm-canonical-anchor="understand-support-activity" aria-hidden="true"></span>

## サポート活動を理解する

**統計** を開き、関連する時間範囲と使用可能なフィルターを選択します。リアルタイムの概要、会話、チケット、満足度、メッセージ、エージェント、フィードバック、知識統計を確認します。

複数のメトリクスを組み合わせて使用​​します。会話の量は需要を示し、チケットのステータスはフォローアップ作業を示し、評価は個人のエクスペリエンスに関するフィードバックを提供します。ナレッジの閲覧数が多いだけでは、問題が解決されたことを証明するものではありません。

<span id="compare-like-for-like-data" data-sixmm-canonical-anchor="compare-like-for-like-data" aria-hidden="true"></span>

## 類似データを比較する

結果を比較するときは、同じ時間範囲、タイムゾーン、フィルター、モジュール スコープを維持してください。すべての数値が一意の人物をカウントしていると仮定するのではなく、フィールドのラベルを確認してください。値が別の画面と異なる場合は、最初にその定義とフィルタリングを比較してください。

MCP は統計をクエリし、傾向を要約するのに役立ちます。読み取り専用統計ツールを使用して統計レコードを変更することはできません。コンソールで結果を確認できるように、クエリされた期間とソース メトリクスを概要に含めるように依頼します。

## 質問のビューを選択してください

| 質問 | 便利なビュー |
| --- | --- |
| サポート需要に何が変化したのでしょうか? | メッセージ、人間の会話、ボットの活動、および国の分布。 |
| フォローアップ作業は蓄積されていますか? | チケットとフィードバック、同じレポート期間。 |
| 訪問者はサービスをどのように評価しますか? | 満足した後、基礎となる会話を見直します。 |
| 注意が必要なヘルプ コンテンツはどれですか? | FAQ と知識統計を、実際のセッションで繰り返された質問と比較しました。 |

<span id="example-prepare-a-weekly-review" data-sixmm-canonical-anchor="example-prepare-a-weekly-review" aria-hidden="true"></span>

### 例: 週次レビューを準備する

1. 合意された週を選択し、日付範囲とアクティブなフィルターをレビューに記録します。
2. 需要、未完了の作業、訪問者のフィードバックを個別にまとめます。異なるメトリクスを一緒に追加しないでください。
3. 関連する会話やチケットの小さなセットを開いて、変更の背後にある理由を理解します。
4. 具体的なアクションを選択してください。不明瞭な記事を修正する、クイック返信を更新する、チームの対応を確認するなどです。同じ定義を使用して次の期間を比較します。

MCP-接続された AI に、選択した統計を要約して、調査すべき質問を特定するよう依頼できます。期間に名前を付け、観察された数字と提案された説明を区別するよう要求します。

## よくある質問

<AccordionGroup>

<Accordion title="人気のある記事とは、ほとんどの疑問が解決されることを意味しますか?">
ビューとインタラクションはアクティビティを説明するものであり、解決が保証されるものではありません。結論を下す前に、訪問者の質問と結果を読んでください。
</Accordion>

<Accordion title="2 つのレポートで異なる合計が表示されるのはなぜですか?">
まず、時間ベース、フィルター、メトリック定義を比較します。セッション数、メッセージ、ユニーク訪問者数はさまざまな量です。
</Accordion>

</AccordionGroup>
