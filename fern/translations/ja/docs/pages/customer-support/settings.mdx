訪問者がサポートに入る方法、表示される内容、利用可能なインテリジェント サービスを設定します。設定の変更を小規模なリリースとして扱います。保存し、実際のエントリをテストして、結果を確認します。

<div className="sixmm-support-flow">

1. **設定を選択します** — 変更する動作のタブを見つけます。
2. **変更を保存** — 影響を受けるエントリまたはサービスを確認します。
3. **訪問者としてテスト** — 実際の Web サイトを開いて結果を確認します。

</div>


<span id="configure-the-visitor-experience" data-sixmm-canonical-anchor="configure-the-visitor-experience" aria-hidden="true"></span>

## 訪問者のエクスペリエンスを構成する

**システム設定**を開きます。使用可能なコントロールは、役割と有効なテナント サービスによって異なります。

| タブ | 何を設定するか |
| --- | --- |
| 外観と統合 | 利用可能なビジュアル設定と入力設定 |
| ホームページとコピー | 顧客向けホームページのテキストとガイダンス |
| 会話とタイムアウト | 会話の動作とタイムアウトの制御 |
| 訪問者ダイアログ | 訪問者の入場時に収集される情報とプロンプト |
| インテリジェントなサービス | AI、検索、翻訳機能をテナント向けに公開 |
| ウェブサイトの統合 | ドメイン許可リスト、埋め込みコード、署名付き ID、言語/テーマの統合 |
| MCP 接続 | サービスアドレス、許可された申請および失効 |

設定を保存し、訪問者のエントリから確認します。プレビューまたは保存の成功は、個別に埋め込まれた Web サイトがすでに最新の設定を使用していることを証明するものではありません。

<span id="keep-boundaries-clear" data-sixmm-canonical-anchor="keep-boundaries-clear" aria-hidden="true"></span>

## 境界線を明確に保つ

テナント設定では、テナントのカスタマー サポートを構成します。プラットフォーム全体のプロバイダー キー、他のテナント、リチャージ操作、取引口座へのアクセスは許可されません。 MCP は、現在のロールで許可されているサポートされている構成フィールドのみを公開します。 MCP によるドメイン許可リストの変更には確認が必要です。


<span id="plan-the-initial-setup" data-sixmm-canonical-anchor="plan-the-initial-setup" aria-hidden="true"></span>

## 初期セットアップを計画する

1. **外観とコピー:** 目に見えるブランド、ホームページのガイダンス、およびサポートの文言を確認してください。説明は実際に提供する交換サービスと一致するようにしてください。
2. **訪問者のエントリ:** 収集する情報を決定し、利用可能なプロンプト動作を確認します。必要に応じて、新規訪問と再訪問の両方をテストします。
3. **受信動作:** ライブ会話を処理するチームとセッションとタイムアウトの制御を確認します。
4. **インテリジェント サービス:** 有効なテナント機能を確認し、代表的な質問または翻訳をテストします。構成されたスイッチだけでは、アップストリーム要求が成功したことを証明することはできません。
5. **Web サイトの統合:** 許可されている Web サイトのドメインを確認し、埋め込みコード、ログイン ID、言語、テーマに関する統合ガイドを使用します。
6. **MCP:** 認証アカウントと利用可能な権限を確認した後にのみ、外部 AI に接続してください。

<span id="example-a-saved-change-is-not-visible-on-your-website" data-sixmm-canonical-anchor="example-a-saved-change-is-not-visible-on-your-website" aria-hidden="true"></span>

### 例: 保存された変更が Web サイトに表示されない

まず、テスト対象のテナントと訪問者のエントリを確認します。そのエントリをリロードし、埋め込み Web サイトが独自の言語またはテーマを渡すかどうかを確認し、意図した構成が保存されたことを確認します。アクセスが失敗した場合は、無関係な設定を繰り返し変更する前に、許可されたドメインと統合構成を確認してください。

## よくある質問

<AccordionGroup>

<Accordion title="設定タブが表示されないのはなぜですか?">
アカウントの権限と有効なテナント サービスによって、何が利用できるかが決まります。別のテナントやアカウントを変更するのではなく、テナント管理者に関連するアクセスを確認するよう依頼してください。
</Accordion>

<Accordion title="モデルの認証情報と補充はどこで管理されますか?">
プロバイダーの資格情報とプラットフォームのバランス調整はテナント設定の外にあります。プラットフォーム運営者と合意したサービス協定を利用してください。
</Accordion>

</AccordionGroup>
