操作ログを使用して、誰がいつ何を変更したかを回答します。ログの説明を個別に読むのではなく、アクション、ターゲット、ソースをビジネス レコードと組み合わせます。

<div className="sixmm-support-flow">

1. **イベントを検索** — 時間、キーワード、カテゴリでフィルターします。
2. **詳細をお読みください** — アクター、ターゲット、ソース、結果を確認します。
3. **結果を確認します** — 再試行する前に、影響を受けるレコードを開いてください。

</div>


<span id="trace-an-operation" data-sixmm-canonical-anchor="trace-an-operation" aria-hidden="true"></span>

## 操作をトレースする

**操作ログ**を開きます。利用可能なコントロールを使用して、キーワード、カテゴリ、アクション、アクター タイプ、ターゲット タイプ、および日付でフィルタリングします。詳細を読んで、誰が操作したのか、どのレコードが変更されたのか、そしてその結果を特定します。

MCP オペレーションは、アプリケーション/ソースおよび実行ステータスとともに表示されます。操作によっては、ビジネス変更とその MCP 実行記録の両方が表示される場合があります。 2 つの監査エントリ自体は、アクションが 2 回実行されたことを意味するものではありません。

<span id="distinguish-authorization-from-execution" data-sixmm-canonical-anchor="distinguish-authorization-from-execution" aria-hidden="true"></span>

## 承認と実行を区別する

アプリケーション接続は承認を証明するだけです。提案された書き込み、承認待ち、完了した書き込みは異なる状態です。ログは、外部 AI に対して行われたすべての内容を完全に記録したものではないため、読み取り専用のクエリによってビジネス書き込みレコードが作成されると想定すべきではありません。

失敗した MCP 呼び出しを調査する場合は、その操作 ID、時刻、エラー メッセージを保持します。再試行する前に操作結果を問い合わせてください。操作ログは、MCP を通じて読み取り専用です。


<span id="read-one-log-entry" data-sixmm-canonical-anchor="read-one-log-entry" aria-hidden="true"></span>

## 1 つのログ エントリを読み取る

| 詳細 | なぜそれが重要なのか |
| --- | --- |
| 時間 | 調査しているイベントのシーケンスにアクションを配置します。 |
| カテゴリとアクション | コンテンツの更新、セッション アクション、またはその他のサポートされている操作を区別します。 |
| 俳優 | アカウントまたはシステムアクションを識別します。会話の相手は必ずしも訪問者であるとは限りません。 |
| ソース | MCP アプリケーションのアクティビティを他の操作から区別するのに役立ちます。 |
| ターゲット | レコードによって参照されるビジネス オブジェクトまたは MCP オペレーションを識別します。 |
| 詳細と結果 | 利用可能な説明と実行状態を提供します。再試行するかどうかを決定する前に、エラーを読んでください。 |

<span id="example-an-mcp-article-change-did-not-appear" data-sixmm-canonical-anchor="example-an-mcp-article-change-did-not-appear" aria-hidden="true"></span>

### 例: MCP 記事の変更は表示されませんでした

1. 日付範囲を絞り込んで、アプリケーションまたは関連する操作を探します。
2. 操作が確認待ちであるか、失敗したか、完了したかを確認します。承認だけでは変更が実行されたことを意味しません。
3. 対象の記事を開いて現在の内容を比較してください。バージョンの競合が報告された場合は、古いコンテンツを再利用するのではなく、最新バージョンを読んで新しいリクエストを準備してください。
4. さらに調査が必要な場合は、操作 ID とエラーの詳細を保存してください。関連するビジネス監査レコードと MCP 実行レコードは、同じ変更を記述することができます。

有用なハンドオフには、時間、ターゲット識別子、操作 ID (存在する場合)、および観察された結果が含まれます。アカウントのパスワードや API のシークレットを含めないでください。

## よくある質問

<AccordionGroup>

<Accordion title="AI の会話の記録が存在しないのはなぜですか?">
操作ログは外部AIアプリケーションでのチャットの記録ではありません。読み取り専用ツールの呼び出しでは、必ずしもビジネス変更ログが作成されるわけではありません。
</Accordion>

<Accordion title="失敗したと思われる操作をすぐにやり直す必要がありますか?">
まずは操作結果と対象レコードを確認してください。クライアントが応答を失った場合、サーバーはすでに要求を処理している可能性があります。
</Accordion>

</AccordionGroup>
