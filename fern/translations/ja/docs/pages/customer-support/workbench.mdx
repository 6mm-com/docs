最初のレビューからハンドオフまで、着信した会話を処理します。このワークスペースを使用して、質問を理解し、人間によるサポートを調整し、会話を文脈に沿った状態に保ちます。

<div className="sixmm-support-flow">

1. **会話を読む** — 質問と最近のメッセージを確認します。
2. **ハンドラーを選択してください** — 参加または転送する前に所有権を確認してください。
3. **返信とフォローアップ** — 返信するか、フィードバックを招待するか、チケットで続行します。

</div>


<span id="work-from-one-conversation-workspace" data-sixmm-canonical-anchor="work-from-one-conversation-workspace" aria-hidden="true"></span>

## 1 つの会話ワークスペースから作業する

**オンライン会話**を開きます。人間、監視、ボットのタブでは、アカウントに表示される会話が整理されます。モニタリング アクセスと会話の所有権は引き続き適用されます。エージェントはテナントのすべての会話を自動的に確認するわけではありません。

1. 会話を選択し、その最近のメッセージと利用可能な訪問者情報を読みます。
2. ロールで許可されているアクションを使用して、参加、引き継ぎ、割り当て、または転送します。
3. テキスト、サポートされている添付ファイル、またはクイック返信で返信します。必要に応じて言語認識と翻訳を使用します。
4. 訪問者のアップロード許可を管理し、可能な場合は評価を招待します。
5. 会話を終了するか、さらなる作業が必要な場合はチケットを作成/フォローアップします。

<span id="understand-visitor-information" data-sixmm-canonical-anchor="understand-visitor-information" aria-hidden="true"></span>

## 訪問者情報の把握

読み取り可能な訪問者名は表示ラベルであり、検証済みの Exchange アカウントの証拠ではありません。サインインしているユーザー ID、エントリー用電子メール、サポート中に提供された連絡先用電子メールを区別します。利用可能なセッションの詳細を使用してケースを理解します。同じ電子メールを持つ 2 人の訪問者が同じ認証されたユーザーであると想定しないでください。

送信する前に現在の会話を確認してください。 AI- 外部 MCP クライアントから生成されたテキストは、単に AI チャットに表示されるという理由だけで送信されるわけではありません。 MCP 経由で送信するには、プラットフォームの確認フローが必要です。

<span id="when-human-support-is-unavailable" data-sixmm-canonical-anchor="when-human-support-is-unavailable" aria-hidden="true"></span>

## 人間によるサポートが受けられない場合

訪問者のエントリは、設定された可用性とフォールバック動作に従います。チケットには、後で処理できるように質問を保存できます。表示される指示は、実際の人員配置および対応ポリシーと一致するようにしてください。サポートされていない応答時間を約束することは避けてください。

## どのワークスペースを使用するかを知る

| ワークスペース | ここで何をすべきか |
| --- | --- |
| 人間 | 利用可能な会話を確認し、割り当てられた作業を処理します。返信する前に現在のエージェントを確認してください。 |
| 監視 | 監視権限内の会話を確認します。セッションの表示と引き継ぎは別のアクションです。 |
| ボット | 人間による対応が必要かどうかを判断する前に、質問とボットの応答を調べてください。 |

<span id="example-a-user-asks-about-exchange-integration" data-sixmm-canonical-anchor="example-a-user-asks-about-exchange-integration" aria-hidden="true"></span>

### 例: ユーザーが Exchange の統合について質問しました。

1. 会話を読んで、ドキュメントのリクエストとアカウント固有の問題を区別してください。
2. 検討済みの知識に関する回答または適切なクイック返信を使用します。送信する前に、プラットフォーム名、リンク、金額を確認してください。
3. 別の言語の場合は、利用可能な認識および翻訳コントロールを使用し、返信する前に意味を確認してください。
4. 同僚が続行する必要がある場合は、あなたの権限の範囲内で転送または割り当ててください。問題を後で調査する必要がある場合は、適切なチケット ワークフローを続行します。

**閉じる前に:** ユーザーが応答を受け取ったことを確認し、未完了の質問があれば特定し、フォローアップのために関連する会話番号を保管してください。

## よくある質問

<AccordionGroup>

<Accordion title="会話は表示されるのに返信できないのはなぜですか?">
現在の所有者、アカウントの権限、最初に参加する必要があるか引き継ぐ必要があるかを確認してください。モニタリングでは、自動的に処理権限が付与されるわけではありません。
</Accordion>

<Accordion title="AI-ラベル付きの返信は常に大規模なモデルから送信されるのでしょうか?">
いいえ。保存された返信や以前のマッチング段階も AI メッセージとして表示される場合があります。応答パスを診断する必要がある場合は、ボット フロー テストを使用します。
</Accordion>

</AccordionGroup>
