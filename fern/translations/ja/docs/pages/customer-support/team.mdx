## サポートチームを組織する

**エージェント管理** を使用して、エージェントのアカウント、役割、クイック返信を管理します。各人が実際に必要とするモジュールとアクションに基づいて役割を割り当てます。 1 つの管理者ログインをチーム全体で共有するのではなく、アカウントの資格情報を個人用に保ちます。

ロールを変更した後、影響を受けるアカウントでロールを確認してください。表示されるメニュー、会話モニタリング、コンテンツ編集、および設定へのアクセスは異なる場合があります。アカウントの状態、セッションの所有権、およびフィールドレベルのチェックは、メニューの存在を超えて引き続き適用されます。

<span id="mcp-inherits-the-same-identity" data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP は同じアイデンティティを継承します

MCP 接続は、認証テナントとエージェント アカウントにバインドされます。 AI には個別の管理者の役割は与えられません。サービスは通話時のアカウント権限を再評価します。使用できないツールは、その名前を推測したり、別のテナント ID を指定したりして有効にすることはできません。

**システム設定 → MCP 接続**で接続アプリケーションを管理します。不要になった接続を取り消します。ブラウザからログアウトしても、外部 AI アプリケーションの承認は取り消されません。

MCP による役割とエージェント アカウントの変更には確認が必要です。 MCP を通じてエージェントを作成する場合、初期パスワードは AI に返されるのではなく、ユーザーによってバックエンド確認ページに入力されます。
