各エージェントに個別のアカウントを与え、役割を選択し、レビュー済みのクイック返信を準備します。各人が実行する作業に基づいてアクセスを整理し、そのアカウントでそれを確認します。

<div className="sixmm-support-flow">

1. **アカウントの作成** — エージェントとアカウントの状態を特定します。
2. **ロールの割り当て** — ジョブに必要なモジュールとアクションを付与します。
3. **ワークフローを確認する** — アクセスをテストし、クイック返信を準備します。

</div>


<span id="organize-the-support-team" data-sixmm-canonical-anchor="organize-the-support-team" aria-hidden="true"></span>

## サポートチームを組織する

**エージェント管理** を使用して、エージェントのアカウント、役割、クイック返信を管理します。各人が実際に必要とするモジュールとアクションに基づいて役割を割り当てます。 1 つの管理者ログインをチーム全体で共有するのではなく、アカウントの資格情報を個人用に保ちます。

ロールを変更した後、影響を受けるアカウントでロールを確認してください。表示されるメニュー、会話モニタリング、コンテンツ編集、および設定へのアクセスは異なる場合があります。アカウントの状態、セッションの所有権、およびフィールドレベルのチェックは、メニューの存在を超えて引き続き適用されます。

<span id="mcp-inherits-the-same-identity" data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP は同じアイデンティティを継承します

MCP 接続は、認証テナントとエージェント アカウントにバインドされます。 AI には個別の管理者の役割は与えられません。サービスは通話時のアカウント権限を再評価します。使用できないツールは、その名前を推測したり、別のテナント ID を指定したりして有効にすることはできません。

**システム設定 → MCP 接続**で接続アプリケーションを管理します。不要になった接続を取り消します。ブラウザからログアウトしても、外部 AI アプリケーションの承認は取り消されません。

MCP による役割とエージェント アカウントの変更には確認が必要です。 MCP を通じてエージェントを作成する場合、初期パスワードは AI に返されるのではなく、ユーザーによってバックエンド確認ページに入力されます。


<span id="understand-the-three-management-areas" data-sixmm-canonical-anchor="understand-the-three-management-areas" aria-hidden="true"></span>

## 3 つの管理領域を理解する

| エリア | 何を維持するか |
| --- | --- |
| エージェントアカウント | 名前、ログイン電子メール、役割、有効な状態、およびページによって公開される受信コントロール。 |
| 役割管理 | エージェントのグループに対して許可されるモジュールとアクション。変更を保存する前に、既存のメンバーへの影響を確認してください。 |
| クイック返信 | 再利用可能な応答のタイトル、内容、順序、有効な状態。機能が利用可能な翻訳を確認します。 |

<span id="prepare-an-agent-for-their-first-shift" data-sixmm-canonical-anchor="prepare-an-agent-for-their-first-shift" aria-hidden="true"></span>

### エージェントの最初のシフトを準備する

1. ログイン電子メールと目的の役割を確認します。アカウントの可用性、ログイン状態、動作ステータスを同じものとして扱わないでください。
2. 監視アクセス、受信優先順位、設定されている最大同時セッションを確認します。これらのコントロールは役割の権限を補完します。
3. エージェントにサインインして、メニューと作業に必要な処理アクションを確認するように依頼します。
4. よくある質問に対する簡単な回答を準備し、そこに最新のリンクが含まれていて、訪問者固有の情報が含まれていないことを確認します。

**引継ぎルーチン:** エージェントのアクセス権を変更する前に、未解決の責任を確認します。ロールまたはアカウントを変更した後は、ロール名だけに依存するのではなく、有効な権限を確認してください。

## よくある質問

<AccordionGroup>

<Accordion title="管理者権限のあるAIは通常のエージェントとして動作するのでしょうか？">
いいえ。MCP 接続は、それを承認したアカウントを使用します。目的の作業に適切なアクセス権を持つアカウントに接続します。
</Accordion>

<Accordion title="サインアウトすると外部 AI は切断されますか?">
コンソールからのサインアウトは、MCP 接続の取り消しとは別のものです。アプリケーションを取り消すには、システム設定 → MCP 接続を使用します。
</Accordion>

</AccordionGroup>
