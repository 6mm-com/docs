チケットを使用して、1 回の会話では完了できない作業をフォローします。次のエージェントが続行できるように、記録の種類、責任者、現在の進行状況を明確にしておきます。

<div className="sixmm-support-flow">

1. **レコードの特定** — エージェント チケット、ユーザー チケット、またはフィードバックを選択します。
2. **調査と割り当て** — 説明を読み、誰がそれを処理するかを確認します。
3. **結果を更新します** — 進行状況を記録し、保存されたステータスを確認します。

</div>


<span id="choose-the-correct-record" data-sixmm-canonical-anchor="choose-the-correct-record" aria-hidden="true"></span>

## 正しいレコードを選択してください

**チケット管理** を開き、適切なタブを選択します。

| 記録 | 目的 |
| --- | --- |
| エージェントチケット | サポートチームによって作成および維持される作品 |
| ユーザーチケット | フォローアップのために訪問者によって送信された質問 |
| ユーザーからのフィードバック | フィードバック エントリを通じて送信された提案または問題 |

<span id="handle-a-case" data-sixmm-canonical-anchor="handle-a-case" aria-hidden="true"></span>

## 事件を処理する

記録にある説明、連絡先の詳細、関連する会話、添付ファイルを読んでください。これを適切なハンドラーに割り当て、作業の進行に応じてステータスを更新します。エージェント チケットに対してサポートされている編集コントロールを使用します。ユーザーチケットとフィードバックには、独自の利用可能なアクションがあります。

ステータスを更新しても、それ自体では訪問者が電子メールまたはチャットの返信を受け取ったことが証明されるわけではありません。必要に応じて、利用可能な通信チャネルを通じて応答を送信し、結果を確認します。個人情報は、承認されたテナントのワークフロー内に保管してください。

<span id="use-mcp-for-triage" data-sixmm-canonical-anchor="use-mcp-for-triage" aria-hidden="true"></span>

## トリアージには MCP を使用してください

接続された AI に、未解決のケースをリストし、問題ごとにグループ化し、提案される対応を準備するように依頼します。実際のケースに適用する前に、割り当てとステータスの変更を確認してください。エージェントによるチケットの作成とユーザーによるチケットの送信は、異なるワークフローです。一方のツールが他方をサポートすることを意味するものではありません。 MCP を通じてチケットを削除するには確認が必要です。


<span id="use-status-and-priority-deliberately" data-sixmm-canonical-anchor="use-status-and-priority-deliberately" aria-hidden="true"></span>

## ステータスと優先度を意図的に使用する

エージェント チケットは、保留中、処理中、解決済み、およびクローズされた状態をサポートします。ユーザーチケットとフィードバックは独自のステータスコントロールを公開します。すべてのタブにまったく同じアクションがあるとは想定しないでください。

| 詳細 | どのように役立つか |
| --- | --- |
| チケット番号 | 別のエージェントに作業を引き渡すときに、正確な記録を見つけます。 |
| 説明と関連セッション | 何が起こったのか、何がすでに議論されたのかを理解します。 |
| 譲受人または担当者 | 次のアクションの責任者を特定します。 |
| 代理店チケット優先 | 緊急性をワークフローのステータスから切り離します。優先度の高いチケットは自動的には解決されません。 |
| 作成時間と解決時間 | 選択した日付基準を使用してタイムラインを確認します。 |

<span id="example-an-issue-needs-technical-investigation" data-sixmm-canonical-anchor="example-an-issue-needs-technical-investigation" aria-hidden="true"></span>

### 例: 問題には技術的な調査が必要です

1. 元のレコードを開き、提供された情報から時間、影響を受けたページ、再現可能な手順を収集します。
2. 可能な場合は、リンクされた会話を確認してください。訪問者にすでに記録された情報を繰り返すよう求めることは避けてください。
3. 適切なハンドラーを割り当て、作業の進行に応じてステータスを更新します。内部メモを事実のままにしておきます。
4. 問題が確認されたら、結果を更新し、利用可能なチャネルを通じて訪問者に連絡します。ページを離れる前に、保存された記録を確認してください。

## よくある質問

<AccordionGroup>

<Accordion title="チケットを解決すると、訪問者に自動的に通知されますか?">
ステータスの変更だけでは、電子メールまたはチャット メッセージが送信されたことを証明するものではありません。通信経路と配信結果は別途ご確認ください。
</Accordion>

<Accordion title="チケットが見つからないのはなぜですか?">
レコード タブ、日付基準、日付範囲、ステータス、担当者フィルターを確認します。再度検索する前に、不要なフィルターをクリアしてください。
</Accordion>

</AccordionGroup>
