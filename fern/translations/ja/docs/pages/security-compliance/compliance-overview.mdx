6MM 認可パートナーに対して技術インフラとコンプライアンス志向のサポートを提供します。コンプライアンス要件は管轄区域やビジネスモデルによって異なるため、各ローンチはパートナー自身の義務と照らし合わせて検討されるべきです。

<h2 id="what-this-section-covers">このセクションで扱う内容</h2>

| 面積 | 概要 |
| --- | --- |
| ライセンスサポート | サポートされる免許パスや必要な準備資料に関するガイダンス。 |
| パートナーの義務 | ユーザーオンボーディング、開示、ローカルコンプライアンス管理、顧客関係管理。 |
| 技術的な制御 | 署名、ログ記録、アクセス制御、ウェブフック検証、本番監視。 |
| 打ち上げレビュー | 取引機能をユーザーに公開する前にチェックリストベースの確認を行います。 |

<h2 id="important-boundary">重要な境界線</h2>

6MM 文書は、パートナーが技術的および運用上の管理を準備するのに役立ちます。法的助言、管轄区域ごとのコンプライアンス審査、またはパートナー自身の規制義務に代わるものではありません。

<h2 id="information-to-prepare">準備する情報</h2>

コンプライアンスやローンチレビューの前に、以下の書類を作成しましょう:

- 対象国や地域、アクセス権を得るユーザータイプ。
- 組み込み取引、ホワイトラベルデリバリー、流動性、ウォレット、カストディ、またはブローカレッジ機能を含む製品の範囲。
- ユーザーのオンボーディング、身元確認、開示、保管、サポート、インシデントコミュニケーションを担当する組織。
- パートナーのフロントエンド、バックエンド、 6MM API、 SDK、ウェブフック、運用システム間のデータフロー。
- 認証情報保存、アクセス制御、監査ログ、監視、エスカレーション所有者。

<h2 id="recommended-review-path">推奨レビューパス</h2>

1. 使用 [パートナー責任マトリックス](/ja/security-compliance/partner-responsibilities) 所有権の割り当てを。
2. レビュー [ライセンスサポート](/ja/security-compliance/license-support) ターゲットのオペレーティングモデルに対して。
3. 確認 [セキュリティアーキテクチャ](/ja/security-compliance/security-architecture) および API/Webhookの操作。
4. 完成 [生産開始チェックリスト](/ja/resources/production-launch-checklist).

法的およびコンプライアンスの結論は、資格を持つアドバイザーおよび責任パートナー団体の承認が必要です。これらのページは統合準備および責任範囲を記述しており、法的意見や特定のライセンスが利用可能かどうかの保証ではありません。
