明確な責任モデルは運用リスクを減らし、サポートチームの迅速な対応を可能にします。

<h2 id="responsibility-split">責任分担</h2>

| 面積 | 6MM | パートナー |
| --- | --- | --- |
| 貿易インフラ | マッチング、リスク、取引エンジン、 API および SDK 機能 | 正しい統合と生産監視 |
| エンドユーザー関係 | 別途合意がない限り、直接的な顧客関係はありません | ユーザーオンボーディング、サポート、開示、アカウントライフサイクル |
| 秘密と資格 | 認証モデルおよび署名要件を提供します | 秘密を安全に保存し、内部アクセスを制限します |
| ウェブフック | 署名されたライフサイクルイベントを送信します | 署名の検証と事象の冪等処理 |
| コンプライアンス業務 | コンプライアンス志向の技術およびサポート資料を提供します | 地域の義務およびユーザー向けの要件を確認しています |
| 統合リリース | プラットフォームおよび統合機能を文書化して維持しています | リリース前にパートナーコード、設定、ユーザージャーニーをテストします |
| インシデント対応 | 関連 6MM インフラの調査とパートナー支援チャネルの提供 | ユーザーへの影響を検出し、証拠を保存し、パートナーシステムを含み、エスカレーションします |

<h2 id="responsibilities-by-lifecycle">ライフサイクル別の責任</h2>

| 舞台 | パートナーアクション |
| --- | --- |
| 設計 | ユーザー所有権、資産フロー、データフロー、サポートモデル、ターゲット法域を定義します。 |
| 建設 | バックエンドで秘密を保持し、対応する認証を実装し、ビジネス識別子を保持しましょう。 |
| テスト | タイムアウト、再試行、重複ウェブフック、期限切れトークン、失敗シナリオを演算してください。 |
| 開局 | 準備状況のレビューを完了し、監視を確立し、サポートのエスカレーションを文書化します。 |
| 作動 | アラートの確認、異常な運用の照合、認証情報のローテーション、監査証拠の維持。 |
| 事件 | パートナーが管理するシステムを組み込み、認証情報を保護し、タイムラインを保持し、適切な6MMチャネルに連絡UTC。 |

<h2 id="handoff-checklist">運用ハンドオフチェックリスト</h2>

- 統合の健康、セキュリティ、コンプライアンス、エンドユーザーサポートの所有者を指定する。
- プロダクションベースのURL、認証情報所有者、ローテーション手順を文書化する。
- 認証、注文、転送、ウェブフックの失敗に関するダッシュボードやアラートの確認。
- リクエストID、パートナー注文番号、イベントIDを検索可能なログに保存します。
- 即時のエスカレーションが必要な事象を定義すること。
- 持って [サポートリクエストテンプレート](/ja/resources/support-request-template) オペレーションチームが利用可能です。
