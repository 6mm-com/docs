選択したワークスペースのメニューと権限を開始点として使用します。個人およびチームのウォレットは、ウォレットの資産とデバイスの署名を重視します。エンタープライズ ワークスペースでは、ビジネスの承認と運用ビューも公開されます。

<span id="receive-assets" data-sixmm-canonical-anchor="receive-assets" aria-hidden="true"></span>

## アセットを受け取る

目的のネットワークと資産を選択し、そのウォレットまたはビジネス ユーザーに提供された受信詳細を使用します。一部のネットワークでは、アドレスに加えてメモまたはタグが必要です。これらの詳細をまとめて保管し、送信する前に確認してください。

アドレスが割り当てられたからといって、デポジットが到着したわけではありません。入金記録、チェーン確認、リスクホールドを個別に追跡します。チェーン トランザクションは、ビジネス アカウントで資金が利用可能になる前に確認できる場合があります。

<span id="transfer-assets" data-sixmm-canonical-anchor="transfer-assets" aria-hidden="true"></span>

## 資産の譲渡

1. 送金元のウォレットまたは残高を選択し、送金先、金額、必要なメモを入力します。
2. プレビュー、料金情報、目的地の確認を確認してください。関連する手数料資産がウォレット モデルで必要な場所で利用可能であることを確認してください。
3. 一度送信して、リクエスト識別子を保持します。製品によって提示される承認またはデバイスの確認を完了します。
4. 最終結果が確定するまで、署名、ブロードキャスト、チェーン確認を続けます。

承認はトランザクションが署名されたことを意味するものではなく、ブロードキャストはトランザクションが確認されたことを意味するものではありません。個人およびチームのフローは、企業の引き出しと同じ Web 承認プロセスを使用すると想定すべきではありません。

<span id="understand-enterprise-wallet-roles" data-sixmm-canonical-anchor="understand-enterprise-wallet-roles" aria-hidden="true"></span>

## エンタープライズウォレットの役割を理解する

| 役割 | 目的 |
| --- | --- |
| 預金ウォレット | 受信アセットを受け取り、収集ワークフローをサポートします |
| ホットウォレットまたは引き出しウォレット | 運用上の送信転送を処理する |
| トランジットウォレット | 運用協定と予備協定の間で資産を移動する |
| リザーブウォレット | リザーブ用途に適した契約に基づいて資産を保有 |

一部の商品では、手数料による資金調達と独立したファンドを区別することもできます。これらは運用上の役割であり、すべての製品がすべてのウォレットのタイプを公開することを約束するものではありません。予約ラベルだけでは、デバイスがオフラインであることを証明できません。

<span id="reconcile-uncertain-results" data-sixmm-canonical-anchor="reconcile-uncertain-results" aria-hidden="true"></span>

## 不確実な結果を調整する

ビジネスリクエスト、ウォレットレコード、チェーントランザクションを比較します。利用可能な残高、凍結された残高、元帳エントリ、およびチェーン観察を区別してください。

リクエストがタイムアウトした場合、または検証中のままの場合は、その既存のレコードをクエリします。成功画面や通知が表示されないという理由だけで別の転送を作成しないでください。キャンセルには実際の署名状態が条件となります。提出されたキャンセルは、資金を移動できないことを証明するものではありません。開発者はフォローする必要があります [トランザクションと再試行](/ja/mpc-wallet/transactions).
