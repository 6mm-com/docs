<h2 id="error-response-format">エラー応答フォーマット</h2>

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

ビジネスエラーは通常、統一された JSON 構造を返します。インテグレーターはまずその `code` を確認するべきです。認証失敗は HTTP `401`を返すことがあります;レート制限は HTTP `429`を返すことがあります。

<h2 id="common-error-codes">一般的なエラーコード</h2>

| エラーコード      | 概要                                  |
| --------------- | -------------------------------------------- |
| `0`             | 成功                                      |
| `1001`          | 有効な認証情報は提供されていません |
| `1002`          | トークンの期限切れ                                |
| `1003`          | 無効なトークン、 API Key、または署名         |
| `1004`          | トークンの取り消し                                |
| `1006`          | ミスマッチ IP 原因                           |
| `2001`          | 必要なパラメータが欠けている                   |
| `2002`          | 無効なパラメータ値                      |
| `2003`          | パラメータの範囲外                       |
| `3001`          | 不十分な残高                         |
| `3003`          | 注文が見つかりません                              |
| `3004`          | 重複リクエスト                            |
| `3005`          | 注文はキャンセルできません                     |
| `3006`          | 許可は拒否されます                            |
| `3100` - `3112` | 条件順序パラメータ検証誤差   |
| `5001`          | 内部サーバーエラー                        |
| `5002`          | サービスは一時的に利用不可              |
| `5003`          | レートリミットが発動                         |

<h2 id="troubleshooting">トラブルシューティング</h2>

| 問題                                     | 推奨事項                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 有効な認証情報がない`1001`  | `Authorization: Bearer <accessToken>`か`X-API-KEY`が含まれているかを確認してください。                  |
| `1002` トークンの期限切れ                        | 再試す前にトークンをリフレッシュするか、再度ログインしてください。                                                   |
| `1003` 無効なトークン、 API Key、または署名 | API Key、署名ペイロード、リクエストボディのJSON文字列、クエリパラメータの順序をチェックします。           |
| `1006` 源 IP 不一致                   | API Key IPホワイトリストの設定を確認してください。                                                    |
| `3004` 重複リクエスト                    | 順序に関連するパスで同じ署名を再利用しないでください。 `timestamp` と `signature`を再生成してください。 |
| `5003` 金利制限が発動しました                 | リクエスト頻度を減らし、再試行する場合は指数的バックオフを使いましょう。                                |
| `Timestamp outside of tolerance window`     | `/v1/time`に電話して時間オフセットのキャリブレーションを行い、再度リクエストに署名してください。                             |
