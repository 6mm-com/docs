> REST ベース URL: `https://api.6mm.com`\
> WebSocket URL: `wss://ws.6mm.com/ws`

このドキュメントは、 6MM API サービスと統合する外部システム向けに設計されています。ログイン、 JWT 認証、 API Key 管理、 API Key HMAC 署名、アカウント照会、注文、ポジション、市場データ、 WebSocket ストリームなどをカバーしています。

アカウントのプロビジョニングおよび資金準備はプラットフォーム側のプロセスを通じて処理されます。このドキュメントは外部呼び出し可能な API サービスエンドポイントのみを記述しています。

<span id="service-endpoints" data-sixmm-canonical-anchor="service-endpoints" aria-hidden="true"></span>

## サービスエンドポイント

| 種類      | 終着点              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<span id="integration-flow" data-sixmm-canonical-anchor="integration-flow" aria-hidden="true"></span>

## 積分フロー

推奨される統合順序:

1. プラットフォームが提供するアカウントでログインし、 `accessToken`を取得します。
2. サーバー側のプログラムアクセスのために、まずJWTでAPI Keyを作成し、一度だけ返された`apiSecret`を安全に保存します。
3. プライベートクエリ、順序端点、位置端点は `Authorization: Bearer <accessToken>` または API Key 署名のいずれかで呼び出すことができます。
4. プライベート WebSocket ストリームの場合、まず `listenKey` を作成し、その後 `wss://ws.6mm.com/ws?listenKey=...`に接続します。
5. エンドポイントやパブリックWebSocketチャネルREST市場データは認証を必要としません。

<span id="authentication-choice" data-sixmm-canonical-anchor="authentication-choice" aria-hidden="true"></span>

## 認証選択

| シナリオ                               | 推奨方法         |
| -------------------------------------- | -------------------------- |
| フロントエンドのユーザーアクション                  | JWT                        |
| サーバーサイドのプログラマティックコール         | API Key + HMAC シグネチャー   |
| API Key 作成、更新、削除 | JWT                        |
| 公共市場 REST /公共 WebSocket  | 認証は不要です |
