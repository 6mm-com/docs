각 상담원에게 개별 계정을 부여하고 역할을 선택한 후 검토된 빠른 답변을 준비하세요. 각 사람이 수행하는 작업에 대한 액세스를 구성한 다음 해당 계정으로 확인하세요.

<div className="sixmm-support-flow">

1. **계정 생성** — 상담원 및 계정 상태를 식별합니다.
2. **역할 할당** — 작업에 필요한 모듈과 작업을 부여합니다.
3. **워크플로 확인** — 액세스를 테스트하고 빠른 응답을 준비합니다.

</div>


<span id="organize-the-support-team" data-sixmm-canonical-anchor="organize-the-support-team" aria-hidden="true"></span>

## 지원팀을 구성하세요

**상담원 관리**를 사용하여 상담원 계정, 역할, 빠른 답변을 유지하세요. 각 사람에게 실제로 필요한 모듈과 작업을 기반으로 역할을 할당합니다. 팀 전체에 하나의 관리자 로그인을 공유하는 대신 계정 자격 증명을 개인별로 유지하세요.

역할을 변경한 후 영향을 받는 계정으로 확인하세요. 표시되는 메뉴, 대화 모니터링, 콘텐츠 편집 및 설정 액세스가 다를 수 있습니다. 계정 상태, 세션 소유권 및 필드 수준 확인은 메뉴가 존재하는 것 이상으로 계속 적용됩니다.

<span id="mcp-inherits-the-same-identity" data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP는 동일한 ID를 상속받습니다.

MCP 연결은 승인하는 테넌트 및 에이전트 계정에 바인딩됩니다. AI는 별도의 관리자 역할을 받지 않습니다. 이 서비스는 통화에 대한 계정 권한을 재평가합니다. 사용할 수 없는 도구는 이름을 추측하거나 다른 테넌트 ID를 제공하여 활성화할 수 없습니다.

**시스템 설정 → MCP 연결**에서 연결된 애플리케이션을 관리하세요. 더 이상 필요하지 않은 연결을 취소합니다. 브라우저에서 로그아웃한다고 해서 외부 AI 애플리케이션의 인증이 자체적으로 취소되는 것은 아닙니다.

MCP을(를) 통해 역할 및 에이전트 계정을 변경하려면 확인이 필요합니다. MCP을 통해 에이전트 생성 시 초기 비밀번호는 AI에 반환되지 않고 백엔드 확인 페이지에서 사용자가 입력합니다.


<span id="understand-the-three-management-areas" data-sixmm-canonical-anchor="understand-the-three-management-areas" aria-hidden="true"></span>

## 세 가지 관리 영역 이해

| 영역 | 유지해야 할 사항 |
| --- | --- |
| 에이전트 계정 | 이름, 로그인 이메일, 역할, 활성화된 상태 및 페이지에 노출된 수신 제어. |
| 역할 관리 | 에이전트 그룹에 허용되는 모듈 및 작업입니다. 변경 사항을 저장하기 전에 기존 회원에게 미치는 영향을 검토하세요. |
| 빠른 답장 | 재사용 가능한 응답 제목, 콘텐츠, 주문 및 활성화된 상태. 기능을 사용할 수 있는 경우 번역을 검토하세요. |

<span id="prepare-an-agent-for-their-first-shift" data-sixmm-canonical-anchor="prepare-an-agent-for-their-first-shift" aria-hidden="true"></span>

### 상담원의 첫 교대 근무 준비

1. 로그인 이메일과 원하는 역할을 확인하세요. 계정 가용성, 로그인 상태 및 작업 상태를 동일한 것으로 취급하지 마십시오.
2. 모니터링 액세스, 수신 우선순위 및 구성된 경우 최대 동시 세션을 검토합니다. 이러한 제어는 역할 권한을 보완합니다.
3. 상담원에게 로그인하여 업무에 필요한 메뉴 및 처리 작업을 확인하도록 요청하세요.
4. 일반적인 질문에 대한 빠른 답변을 준비한 다음 현재 링크가 포함되어 있고 방문자별 정보가 없는지 확인하세요.

**인계 루틴:** 상담사의 액세스 권한을 변경하기 전에 열려 있는 책임을 검토하세요. 역할이나 계정이 변경된 후에는 역할 이름에만 의존하기보다는 유효 권한을 확인하세요.

## 일반적인 질문

<AccordionGroup>

<Accordion title="관리자가 승인한 AI가 일반 에이전트 역할을 합니까?">
아니요. MCP 연결은 이를 승인한 계정을 사용합니다. 의도한 작업에 적합한 액세스 권한을 가진 계정에 연결하세요.
</Accordion>

<Accordion title="로그아웃하면 외부 AI 연결이 끊어지나요?">
콘솔에서 로그아웃하는 것은 MCP 연결 취소와 별개입니다. 신청을 취소하려면 시스템 설정 → MCP 연결을 이용하세요.
</Accordion>

</AccordionGroup>
