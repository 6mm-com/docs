새로운 통합을 준비하거나 기존 통합을 프로덕션으로 옮길 때 이 템플릿을 사용하세요.

<h2 id="partner-information">파트너 정보</h2>

| 필드 | 설명 |
| --- | --- |
| 파트너 이름 | 통합에 법적 또는 프로젝트 명칭을 사용하세요. |
| 제품 유형 | 앱, 지갑, 중개 포털, 화이트라벨 거래소, 기관 플랫폼 또는 기타 수단입니다. |
| 주요 접촉 | 비즈니스, 기술, 운영, 비상 연락처. |
| 발사 지역 | 통합이 드러날 국가나 지역들. |

<h2 id="technical-information">기술 정보</h2>

| 필드 | 설명 |
| --- | --- |
| 프론트엔드 도메인 | 위젯이나 입력 페이지를 불러올 도메인들. |
| 백엔드 도메인 | Agent SDK 또는 API 통화에 사용되는 서버 도메인. |
| Webhook URL | 프로덕션 webhook 엔드포인트와 예상 IP 허용 목록 요구사항. |
| 통합 범위 | Trading Widget, Agent SDK, REST API, WebSocket, 화이트라벨 시스템, 또는 유동성 통합. |

<h2 id="operational-information">운영 정보</h2>

- 예상 발사일.
- 예상 트래픽 또는 활성 사용자 범위.
- 지원 시간 및 에스컬레이션 소유자.
- 소유주 및 사고 접촉 모니터링.

<h2 id="security-and-review-information">보안 및 검토 정보</h2>

- 인증 방법과 API Key 권한 범위.
- 비밀 저장소, 회전 소유자, 승인된 소스 IP.
- Webhook 서명 검증 및 멮등성 설계.
- 로그, 모니터링, 조정, 롤백, 사고 대응 소유자
- 대상 시장, 사용자 유형, 수탁 모델, 그리고 사용자 대면 의무를 담당하는 주체.

이 템플릿에는 생산 비밀, 완전 접근 토큰, 개인 키, 또는 편집되지 않은 사용자 데이터는 포함하지 마세요.

다음 기능을 사용하세요 [생산 출시 체크리스트](/ko/resources/production-launch-checklist) 최종 승인과 [지원 요청 템플릿](/ko/resources/support-request-template) 문제 심사를 위해서요.
