6MM기반 거래 기능을 실제 사용자에게 공개하기 전에 이 체크리스트를 사용하세요.

<h2 id="integration-readiness">통합 준비 상태</h2>

- 생산 도메인과 리디렉션 경로가 확인됩니다.
- Trading Widget, Agent SDK, API또는 WebSocket 흐름이 끝에서 끝까지 테스트되었습니다.
- 파트너 백엔드는 모든 비밀을 서버 측에 저장합니다.
- Webhook 수신, 서명 검증, 재시도 처리, 몪시성 등이 활성화됩니다.
- 로그에는 요청 ID, 사용자 매핑 ID, 주문 ID, 타임스탬프가 포함됩니다.

<h2 id="product-and-resource-readiness">제품 및 자원 준비 상태</h2>

- 진입 지점, 배너, 카드 자산은 승인된 언어 버전을 사용합니다.
- 화이트라벨 자산은 협력 계약이 허용할 때만 사용됩니다.
- 사용자 대상 위험 안내문과 거래 진입 사본은 파트너 팀이 검토합니다.
- 지원 및 에스컬레이션 소유자가 배정됩니다.

<h2 id="operational-readiness">작전 준비태세</h2>

- 모니터링은 API 오류, 토큰 발행, 위젯 초기화, webhook 실패, 주문 수명주기 이벤트를 포함합니다.
- 비상 접촉 경로 확인.
- 거래 진입을 위해 롤백 또는 임시 비활성화 계획이 준비됩니다.

<h2 id="security-and-compliance-readiness">보안 및 준수 준비 태세(Compliance Ready)</h2>

- API 키는 최소 권한을 사용하고 해당 시 승인된 IP 제한을 사용합니다.
- 자격증 교체 및 취소 절차가 검증되었습니다.
- Webhook 서명은 원시 요청 기관과 대조됩니다.
- 사용자 공개, 위험 통지, 책임 경계 및 목표 시장 검토가 완료되었습니다.
- 사건, 조정, 지원 증거를 비밀을 노출하지 않고 회수할 수 있습니다.
