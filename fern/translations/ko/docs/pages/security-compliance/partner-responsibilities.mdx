명확한 책임 모델은 운영 위험을 줄이고 지원팀이 더 빠르게 대응할 수 있도록 돕습니다.

<h2 id="responsibility-split">책임 분담</h2>

| 면적 | 6MM | 파트너 |
| --- | --- | --- |
| 무역 인프라 | 매칭, 리스크, 트레이딩 엔진, API 및 SDK 기능 | 올바른 통합 및 생산 모니터링 |
| 최종 사용자 관계 | 별도로 합의하지 않는 한 직접적인 고객 관계는 없습니다 | 사용자 온보딩, 지원, 공지 및 계정 수명주기 |
| 비밀과 자격 증명 | 자격 증명 모델 및 서명 요구사항을 제공합니다 | 비밀을 안전하게 저장하고 내부 접근을 제한합니다 |
| Webhooks | 서명된 라이프사이클 이벤트 전송 | 시그니처를 검증하고 사건을 멩등성적으로 처리합니다 |
| 준수 운영 | 준수 지향 기술 및 지원 자료를 제공합니다 | 지역 의무 및 사용자 대상 요구 사항 확인 |
| 통합 릴리스 | 문서화된 플랫폼 및 통합 기능을 유지합니다 | 출시 전 파트너 코드, 설정, 사용자 여정을 테스트합니다 |
| 사고 처리 | 관련 6MM 인프라를 조사하고 파트너 지원 채널을 제공합니다 | 사용자 대상 영향을 감지하고, 증거를 보존하며, 파트너 시스템을 포함하고, 상위 단계 조정합니다 |

<h2 id="responsibilities-by-lifecycle">라이프사이클별 책임</h2>

| 무대 | 파트너 행동 |
| --- | --- |
| 설계 | 사용자 소유권, 자산 흐름, 데이터 흐름, 지원 모델, 대상 관할구역을 정의하세요. |
| 건축 | 비밀을 백엔드에 유지하고, 지원 인증을 구현하며, 비즈니스 식별자를 보존하세요. |
| 테스트 | 타임아웃, 재시도, 복제 -webhook, 만료된 토큰, 실패 시나리오를 실행하세요. |
| 출범 | 준비 상태 검토를 완료하고, 모니터링을 수립하며, 지원 강화 문서를 작성합니다. |
| 운영 | 경고 검토, 비정상 운영 조정, 자격 증명 교체, 감사 증거 유지. |
| 사건 | 파트너가 통제하는 시스템을 포함하고, 자격 증명을 보호하며, UTC 일정을 유지하고, 올바른 6MM 채널에 연락하세요. |

<h2 id="handoff-checklist">운영 인계 체크리스트</h2>

- 통합 건강, 보안, 준수 및 최종 사용자 지원을 위한 소유자를 지정합니다.
- 프로덕션 베이스 URL, 자격 증명 소유자, 회전 절차를 문서화합니다.
- 인증, 주문, 전송, webhook 실패에 대한 대시보드 및 알림 확인.
- 요청 ID, 파트너 주문 번호, 이벤트 ID를 검색 가능한 로그에 저장합니다.
- 즉각적인 에스컬레이션이 필요한 사건을 정의합니다.
- 그냥 [지원 요청 템플릿](/ko/resources/support-request-template) 운영팀에 제공됨.
