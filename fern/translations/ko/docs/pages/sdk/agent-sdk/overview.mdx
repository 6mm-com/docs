6MM Agent SDK는 서명 및 요청 처리를 처음부터 구현하지 않고 권한 있는 에이전트 APIs를 호출해야 하는 파트너 백엔드 서비스용입니다. 통합에서는 파트너 API 보안 비밀을 사용하므로 브라우저, 모바일 또는 공개 데스크톱 코드에서 실행하면 안 됩니다.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Agent SDK를 사용하는 경우

백엔드가 파트너 사용자를 연결하고, 승인된 워크플로를 통해 자산을 이동하고, 거래 기록을 쿼리하고, 내장된 거래 항목 URL 을 생성하거나, webhook 알림을 확인해야 하는 경우 Agent SDK를 사용하세요. 사용 [Trading Widget SDK](/ko/sdk/trading-widget/overview) 파트너 프런트엔드가 거래 인터페이스를 표시해야 하는 경우 별도로.

## 공통 구성

| 열쇠 | 예 | 설명 |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM 에이전트 API 서비스 URL 뒤에 슬래시가 없습니다. |
| agentCode | AGENT001 | 파트너 에이전트 코드. |
| apiSecret | 귀하의 API 비밀 | API 서명 비밀은 백엔드에만 저장됩니다. |
| defaultCurrency | USDT | 이체 및 계정의 기본 통화 APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | 6MM webhook 알림에 대한 파트너 엔드포인트입니다. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## 일반적인 통합 흐름

1. 파트너 프런트엔드는 파트너의 자체 계정 시스템을 통해 사용자를 인증합니다.
2. 파트너 백엔드는 사용자를 안정적인 파트너 측 식별자에 매핑합니다.
3. 백엔드는 `agentCode` 및 보호된 API 보안 비밀을 사용하여 Agent SDK을 호출합니다.
4. SDK는 에이전트 API 요청에 서명하고 보냅니다.
5. 백엔드는 반환된 비즈니스 식별자를 저장하고 나중에 webhooks를 멱등적으로 처리합니다.
6. 프런트엔드는 필요한 단기 결과 또는 항목 자격 증명만 받습니다.

## 생산 체크리스트

- 소스 코드가 아닌 백엔드 Secret Manager에서 `apiSecret`를 로드합니다.
- 개발, 스테이징, 프로덕션 자격 증명을 별도로 유지하세요.
- 안정적인 파트너 사용자 매핑과 고유한 비즈니스 주문 식별자를 사용하세요.
- 시간 초과된 요청의 상태를 확인할 때 원래 식별자를 유지하세요.
- webhook 서명을 확인하고 처리된 이벤트 ID를 저장합니다.
- 지원 요청 ID를 유지하면서 로그에서 비밀과 서명을 수정하세요.

## Java SDK v0.3.0 기능

Java SDK에는 이제 자금 지갑, 명시적 자금 환경, 6개의 영구 데이터 쿼리 및 법정화폐 기준 금리가 포함됩니다. PHP 기능은 파트너가 제공한 패키지와 비교하여 확인해야 합니다. Java 추가는 PHP 메서드 일치를 의미하지 않습니다.
