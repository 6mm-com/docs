개발자 가이드는 현재 기업 지갑 통합 표면을 설명합니다. MPC 지갑이 출시되지 않았습니다. 엔드포인트 예시는 구현 참조이지 공개적으로 사용 가능한 서비스에 대한 약속이나 동결된 API 계약이 아닙니다.

<span id="obtain-integration-information" data-sixmm-canonical-anchor="obtain-integration-information" aria-hidden="true"></span>

## 통합 정보 얻기

테스트 베이스 URL, API 버전, 워크스페이스 ID, 보관 모델, 활성화된 네트워크 및 자산, API 권한, 고객 인증 요구 사항 및 webhook 설정을 확인하세요. 네트워크 및 자산 식별자는 합의된 환경에서 나옵니다. 퍼블릭 체인 식별자와 동일하다고 가정하지 마십시오.

지갑 통합 자격 증명을 거래 API 자격 증명과 별도로 보관하십시오. 공유 문서 사이트에서는 서비스나 계정 모델을 상호 교환할 수 없습니다.

<span id="connect-the-business-flow" data-sixmm-canonical-anchor="connect-the-business-flow" aria-hidden="true"></span>

## 비즈니스 흐름을 연결하세요

1. 원하는 엔터프라이즈 작업 공간에 대한 최소 권한 API 키를 만들고 백엔드에서 비밀을 유지하세요.
2. 전송을 도입하기 전에 읽기 전용으로 서명된 요청과 오류 처리를 검증하세요.
3. 안정적인 비즈니스 사용자 식별자를 위해 수신 주소를 할당한 후 반환된 주소와 메모를 확인합니다.
4. 입금 이벤트를 수신하고 API 쿼리와 자신의 기록으로 조정합니다.
5. 철회 승인, 안정적인 비즈니스 요청 식별자 및 결과 추적을 추가합니다.

<span id="core-api-areas" data-sixmm-canonical-anchor="core-api-areas" aria-hidden="true"></span>

## 핵심 API 영역

| 영역 | 현재 경로 예 | 목적 |
| --- | --- | --- |
| 수신 주소 | `POST /api/v1/addresses`, `GET /api/v1/addresses` | 주소 할당 및 쿼리 |
| 매장 | `GET /api/v1/deposits`, `GET /api/v1/deposits/{id}` | 들어오는 전송을 따르십시오. |
| 인출 | `POST /api/v1/withdrawals`, `GET /api/v1/withdrawals/{id}` | 요청 제출 및 결과 쿼리 |
| 요청 조회 | `GET /api/v1/withdrawals/by-request` | 불확실한 응답 후 요청 조정 |
| 잔액 | `GET /api/v1/balances` | 승인된 범위 내에서 업무 잔액 조회 |

경로 등록이 모든 API 키가 모든 작업을 호출할 수 있다는 것을 의미하지는 않습니다. 제품 액세스, 작업 공간 권한, 보관 모드 및 초기화는 모두 가용성에 영향을 미칠 수 있습니다. 관리 및 개인 장치 인터페이스는 이 엔터프라이즈 빠른 시작 흐름 외부에 있습니다.

## 수신 주소 확인

제공된 SDK 구현은 서명된 주소 증명을 지원합니다. 통합 패키지에 지정된 신뢰할 수 있는 구성원 또는 신뢰 자료를 구성하고 필요한 경우 예상 작업 공간, 체인 및 키 그룹 정보를 독립적으로 제공합니다. 확인하고 있는 동일한 응답에서 모든 신뢰 기대치를 도출하지 마십시오.

완전 관리형 풀 주소의 경우 증명은 고객에 대한 할당이 서버 측 문으로 유지되는 동안 플랫폼 소유 주소를 식별할 수 있습니다. 해당 할당을 고객 소유권에 대한 암호화된 증거로 설명하지 마십시오.
