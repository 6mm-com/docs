Webhooks 비즈니스 이벤트에 대해 백엔드에 알립니다. 배송이 지연되거나 누락되어 기록이 해결되지 않는 일이 없도록 API 쿼리와 함께 사용하세요.

## 처리하기 전에 확인하세요

현재 전송에는 `X-Webhook-Signature` 및 `X-Webhook-Timestamp`이 포함됩니다. 서명은 타임스탬프 헤더 텍스트, 점 및 정확한 원시 요청 본문 위에 HMAC-SHA256를 사용합니다. 헤더 값의 형식은 `sha256=<HEX_SIGNATURE>`입니다.

1. JSON를 구문 분석하기 전에 원시 본문을 유지합니다.
2. 합의된 클록 허용 오차를 사용하여 타임스탬프를 검증합니다.
3. 상수 시간 비교를 사용하여 webhook 비밀로 서명을 확인합니다.
4. 그런 다음에만 페이로드를 해석하고 비즈니스 기록을 업데이트합니다.

확인하기 전에 구문 분석된 JSON 형식을 다시 지정하면 서명된 바이트가 변경됩니다. Webhook 확인은 API 요청 비밀번호나 고객 인증 키가 아닌 webhook 비밀번호를 사용합니다.

## 저장 및 중복 제거

봉투에는 `event_id`, `event_type`, `created_at`, `tenant_id` 및 `data`가 포함됩니다. 일반적인 이벤트 전달의 경우 반복 적용을 방지하려면 끝점 또는 작업 영역 컨텍스트와 함께 확인된 이벤트 ID를 사용하세요. 결과 비즈니스 업데이트로 해당 결정을 원자적으로 유지하거나 확인된 이벤트를 승인하기 전에 지속적으로 대기열에 추가합니다.

`X-Webhook-Idempotency-Key`은 일반 발신함 전송에도 제공됩니다. 독립적으로 서명된 페이로드 필드가 아닌 배달 메타데이터입니다. 변경된 헤더로 인해 동일한 확인된 이벤트로 인해 자금이 두 번 이동되지 않도록 하십시오. 테스트 제공과 수동 작업에는 서로 다른 식별자가 있거나 이 헤더가 생략될 수 있습니다.

지속적으로 이벤트를 수락한 후 성공적인 응답을 반환합니다. 중복 및 지연되거나 순서가 잘못된 이벤트를 위한 디자인입니다. 배송 타임스탬프는 보장된 비즈니스 발생 시간이 아닙니다. 이벤트가 나중에 알려진 결과와 충돌하는 경우 기본 리소스를 쿼리합니다.

## 통합 패키지를 선택하세요

| 패키지 제품군 | 현재 구현 범위 |
| --- | --- |
| Go 및 Python API SDKs | 주소, 입출금 자원, 서명 요청 및 관련 도우미 |
| Go, Node.js 및 Python webhook 도우미 | Webhook 서명 확인 및 프레임워크 통합 도우미 |

이는 소스 구현 범위이지 패키지 레지스트리 가용성이나 일반 릴리스 확인이 아닙니다. 온보딩 중에 버전이 일치하는 패키지와 해당 설치 지침을 얻습니다. 다른 리소스에는 직접 API 호출이 필요할 수 있습니다. webhook 패키지가 있다고 해서 전체 API 클라이언트를 추론하지 마세요.

## 수신 경로 테스트

유효한 전달, 수정된 본문, 잘못된 서명, 오래된 타임스탬프, 중복 이벤트 및 수신기 다시 시작을 테스트합니다. 통합 환경을 통해 재시도 및 재생 준비를 확인하세요. 누락된 콜백은 두 번째 철회 요청이 아닌 조정을 트리거해야 합니다.
