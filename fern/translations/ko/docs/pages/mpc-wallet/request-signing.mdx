세 가지 별도의 서명 문제가 있습니다. HTTP 요청 인증, 특정 출금 승인, MPC 참가자를 통한 블록체인 서명 생성입니다. 첫 번째 검사를 통과해도 나머지 두 검사를 대체하지 않습니다.

## API 요청 인증

현재 API는 API 키 식별자 및 비밀번호와 함께 HMAC-SHA256를 사용합니다. 정규 요청에는 줄 바꿈으로 구분되고 후행 줄 바꿈 없이 다섯 줄이 포함되어 있습니다.

```text
METHOD
PATH
SORTED_QUERY
BODY_SHA256_HEX
UNIX_TIMESTAMP_SECONDS
```

호스트 없이 대문자 HTTP 메서드와 요청 경로를 사용하세요. 쿼리 키를 정렬하고, 반복되는 값의 순서를 유지하고, 공백에 `+`를 포함하여 URL 인코딩 형식을 적용합니다. 쿼리가 없으면 쿼리 줄은 비어 있습니다. 본문 없는 요청의 빈 본문을 포함하여 SHA-256를 사용하여 정확한 본문 바이트를 해시합니다.

제공된 비밀번호를 UTF-8 바이트로 사용하여 HMAC-SHA256를 계산합니다. 단순히 16진수로 보인다는 이유로 16진수로 디코딩하지 마세요. 결과를 소문자 16진수로 인코딩합니다. 헤더 필드는 공백으로 구분됩니다.

```text
Authorization: HMAC-SHA256 keyId=<KEY_ID> signature=<HEX_SIGNATURE> timestamp=<UNIX_SECONDS>
```

## 읽기 전용 서명 예

이 표준 라이브러리 도우미는 입금 쿼리에 대한 헤더를 구성합니다. 요청을 보내지 않습니다. 애플리케이션에 안전하게 자격 증명을 로드하고 반환된 경로를 변경하지 않고 환경에 제공된 기본 URL 로 보냅니다.

```python
import hashlib
import hmac
import time
from urllib.parse import urlencode


def signed_read_headers(key_id, secret, timestamp=None):
    method = "GET"
    path = "/api/v1/deposits"
    query = urlencode(sorted([("page", "1"), ("page_size", "20")]))
    body = b""
    ts = str(int(time.time()) if timestamp is None else timestamp)
    canonical = "\n".join([
        method, path, query, hashlib.sha256(body).hexdigest(), ts
    ])
    signature = hmac.new(
        secret.encode("utf-8"), canonical.encode("utf-8"), hashlib.sha256
    ).hexdigest()
    return path + "?" + query, {
        "Authorization": (
            f"HMAC-SHA256 keyId={key_id} signature={signature} timestamp={ts}"
        )
    }
```

시계를 동기화된 상태로 유지하세요. 서명 후 경로, 쿼리 또는 본문을 변경하는 프록시는 인증을 무효화할 수 있습니다. 인증이 실패한 경우 재시도하기 전에 응답 이유와 요청 식별자를 검사하세요. 비밀 또는 전체 인증 헤더를 기록하지 마십시오.

## API 철회 승인

현재 기업 API 출금 흐름에는 `client_authorization`에서 Ed25519 고객 승인도 필요합니다. 요청 식별자, 대상, 자산 및 금액을 포함하여 의도된 거래 컨텍스트를 바인딩합니다. 공개 키 등록 또는 신뢰 구성은 보관 계약에 따라 다릅니다.

일치하는 통합 패키지를 사용하여 정식 페이로드, 서명 및 공개 키를 생성합니다. 이 인증 키는 HMAC 비밀 및 MPC 공유와 별개입니다. 고객이 통제할 수 있도록 개인 키를 보존하세요. 이 개요에서 사용자 정의 형식을 구축하는 대신 통합 중에 페이로드 버전과 유효성 규칙을 확인하세요.

요청이 승인된 후에도 비즈니스 확인 및 승인이 계속 적용될 수 있으며, 이어서 MPC 서명 및 체인 확인이 이어질 수 있습니다. 보다 [트랜잭션 및 재시도](/ko/mpc-wallet/transactions).
