임베디드 트레이딩은 보통 기존 제품에 도입되며, 독립적인 목적지로 출시되지는 않습니다. 최적의 통합 경로는 사용자가 이미 어디에 시간을 보내는지, 그리고 어떤 시스템이 신원, 자금, 운영을 소유하는지에 따라 달라집니다.

<h2 id="common-scenarios">일반적인 시나리오</h2>

| 시나리오 | 최고의 출발점 | 주석 |
| --- | --- | --- |
| 앱이나 지갑이 거래 입력을 원합니다 | Trading Widget SDK | 네이티브 또는 H5 진입 지점을 사용하고, 사용자 승인 후 내장된 거래 경험을 열어보세요. |
| 중개업체나 채널 플랫폼이 파생상품 접근을 원합니다 | Agent SDK + Trading Widget SDK | 고객 관계와 백엔드 검증은 파트너 시스템 내에 유지하세요. |
| 플랫폼은 가이드 트레이딩 플로우를 원합니다 | API + 선택된 SDK 모듈 | 계정, 전송, 주문 워크플로우에는 백엔드 APIs 을 사용하고, 필요한 프론트엔드 항목만 노출하세요. |
| 기존 거래소는 추가 시장을 원합니다 | 유동성 + API 통합 | 시장 깊이, 계정 워크플로우, 운영 모니터링을 결합하세요. |

<h2 id="product-decisions-before-integration">통합 전 제품 결정</h2>

- 사용자가 홈페이지 카드, 자산 페이지, 캠페인 페이지, 계정 센터 중 어느 쪽에서 진입할지 결정합니다.
- 로그인 주, 사용자 자격 여부, 국가 또는 지역 가용성을 어떤 시스템이 소유하는지 결정합니다.
- 이체, 결제 기록, 고객 지원 티켓이 사용자에게 어떻게 보여지는지 결정합니다.
- 어떤 이벤트를 내부 분석, CRM, 또는 위험 운영으로 전달해야 하는지 결정합니다.
