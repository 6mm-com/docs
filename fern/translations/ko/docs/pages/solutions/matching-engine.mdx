화이트라벨 교환은 프론트엔드 셸 이상의 것을 요구합니다. 사용자 경험은 거래, 계좌, 위험, 결제 등 신뢰할 수 있는 핵심 모듈에 의존합니다.

<h2 id="core-modules">코어 모듈</h2>

| 모듈 | 역할 |
| --- | --- |
| 매칭 및 주문 수명 주기 | 주문 제출, 상태 매칭, 취소 및 실행 기록을 처리합니다. |
| 계정 및 위치 시스템 | 잔액, 마진 상태, 포지션, 거래 가능 상태를 유지합니다. |
| 위험 관리 | 레버리지, 마진, 청산, 그리고 비정상적인 시장 행동을 조율합니다. |
| 시장 데이터 | 가격, 깊이, 거래 내역, 차트 데이터를 거래 인터페이스에 배포합니다. |
| 정착과 기록 | 거래 내역, 잔액 변동, 운영 기록을 정렬할 수 있습니다. |

<h2 id="implementation-questions">구현 질문</h2>

- 사용자에게 노출되는 순서 및 조건 순서 유형은 무엇인가요?
- 심볼규칙, 정밀 검증, 거래 가용성을 소유하는 서비스는 어디인가요?
- 주문, 무역, 포지션, 잔액, 결제 기록은 어떻게 조정되나요?
- 어떤 식별자가 REST 응답, WebSocket 이벤트, 파트너 레코드에서 안정적으로 유지되나요?
- 매칭, 리스크 또는 시장 데이터가 불가능해질 때 어떤 모니터링 및 롤백 경로가 적용되나요?

프론트엔드 개발 전에 이 질문들에 답해 제품 동작, API 처리, 운영, 지원이 동일한 거래 모델을 사용하도록 하세요.
