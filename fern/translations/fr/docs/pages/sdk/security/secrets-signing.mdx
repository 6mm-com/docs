Les requêtes Agent SDK sont authentifiées avec un secret API partenaire. Gardez ce secret dans un service backend de confiance et laissez SDK générer des champs de signature autant que possible.

> **Deux protocoles de signature**
>
> La signature Agent SDK utilise des champs de requête triés, un horodatage basé sur les secondes et un nom occasionnel. Les requêtes directes Developer API utilisent le processus distinct décrit dans [Demande de signature](/fr/developer-api/request-signing). Ne réutilisez pas un format de charge utile pour un autre.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## Règle de signature

Pour les requêtes Agent SDK :

1. Excluez le champ `sign`.
2. Omettez les champs avec des valeurs vides.
3. Triez les noms de champs restants dans l'ordre ASCII.
4. Joignez les champs sous la forme `k=v&k2=v2`.
5. Calculez la signature hexadécimale HMAC-SHA256 avec `apiSecret`.

Les valeurs du tableau sont sérialisées sous forme compacte JSON avant de rejoindre la charge utile de signature. Par exemple, `platformUserIds` signe comme `["1188041528"]`, donnant `platformUserIds=["1188041528"]` dans la charge utile `k=v`. Conservez l'ordre des éléments du tableau, les guillemets doubles et les ID de chaîne ; n'insérez pas d'espaces de formatage et n'utilisez pas Java `List.toString()` (comme `[1188041528]`). Le SDK gère automatiquement cette sérialisation.

Le SDK doit construire cette valeur à partir des mêmes données qu'il envoie. La modification d'un champ signé après la génération de la signature entraîne l'échec de la vérification.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## SDK-champs gérés

| Champ | Source | Description |
| --- | --- | --- |
| agentCode | SDK configuration | Code de l'agent partenaire. |
| horodatage | Heure actuelle du serveur | Horodatage Unix en secondes. |
| occasionnellement | Valeur aléatoire sécurisée | Chaîne aléatoire de protection contre la relecture. |
| signe | HMAC-SHA256 | Demander une signature. |
| devise | Devise par défaut | Utilisé lorsque le transfert/compte APIs omet la devise. |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## Stockage secret

- Chargez `apiSecret` à partir d'un gestionnaire de secrets backend ou d'une configuration d'exécution protégée.
- Ne placez jamais le secret dans les bundles frontaux, les applications mobiles, les clients de bureau, les captures d'écran ou les tickets d'assistance.
- Séparez les informations d’identification pour le développement, la préparation et la production.
- Limiter l’accès aux services et aux opérateurs qui en ont besoin.
- Supprimez les signatures de requêtes, les valeurs d’autorisation et les secrets des journaux.
- Révoquer et remplacer les informations d'identification lorsqu'une exposition est suspectée.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Protection de l'horloge et de la relecture

Le SDK inclut `timestamp` et `nonce` pour réduire le risque de relecture. Gardez les horloges back-end synchronisées et ne réutilisez pas un occasionnel construit manuellement. Si la validation de la signature échoue, confirmez le secret configuré, l'heure du serveur, les champs sérialisés et l'environnement avant de réessayer.

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## Liste de contrôle d'intégration

| Vérifier | Résultat attendu |
| --- | --- |
| Lieu secret | Stockage secret back-end uniquement. |
| Environnement | La base URL et les informations d'identification appartiennent au même environnement. |
| Manipulation sur le terrain | SDK génère `timestamp`, `nonce` et `sign`. |
| Enregistrement | Les identifiants d'entreprise restent visibles pendant que les informations d'identification sont rédigées. |
| Rotation | Le propriétaire des informations d’identification et le processus de remplacement sont documentés. |
