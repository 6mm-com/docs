Commencez par l’environnement, l’horodatage et l’identifiant d’entreprise de l’opération ayant échoué. Une vérification structurée sépare généralement les problèmes de configuration des problèmes d'authentification, de réseau et de traitement asynchrone.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Ordre de diagnostic recommandé

1. Confirmez l'environnement concerné et basez URL.
2. Enregistrez la plage horaire UTC et la première requête ayant échoué.
3. Identifiez le module : Trading Widget, Agent SDK, REST API, WebSocket ou webhook.
4. Capturez l'ID de demande, l'ID d'utilisateur partenaire, le `agentOrderNo`, l'ID de commande ou l'ID d'événement webhook.
5. Vérifiez le code récent, les informations d'identification, la liste blanche IP ou les modifications de déploiement.
6. Reproduisez avec le plus petit cas de test sûr.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget problèmes

| Symptôme | Cause probable | Réparer |
| --- | --- | --- |
| iframe demande un domaine local partenaire | baseUrl est manquant | Passez baseUrl : 'https://app.6mm.com'. |
| l'iframe est invisible ou très courte | Le conteneur parent n'a pas de hauteur | Réglez la hauteur du conteneur ou la hauteur du passage. |
| token_provider_missing | le mode jeton partenaire n'a pas de fournisseur | Ajouter une authentificationtokenProvider. |
| auth_exchange_failed | Jeton d'intégration invalide, expiré ou incompatible | Vérifiez la réponse du jeton backend et channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK problèmes

| Symptôme | Cause probable | Réparer |
| --- | --- | --- |
| Signature rejetée | Mauvais secret, dérive d'horloge ou champs signés modifiés manuellement | Laissez SDK générer les champs de signature et synchroniser l'heure du serveur. |
| Risque de mouvements de fonds en double | Nouveau numéro de commande utilisé après l'expiration du délai | Requête par agentOrderNo d'abord. |
| PROCESSING traité comme un échec | État en attente mal compris | Attendez webhook ou appelez queryOrder. |
| Webhook traité plusieurs fois | Réessayer le comportement sans idempotence | Ajoutez une clé d’idempotence et des vérifications de l’état final. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Des preuves à capturer

| Intégration | Preuve utile |
| --- | --- |
| Trading Widget | Page URL, chemin de version SDK, console du navigateur, requêtes réseau ayant échoué, charge utile `onError` et dimensions du conteneur. |
| Agent SDK | SDK langue/version, base URL, UTC horodatage, ID de demande, `agentOrderNo`, code de réponse et journaux nettoyés. |
| Webhook | Délai de livraison, clé d'événement ou d'entreprise, résultat de validation de signature, état de traitement et hachage de corps brut aseptisé. |
| REST API | Méthode, chemin, environnement, ID de demande, code de réponse et paramètres nettoyés. |

N'incluez jamais de mots de passe, de jetons d'accès, de secrets API, de signatures complètes, de clés privées ou de données personnelles non expurgées dans les diagnostics.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Avant d'escalader

- Réessayez uniquement lorsque l'opération est documentée comme pouvant être réessayée en toute sécurité.
- Après un délai d'attente, interrogez l'identifiant d'entreprise d'origine au lieu d'en créer un nouveau.
- Confirmez l'horloge système et l'environnement d'identification pour les erreurs de signature.
- Conservez le premier échec et les résultats des tentatives ultérieures.
- Utilisez le [Modèle de demande d'assistance](/fr/resources/support-request-template) d'envoyer un rapport complet et rédigé.

## Diagnostic Java v0.3.0

| Symptôme | Vérification et récupération |
| --- | --- |
| La demande de financement a un résultat inconnu | Conservez l'original `agentOrderNo` ; appelez `queryWalletTransfer` avec l'environnement d'origine. N'utilisez pas `queryOrder`. |
| L'interface utilisateur de simulation affiche des fonds inattendus | Vérifiez le frontend `tradingMode` séparément du backend `environment` ; le compte `isSimulatedUser` n'achemine pas les requêtes. |
| Erreur de requête `6905` | Reculez en utilisant le quota de partenaire partagé, puis réessayez le même curseur et les mêmes filtres via le SDK. |
| Erreur de requête `6904` | Réduisez les requêtes simultanées et réduisez la fenêtre temporelle ; contactez le support si vous persistez. |
| Curseur invalide ou expiré | Redémarrez la même fenêtre d'historique fixe et dupliquez les enregistrements enregistrés. |
| Nouvelle méthode Java manquante | Vérifiez l'artefact Maven résolu par rapport à la balise publique `v0.3.0` ; supprimez les dépendances conflictuelles conformément à votre politique d’artefact. |
