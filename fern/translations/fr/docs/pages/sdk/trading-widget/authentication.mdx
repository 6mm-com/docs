## Mode recommandé : jeton partenaire

Partner-Token évite de mettre des jetons courts dans les URL et conserve apiSecret sur le backend du partenaire.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'partner-token',
    tokenProvider: async ({ channelId, symbol, reason }) => {
      const resp = await fetch('/api/trading/embed-token', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ channelId, symbol, reason }),
      })

      if (!resp.ok) {
        throw new Error('Failed to request embed token')
      }

      return resp.json()
    },
  },
})
```

<span id="backend-flow" data-sixmm-canonical-anchor="backend-flow" aria-hidden="true"></span>

## Flux back-end

```text
1. Partner frontend receives auth_request from the iframe.
2. SDK calls tokenProvider.
3. Partner frontend calls its own backend.
4. Partner backend validates the partner session.
5. Partner backend calls 6MM Agent API or Java SDK createEmbedToken.
6. SDK sends embedToken to the iframe through postMessage.
7. iframe exchanges embedToken for a 6MM access token.
8. iframe continues initialization and emits ready.
```

<span id="tokenprovider-contract" data-sixmm-canonical-anchor="tokenprovider-contract" aria-hidden="true"></span>

## Contrat tokenProvider

| Champ | Direction | Description |
| --- | --- | --- |
| channelId | SDK -> Backend partenaire | Identificateur unique de session de widget. Le backend doit le transmettre à createEmbedToken. |
| symbole | SDK -> Backend partenaire | Symbole commercial actuellement demandé. Utilisez-le pour définir la portée du jeton si nécessaire. |
| raison | SDK -> Backend partenaire | Pourquoi le SDK demande un jeton, tel qu'un chargement initial ou une actualisation. |
| embedToken | Backend partenaire -> SDK | Jeton de courte durée créé par le Agent SDK ou l'agent API. |
| expireAt | Backend partenaire -> SDK | Horodatage d'expiration du jeton renvoyé par 6MM. |

<span id="failure-handling" data-sixmm-canonical-anchor="failure-handling" aria-hidden="true"></span>

## Gestion des pannes

| Condition | Manipulation recommandée |
| --- | --- |
| Session partenaire expirée | Renvoyez 401 depuis le point de terminaison partenaire et demandez à l’utilisateur de se reconnecter. |
| La création du jeton a échoué temporairement | Génère une erreur dans tokenProvider et permet au widget de faire apparaître une erreur d'authentification. |
| channelId incohérence | Rejetez la demande et recréez l'instance de widget. |
| L'utilisateur n'est pas autorisé à échanger | Renvoie une erreur contrôlée par le partenaire et ne crée pas de jeton d'intégration. |

<span id="compatibility-mode-agent-sso" data-sixmm-canonical-anchor="compatibility-mode-agent-sso" aria-hidden="true"></span>

## Mode de compatibilité : agent-sso

agent-sso conserve l'ancien flux de tickets /agent-entry. Préférez le jeton partenaire pour les nouvelles intégrations.

```js
const widget = TradingWidget.create('#trading-widget', {
  baseUrl: 'https://app.6mm.com',
  auth: {
    mode: 'agent-sso',
    entryUrlProvider: async ({ redirectPath }) => {
      const resp = await fetch('/api/trading-entry', {
        method: 'POST',
        credentials: 'include',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ redirectPath }),
      })
      const data = await resp.json()
      return data.webUrl
    },
  },
})
```

<span id="seconds-trading-and-environment-rules" data-sixmm-canonical-anchor="seconds-trading-and-environment-rules" aria-hidden="true"></span>

## Règles d'échange de secondes et d'environnement

Pour les pages secondes, utilisez la même authentification `partner-token` avec `page` et `tradingMode` configurées sur le widget. Il n’existe pas de jeton de prédiction distinct. Chaque appel tokenProvider doit obtenir un nouveau jeton unique de votre backend.

Renvoie `embedToken`, `expireAt` en secondes Unix et l'original `channelId` en tant qu'objet de niveau supérieur. La réponse du jeton Agent SDK ne contient pas `channelId` ; votre backend fait écho au canal Widget actuel. Si votre point de terminaison encapsule les réponses dans `data`, déballez-le avant de revenir de tokenProvider.
