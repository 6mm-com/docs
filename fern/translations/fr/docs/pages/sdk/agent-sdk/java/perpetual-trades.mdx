Ce guide cible **Agent Java SDK `v0.3.0`**, Java 8+ et le contrat public étiqueté. Exemples exécutés dans un backend partenaire après l'initialisation de `client` dans [Démarrage rapide](/fr/sdk/agent-sdk/java/quick-start).

## Exemples de prérequis

Les extraits de code Java partagent ces importations. Initialisez `client` à l'aide de Quick Start et obtenez `platformUserId` à partir de la liaison enregistrée. Les exemples d’ID utilisateur/commande doivent être remplacés par vos propres valeurs persistantes.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

<span data-sixmm-canonical-anchor="listperpetualtrades" aria-hidden="true"></span>

## `listPerpetualTrades`

Modèle de demande : `PerpetualTradesRequest`.

```java
import com.sixmm.agent.model.PerpetualTradesRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualTradesRequest request = new PerpetualTradesRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualTrades(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Champs de requête

| Champ | Java tapez | Requis | Signification |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Conditionnel | 1 à 100 identifiants publics uniques ; requis pour les exécutions et les commandes conditionnelles. Omettre les requêtes prises en charge pour la portée directe du lecteur ; [] n'est pas valide. |
| `symbol` | `String` | Non | Filtre de paire de trading en option. |
| `orderId` | `String` | Non | ID de commande ordinaire ; pas un numéro d'ordre de transfert de partenaire. |
| `startTime` | `Long` | Non | Millisecondes Unix incluses ; utilisez une fenêtre d'historique UTC fixe. |
| `endTime` | `Long` | Non | Millisecondes Unix exclusives. |
| `limit` | `Integer` | Non | Par défaut 500 ; 1 à 1000. |
| `cursor` | `String` | Non | Utilisez le nextCursor renvoyé avec des filtres inchangés ; arrêter lorsque hasMore est faux. |

L'exemple lit une page. Pour les champs obligatoires, la portée du joueur, la sémantique du filtre, la limite, le curseur et les tentatives limitées, suivez [Présentation de la requête](/fr/sdk/agent-sdk/java/perpetual-queries). Gardez tous les filtres inchangés pendant la pagination ; n’interprètez pas une erreur comme un résultat vide.

## Détails du remplissage des échanges

Interface : `trades`. Nécessite un platformUserIds.

| Champ `data` | taper | signification |
| --- | --- | --- |
| `fillId` | string | ID des détails de remplissage du commerce, correspondant à cet enregistrement entityId |
| `tradeId` | string | L'ID de transaction correspondant associé à la transaction ; ne remplace pas l'identifiant détaillé |
| `orderId` | string | L'ID de commande générale à laquelle appartient ce détail |
| `positionId` | string | ID de poste associé |
| `symbol` | string | paire de trading |
| `side` | string | Direction d'achat et de vente de ce joueur BUY / SELL |
| `roleType` | string | Le personnage de transaction de ce joueur MAKER / TAKER |
| `positionSide` | string | Sens de position, expliqué en fonction de la valeur réelle LONG / SHORT / BOTH etc. |
| `price` | string | Ce prix de transaction |
| `quantity` | string | La quantité de cette transaction n'est pas la quantité totale de la commande initiale. |
| `tradeValue` | string | La valeur nominale de cette transaction provient du notionnel de la transaction |
| `handlingFee` | string | Les frais de transaction pour cette transaction conservent le symbole de la source et l'exactitude, et ne prennent pas en eux-mêmes la valeur absolue. |
| `realizedPnl` | string | Le profit et la perte réalisés correspondant à cette opération ; pas le profit et la perte flottants en temps réel de la position actuelle |
| `tradedAt` | integer | Temps de transaction, millisecondes ; utiliser ce champ pour le filtrage temporel |

Une commande peut avoir plusieurs exécutions, qui doivent être enregistrées en détail. Ne fusionnez pas les enregistrements de différents joueurs/remplissez des rôles par tradeId, puis supprimez leurs identités d'enregistrement.
