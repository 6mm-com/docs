Le 6MM Agent SDK est destiné aux services backend partenaires qui doivent appeler l'agent privilégié APIs sans implémenter la signature et le traitement des demandes à partir de zéro. Il ne doit pas s'exécuter dans le code d'un navigateur, d'un appareil mobile ou d'un ordinateur de bureau public, car l'intégration utilise un secret API partenaire.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Quand utiliser le Agent SDK

Utilisez l’Agent SDK lorsque votre backend doit associer un utilisateur partenaire, transférer des actifs via un workflow approuvé, consulter les historiques de trading, créer une URL d’accès au trading intégré ou vérifier les notifications Webhook. Utilisez le [Trading Widget SDK](/fr/sdk/trading-widget/overview) séparément lorsque le frontend partenaire doit afficher l’interface de trading.

<span id="common-configuration" data-sixmm-canonical-anchor="common-configuration" aria-hidden="true"></span>

## Configuration commune

| Clé | Exemple | Description |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API service URL sans barre oblique finale. |
| agentCode | AGENT001 | Code de l'agent partenaire. |
| apiSecret | votre-api-secret | API secret de signature stocké uniquement sur le backend. |
| defaultCurrency | USDT | Devise par défaut pour le transfert et le compte APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Point de terminaison partenaire pour les notifications 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Flux d'intégration typique

1. L'interface du partenaire authentifie l'utilisateur via le propre système de compte du partenaire.
2. Le backend partenaire mappe l’utilisateur à un identifiant stable côté partenaire.
3. Le backend appelle le Agent SDK avec `agentCode` et le secret protégé API.
4. Le SDK signe et envoie la demande à l'agent API.
5. Le backend stocke l'identifiant d'entreprise renvoyé et traite ensuite webhooks de manière idempotente.
6. Le frontend ne reçoit que le résultat de courte durée ou les informations d’identification dont il a besoin.

## Liste de contrôle de production

- Chargez `apiSecret` à partir d'un gestionnaire de secrets backend, pas du code source.
- Séparez les informations d’identification en matière de développement, de préparation et de production.
- Utilisez un mappage d’utilisateurs partenaires stable et des identifiants de commandes commerciales uniques.
- Conservez l’identifiant d’origine lors de la vérification de l’état d’une demande expirée.
- Vérifiez les signatures webhook et stockez les ID d'événement traités.
- Supprimez les secrets et les signatures des journaux tout en conservant les ID de demande d’assistance.
