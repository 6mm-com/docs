<h2 id="service-endpoints">Points de terminaison de service</h2>

| Type      | Extrémité              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<h2 id="time-and-numeric-values">Temps et valeurs numériques</h2>

* Sauf indication contraire, les champs temporels sont des horodatages Unix milliseconde.
* Les statistiques quotidiennes, les instantanés de solde et les statistiques de volume de transactions utilisent par défaut les limites UTC jours.
* Les champs sensibles à la précision tels que quantité, prix, quantité et débit sont transmis sous forme de chaînes de caractères.
* Les grands IDs entiers tels que `orderId`, `conditionId`, et `strategyId` sont retournés sous forme de chaînes dans JSON.

<h2 id="response-format">Format de réponse</h2>

Réponse réussie :

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-12345678"
}
```

Réponse à l’erreur :

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Notes :

* Les erreurs métier retournent généralement toujours la structure JSON unifiée. Les intégrateurs doivent vérifier `code` d’abord.
* Les échecs d’authentification peuvent retourner HTTP `401`; la limitation de taux peut retourner HTTP `429`.
* Vous pouvez envoyer `X-Request-ID` dans l’en-tête de la requête. Le serveur le retournera comme `requestId` dans la réponse.
