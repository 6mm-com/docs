6MM Agentic AI Hub est l'interface native de AI-pour les données de marché 6MM, les flux de travail des comptes et les futures opérations de trading contrôlées.

Au lieu de basculer entre les tableaux de bord, les documents API et les scripts, les utilisateurs peuvent demander à un client IA d'interroger 6MM, d'expliquer les conditions du marché, d'examiner le risque du compte ou de préparer un aperçu de l'ordre. Le client AI ne remplace pas le modèle de sécurité 6MM API ; il appelle des outils 6MM structurés via CLI, MCP ou des modèles de workflow.

<span id="what-you-can-ask-an-ai-client" data-sixmm-canonical-anchor="what-you-can-ask-an-ai-client" aria-hidden="true"></span>

## Ce que vous pouvez demander à un client IA

Utilisez AI Hub lorsque vous souhaitez poser des questions telles que :

```text
Show me the BTC-USDT-PERP order book and explain current liquidity.
```

```text
Compare BTC and ETH funding rates over the last 24 hours.
```

```text
Check my testnet positions and explain liquidation risk. Do not place orders.
```

```text
Preview a small BTC long order and explain fees, margin impact, and risk checks.
```

<span id="why-ai-agents-need-a-dedicated-access-layer" data-sixmm-canonical-anchor="why-ai-agents-need-a-dedicated-access-layer" aria-hidden="true"></span>

## Pourquoi les agents IA ont besoin d'une couche d'accès dédiée

Les agents IA fonctionnent mieux lorsqu’ils disposent d’outils structurés plutôt que de pages Web brutes ou de texte copié non structuré. AI Hub leur offre :

| Exigence | Approche 6MM |
| --- | --- |
| Contexte de marché en direct | Outils et ressources de données de marché publiques pour les symboles, les carnets d'ordres, les transactions, le financement, les frais et les règles. |
| Effacer les autorisations | Séparez les données publiques, la lecture du compte, l'aperçu et les étendues de trading contrôlées. |
| Exécution plus sûre | Aperçu du flux de commande en premier, confirmation explicite, idempotence, limites et journaux d'audit. |
| Flexibilité client | Compétences hébergées MCP, locales MCP, CLI, distantes MCP et agents pour différents environnements d'IA. |

## Chemins de configuration

| Chemin | Idéal pour | L'utilisateur doit savoir |
| --- | --- | --- |
| Hébergé MCP | Accès rapide aux données du marché public | Aucune installation et aucune clé utilisateur API pour les données publiques. Le trading n’est pas l’objectif de la première version. |
| Local MCP | Clients IA qui ont besoin d'un contexte de compte privé | Le serveur MCP s'exécute localement et les informations d'identification restent sur la machine de l'utilisateur. |
| CLI | Agents de codage, scripts et utilisateurs de terminaux | Produit une sortie de commande conviviale pour les agents et peut être utilisé sans serveur MCP. |
| À distance MCP | Institutions et équipes qui souhaitent avoir leur propre point de terminaison | L'utilisateur ou l'institution contrôle l'hébergement, les informations d'identification, l'accès au réseau et les journaux. |
| Compétences d'agent | Flux de travail reproductibles | Les compétences guident l'IA à travers les étapes d'analyse et de risque à l'aide d'outils approuvés. |

## Ce qui est disponible en premier

AI Hub devrait commencer par des données du marché public et des ressources sur les règles commerciales :

- Marchés.
- Tickers.
- Commandez des carnets.
- Les métiers.
- Klines.
- Taux de financement.
- État du système.
- Frais, spécifications du contrat, règles de marge et ressources en matière de règles de risque.

L'accès au compte privé et le trading doivent être organisés :

- Les outils de lecture de compte nécessitent des informations d'identification explicites en lecture seule.
- L’aperçu de la commande doit intervenir avant toute véritable création de commande.
- Le trading contrôlé nécessite des étendues d'autorisation, des vérifications des risques côté service, une confirmation de l'utilisateur, une idempotence et des journaux d'audit.
