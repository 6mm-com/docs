Le trading intégré est généralement introduit dans un produit existant, et n’est pas lancé comme une destination autonome. La meilleure voie d’intégration dépend de l’endroit où les utilisateurs passent déjà du temps et du système qui possède l’identité, les fonds et les opérations.

<h2 id="common-scenarios">Scénarios courants</h2>

| Scénario | Meilleur point de départ | Notes |
| --- | --- | --- |
| L’application ou le portefeuille demande une entrée de trading | Trading Widget SDK | Utilisez un point d’entrée natif ou H5 et ouvrez l’expérience de trading intégrée après l’autorisation utilisateur. |
| Le courtier ou la plateforme de distribution souhaite l’accès aux dérivés | Agent SDK + Trading Widget SDK | Gardez la relation client et la validation backend dans le système partenaire. |
| La plateforme souhaite un flux de trading guidé | API + modules SDK sélectionnés | Utilisez les APIs backend pour les flux de travail de compte, de transfert et de commande tout en exposant uniquement l’entrée frontale nécessaire. |
| La bourse existante souhaite des marchés supplémentaires | Intégration liquidité + API | Alliez la profondeur du marché, les flux de travail de compte et la surveillance opérationnelle. |

<h2 id="product-decisions-before-integration">Décisions produit avant l’intégration</h2>

- Décider si les utilisateurs entrent depuis une carte de page d’accueil, une page d’actifs, une page de campagne ou un centre de compte.
- Décider quel système possède l’état de connexion, l’éligibilité des utilisateurs et la disponibilité dans le pays ou la région.
- Décider comment les transferts, les registres de règlement et les tickets de support client sont affichés aux utilisateurs.
- Décider quels événements doivent être transférés dans l’analytique interne, la CRMou les opérations de risque.
