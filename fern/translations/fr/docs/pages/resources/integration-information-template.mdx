Utilisez ce modèle lors de la préparation d’une nouvelle intégration ou lors du passage en production d’une intégration existante.

<h2 id="partner-information">Informations sur les partenaires</h2>

| Terrain | Description |
| --- | --- |
| Nom du partenaire | Nom légal ou de projet utilisé pour l’intégration. |
| Type de produit | App, portefeuille, portail courtier, plateforme d’échange en marque blanche, plateforme institutionnelle ou autre. |
| Contacts principaux | Contacts professionnels, techniques, opérationnels et d’urgence. |
| Régions de lancement | Pays ou régions où l’intégration sera exposée. |

<h2 id="technical-information">Informations techniques</h2>

| Terrain | Description |
| --- | --- |
| Domaines frontend | Des domaines qui chargeront le widget ou les pages d’entrée. |
| Domaines backend | Domaines de serveur utilisés pour les appels Agent SDK ou API . |
| Webhook URL | Endpoint webhook de production et exigences attendues IP liste d’autorisations. |
| Portée d’intégration | Trading Widget, Agent SDK, REST API, WebSocket, système en marque blanche ou intégration de liquidité. |

<h2 id="operational-information">Informations opérationnelles</h2>

- Date de lancement prévue.
- Trafic attendu ou plage d’utilisateurs actifs.
- Responsable des heures de support et de l’escalade.
- Surveillance du propriétaire et du contact des incidents.

<h2 id="security-and-review-information">Informations de sécurité et de révision</h2>

- Méthode d’authentification et API Key portée des permissions.
- Stockage secret, propriétaire de rotation et IP source approuvées.
- Vérification de signature Webhook et conception d’idempotence.
- Propriétaires de la journalisation, de la surveillance, du rapprochement, du retour en arrière et de la réponse aux incidents.
- Marchés cibles, type d’utilisateur, modèle de garde et l’entité responsable des obligations à l’égard des utilisateurs.

N’incluez pas les secrets de production, les jetons d’accès complets, les clés privées ou les données utilisateur non expurgées dans ce modèle.

Utilisez la [checklist de lancement en production](/fr/resources/production-launch-checklist) pour l’approbation finale et le [support request template](/fr/resources/support-request-template) pour l’escalade des problèmes.
