Utilisez l'historique des conversations pour récupérer le contexte, examiner la qualité du service et enquêter sur une consultation spécifique. Commencez par un numéro de conversation ou une plage horaire étroite au lieu de parcourir chaque enregistrement.

<div className="sixmm-support-flow">

1. **Trouver la session** — Choisissez les filtres et la base de date correcte.
2. **Lire le contexte complet** — Consultez les messages, les détails de l'agent et du visiteur.
3. **Suivi** — Améliorez une réponse ou poursuivez le cas non résolu.

</div>


<span id="find-an-earlier-conversation" data-sixmm-canonical-anchor="find-an-earlier-conversation" aria-hidden="true"></span>

## Rechercher une conversation antérieure

Ouvrez **Historique des conversations**. Utilisez les filtres disponibles de recherche d'utilisateur/session, de type de conversation, d'évaluation, d'agent, de catégorie, de langue et de temps. Ouvrez les détails pour lire les messages et les informations de session.

La colonne de la liste de courrier électronique des utilisateurs préfère l'e-mail du contact et utilise sinon l'e-mail du visiteur. La vue détaillée conserve les deux champs afin que les agents puissent distinguer leurs sources. Une valeur vide signifie que ce champ n'a pas été collecté ; cela ne prouve pas qu'un client n'a pas de compte de messagerie.

<span id="review-service-quality" data-sixmm-canonical-anchor="review-service-quality" aria-hidden="true"></span>

## Vérifier la qualité du service

Utilisez la conversation, l'agent et l'évaluation ensemble pour comprendre le cas. Une réponse affichée sous forme de message AI peut provenir d'une réponse configurée ou d'une étape de correspondance plutôt que d'un appel à grande échelle. Comparez le contenu avec les connaissances actuelles et utilisez un test de flux lors de l'étude du comportement de réponse.

La suppression n'est disponible qu'avec les autorisations appropriées. Lisez la confirmation avant de supprimer un ou plusieurs enregistrements. Les requêtes d'historique MCP utilisent la portée autorisée et la suppression nécessite une confirmation ; ne présumez pas que l’historique complet des locataires est disponible pour chaque agent.


<span id="read-the-fields-without-mixing-identities" data-sixmm-canonical-anchor="read-the-fields-without-mixing-identities" aria-hidden="true"></span>

## Lire les champs sans mélanger les identités

| Champ | Interprétation |
| --- | --- |
| Numéro de conversation | Identifie la consultation que vous examinez. Utilisez-le pour éviter de confondre des sessions distinctes. |
| Nom du visiteur | Une étiquette d'affichage lisible, pas une preuve d'un compte d'échange vérifié. |
| Type d'entrée et ID utilisateur | Aide à distinguer l’accès anonyme d’une identité de connexion intégrée. Les données d'identité manquantes ne doivent pas être devinées. |
| E-mail de l'utilisateur | Utilise d'abord l'e-mail du contact, puis l'e-mail du visiteur ; les détails maintiennent les deux sources séparées. |
| Langue et localisation IP | Contexte utile pour l'assistance, pas une preuve de l'identité de l'utilisateur ou de sa localisation physique exacte. |
| Notation | Commentaires qui existent pour cette session. Aucune note n’est la même chose qu’une note négative. |

<span id="example-review-a-low-rated-consultation" data-sixmm-canonical-anchor="example-review-a-low-rated-consultation" aria-hidden="true"></span>

### Exemple : examiner une consultation mal notée

1. Filtrez par date, agent et note, le cas échéant, puis ouvrez le dossier complet.
2. Lisez ce que le visiteur a demandé avant d'évaluer la réponse. Vérifiez si un transfert ou un malentendu linguistique a affecté la conversation.
3. Si la réponse était incomplète, examinez le contenu des connaissances et la configuration du bot correspondants. Un mauvais résultat ne signifie pas toujours que le modèle lui-même a échoué.
4. Conservez le numéro de séance avec votre suivi interne afin que l’équipe puisse revenir sur les mêmes preuves.

## Questions courantes

<AccordionGroup>

<Accordion title="Pourquoi l'e-mail est-il vide ?">
La session n'a peut-être pas collecté d'e-mail de contact ou reçu d'e-mail de l'intégration d'entrée. Examinez les deux champs en détail avant de conclure que les données sont manquantes de manière inattendue.
</Accordion>

<Accordion title="Pourquoi la modification du filtre de date modifie-t-elle les résultats ?">
La page peut filtrer par heure de début ou heure de fermeture. Une conversation qui commence un jour et se termine un autre appartient à des résultats différents selon ces deux choix.
</Accordion>

</AccordionGroup>
