El 6MM Agent SDK es para servicios de backend asociados que necesitan llamar a APIs de Agente privilegiado sin implementar la gestión de firmas y solicitudes desde cero. No debe ejecutarse en código de navegador, móvil o escritorio público porque la integración utiliza un socio API secreto.

<h2 id="when-to-use-the-agent-sdk">¿Cuándo usar el Agent SDK</h2>

Utiliza un Agent SDK cuando tu backend necesite vincular a un usuario socio, mueve activos por un flujo de trabajo aprobado, consulta registros de trading, crea una entrada de trading incrustada URLo verifica notificaciones de webhook. Usa el [Trading Widget SDK](/es-AR/sdk/trading-widget/overview) por separado cuando el frontend del socio necesite mostrar la interfaz de trading.

<h2 id="common-configuration">Configuración común</h2>

| Clave | Ejemplo | Descripción |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API servicio URL sin barra lateral. |
| agentCode | AGENT001 | Código de agente asociado. |
| apiSecret | tu-api-secreto | API secreto de firma almacenado solo en el backend. |
| defaultCurrency | USDT | Moneda predeterminada para transferencias y APIsde cuenta. |
| webhookUrl | https://partner.example.com/6mm/webhook | Endpoint de socios para notificaciones de 6MM webhook. |

<h2 id="typical-integration-flow">Flujo típico de integración</h2>

1. El frontend del socio autentica al usuario a través del propio sistema de cuenta del socio.
2. El backend del socio asigna al usuario a un identificador estable del lado del socio.
3. El backend llama al Agent SDK con `agentCode` y el API protegido secreto.
4. El SDK firma y envía la solicitud API Agente.
5. El backend almacena el identificador de negocio retornado y procesa los webhooks posteriores de manera idempotente.
6. El frontend solo recibe el resultado efímero o la credencial de entrada que necesita.

<h2 id="production-checklist">Lista de verificación de producción</h2>

- Cargar `apiSecret` desde un gestor de secretos backend, no desde el código fuente.
- Mantener separadas las credenciales de desarrollo, puesta en escena y producción.
- Utilizar un mapeo de usuario de socios estables e identificadores únicos de órdenes de negocio.
- Conservar el identificador original al comprobar el estado de una solicitud con tiempo de espera.
- Verificar firmas de webhook y almacenar los IDs de eventos procesados.
- Redactar secretos y firmas de los registros mientras se conservan los IDs de solicitud para el soporte.
