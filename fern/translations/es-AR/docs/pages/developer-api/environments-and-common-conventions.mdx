<h2 id="service-endpoints">Puntos finales de servicio</h2>

| Tipo      | Punto final              |
| --------- | --------------------- |
| REST API  | `https://api.6mm.com` |
| WebSocket | `wss://ws.6mm.com/ws`    |

<h2 id="time-and-numeric-values">Tiempo y valores numéricos</h2>

* Salvo que se especifique lo contrario, los campos de tiempo son marcas de tiempo de milisegundos de Unix.
* Las estadísticas diarias, instantáneas de saldo y estadísticas de volumen de operaciones utilizan por defecto los límites UTC días.
* Los campos sensibles a la precisión como cantidad, precio, cantidad y tasa se transmiten como cadenas.
* Los IDs enteros grandes como `orderId`, `conditionId`y `strategyId` se devuelven como cadenas en JSON.

<h2 id="response-format">Formato de respuesta</h2>

Respuesta exitosa:

```json
{
  "code": 0,
  "message": "success",
  "data": {},
  "requestId": "req-12345678"
}
```

Respuesta al error:

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Notas:

* Los errores de negocio suelen seguir devolviendo la estructura unificada de JSON . Los integradores deberían comprobar `code` primero.
* Los fallos de autenticación pueden devolver HTTP `401`; La limitación de velocidad puede devolver HTTP `429`.
* Puedes enviar `X-Request-ID` en la cabecera de la solicitud. El servidor lo devolverá como `requestId` en la respuesta.
