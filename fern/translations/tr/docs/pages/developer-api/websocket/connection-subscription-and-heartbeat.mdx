Piyasa verileri ve özel kullanıcı durumu güncellemeleri için WebSocket akışlarını kullanın; bu güncellemeler anket olmadan güncel kalmalıdır.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Bağlantı URL

```text
wss://ws.6mm.com/ws
```

Özel akışlar, özel kanal dokümantasyonunda tanımlandığı gibi listenKey veya erişim belirteci gibi kimlik doğrulama bağlamı gerektirir.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## Abone Olun

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Başarılı abonelik onayı:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## Abonelikten Çekilme

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

<span id="application-ping" data-sixmm-canonical-anchor="application-ping" aria-hidden="true"></span>

## Uygulama pingi

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<span id="message-envelope" data-sixmm-canonical-anchor="message-envelope" aria-hidden="true"></span>

## Mesaj zarfı

Kamu baskıları tutarlı bir zafı kullanır:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## Operasyonel öneriler

- Her abonelik, abonelikten çıkarma ve ping talebi için benzersiz bir istemci tarafı `id` oluşturun.
- Yeniden bağlantı kurmayı yeni bir oturum olarak ele alın ve gerekli konulara yeniden abone olun.
- Geri gönderilen `topic` hizmetinizin beklediği kanalla eşleşip eşleşmediğini doğrulayın.
- Özel sipariş veya hesap olayları olduğunda mesaj işleme idempotent kalın.
- Bağlantı durumu değişikliklerini, abonelik onaylarını ve anormal bağlantı kesilmelerini kaydet.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## Yeniden Bağlantı İş Akışı

1. Önceki soketi kapatın veya atın ve yeni bir bağlantı oluşturun.
2. Geçerli bir listenKey veya erişim tokenı ile özel akışları yeniden doğrulayın.
3. Gerekli her konuya yeniden abone olun ve başarılı teşekkürleri bekleyin.
4. Yerel sipariş defteri durumunu yeni, ardından kademeli güncellemeler uygulamadan önce yeni bir anlık görüntüyle değiştirin.
5. Açık emirleri, pozisyonları ve bakiyeleri REST özel etkinliklerin kaçırıldığı durumlarda uzlaştırın.

Yeniden bağlantı girişimleri için jitter ile sınırlı üstel geri çekilme kullanın. Sürekli yeniden bağlanan bir istemci, görünürlük olmadan süresiz tekrar denemek yerine operatörleri uyarmalıdır.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## Kalp atışı ve bayat bağlantılar

- En son gelen mesajı ve başarılı ping onayını takip edin.
- Üretim ortamı için onaylanan kalp atış aralığı ve boşta eşik değerini kullanın.
- Yapılandırma eşiği aşıldığında, TCP soketi hala açık görünse bile, bağlantıyı bayat olarak kabul edin.
- Eski bir soketten abonelikleri tekrar kullanmayın; Her yeniden bağlantıdan sonra açıkça yeniden abone ol.
