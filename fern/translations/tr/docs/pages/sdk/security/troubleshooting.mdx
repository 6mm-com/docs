Başarısız işlemin ortamı, zaman damgası ve iş tanımlayıcısıyla başlayın. Yapılandırılmış bir kontrol genellikle yapılandırma sorunlarını kimlik doğrulama, ağ ve eşzamansız işleme sorunlarından ayırır.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Önerilen teşhis sırası

1. Etkilenen ortamı ve tabanı URL doğrulayın.
2. UTC zaman aralığını ve ilk başarısız isteği kaydedin.
3. Modülü tanımlayın: Trading Widget, Agent SDK, REST API, WebSocket veya webhook.
4. İstek kimliğini, iş ortağı kullanıcı kimliğini, `agentOrderNo`, sipariş kimliğini veya webhook olay kimliğini yakalayın.
5. En son kodu, kimlik bilgilerini, IP beyaz listeyi veya dağıtım değişikliklerini kontrol edin.
6. En küçük güvenli test durumuyla çoğaltın.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget sorunlar

| Belirti | Muhtemel sebep | Düzeltmek |
| --- | --- | --- |
| iframe, iş ortağının yerel alan adını ister | baseUrl eksik | baseUrl iletin: 'https://app.6mm.com'. |
| iframe görünmez veya çok kısa | Ana kabın yüksekliği yok | Konteyner yüksekliğini veya geçiş yüksekliğini ayarlayın. |
| token_provider_missing | iş ortağı belirteci modunun sağlayıcısı yok | Kimlik doğrulama ekletokenProvider. |
| auth_exchange_failed | Geçersiz, süresi dolmuş veya eşleşmeyen yerleştirme jetonu | Arka uç jeton yanıtını ve channelId kontrol edin. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK sorunlar

| Belirti | Muhtemel sebep | Düzeltmek |
| --- | --- | --- |
| İmza reddedildi | Yanlış sır, saat kayması veya imzalı alanların manuel olarak değiştirilmesi | SDK'in imzalama alanları oluşturmasına ve sunucu zamanını senkronize etmesine izin verin. |
| Yinelenen fon hareketi riski | Zaman aşımından sonra kullanılan yeni sipariş numarası | Önce orijinal agentOrderNo ile sorgulayın. |
| PROCESSING başarısızlık olarak değerlendirildi | Bekleme durumu yanlış anlaşıldı | webhook bekleyin veya queryOrder'i arayın. |
| Webhook birden çok kez işlendi | İdempotans olmadan davranışı yeniden dene | Bağımsızlık anahtarı ve son durum kontrollerini ekleyin. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Yakalanacak kanıt

| Entegrasyon | Yararlı kanıtlar |
| --- | --- |
| Trading Widget | Sayfa URL, SDK sürüm yolu, tarayıcı konsolu, başarısız ağ istekleri, `onError` yükü ve kapsayıcı boyutları. |
| Agent SDK | SDK dil/sürüm, temel URL, UTC zaman damgası, istek kimliği, `agentOrderNo`, yanıt kodu ve temizlenmiş günlükler. |
| Webhook | Teslim süresi, olay veya iş anahtarı, imza doğrulama sonucu, işleme durumu ve sterilize edilmiş ham gövde karması. |
| REST API | Yöntem, yol, ortam, istek kimliği, yanıt kodu ve arındırılmış parametreler. |

Tanılamaya hiçbir zaman parolaları, erişim belirteçlerini, API sırları, tam imzaları, özel anahtarları veya düzenlenmemiş kişisel verileri dahil etmeyin.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Sorunu tırmandırmadan önce

- Yalnızca işlemin yeniden denemenin güvenli olduğu belgelendiğinde yeniden deneyin.
- Zaman aşımından sonra yeni bir işletme tanımlayıcısı oluşturmak yerine orijinal işletme tanımlayıcısını sorgulayın.
- İmza hataları için sistem saatini ve kimlik bilgisi ortamını doğrulayın.
- İlk başarısızlığı ve daha sonraki yeniden deneme sonuçlarını koruyun.
- Kullan [Destek Talebi Şablonu](/tr/resources/support-request-template) Tam, düzeltilmiş bir rapor göndermek için.

## Java v0.3.0 teşhisi

| Belirti | Kontrol ve kurtarma |
| --- | --- |
| Finansman isteğinin bilinmeyen bir sonucu var | Orijinali saklayın `agentOrderNo`; orijinal ortamla `queryWalletTransfer`'i arayın. `queryOrder` kullanmayın. |
