Avvalo, muvaffaqiyatsiz operatsiya uchun muhit, vaqt tamg'asi va biznes identifikatoridan boshlang. Tuzilgan tekshiruv odatda konfiguratsiya muammolarini autentifikatsiya, tarmoq va asinxron ishlov berish muammolaridan ajratadi.

<h2 id="diagnostic-order">Tavsiya etilgan diagnostika tartibi</h2>

1. Ta'sirlangan muhit va asosiy URLtasdiqlang.
2. UTC vaqt oralig'ini va birinchi muvaffaqiyatsiz so'rovni yozib oling.
3. Modulni aniqlang: Trading Widget, Agent SDK, REST API, WebSocket, yoki webhook.
4. So'rov ID, hamkor foydalanuvchi ID, `agentOrderNo`, buyurtma ID yoki webhook hodisa IDsini yozib oling.
5. So'nggi kod, credential, IP oq ro'yxati yoki joylashtirish o'zgarishlarini tekshiring.
6. Eng kichik xavfsiz test holati bilan ko'paytiring.

<h2 id="trading-widget-issues">Trading Widget masalalari</h2>

| Simptom | Ehtimoliy sabab | Tuzatish |
| --- | --- | --- |
| iframe hamkor mahalliy domenini so'raydi | baseUrl yo'qolgan | Pass baseUrl: 'https://app.6mm.com'. |
| iFrame ko'rinmas yoki juda qisqa | Ota konteynerning balandligi yo'q | Konteyner balandligini yoki uzatish balandligini belgilang. |
| token_provider_missing | Hamkor-token rejimida provayder yo'q | Auth.tokenProviderqo'shing. |
| auth_exchange_failed | Noto'g'ri, muddati o'tgan yoki mos kelmaydigan embed tokeni | Backend token javobini tekshiring va channelId. |

<h2 id="agent-sdk-issues">Agent SDK masalalari</h2>

| Simptom | Ehtimoliy sabab | Tuzatish |
| --- | --- | --- |
| Imzo rad etildi | Noto'g'ri sir, soat siljishi yoki qo'lda o'zgartirilgan imzolangan maydonlar | SDK imzo maydonlarini yaratib, server vaqtini sinxronlashtirsin. |
| Duplikat mablag' harakati xavfi | Tanaffusdan keyin yangi buyurtma raqami qo'llanildi | Asl so'rov agentOrderNo birinchi. |
| PROCESSING muvaffaqiyatsizlik sifatida ko'riladi | Kutilayotgan davlat noto'g'ri tushunilishi | Webhookni kuting yoki queryOrderqo'ng'iroq qiling. |
| Webhook bir necha marta qayta ishlangan | Idempotency bo'lmagan qayta urinish xatti-harakati | Idempotency kalitini va yakuniy holat tekshiruvlarini qo'shing. |

<h2 id="evidence-to-capture">Qo'lga olish uchun dalillar</h2>

| Integratsiya | Foydali dalillar |
| --- | --- |
| Trading Widget | Sahifa URL, SDK versiya yo'li, brauzer konsoli, muvaffaqiyatsiz tarmoq so'rovlari, `onError` yuk va konteyner o'lchamlari. |
| Agent SDK | SDK til/versiya, asosiy URL, UTC vaqt tamg'asi, so'rov ID, `agentOrderNo`, javob kodi va tozalangan jurnallar. |
| Webhook | Yetkazib berish vaqti, voqea yoki biznes kaliti, imzo-tasdiqlash natijasi, ishlov berish holati va tozalangan xom korpus xeshi. |
| REST API | Metod, yo'l, muhit, so'rov identifikatori, javob kodi va tozalangan parametrlar. |

Hech qachon parollar, kirish tokenlari, API sirlar, to'liq imzolar, shaxsiy kalitlar yoki tahrirlanmagan shaxsiy ma'lumotlarni diagnostikaga kiritmang.

<h2 id="before-escalating">Keskinlashishdan oldin</h2>

- Faqat operatsiya qayta sinab ko'rish xavfsiz deb hujjatlashtirilganda qayta urinib ko'ring.
- Timeoutdan so'ng, yangi identifikator yaratish o'rniga asl biznes identifikatorini so'rang.
- Imzo xatolari uchun tizim soati va credential muhitini tasdiqlang.
- Birinchi muvaffaqiyatsizlik va keyingi qayta urinish natijalarini saqlab qolish.
- [Support Request Template](/tr/resources/support-request-template) dan foydalanib, to'liq, yashirilgan hisobotni yuboring.
