Agent SDK isteklerinin kimliği, bir iş ortağının API sırrıyla doğrulanır. Bu sırrı güvenilir bir arka uç hizmetinde saklayın ve mümkün olduğunda SDK'nin imzalama alanları oluşturmasına izin verin.

> **İki imzalama protokolü**
>
> Agent SDK imzalama, sıralanmış istek alanlarını, saniyeye dayalı bir zaman damgasını ve bir kez olmayanı kullanır. Doğrudan Developer API istekleri, içinde açıklanan ayrı süreci kullanır. [İmza İsteği](/tr/developer-api/request-signing). Bir veri yükü biçimini diğeri için yeniden kullanmayın.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## İmza kuralı

Agent SDK istekleri için:

1. `sign` alanını hariç tutun.
2. Boş değerleri olan alanları atlayın.
3. Kalan alan adlarını ASCII sırasına göre sıralayın.
4. Alanlara `k=v&k2=v2` olarak katılın.
5. HMAC-SHA256 onaltılı imzayı `apiSecret` ile hesaplayın.

Dizi değerleri, imzalama yüküne katılmadan önce kompakt JSON olarak serileştirilir. Örneğin, `platformUserIds`, `["1188041528"]` olarak işaretler ve `k=v` yükünde `platformUserIds=["1188041528"]` verir. Dizi öğesi sırasını, çift tırnakları ve dize kimliklerini koruyun; biçimlendirme boşlukları eklemeyin veya Java `List.toString()` (`[1188041528]` gibi) kullanmayın. SDK bu serileştirmeyi otomatik olarak gerçekleştirir.

SDK bu değeri gönderdiği verilerden oluşturmalıdır. İmza oluşturulduktan sonra imzalı bir alanın değiştirilmesi doğrulamanın başarısız olmasına neden olur.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## SDK-yönetilen alanlar

| Alan | Kaynak | Tanım |
| --- | --- | --- |
| agentCode | SDK yapılandırma | İş ortağı temsilcisi kodu. |
| zaman damgası | Geçerli sunucu zamanı | Saniye cinsinden Unix zaman damgası. |
| bir kez | Güvenli rastgele değer | Tekrar korumalı rastgele dizi. |
| imza | HMAC-SHA256 | İmza isteyin. |
| para birimi | Varsayılan para birimi | Transfer/hesap APIs para birimini çıkardığında kullanılır. |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## Gizli depolama

- Bir arka uç gizli yöneticisinden veya korumalı çalışma zamanı yapılandırmasından `apiSecret` dosyasını yükleyin.
- Sırrı asla ön uç paketlerine, mobil uygulamalara, masaüstü istemcilere, ekran görüntülerine veya destek biletlerine koymayın.
- Geliştirme, hazırlama ve üretime ilişkin kimlik bilgilerini ayrı tutun.
- Gereken hizmetlere ve operatörlere erişimi sınırlayın.
- Günlüklerden istek imzalarını, yetkilendirme değerlerini ve gizli dizileri çıkarın.
- Etkilendiğinden şüphelenildiğinde kimlik bilgilerini iptal edin ve değiştirin.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Saat ve tekrar koruması

SDK, tekrar oynatma riskini azaltmak için `timestamp` ve `nonce` içerir. Arka uç saatlerini senkronize tutun ve manuel olarak oluşturulmuş bir kezliği yeniden kullanmayın. İmza doğrulaması başarısız olursa, yeniden denemeden önce yapılandırılmış sırrı, sunucu saatini, serileştirilmiş alanları ve ortamı onaylayın.

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## Entegrasyon kontrol listesi

| Kontrol etmek | Beklenen sonuç |
| --- | --- |
| Gizli konum | Yalnızca arka uçta gizli depolama. |
| Çevre | Temel URL ve kimlik bilgisi aynı ortama aittir. |
| Saha kullanımı | SDK, `timestamp`, `nonce` ve `sign` üretir. |
| Günlüğe kaydetme | Kimlik bilgileri düzenlenirken işletme kimlikleri görünür durumda kalır. |
| Döndürme | Kimlik bilgisi sahibi ve değiştirme süreci belgelenir. |
