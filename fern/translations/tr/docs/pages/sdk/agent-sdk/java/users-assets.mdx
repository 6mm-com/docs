Bu kılavuz **Agent Java SDK `v0.3.0`**, Java 8+ ve etiketli kamu sözleşmesini hedefler. Örnekler, `client` başlatıldıktan sonra bir iş ortağı arka ucunda çalıştırılır. [Hızlı Başlangıç](/tr/sdk/agent-sdk/java/quick-start).

<span id="example-prerequisites" data-sixmm-canonical-anchor="example-prerequisites" aria-hidden="true"></span>

## Örnek önkoşullar

Java parçacıkları bu içe aktarmaları paylaşır. Hızlı Başlangıç'ı kullanarak `client`'ı başlatın ve kaydedilen bağlamadan `platformUserId`'i edinin. Örnek kullanıcı/sipariş kimlikleri kendi kalıcı değerlerinizle değiştirilmelidir.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

<span id="user-id-rules" data-sixmm-canonical-anchor="user-id-rules" aria-hidden="true"></span>

## Kullanıcı Kimliği Kuralları

`platformUserId`, 6MM harici kullanıcı kimliğidir. Şu anda 10 haneli bir rakamdır
dize, örneğin:

```text
1188041528
```

Tüzük:

- Tamsayı olarak değil, dize olarak saklayın.
- Bundan anlam üretmeyin, kodunu çözmeyin veya çıkarmayın.
- Kendi iş ortağı tarafı kullanıcı kimliğinizi `agentUserId` olarak kullanın.
- `agentUserId`, `platformUserId` ve `agentOrderNo` arasındaki ilişkiyi sürdürün.


<span id="bind-user" data-sixmm-canonical-anchor="bind-user" aria-hidden="true"></span>

## Kullanıcıyı Bağla

Bind, bir iş ortağı kullanıcısı ile bir 6MM arasındaki ilişkiyi oluşturur veya getirir
platformu kullanıcısı Kullanıcı işlem akışına ilk girdiğinde veya işlem yapılmadan önce bunu çağırın.
6MM'a ilk transfer.

```java
import com.sixmm.agent.model.BindRequest;
import com.sixmm.agent.model.BindResponse;

BindResponse resp = client.bind(
        BindRequest.of("agent-user-001")
                .withUsername("alice")
                .withExt("{\"source\":\"web\"}"));

System.out.println(resp.platformUserId);
System.out.println(resp.bindStatus);
System.out.println(resp.isSimulatedUser);
```

Talep alanları:

| Alan | Tip | Gerekli | Tanım |
| --- | --- | --- | --- |
| `agentUserId` | string | Evet | Benzersiz iş ortağı tarafı kullanıcı kimliği |
| `username` | string | HAYIR | Platform kullanıcısının takma adı olarak kullanılan iş ortağı tarafında görünen ad |
| `ext` | string | HAYIR | Uzatma alanı. JSON dizesi önerilir |

Yanıt alanları:

| Alan | Tip | Tanım |
| --- | --- | --- |
| `platformUserId` | string | 6MM harici kullanıcı kimliği |
| `bindStatus` | string | Genellikle `BOUND` |
| `isSimulatedUser` | boolean | Bunun simüle edilmiş bir kullanıcı olup olmadığı |


<span id="query-partner-account" data-sixmm-canonical-anchor="query-partner-account" aria-hidden="true"></span>

## İş Ortağı Hesabını Sorgula

```java
import com.sixmm.agent.model.QueryAccountRequest;
import com.sixmm.agent.model.QueryAccountResponse;

QueryAccountResponse resp = client.queryAccount(QueryAccountRequest.of("USDT"));

System.out.println(resp.agentCode);
System.out.println(resp.agentStatus);
resp.assets.forEach(asset -> {
    System.out.println(asset.currency);
    System.out.println(asset.depositBalance);
});
```

`currency` bulunmadığında, SDK, `defaultCurrency` öğesini kullanır.

## Kullanıcı Varlıklarını Sorgula

```java
import com.sixmm.agent.model.QueryUserAssetsRequest;
import com.sixmm.agent.model.QueryUserAssetsResponse;

QueryUserAssetsResponse resp = client.queryUserAssets(
        QueryUserAssetsRequest.of("1188041528"));

System.out.println(resp.walletBalance);
System.out.println(resp.availableBalance);
System.out.println(resp.version);
```

Alanlar:

| Alan | Tip | Tanım |
| --- | --- | --- |
| `walletBalance` | string | Cüzdan bakiyesi |
| `frozenMargin` | string | Dondurulmuş marj |
| `usedMargin` | string | Kullanılan marj |
| `availableBalance` | string | Mevcut bakiye |
| `isolatedMargin` | string | İzole kenar boşluğu |
| `version` | int64 | Varlık sürümü |
| `isSimulatedUser` | boolean | Bunun simüle edilmiş bir kullanıcı olup olmadığı |


<span id="distinguish-the-three-wallets" data-sixmm-canonical-anchor="distinguish-the-three-wallets" aria-hidden="true"></span>

### Üç cüzdanı ayırt edin

| cüzdan | Denge kaynağı | kullanmak |
| --- | --- | --- |
| Satıcının kendi kullanıcı cüzdanı | Satıcının kendi muhasebe sistemi | Kullanıcının satıcı tarafındaki mevcut bakiyesi |
| Platform Finansmanı | `queryUserAssets` / `funding` | Saniye alım satım fonları ve Finansman/Sözleşme karşılıklı transferi |
| Platform Sözleşmesi | `queryUserAssets` sözleşme varlığı alanı | Sürekli sözleşme marjı ve devredilebilir bakiye |

`queryAccount` Satıcı kullanıcı cüzdanını değil, satıcı platformu marj hesabını sorgulayın. Bu arayüzde `environment` parametreler yoktur ve simüle edilmiş bir kullanıcı varlığı olarak sorgulanamaz.

Simüle edilmiş kullanıcıların iki platform cüzdanını sorgulayın:

```java
QueryUserAssetsResponse assets = client.queryUserAssets(
        QueryUserAssetsRequest.of(platformUserId)
                .withFunding()
                .withEnvironment(ExecutionEnvironment.SIMULATED));
```

Arayüz: `POST /v1/agent/query-user-assets`. Finansman yalnızca `includeFunding=true` olduğunda talep edilir; orijinal sözleşme varlığı sorgu semantiği varsayılan olarak kullanılır.

| yanıt alanları | Anlam |
| --- | --- |
| `walletBalance`, `availableBalance`, `frozenMargin`, `usedMargin`, `isolatedMargin` | Sözleşme cüzdanıyla ilgili tutarlar |
| `funding.assetCode` | Şu anda USDT |
| `funding.availableAmount`, `heldAmount`, `totalAmount` | Mevcut fon, dolu ve toplam tutar |
| `funding.materialized` | Finansman hesabının hayata geçirilip geçirilmediği? |
| `environment` | Bu alan, ortam açıkça iletildiğinde yankılanır; ortamı atlayan eski istekler bu alanı döndürmez. |
| `isSimulatedUser` | Hesap sınıflandırması; ticaret ortamı seçiminin yerini alamaz |

Tutarlar, `float`/`double` olarak değil, dizeler veya `BigDecimal` olarak işlenir.
