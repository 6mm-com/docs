## Örnek önkoşullar

Java parçacıkları bu içe aktarmaları paylaşır. Hızlı Başlangıç'ı kullanarak `client`'ı başlatın ve kaydedilen bağlamadan `platformUserId`'i edinin. Örnek kullanıcı/sipariş kimlikleri kendi kalıcı değerlerinizle değiştirilmelidir.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

## `listPerpetualTrades`

Talep modeli: `PerpetualTradesRequest`.

```java
import com.sixmm.agent.model.PerpetualTradesRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualTradesRequest request = new PerpetualTradesRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualTrades(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Talep alanları

| Alan | Java türü | Gerekli | Anlam |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Koşullu | 1-100 benzersiz genel kimlik; Dolumlar ve koşullu siparişler için gereklidir. Doğrudan oynatıcı kapsamı için desteklenen sorguları hariç tutun; [] geçersiz. |
| `symbol` | `String` | HAYIR | İsteğe bağlı işlem çifti filtresi. |
| `orderId` | `String` | HAYIR | Sıradan sipariş kimliği; iş ortağı transfer emri numarası değil. |
| `startTime` | `Long` | HAYIR | Kapsamlı Unix milisaniye; sabit bir UTC geçmiş penceresi kullanın. |
| `endTime` | `Long` | HAYIR | Özel Unix milisaniyesi. |
| `limit` | `Integer` | HAYIR | Varsayılan 500; 1–1000. |
| `cursor` | `String` | HAYIR | Döndürülen nextCursor öğesini değişmemiş filtrelerle kullanın; hasMore yanlış olduğunda dur. |

Örnek bir sayfayı okuyor. Gerekli alanlar, oynatıcı kapsamı, filtre semantiği, limit, imleç ve sınırlı yeniden denemeler için aşağıdaki adımları izleyin [Sorguya genel bakış](/tr/sdk/agent-sdk/java/perpetual-queries). Sayfalama sırasında tüm filtreleri değiştirmeden tutun; Bir hatayı boş bir sonuç olarak yorumlamayın.

## Ticaret doldurma ayrıntıları

Arayüz: `trades`. Açıkça platformUserIds gerektirir.

| `data` alanı | tip | Anlam |
| --- | --- | --- |
| `fillId` | string | Bu kayda karşılık gelen takas doldurma ayrıntıları kimliği entityId |
| `tradeId` | string | İşlemle ilişkili eşleşen işlem kimliği; ayrıntılı kimliğin yerine geçmez |
| `orderId` | string | Bu detayın ait olduğu genel sipariş kimliği |
| `positionId` | string | İlişkili konum kimliği |
| `symbol` | string | ticaret çifti |
| `side` | string | Bu oyuncunun alış ve satış yönü BUY / SELL |
| `roleType` | string | Bu oyuncunun işlem karakteri MAKER / TAKER |
| `positionSide` | string | Gerçek değere göre açıklanan konum yönü LONG / SHORT / BOTH vb. |
| `price` | string | Bu işlem fiyatı |
| `quantity` | string | Bu işlemin miktarı orijinal siparişin toplam miktarı değildir. |
| `tradeValue` | string | Bu işlemin nominal değeri, işlemin kavramsal değerinden gelir. |
| `handlingFee` | string | Bu işleme ilişkin işlem ücreti, kaynak sembolünü ve doğruluğunu korur ve tek başına mutlak değeri almaz. |
| `realizedPnl` | string | Bu işleme ilişkin gerçekleşen kar ve zarar; mevcut pozisyonun gerçek zamanlı değişken kar ve zararı değil |
| `tradedAt` | integer | İşlem süresi, milisaniye; bu alanı zaman filtreleme için kullanın |

Bir siparişin birden fazla dolumu olabilir ve bunların ayrıntılı olarak kaydedilmesi gerekir. Farklı oyuncuların/doldurma rollerinin kayıtlarını tradeId ile birleştirmeyin ve ardından kayıt kimliklerini atmayın.

## Örnek yanıt zarfı

Bu, tamamlanmış bir işlemin örneği değil, açıklayıcı boş bir sayfadır. Yukarıdaki kaynağa özgü alan tablolarında doldurulmuş `items[].data` açıklanmaktadır.

```json
{"code":0,"message":"success","data":{"items":[],"nextCursor":"","hasMore":false}}
```
