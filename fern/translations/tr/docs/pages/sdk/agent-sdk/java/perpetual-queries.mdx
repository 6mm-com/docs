## Kalıcı sözleşme verilerini sorgulama

<span id="six-types-of-interfaces-and-java-methods" data-sixmm-canonical-anchor="six-types-of-interfaces-and-java-methods" aria-hidden="true"></span>

### Altı tür arayüz ve Java yöntemleri

Tüm istekler, ortak bir `/v1/agent/perpetual` önekiyle POST imzalanır.

| yol son eki | Java Yöntem/İstek Türü | oyuncu aralığı |
| --- | --- | --- |
| `/orders/current` | `listCurrentPerpetualOrders(CurrentPerpetualOrdersRequest)` | NORMAL Oyuncu çıkarılabilir; CONDITIONAL Oyuncu belirtilmeli |
| `/orders/history` | `listPerpetualOrderHistory(PerpetualOrderHistoryRequest)` | Yukarıdakiyle aynı |
| `/trades` | `listPerpetualTrades(PerpetualTradesRequest)` | Oyuncu belirtilmeli |
| `/positions/current` | `listCurrentPerpetualPositions(CurrentPerpetualPositionsRequest)` | Oyuncular çıkarılabilir |
| `/positions/history` | `listPerpetualPositionHistory(PerpetualPositionHistoryRequest)` | Oyuncular çıkarılabilir |
| `/account/ledger` | `listPerpetualLedger(PerpetualLedgerRequest)` | Oyuncular çıkarılabilir |

`platformUserIds` genel platform kimliklerinden oluşan bir dize dizisidir. Belirtildiğinde, erişimi olan 1 ila 100 benzersiz oyuncu gereklidir; ihmale izin veren uç noktalarda, yalnızca mevcut satıcının erişebildiği doğrudan oynatıcıların aralığı sorgulanır. Takas doldurma sorguları her zaman bu diziyi gerektirir; koşullu sıralı sorgular ayrıca açık kullanıcı kimlikleri gerektirir. İhmal etme, `[]` ile eşdeğer değildir ve boş diziler yasa dışıdır. Kapsam, imzayı atan üye işyeri tarafından belirlenir ve kapsamın genişletilmesi için diğer üye işyeri kimlikleri aktarılamaz.

Dizi değerleri, imzalama yüküne katılmadan önce kompakt JSON olarak serileştirilir. Örneğin, `platformUserIds`, `["1188041528"]` olarak işaretler ve `k=v` yükünde `platformUserIds=["1188041528"]` verir. Dizi öğesi sırasını, çift tırnakları ve dize kimliklerini koruyun; biçimlendirme boşlukları eklemeyin veya Java `List.toString()` (`[1188041528]` gibi) kullanmayın. SDK bu serileştirmeyi otomatik olarak gerçekleştirir.

Sipariş sorgusu `orderCategory=NORMAL` veya `CONDITIONAL`'i geçmelidir. Sıradan siparişler için `orderId` ve koşullu siparişler için `conditionId` kullanın. Kategoriler arasında karıştırılamazlar. Koşullu emirler ve bunların tetiklenmesiyle oluşan olağan emirler ayrı ayrı varlık olarak işlenir.

### Filtre koşulları

| Sorgu | Mevcut işletme filtreleri |
| --- | --- |
| Mevcut sipariş | `orderCategory`, `symbol` |
| tarihsel sıra | `orderCategory`, `symbol`, `startTime`, `endTime`, `orderId`, `conditionId`, `clientOrderId`, `side`, `status` |
| anlaşma yapmak | `symbol`, `startTime`, `endTime`, `orderId` |
| Mevcut konum | `symbol` |
| Tarihsel konumlar | `symbol`, `startTime`, `endTime`, `positionSide` |
| Sözleşme değişiklikleri | `startTime`, `endTime`, `assetType`, `changeType` |

Geçmiş sorgunun süresi Unix **milisaniye** ve aralık `[startTime, endTime)`'dır; imza isteme süresi `timestamp` Unix **saniyedir**. Segmentlerdeki UTC zaman aralığının ve sorgunun düzeltilmesi önerilir; Günlük mutabakat için UTC kullanın. Durum ve tür, platform sözleşme numaralandırmasını kullanır ve kendi başlarına Çince dizelere çevrilmez.

`limit` Varsayılan 500'dür, aralık 1~1000'dir; sayfa boyutu her seferinde aynı sayının döndürüleceğini garanti etmez. Altı arayüz şu anda saniyede 2 kez ve satıcı başına 4 patlamadan oluşan bir sorgu kotasını paylaşmaktadır ve örnek içindeki her satıcı için maksimum eşzamanlılık sınırı 2'dir. Satıcı tarafı birleştirilmiş bir kuyruk kullanır ve sıralı sayfalama ve daha küçük bir geçmiş penceresiyle başlanması önerilir.

### Java sorgu örnekleri

Bir oyuncunun mevcut olağan sırasını sorgulayın:

```java
CurrentPerpetualOrdersRequest current = new CurrentPerpetualOrdersRequest();
current.orderCategory = "NORMAL";
current.platformUserIds = Collections.singletonList(platformUserId);
current.symbol = "BTCUSDT";
current.limit = 100;
PerpetualResponse currentPage = client.listCurrentPerpetualOrders(current);
```

Son saatteki sözleşme değişikliklerini sorgulayın ve imleci işleyin. Aşağıdaki örnek otomatik olarak yeniden denenmez; gerçek uygulama mevcut sınırlamayla veya geçici arızayla karşılaştığında, aynı sayfayı geri yüklemek için bağlantılı ilgili kılavuzu izleyin.

```java
PerpetualLedgerRequest ledger = new PerpetualLedgerRequest();
ledger.platformUserIds = Collections.singletonList(platformUserId);
ledger.endTime = System.currentTimeMillis();
ledger.startTime = ledger.endTime - 3_600_000L;
ledger.limit = 100;
Set<String> seenCursors = new HashSet<>();

while (true) {
    PerpetualResponse page = client.listPerpetualLedger(ledger);
    for (PerpetualRecord row : page.data.items) {
        // Persist records idempotently by platformUserId, entityType and entityId.
    }
    if (!page.data.hasMore) {
        break;
    }
    String next = page.data.nextCursor;
    if (next == null || next.isEmpty() || !seenCursors.add(next)) {
        throw new IllegalStateException("游标未推进，停止查询并排查");
    }
    ledger.cursor = next;
    Thread.sleep(650L); // Other queries must share the same partner rate-limit queue.
}
```

### İade yapısı ve kaydetme kuralları

Görmek [Ortak yanıt ve sayfalandırma](#common-response-and-pagination) Paylaşılan alanlar için. Kaynak alanları şurada belgelenmiştir: [Siparişler](/tr/sdk/agent-sdk/java/perpetual-orders), [Ticaret doluyor](/tr/sdk/agent-sdk/java/perpetual-trades), [Pozisyonlar](/tr/sdk/agent-sdk/java/perpetual-positions) Ve [Sözleşme defteri](/tr/sdk/agent-sdk/java/perpetual-ledger).

Altı arayüz aynı şekilde `PerpetualResponse` değerini döndürür:

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "items": [],
    "nextCursor": "",
    "hasMore": false
  }
}
```

Her `items`, `platformUserId`, `entityType`, `entityId`, `data` içerir. Varlık türleri arasında `ORDER`, `CONDITION_ORDER`, `TRADE_FILL`, `POSITION`, `ACCOUNT_LEDGER` bulunur. İdempotent bir anahtar oluşturmak için bu üç kimlik alanını kullanın; koşullu sipariş kimliğini, sipariş kimliğini ve dolum kimliğini aynı numara olarak değerlendirmeyin.

`data` Kaynağa göre fiyat, miktar, durum, gider, kar ve zarar veya bakiye değişikliği gibi alanlar sağlar. Tutar, fiyat, miktar ve varlık kimliği dizeler olarak işlenir; iş süresi milisaniye cinsindendir. Eksik alanlar 0'a kadar doldurulmaz ve diğer varlıklardan çıkarım yapılmaz.

İmleç, bir sorgunun sayfalama konumudur; güvenilir bir artımlı abonelik veya garantili bir sayfalar arası atomik anlık görüntü değildir. Geçerli imleç, ilk oluşturma turundan itibaren 24 saat boyunca geçerlidir; sonraki sayfalama aynı satıcıları, kaynakları, oyuncu koleksiyonlarını ve filtre koşullarını korur. Geçmiş çekme için sabit pencere tekrar tekrar çekildiğinde önemsizdir; Mevcut emir/pozisyonun durumu yeniden sorgulama sonrasında yenilenir. Gerçek zamanlı bir arayüze ihtiyaç duyulduğunda, platformun ön ucunun veri mekanizması kullanılır ve oylama altı arayüzü, yüksek frekanslı bir piyasa arayüzü olarak kabul edilemez.

### Hatalar ve kurtarma

HTTP başarısı iş başarısı anlamına gelmez; `code`'ı kontrol etmelisiniz. Java SDK, `AgentApiException` olarak bir iş hatası oluşturacaktır.

| İşletme kodu | Tipik anlam | Taşıma |
| --- | --- | --- |
| `102001` | Gerekli parametreler eksik, örneğin koşullu sıralama sorgusunda oyuncular eksik. | Eksik parametreleri sağlayın |
| `102002` | Geçersiz parametreler, boş dizi, eşleşmeyen imleç veya süresi dolmuş | Parametreleri düzeltin; Süresi dolmuş imleci temizledikten sonra sabit pencereyi yeniden kontrol edin ve onu tam olarak kaydedin. |
| `102003` | Yasa dışı limit, oyuncu sayısı veya zaman aralığı | Dar veya doğru kapsam |
| `6001` | İmza hatası | Anahtar, dizi serileştirme ve imza alanlarını kontrol edin |
| `6009` | Satıcı erişim yöntemine veya erişim kapsamına izin verilmiyor | Satıcı izinlerini ve oyuncu sahipliğini kontrol edin |
| `6904` | Hizmet geçici olarak kullanılamıyor, eşzamanlılık veya sorgu kaynağı koruması | Eşzamanlılığı azaltın ve pencereleri küçültün; hata devam ederse desteğe başvurun |
| `6905` | Altı sorgu türü için paylaşılan kota tükendi | Geri çekilin ve ardından orijinal başarısız sayfayı yeniden deneyin |

Orijinal başarısız sayfanın `cursor` ve tüm filtre koşulları, mevcut sınırlama, zaman aşımı veya geçici arızadan sonra korunacaktır; SDK her yeniden çağrıldığında, yeni `timestamp`, `nonce`, `sign` oluşturulacaktır. Doğrudan bir sonraki sayfaya atlayamazsınız ve başarısızlıkları boş sonuçlar olarak değerlendiremezsiniz. SDK, fon işlemlerinin otomatik olarak yeniden denenmesinden sorumlu değildir.

## Ortak yanıt ve sayfalandırma

| Alan | JSON türü | göstermek |
| --- | --- | --- |
| `code` | integer | İşletme kodu, 0 başarı anlamına gelir; 0 değilse hata olarak değerlendirilecek, başarısızlık ise boş sayfa olarak değerlendirilmeyecektir. |
| `message` | string | Sonuçların açıklaması iş muhakemesi için tek temel değildir. |
| `data` | object | Başarıyla ilgili sayfalandırılmış sonuçlar |
| `data.items` | array | Bu sayfadaki kayıtlar; yasal boş sayfa: `[]` |
| `data.nextCursor` | string | Sonraki sayfa imleci; sonraki sayfa yoksa genellikle boş bir dize |
| `data.hasMore` | boolean | Sonraki sayfaların olup olmadığı; doğru olduğunda, aynı sorguya devam etmek için nextCursor kullanın |

Her `data.items[]`'in yapısı:

| Alan | JSON türü | göstermek |
| --- | --- | --- |
| `platformUserId` | string | Bir dize olarak kaydedilen platform genel kullanıcı kimliği; dahili veritabanı kullanıcı kimliği değil |
| `entityType` | string | Kaydın ait olduğu varlık türü, aşağıdaki tabloya bakın |
| `entityId` | string | Geçerli varlığın tanımlayıcısı, yerel bir eş yetkili anahtar oluşturmak için platform kullanıcısı ve varlık türüyle birleştirilir. |
| `data` | object | Bu kuruluşun iş alanları; farklı kaynak alanları farklıdır |

| Kaynakları sorgula | `entityType` | `entityId` Yazışma |
| --- | --- | --- |
| Sıradan düzen | `ORDER` | `data.orderId` |
| şartlı emirler | `CONDITION_ORDER` | `data.conditionId` |
| Ticaret doldurma ayrıntıları | `TRADE_FILL` | `data.fillId`, tradeId değil |
| Güncel/geçmiş konumları | `POSITION` | `data.positionId` |
| Sözleşme defteri kayıtları | `ACCOUNT_LEDGER` | Tek hesap değişikliği ayrıntılarının tanımlanması, ** veri değildir.ledgerId** |

Aynı `ledgerId`, işlem ücretleri, kar ve zarar vb. gibi birden fazla ayrıntıyı ayırabilir; kopyaları kaldırmak için ledgerId tuşuna basmak veri kaybına neden olacaktır. Farklı kaynaklardan gelen kimlikler karıştırılamaz. Sayfalama ve alan kaydetme kuralları için Erişim Kılavuzu'nun bağlantılı ilgili kılavuzuna bakın.

## Türler, birimler ve ihmal edilen alanlar

- Tutar, fiyat, miktar ve varlık kimliği kullanım dizesi; miktarları işlemek için ondalık sayıyı kullanın ve kayan noktalı sayıları kullanamaz veya uzun kimlikleri JavaScript Numaralarına dönüştüremez. Tutar para birimi ve miktar birimi, işlem çifti/sözleşme spesifikasyonlarına göre açıklanır.
- İş zamanı tamsayıyı (int64) kullanır; her ikisi de Unix milisaniyedir; kimlik doğrulama zaman damgası isteği ve giriş kimlik bilgileri expireAt saniyeleri kullanır ve karıştırılamaz.
- Dize iş alanları genellikle boş olduklarında çıktılanmaz ve sayısal alanlar 0 olduğunda bazıları atlanır. **Eksik alan, iş değerinin 0 olduğu anlamına gelmez**.
- Genel kayıt modelinde `reduceOnly`, `closeOnly`, `makerOnly`, false'u atlamaz, dolayısıyla bu üç false, işlemlerde veya pozisyonlarda da görünebilir. Bunlar yalnızca sipariş kaynaklarında açıklanmaktadır; işlemin/pozisyonun ilgili emir kurallarını yerine getirdiği düşünülemez.
- `closePosition` isteğe bağlı bir boole değeridir: koşullu emirlerle sağlanır, genellikle diğer kaynaklar için atlanır. Eksikliğin yanlıştan farklı bir anlamı vardır.
- Aşağıdaki "şu anda sağlanan" tablo, okuma mantığının bir alan kaynağına sahip olduğu anlamına gelir; isteğe bağlı alanlar, değerleri olmadığından yine de atlanabilir. Modelde bulunan alanların her arayüzde doldurulması garanti edilmez.

## Durum ve kenar boşluğu modu arasındaki fark

| kaynak | geçerli dönüş değeri |
| --- | --- |
| Mevcut olağan sipariş durumu | NEW, PENDING, PARTIALLY_FILLED |
| Geçmiş olağan sipariş durumu | FILLED, CANCELED, REJECTED, PARTIAL_FILLED_CANCELED veya PARTIALLY_FILLED_CANCELED; asıl kaynağın yazılışını koruyun |
| Mevcut durum sipariş durumu / triggerStatus | PENDING_ACTIVATION, PENDING, TRIGGERING |
| Geçmiş durum sipariş durumu / triggerStatus | TRIGGERED, CANCELLED, REJECTED, FIRED |
| Mevcut konum durumu | Sayısal dizi "1" konumunda, "3" tasfiye halinde |
| Geçmiş konum durumu | Sayısal dizi "2" pozisyonu kapattı, "4" zorunlu tasfiyeye uğradı |

Sıradan bir sipariş için CANCELED yazımı, koşullu bir sipariş için CANCELLED yazımından farklıdır; Koşullu bir emrin tetiklenmesi, oluşturulan olağan emrin yerine getirildiği anlamına gelmez. Tüm kaynaklar için aynı durum çeviri tabloları kümesini yeniden kullanmayın.

Koşullu sipariş marginMode, CROSS / ISOLATED değerini döndürür; tarihsel olağan emirler ve pozisyonlar şu anda sırasıyla çapraz/izole marj olan "1" / "2" değerini döndürmektedir. marginMode şu anda sıradan siparişler için mevcut değil. Satıcılar kendi görüntüleme katmanlarında kaynağa göre normalleştirme yapabilirler ve orijinal değerlerin yine de kaydedilmesi gerekir.

## Modelde bildirilen ancak bu sorguda sağlanmayan alanlar

Generic RecordData / Java PerpetualData modeli ayrıca aşağıdaki alanları da bildirir, ancak mevcut altı kategorili üretim okuma mantığı bunları doldurmaz. **Mevcut iş verileri olarak listelenmemeli veya alan varsayılanları gerçek sonuçların yerine kullanılmamalıdır. **

| Alan | Modeli türü | akım sınırı |
| --- | --- | --- |
| `closeReason` | string | Geçmiş pozisyonların kapatılmasına ilişkin nedenler belirtilmemiştir |
| `walletDelta` | string | Hesap değiştirme arayüzü cüzdan deltasını döndürmüyor |
| `frozenDelta` | string | Hesap değiştirme arayüzü dondurulmuş deltayı döndürmüyor |
| `usedDelta` | string | Hesap değişikliği arayüzü kullanılan marjin deltasını döndürmüyor |
| `feeDelta` | string | Hesap değişikliği arayüzü ücret deltasını döndürmüyor |
| `pnlDelta` | string | Hesap değişikliği arayüzü kar ve zarar deltasını döndürmüyor |
| `accountVersion` | string | Hesap değişikliği arayüzü hesap sürümünü döndürmez ve güvenilir artımlı senkronizasyon için kullanılamaz. |
| `occurredAt` | integer | Hesap değişikliği arayüzü createdAt kullanır ve başka bir olay oluşum zamanı kümesi sağlamaz. |

Gerçek saha uygulama kapsamı yukarıdaki kaynak tablolarına tabidir; Platform, alanları veya numaralandırmaları güncellediğinde, yeni arayüz açıklamasına ve SDK sürümüne göre uyarlanacaktır.
