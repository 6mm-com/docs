Gunakan aliran WebSocket untuk data pasar dan pembaruan status pengguna pribadi yang harus tetap terkini tanpa melakukan polling.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Koneksi URL

```text
wss://ws.6mm.com/ws
```

Aliran privat memerlukan konteks autentikasi seperti listenKey atau token akses seperti yang dijelaskan dalam dokumentasi saluran privat.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## Berlangganan

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Pengakuan langganan yang berhasil:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## Berhenti berlangganan

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

## Amplop pesan

Dorongan publik menggunakan batas yang konsisten:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## Rekomendasi operasional

- Menghasilkan `id` sisi klien yang unik untuk setiap permintaan langganan, berhenti berlangganan, dan ping.
- Anggap reconnect sebagai sesi baru dan langganan kembali topik yang diperlukan.
- Validasi bahwa `topic` yang dikembalikan sesuai dengan saluran yang diharapkan layanan Anda.
- Jaga agar pemrosesan pesan tetap sama di mana pesanan pribadi atau acara akun terlibat.
- Catat perubahan status koneksi, pengakuan langganan, dan pemutusan koneksi yang tidak normal.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## Alur kerja Koneksi Kembali

1. Tutup atau buang soket sebelumnya dan buat koneksi baru.
2. Autentikasi ulang aliran pribadi dengan listenKey atau token akses yang valid.
3. Berlangganan ulang setiap topik yang diperlukan dan tunggu ucapan terima kasih yang berhasil.
4. Ganti status orderbook-lokal dengan snapshot baru sebelum menerapkan pembaruan bertahap.
5. Rekonsiliasi pesanan terbuka, posisi, dan saldo melalui REST jika acara pribadi mungkin terlewat.

Gunakan bounded exponential backoff dengan jitter untuk percobaan reconnect. Klien yang terus terhubung kembali seharusnya memberi tahu operator, bukan mencoba ulang tanpa batas waktu tanpa visibilitas.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## Detak jantung dan koneksi yang basi

- Lacak pesan masuk terbaru dan pengakuan ping yang berhasil.
- Gunakan interval detak jantung dan ambang idle yang disetujui untuk lingkungan produksi.
- Perlakukan koneksi sebagai basi ketika ambang batas yang dikonfigurasi terlampaui, meskipun soket TCP masih tampak terbuka.
- Jangan menggunakan ulang langganan dari soket lama; Berlangganan ulang secara eksplisit setelah setiap koneksi ulang.
