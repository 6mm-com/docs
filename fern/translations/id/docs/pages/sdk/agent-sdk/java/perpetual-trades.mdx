## Contoh prasyarat

Cuplikan Java membagikan impor ini. Inisialisasi `client` menggunakan Quick Start dan dapatkan `platformUserId` dari pengikatan yang disimpan. Contoh ID pengguna/pesanan harus diganti dengan nilai Anda yang tetap.

```java
import com.sixmm.agent.*;
import com.sixmm.agent.model.*;
import java.util.*;
```

## `listPerpetualTrades`

Model permintaan: `PerpetualTradesRequest`.

```java
import com.sixmm.agent.model.PerpetualTradesRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualTradesRequest request = new PerpetualTradesRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualTrades(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

<span id="request-fields" data-sixmm-canonical-anchor="request-fields" aria-hidden="true"></span>

### Bidang permintaan

| Bidang | Java ketik | Diperlukan | Arti |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Bersyarat | 1–100 ID publik unik; diperlukan untuk pengisian dan pesanan bersyarat. Hilangkan kueri yang didukung untuk cakupan pemain langsung; [] tidak valid. |
| `symbol` | `String` | TIDAK | Filter pasangan dagang opsional. |
| `orderId` | `String` | TIDAK | ID pesanan biasa; bukan nomor pesanan transfer mitra. |
| `startTime` | `Long` | TIDAK | Milidetik Unix inklusif; gunakan jendela riwayat UTC yang tetap. |
| `endTime` | `Long` | TIDAK | Milidetik Unix eksklusif. |
| `limit` | `Integer` | TIDAK | Bawaan 500; 1–1000. |
| `cursor` | `String` | TIDAK | Gunakan nextCursor yang dikembalikan dengan filter yang tidak berubah; berhenti ketika hasMore salah. |

Contohnya berbunyi satu halaman. Untuk bidang yang wajib diisi, cakupan pemain, semantik filter, batas, kursor, dan percobaan ulang terbatas, ikuti [Ikhtisar kueri](/id/sdk/agent-sdk/java/perpetual-queries). Biarkan semua filter tidak berubah saat melakukan paging; jangan menafsirkan kesalahan sebagai hasil kosong.

## Detail pengisian perdagangan

Antarmuka: `trades`. Membutuhkan platformUserIds yang eksplisit.

| `data` bidang | jenis | arti |
| --- | --- | --- |
| `fillId` | string | ID detail pengisian perdagangan, sesuai dengan catatan ini entityId |
| `tradeId` | string | ID transaksi yang cocok dan terkait dengan transaksi tersebut; tidak menggantikan ID detail |
| `orderId` | string | ID pesanan umum yang memuat detail ini |
| `positionId` | string | ID posisi terkait |
| `symbol` | string | pasangan perdagangan |
| `side` | string | Arah jual beli pemain ini BUY / SELL |
| `roleType` | string | Karakter transaksi pemain ini MAKER / TAKER |
| `positionSide` | string | Arah posisi, dijelaskan berdasarkan nilai sebenarnya LONG / SHORT / BOTH dll. |
| `price` | string | Harga transaksi ini |
| `quantity` | string | Kuantitas transaksi ini bukan total kuantitas pesanan awal. |
| `tradeValue` | string | Nilai nominal transaksi ini berasal dari transaksi nosional |
| `handlingFee` | string | Biaya transaksi untuk transaksi ini mempertahankan simbol sumber dan keakuratannya, dan tidak mengambil nilai absolut dengan sendirinya. |
| `realizedPnl` | string | Realisasi keuntungan dan kerugian terkait dengan transaksi ini; bukan keuntungan dan kerugian mengambang real-time dari posisi saat ini |
| `tradedAt` | integer | Waktu transaksi, milidetik; gunakan bidang ini untuk memfilter waktu |

Suatu pesanan mungkin memiliki beberapa pengisian, yang harus disimpan secara detail. Jangan menggabungkan catatan pemain yang berbeda/mengisi peran sebanyak tradeId dan kemudian membuang identitas catatan mereka.
