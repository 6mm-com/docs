Embedded trading biasanya diperkenalkan ke dalam produk yang sudah ada, bukan diluncurkan sebagai tujuan mandiri. Jalur integrasi terbaik bergantung pada di mana pengguna sudah menghabiskan waktu dan sistem mana yang memiliki identitas, dana, dan operasi.

<h2 id="common-scenarios">Skenario umum</h2>

| Skenario | Titik awal terbaik | Catatan |
| --- | --- | --- |
| Aplikasi atau dompet menginginkan entri trading | Trading Widget SDK | Gunakan titik masuk native atau H5 dan buka pengalaman trading tertanam setelah otorisasi pengguna. |
| Platform broker atau saluran menginginkan akses derivatif | Agent SDK + Trading Widget SDK | Jaga hubungan pelanggan dan validasi backend tetap ada di sistem mitra. |
| Platform menginginkan alur trading yang terpandu | API + modul SDK terpilih | Gunakan API backend untuk alur kerja akun, transfer, dan pesanan sambil hanya menampilkan entri frontend yang diperlukan. |
| Bursa yang ada menginginkan pasar tambahan | Likuiditas + integrasi API | Gabungkan kedalaman pasar, alur kerja akun, dan pemantauan operasional. |

<h2 id="product-decisions-before-integration">Keputusan produk sebelum integrasi</h2>

- Putuskan apakah pengguna masuk dari kartu beranda, halaman aset, halaman kampanye, atau pusat akun.
- Tentukan sistem mana yang memiliki status login, kelayakan pengguna, serta ketersediaan negara atau wilayah.
- Menentukan bagaimana transfer, catatan penyelesaian, dan tiket dukungan pelanggan ditampilkan kepada pengguna.
- Putuskan peristiwa mana yang harus diteruskan ke analitik internal, CRM, atau operasi risiko.
