Eingebettetes Trading wird in der Regel in ein bestehendes Produkt eingeführt und nicht als eigenständiges Ziel gestartet. Der beste Integrationsweg hängt davon ab, wo die Nutzer bereits Zeit verbringen und welches System Identität, Mittel und Abläufe besitzt.

<h2 id="common-scenarios">Häufige Szenarien</h2>

| Szenario | Bester Ausgangspunkt | Anmerkungen |
| --- | --- | --- |
| App oder Wallet möchte einen Handelseintrag | Trading Widget SDK | Verwenden Sie einen nativen oder H5-Einstiegspunkt und öffnen Sie die eingebettete Handelserfahrung nach der Benutzerautorisierung. |
| Broker oder Kanalplattform möchte Zugang zu Derivaten | Agent SDK + Trading Widget SDK | Behalten Sie Kundenbeziehungen und Backend-Validierung im Partnersystem. |
| Die Plattform möchte einen geführten Handelsfluss | API + ausgewählte SDK Module | Nutze Backend- API für Account-, Transfer- und Bestell-Workflows, während du nur die benötigten Frontend-Einträge freilegst. |
| Die bestehende Börse benötigt zusätzliche Märkte | Liquidität + API Integration | Kombinieren Sie Markttiefe, Account-Workflows und operative Überwachung. |

<h2 id="product-decisions-before-integration">Produktentscheidungen vor der Integration</h2>

- Entscheiden, ob Nutzer über eine Startseite, Asset-Seite, Kampagnenseite oder Account Center eintreten.
- Entscheiden, welches System den Login-Zustand, die Benutzerberechtigung sowie die Verfügbarkeit von Land oder Region besitzt.
- Entscheiden, wie Übertragungen, Abwicklungsaufzeichnungen und Kundensupport-Tickets den Nutzern angezeigt werden.
- Entscheiden, welche Ereignisse an interne Analyse-, CRM- oder Risikooperationen weitergeleitet werden müssen.
