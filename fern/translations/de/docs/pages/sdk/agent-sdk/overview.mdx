Das 6MM Agent SDK ist für Partner-Backend-Dienste, die privilegierte Agenten APIs aufrufen müssen, ohne Signing und Request von Grund auf zu implementieren. Es darf nicht im Browser-, Mobil- oder öffentlichen Desktop-Code laufen, da die Integration einen Partner API Secret verwendet.

<h2 id="when-to-use-the-agent-sdk">Wann sollte man die Agent SDK</h2>

Verwenden Sie ein Agent SDK , wenn Ihr Backend einen Partner-Nutzer binden muss, Vermögenswerte durch einen genehmigten Workflow bewegen, Handelsdaten abfragen, einen eingebetteten Handelseintrag URLerstellen oder Webhook-Benachrichtigungen überprüfen müssen. Verwenden Sie das [Trading Widget SDK](/de/sdk/trading-widget/overview) separat, wenn das Partner-Frontend die Handelsoberfläche anzeigen muss.

<h2 id="common-configuration">Gemeinsame Konfiguration</h2>

| Legende | Beispiel | Beschreibung |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API URL ohne Slash zu bedienen. |
| agentCode | AGENT001 | Partneragenten-Code. |
| apiSecret | Dein-api-geheimnis | API Signing-Secret wird nur im Backend gespeichert. |
| defaultCurrency | USDT | Standardwährung für Überweisung und Konto APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Partner-Endpunkt für 6MM Webhook-Benachrichtigungen. |

<h2 id="typical-integration-flow">Typischer Integrationsfluss</h2>

1. Das Partner-Frontend authentifiziert den Nutzer über das eigene Kontosystem des Partners.
2. Das Partner-Backend mappt den Benutzer auf eine stabile Partner-seitige Kennung.
3. Das Backend ruft das Agent SDK mit `agentCode` und dem geschützten API geheim auf.
4. Die SDK unterschreibt und sendet dem Agenten API Anfrage.
5. Das Backend speichert die zurückgegebene Geschäftskennung und verarbeitet spätere Webhooks idempotent.
6. Das Frontend erhält nur das kurzlebige Ergebnis oder die benötigte Zugangsberechtigung.

<h2 id="production-checklist">Produktionscheckliste</h2>

- Laden Sie `apiSecret` aus einem Backend-Secret-Manager, nicht aus dem Quellcode.
- Entwicklungs-, Staging- und Produktionsreferenzen getrennt halten.
- Verwenden Sie eine stabile Partner-Benutzerabbildung und eindeutige Geschäftsordnungskennungen.
- Die ursprüngliche Identifikatorin erhalten bleiben, wenn der Status einer zeitgesteuerten Anfrage überprüft wird.
- Webhook-Signaturen zu überprüfen und verarbeitete Ereignis-IDs zu speichern.
- Geheimnisse und Signaturen aus Protokollen schwärzen, während Anfrage-IDs zur Unterstützung erhalten bleiben.
