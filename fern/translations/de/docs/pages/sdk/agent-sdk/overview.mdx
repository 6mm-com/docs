Der 6MM Agent SDK ist für Partner-Backend-Dienste gedacht, die den privilegierten Agenten APIs aufrufen müssen, ohne die Signierung und Anforderungsbearbeitung von Grund auf zu implementieren. Es darf nicht im Browser-, Mobil- oder öffentlichen Desktop-Code ausgeführt werden, da die Integration ein Partner-API-Geheimnis verwendet.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Wann sollte Agent SDK verwendet werden?

Verwenden Sie das Agent SDK, wenn Ihr Backend einen Partnerbenutzer verknüpfen, Assets über einen genehmigten Workflow übertragen, Handelsdaten abfragen, eine Einstiegs-URL für den eingebetteten Handel erstellen oder Webhook-Benachrichtigungen prüfen muss. Verwenden Sie das [Trading Widget SDK](/de/sdk/trading-widget/overview) separat, wenn das Partner-Frontend die Handelsoberfläche anzeigen soll.

## Gemeinsame Konfiguration

| Schlüssel | Beispiel | Beschreibung |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API Dienst URL ohne abschließenden Schrägstrich. |
| agentCode | AGENT001 | Code des Partneragenten. |
| apiSecret | Dein-API-Geheimnis | API Signaturgeheimnis wird nur im Backend gespeichert. |
| defaultCurrency | USDT | Standardwährung für Überweisung und Konto APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Partnerendpunkt für 6MM webhook-Benachrichtigungen. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Typischer Integrationsablauf

1. Das Partner-Frontend authentifiziert den Benutzer über das eigene Kontosystem des Partners.
2. Das Partner-Backend ordnet dem Benutzer eine stabile partnerseitige Kennung zu.
3. Das Backend ruft den Agent SDK mit `agentCode` und dem geschützten API-Geheimnis auf.
4. Der SDK signiert und sendet die Anfrage des Agenten API.
5. Das Backend speichert die zurückgegebene Geschäftskennung und verarbeitet sie später webhooks idempotent.
6. Das Frontend erhält nur die kurzlebigen Ergebnis- oder Zugangsdaten, die es benötigt.

## Checkliste für die Produktion

- Laden Sie `apiSecret` von einem Backend-Secret-Manager, nicht vom Quellcode.
- Halten Sie die Anmeldeinformationen für Entwicklung, Staging und Produktion getrennt.
- Verwenden Sie eine stabile Partnerbenutzerzuordnung und eindeutige Geschäftsauftragskennungen.
- Behalten Sie die ursprüngliche Kennung bei, wenn Sie den Status einer Anfrage mit Zeitüberschreitung überprüfen.
- Überprüfen Sie webhook Signaturen und speichern Sie verarbeitete Ereignis-IDs.
- Schwärzen Sie Geheimnisse und Signaturen aus Protokollen und behalten Sie gleichzeitig die Anforderungs-IDs für den Support bei.
