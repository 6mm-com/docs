## Beispielvoraussetzungen

Die Java-Snippets teilen diese Importe. Initialisieren Sie `client` mit Quick Start und rufen Sie `platformUserId` aus der gespeicherten Bindung ab. Beispiel-Benutzer-/Bestell-IDs müssen durch Ihre eigenen persistenten Werte ersetzt werden.

```java
import com.sixmm.agent.*;

```

## `listCurrentPerpetualPositions`

Anforderungsmodell: `CurrentPerpetualPositionsRequest`.

```java
import com.sixmm.agent.model.CurrentPerpetualPositionsRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

CurrentPerpetualPositionsRequest request = new CurrentPerpetualPositionsRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
PerpetualResponse response = client.listCurrentPerpetualPositions(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

### Anforderungsfelder

| Feld | Java Typ | Erforderlich | Bedeutung |
| --- | --- | --- | --- |
| `platformUserIds` | `java.util.List<String>` | Bedingt | 1–100 eindeutige öffentliche IDs; erforderlich für Ausführungen und bedingte Bestellungen. Bei unterstützten Abfragen für den Direktspielerbereich weglassen; [] ist ungültig. |
| `symbol` | `String` | NEIN | Optionaler Handelspaarfilter. |
| `limit` | `Integer` | NEIN | Standard 500; 1–1000. |
| `cursor` | `String` | NEIN | Verwenden Sie den zurückgegebenen nextCursor mit unveränderten Filtern. stoppen, wenn hasMore falsch ist. |

## `listPerpetualPositionHistory`

Anforderungsmodell: `PerpetualPositionHistoryRequest`.

```java
import com.sixmm.agent.model.PerpetualPositionHistoryRequest;
import com.sixmm.agent.model.PerpetualResponse;
import java.util.Collections;

PerpetualPositionHistoryRequest request = new PerpetualPositionHistoryRequest();
request.platformUserIds = Collections.singletonList("1188041528");
request.limit = 100;
request.symbol = "BTCUSDT";
request.endTime = System.currentTimeMillis();
request.startTime = request.endTime - 3_600_000L;
PerpetualResponse response = client.listPerpetualPositionHistory(request);
System.out.println(response.data.items.size());
System.out.println(response.data.hasMore);
System.out.println(response.data.nextCursor);
```

## Positionen: aktuell und historisch

| `data` Feld | Typ | Aktuelle Position | Historische Positionen | Bedeutung |
| --- | --- | --- | --- | --- |
| `positionId` | string | liefern | liefern | Positions-ID, entsprechend entityId |
| `symbol` | string | liefern | liefern | Handelspaar |
| `positionSide` | string | liefern | liefern | LONG / SHORT / BOTH und andere Positionsrichtungen |
| `status` | string | liefern | liefern | String mit dem numerischen Status der Position, siehe Abfrageübersicht |
| `leverage` | integer | liefern | liefern | Nutzen Sie mehrere |
| `marginMode` | string | liefern | liefern | Numerische Aufzählungszeichenfolge „1“ für vollständige Position, „2“ für isolierte Position |
| `quantity` | string | liefern | Nicht verfügbar | Aktuelle Positionsmenge |
| `entryPrice` | string | liefern | liefern | Durchschnittlicher Eröffnungspreis der gespeicherten Positionen |
| `margin` | string | liefern | Nicht verfügbar | Der Margin-Betrag der aktuellen Position, nicht der gesamte Vertrags-Wallet-Saldo des Benutzers |
| `maxQuantity` | string | Nicht verfügbar | liefern | Die maximale Anzahl der in dieser historischen Position aufgezeichneten Positionen |
| `closeQuantity` | string | Nicht verfügbar | liefern | Die kumulierte Anzahl der während des historischen Positionslebenszyklus geschlossenen Positionen |
| `closePrice` | string | Nicht verfügbar | liefern | Gespeicherter durchschnittlicher Schlusskurs |
| `pnl` | string | Nicht verfügbar | liefern | Historischer Positionsgewinn und -verlust; Kombinieren Sie es nicht mit der Transaktion realizedPnl, um es einfach zu wiederholen und zu akkumulieren |
| `roe` | string | Nicht verfügbar | liefern | Der proportionale Wert der historischen Positionsrendite, nicht multipliziert mit 100; Beispielsweise steht `"0.043"` für `4.3%`, `"-0.05"` für `-5%` |
| `fundingFeeAccum` | string | liefern | liefern | Kumulierte Finanzierungsgebühr unter Beibehaltung des Quellensymbols und der Genauigkeit |
| `openedAt` | integer | liefern | liefern | Positionsöffnungszeit, Millisekunden |
| `updatedAt` | integer | liefern | Nicht verfügbar | Aktualisierungszeit der aktuellen Position, Millisekunden |
| `closedAt` | integer | Nicht verfügbar | liefern | Schließzeit, Millisekunden; Verwenden Sie dieses Feld, um die historische Positionszeit zu filtern |

Das Berechnungskaliber des Verlaufs `roe` ist `pnl / (entryPrice × maxQuantity / leverage)`, und die Schnittstelle gibt den gespeicherten Anteilswert direkt zurück. Verwenden Sie bei der Anzeige des Prozentsatzes die Dezimaloperation, multiplizieren Sie mit 100 und addieren Sie dann `%`; Der Nenner verwendet die nominale Marge des historischen Positionsdatensatzes, nicht den Kontostand des Kontos. Wenn der Eröffnungspreis oder die maximale Positionsmenge 0 beträgt, der Hebel ungültig ist usw. und nicht berechnet werden kann, wird die Quelle als 0 gespeichert. Daher kann nicht allein auf der Grundlage von `roe=0` gefolgert werden, dass der Gewinn oder Verlust 0 ist.

Für die aktuelle Position gibt es keinen Echtzeit-Markierungspreis, keinen Echtzeit-Floating-Gewinn und -Verlust, keinen Echtzeit-ROE oder keinen Echtzeit-Liquidationspreis. Es spiegelt den gespeicherten Positionsstatus wider und kann die Aktualisierungszeit- und Margin-Felder nicht verwenden, um die aktuellen Echtzeit-Risikokontrollergebnisse zu beanspruchen.
