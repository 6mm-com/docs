| Überweisungen | Festbetragsüberweisung | `transfer` | Geld in oder aus 6MM überweisen |

| Überweisungen | Bestellungen auflisten | `listOrders` | Durchblättern Sie Übertragungsaufträge zum Abgleich |

| Perpetuelle Daten | Aktuelle Daueraufträge | `listCurrentPerpetualOrders` | Fragen Sie aktuelle NORMAL- oder CONDITIONAL-Bestellungen ab |

## Konfiguration

Besorgen Sie sich zuvor die folgenden Werte von 6MM.
integrierend.

| Artikel | Beispiel | Beschreibung |
| --- | --- | --- |
| `baseUrl` | `https://agent-api.6mm.com` | Agent API Basis URL, ohne abschließenden Schrägstrich |
| `agentCode` | `AGENT001` | Partnercode |
| `apiSecret` | `your-api-secret` | API Signaturgeheimnis. Behalten Sie es nur im Backend |
| `defaultCurrency` | `USDT` | Standardwährung, normalerweise `USDT` |
| `webhookUrl` | `https://partner.example.com/6mm/webhook` | Partnerendpunkt für 6MM Rückrufe |

Produktionsempfehlungen:

- Verwenden Sie HTTPS für die Endpunkte Agent API und webhook.
- Speichern Sie `apiSecret` in einem Secret Manager, einem Konfigurationscenter oder einer Umgebungsvariablen.
- Halten Sie die Serverzeit synchronisiert, vorzugsweise mit NTP.
- Behalten Sie alle Partner-Bestellnummern bei und sorgen Sie dafür, dass sie global eindeutig sind.
- Senden Sie niemals `apiSecret` an Browser, Apps, Miniprogramme oder Frontend-Quellcode.

## Automatische Signaturfelder

Bei signierten Agenten-Anrufen API fügt SDK automatisch Folgendes ein:

| Feld | Quelle | Beschreibung |
| --- | --- | --- |
| `agentCode` | `AgentClientConfig.agentCode` | Partnercode |
| `timestamp` | Aktueller UTC Unix-Zeitstempel | Sekunden |
| `nonce` | Sicherer Zufallsgenerator | Wiedergabeschutz |
| `sign` | HMAC-SHA256 | Unterschrift anfordern |
| `currency` | `defaultCurrency` | Wird ausgefüllt, wenn bei Überweisungs-/Kontoanfragen die Währung fehlt |

Signaturregeln:

1. `sign` ausschließen.
2. Leere Werte ausschließen.
3. Sortieren Sie die Schlüssel nach der Reihenfolge ASCII.
4. Treten Sie bei als `k=v&k2=v2`.
5. Berechnen Sie HMAC-SHA256 hex mit `apiSecret`.

Array-Werte werden als kompakte JSON serialisiert, bevor sie der Signierungsnutzlast hinzugefügt werden. Beispielsweise signiert `platformUserIds` als `["1188041528"]` und ergibt `platformUserIds=["1188041528"]` in der Nutzlast `k=v`. Behalten Sie die Reihenfolge der Array-Elemente, doppelte Anführungszeichen und String-IDs bei. Fügen Sie keine Formatierungsleerzeichen ein und verwenden Sie nicht Java `List.toString()` (z. B. `[1188041528]`). Der SDK übernimmt diese Serialisierung automatisch.

Der normale Geschäftscode sollte keine Signaturen berechnen oder manuell festlegen
`agentCode`, `timestamp`, `nonce` oder `sign`.
