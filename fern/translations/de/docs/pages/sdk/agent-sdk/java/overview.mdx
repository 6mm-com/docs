<h2 id="runtime">Laufzeit</h2>

| Gegenstand | Wert |
| --- | --- |
| Minimum Java Version | Java 8+ |
| Empfohlenes Bauwerkzeug | Maven 3.9+ |
| Maven-Gruppe | `com.sixmm.exchange.sdk` |
| Maven-Artefakt | `agent` |
| Dokumentiertes Quell-Tag | `v0.1.1` |

Das öffentliche GitHub-Repository ist Quellcode-Hosting, kein Maven-Abhängigkeitsrepository. Baue und installiere den getaggten Quellcode lokal oder veröffentliche das genehmigte Artefakt im privaten Maven-Repository deiner Organisation, bevor du es in Team-Builds verwendest.

<h2 id="typical-backend-responsibilities">Typische Backend-Aufgaben</h2>

- Validiere die Partnerbenutzersitzung.
- Den Partnerbenutzer auf agentUserIdabbilden.
- Call Bind vor den ersten Handels- oder Transferströmen.
- Rufen Sie createEntryUrl für einmalige Vollstandort- SSOan.
- Ruf createEmbedToken für Trading Widget Partner-Token-Modus an.
- Verifizieren Sie Transfer-Webhooks und verarbeiten Sie sie idempotent.

<h2 id="security-and-operational-rules">Sicherheits- und Betriebsregeln</h2>

- Speichere `apiSecret` nur in einem Backend-Secret-Manager oder einer geschützten Umgebungsvariable.
- Halten Sie die Serverzeit synchron, da signierte Anfragen Zeitstempel enthalten.
- Behandle `agentOrderNo` als dauerhaften Idempotenzschlüssel und halte ihn global einzigartig.
- Speichert `platformUserId` als Zeichenkette und bewahrt seine Beziehung zu `agentUserId`bei.
- Abfrage des ursprünglichen Transfers, bevor man es nach einer Auszeit oder einem unsicheren Netzwerkergebnis erneut versucht.
