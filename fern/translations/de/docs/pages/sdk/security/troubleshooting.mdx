Beginnen Sie mit der Umgebung, dem Zeitstempel und der Geschäftskennung für den fehlgeschlagenen Vorgang. Eine strukturierte Prüfung trennt normalerweise Konfigurationsprobleme von Authentifizierungs-, Netzwerk- und asynchronen Verarbeitungsproblemen.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Empfohlene Diagnosereihenfolge

1. Bestätigen Sie die betroffene Umgebung und Basis URL.
2. Notieren Sie den Zeitraum UTC und die erste fehlgeschlagene Anfrage.
3. Identifizieren Sie das Modul: Trading Widget, Agent SDK, REST API, WebSocket oder webhook.
4. Erfassen Sie die Anforderungs-ID, die Partnerbenutzer-ID, `agentOrderNo`, die Bestell-ID oder die webhook Ereignis-ID.
5. Überprüfen Sie aktuelle Code-, Anmeldeinformationen-, IP-Whitelist- oder Bereitstellungsänderungen.
6. Reproduzieren Sie mit dem kleinsten sicheren Testfall.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget Probleme

| Symptom | Wahrscheinliche Ursache | Fix |
| --- | --- | --- |
| iframe fordert lokale Partnerdomäne an | baseUrl fehlt | Übergeben Sie baseUrl: 'https://app.6mm.com'. |
| Iframe ist unsichtbar oder sehr kurz | Der übergeordnete Container hat keine Höhe | Behälterhöhe oder Durchlaufhöhe einstellen. |
| token_provider_missing | Der Partner-Token-Modus hat keinen Anbieter | Authentifizierung hinzufügentokenProvider. |
| auth_exchange_failed | Ungültiges, abgelaufenes oder nicht übereinstimmendes Einbettungstoken | Überprüfen Sie die Antwort des Backend-Tokens und channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK Probleme

| Symptom | Wahrscheinliche Ursache | Fix |
| --- | --- | --- |
| Unterschrift abgelehnt | Falsches Geheimnis, Abweichung der Uhr oder manuell geänderte signierte Felder | Lassen Sie SDK Signaturfelder generieren und die Serverzeit synchronisieren. |
| Risiko doppelter Geldbewegungen | Nach Zeitüberschreitung wird neue Bestellnummer verwendet | Zuerst nach dem Original agentOrderNo abfragen. |
| PROCESSING wird als Fehler behandelt | Anhängiger Zustand missverstanden | Warten Sie auf webhook oder rufen Sie queryOrder an. |
| Webhook mehrfach verarbeitet | Wiederholungsverhalten ohne Idempotenz | Fügen Sie Idempotenzschlüssel- und Endzustandsprüfungen hinzu. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Beweise, die es zu erfassen gilt

| Integration | Nützliche Beweise |
| --- | --- |
| Trading Widget | Seite URL, SDK Versionspfad, Browserkonsole, fehlgeschlagene Netzwerkanforderungen, `onError` Nutzlast und Containerabmessungen. |
| Agent SDK | SDK Sprache/Version, Basis URL, UTC Zeitstempel, Anforderungs-ID, `agentOrderNo`, Antwortcode und bereinigte Protokolle. |
| Webhook | Lieferzeit, Ereignis- oder Geschäftsschlüssel, Ergebnis der Signaturvalidierung, Verarbeitungsstatus und bereinigter Rohkörper-Hash. |
| REST API | Methode, Pfad, Umgebung, Anforderungs-ID, Antwortcode und bereinigte Parameter. |

Beziehen Sie niemals Passwörter, Zugriffstokens, API Geheimnisse, vollständige Signaturen, private Schlüssel oder nicht redigierte persönliche Daten in die Diagnose ein.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Bevor es eskaliert

- Versuchen Sie es nur erneut, wenn der Vorgang als sicher dokumentiert ist.
- Fragen Sie nach einer Zeitüberschreitung die ursprüngliche Geschäftskennung ab, anstatt eine neue zu erstellen.
- Überprüfen Sie die Systemuhr und die Anmeldeinformationsumgebung auf Signaturfehler.
- Behalten Sie den ersten Fehler und alle späteren Wiederholungsergebnisse bei.
- Benutzen Sie die [Vorlage für Supportanfragen](/de/resources/support-request-template) um einen vollständigen, redigierten Bericht zu senden.

## Java v0.3.0 Diagnose

| Symptom | Überprüfung und Wiederherstellung |
| --- | --- |
| Die Finanzierungsanfrage hat ein unbekanntes Ergebnis | Behalten Sie das Original `agentOrderNo`; Rufen Sie `queryWalletTransfer` mit der ursprünglichen Umgebung auf. Verwenden Sie nicht `queryOrder`. |
| Die Simulations-Benutzeroberfläche zeigt unerwartete Mittel an | Überprüfen Sie das Frontend `tradingMode` getrennt vom Backend `environment`; Konto `isSimulatedUser` leitet keine Anfragen weiter. |
| Abfragefehler `6905` | Nutzen Sie die gemeinsame Partnerquote nicht mehr und versuchen Sie es dann noch einmal mit dem gleichen Cursor und den gleichen Filtern durch SDK. |
| Abfragefehler `6904` | Reduzieren Sie gleichzeitige Abfragen und verengen Sie das Zeitfenster. Wenden Sie sich an den Support, wenn das Problem weiterhin besteht. |
| Ungültiger oder abgelaufener Cursor | Starten Sie dasselbe feste Verlaufsfenster neu und deduplizieren Sie gespeicherte Datensätze. |
| Fehlende neue Methode Java. | Überprüfen Sie das aufgelöste Maven-Artefakt anhand des öffentlichen Tags `v0.3.0`; Entfernen Sie widersprüchliche Abhängigkeiten gemäß Ihrer Artefaktrichtlinie. |
