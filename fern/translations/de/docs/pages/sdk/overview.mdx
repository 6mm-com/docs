<h2 id="recommended-combination">Empfohlene Kombination</h2>

| Partnerziel | Frontend | Backend | Warum es wichtig ist |
| --- | --- | --- | --- |
| Fügen Sie ein eingebettetes Handelsterminal hinzu | Trading Widget SDK | Agent SDK | Das Widget übernimmt die Handels-UI, während das Partner-Backend Token ausgibt und Geheimnisse privat hält. |
| Einen nativen App-Einstiegspunkt erstellen | Native oder H5-Eintrag | Agent SDK | Die App öffnet einen 6MM Eintrag URL , nachdem der Partner die Benutzersitzung validiert hat. |
| Erstellen Sie einen benutzerdefinierten Handelsfluss | Partner-UI | Entwickler API + ausgewählte SDK Flows | Nutzen Sie APIs für Konto-, Auftrags-, Positions- und Marktdaten, während die operative Kontrolle serverseitig bleibt. |

<h2 id="reference-architecture">Referenzarchitektur</h2>

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Geheimnisse auf Serverseite bewahren**
>
> Browser-Code sollte nur Partner-eigene Endpunkte aufrufen. Der Agent API Secret darf niemals an den Frontend-Code ausgeliefert werden.

<h2 id="production-checklist">Produktionscheckliste</h2>

- Speichere apiSecret nur in der Backend-Infrastruktur.
- Verwenden Sie HTTPS für Agenten API Anfragen und Webhook-URLs.
- Persistieren agentUserId, platformUserId, und agentOrderNo Abbildungen.
- Monetäre Beträge als Dezimalstrings anstelle von Gleitkommawerten darstellen.
- Behandeln Sie PROCESSING als ausstehend, nicht als Erfolg oder Misserfolg.
- Webhooks idempotent verarbeiten, da Wiederholungen erwartet werden.
