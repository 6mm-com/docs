Nutzen Sie WebSocket Streams für Marktdaten und private User-State-Updates, die ohne Umfragen aktuell bleiben müssen.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Verbindung URL

```text
wss://ws.6mm.com/ws
```

Private Streams benötigen Authentifizierungskontext wie einen listenKey oder Zugriffstoken, wie in der Dokumentation des privaten Kanals beschrieben.

<span id="subscribe" data-sixmm-canonical-anchor="subscribe" aria-hidden="true"></span>

## Abonnieren

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Erfolgreiche Abonnementbestätigung:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<span id="unsubscribe" data-sixmm-canonical-anchor="unsubscribe" aria-hidden="true"></span>

## Abmelden

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

## Anwendungsping

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<span id="message-envelope" data-sixmm-canonical-anchor="message-envelope" aria-hidden="true"></span>

## Nachrichtenumschlag

Öffentliche Vorstöße nutzen eine einheitliche Grenze:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<span id="operational-recommendations" data-sixmm-canonical-anchor="operational-recommendations" aria-hidden="true"></span>

## Betriebsempfehlungen

- Generiere eine eindeutige clientseitige `id` für jede Abonnieren-, Abmelde- und Ping-Anfrage.
- Behandeln Sie die Wiederverbindung als neue Sitzung und abonnieren Sie erneut erforderliche Themen.
- Überprüfen Sie, dass die zurückgegebene `topic` mit dem Kanal übereinstimmt, den Ihr Dienst erwartet.
- Halte die Nachrichtenverarbeitung idempotent, wenn private Bestellungen oder Kontoereignisse betroffen sind.
- Protokollieren Sie Verbindungszustandsänderungen, Abonnementbestätigungen und abnormale Verbindungsabbrüche.

<span id="reconnect-workflow" data-sixmm-canonical-anchor="reconnect-workflow" aria-hidden="true"></span>

## Workflow Wiederverbinden

1. Schließe oder entsorge die vorherige Buchse und stelle eine neue Verbindung her.
2. Private Streams mit einem gültigen listenKey oder Zugriffstoken erneut authentifizieren.
3. Abonniere jedes erforderliche Thema erneut und warte auf erfolgreiche Danksagungen.
4. Ersetze den lokalen Orderbuch-Status durch einen neuen Snapshot, bevor du inkrementelle Updates anwendest.
5. Offene Befehle, Positionen und Bilanzen durch REST abzustimmen, falls private Ereignisse übersehen wurden.

Nutze bounded exponential backoff mit Jitter für Wiederverbindungsversuche. Ein kontinuierlich wiederverbundener Client sollte die Bediener alarmieren, anstatt es unbegrenzt ohne Sicht zu versuchen.

<span id="heartbeat-and-stale-connections" data-sixmm-canonical-anchor="heartbeat-and-stale-connections" aria-hidden="true"></span>

## Herzschlag und abgestandene Verbindungen

- Verfolgen Sie die aktuellste eingehende Nachricht und die erfolgreiche Ping-Bestätigung.
- Verwenden Sie das für die Produktionsumgebung genehmigte Herzschlagintervall und Leerlaufschwelle.
- Behandle eine Verbindung als veraltet, wenn der konfigurierte Schwellenwert überschritten wird, selbst wenn der TCP Sockel noch offen erscheint.
- Keine Abonnements von einem alten Socket wiederverwenden; Abonniere dich nach jeder Wiederverbindung ausdrücklich wieder.
