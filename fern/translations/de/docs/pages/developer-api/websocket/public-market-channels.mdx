Nutzen Sie öffentliche Marktkanäle, wenn eine Anwendung kontinuierlich aktualisierte Preise, Trades, Candlesticks oder Orderbook-Tiefe benötigt, ohne REST Endpunkte wiederholt zu befragen. Diese Streams können Handelsbildschirme, Preisanzeigen, Benachrichtigungen und Marktüberwachung unterstützen.

<span id="connection-url" data-sixmm-canonical-anchor="connection-url" aria-hidden="true"></span>

## Verbindung URL

```
wss://ws.6mm.com/ws
```

Öffentliche WebSocket erfordert keine Authentifizierung.

Für den Verbindungslebenszyklus, Abmelden, Ping und Wiederverbinden siehe [Verbindung, Abonnement & Herzschlag](/de/developer-api/websocket/connection-subscription-and-heartbeat).

<span id="common-channels" data-sixmm-canonical-anchor="common-channels" aria-hidden="true"></span>

## Gemeinsame Kanäle

| Kanal                            | Beschreibung                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | Bestelle Buchtiefe. Es wird zuerst ein Snapshot gesendet, dann inkrementelle Updates |
| `market.trade.{symbol}`            | Neueste Trades                                                      |
| `market.kline.{symbol}.{interval}` | Klines                                                             |
| `market.ticker.{symbol}`           | Einzelsymbol-Ticker-Zusammenfassung                                       |
| `market.tickers`                   | Zusammenfassung des All-Symbol-Tickers                                          |

<span id="choose-a-channel" data-sixmm-canonical-anchor="choose-a-channel" aria-hidden="true"></span>

## Wählen Sie einen Kanal

| Anwendungsbedarf | Kanal |
| --- | --- |
| Aufbau oder Pflege eines Bestellbuchs | `market.depth.{symbol}` |
| Zeigen Sie einen Live-Handelsfeed an | `market.trade.{symbol}` |
| Zeichne ein Kerzendiagramm | `market.kline.{symbol}.{interval}` |
| Zeigen Sie eine Marktübersicht | `market.ticker.{symbol}` |
| Führen Sie einen Marktüberblick | `market.tickers` |

<span id="subscription-example" data-sixmm-canonical-anchor="subscription-example" aria-hidden="true"></span>

## Abonnementbeispiel

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<span id="push-message-wrapper" data-sixmm-canonical-anchor="push-message-wrapper" aria-hidden="true"></span>

## Push-Nachrichten-Wrapper

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

Verwenden Sie `topic` , um jede Nachricht an den richtigen Behandler zu leiten, und `ts` , um die Lieferzeiten zu beobachten. Das `data` -Objekt enthält die Nutzlast für den abonnierten Kanal.

<span id="order-book-handling" data-sixmm-canonical-anchor="order-book-handling" aria-hidden="true"></span>

## Handhabung des Auftragsbuchs

Der Tiefenkanal sendet zuerst einen Snapshot und dann inkrementelle Updates. Initialisiere das lokale Buch aus dem Snapshot, bevor du Updates anwechsle. Nach der Wiederverbindung erstelle eine neue Sitzung, abonniere erneut und baue das lokale Buch aus dem nächsten Snapshot neu auf, anstatt aus dem veralteten In-Memory-Zustand fortzufahren.

<span id="production-recommendations" data-sixmm-canonical-anchor="production-recommendations" aria-hidden="true"></span>

## Produktionsempfehlungen

- Generiere für jede Abonnier-, Abmelde- und Ping-Anfrage eine eindeutige `id` .
- Bestätigen Sie die Abonnementbestätigungen, bevor ein Kanal als aktiv behandelt wird.
- Nach der erneuten Verbindung zu jedem erforderlichen Thema erneut abonnieren.
- Halte Netzwerklesungen getrennt von langsameren Datenbank- oder UI-Verarbeitungen.
- Überwachung der Trennfrequenz, Nachrichtenverzögerungen und fehlgeformter Nutzlasten.
- Verwenden Sie [Private User Channel](/de/developer-api/websocket/private-user-channel) für authentifizierte Konto- und Bestell-Updates.
