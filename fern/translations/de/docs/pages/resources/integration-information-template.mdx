Verwenden Sie diese Vorlage, wenn Sie eine neue Integration vorbereiten oder eine bestehende Integration in die Produktion bringen.

<span id="partner-information" data-sixmm-canonical-anchor="partner-information" aria-hidden="true"></span>

## Partnerinformationen

| Spielfeld | Beschreibung |
| --- | --- |
| Partnername | Legal oder Projektname, der für die Integration verwendet wird. |
| Produkttyp | App, Wallet, Broker-Portal, White-Label-Börse, institutionelle Plattform oder andere. |
| Primäre Kontakte | Geschäftliche, technische, operative und Notfallkontakte. |
| Startregionen | Länder oder Regionen, in denen die Integration offengelegt wird. |

<span id="technical-information" data-sixmm-canonical-anchor="technical-information" aria-hidden="true"></span>

## Technische Informationen

| Spielfeld | Beschreibung |
| --- | --- |
| Frontend-Domänen | Domains, die das Widget oder die Einstiegsseiten laden. |
| Backend-Domänen | Serverdomänen, die für Agent SDK oder API Aufrufe verwendet werden. |
| Webhook URL | Produktions-Webhook-Endpunkt und erwartete IP Allowlist-Anforderungen. |
| Integrationsumfang | Trading Widget, Agent SDK, REST API, WebSocket, White-Label-System oder Liquiditätsintegration. |

<span id="operational-information" data-sixmm-canonical-anchor="operational-information" aria-hidden="true"></span>

## Betriebsinformationen

- Voraussichtlicher Starttermin.
- Erwarteter Verkehr oder aktiver Benutzerbereich.
- Support-Stunden und Eskalations-Eigentümer.
- Überwachung des Besitzers und des Kontakts zum Vorfall.

<span id="security-and-review-information" data-sixmm-canonical-anchor="security-and-review-information" aria-hidden="true"></span>

## Sicherheits- und Bewertungsinformationen

- Authentifizierungsmethode und API Key Berechtigungsbereich.
- Geheime Speicher-, Rotationsbesitzer und genehmigte Quell-IPs.
- Webhook-Signaturverifikation und Idempotenzdesign.
- Inhaber von Protokollierung, Überwachung, Abstimmung, Rollback und Incident-Response.
- Zielmärkte, Nutzertyp, Verwahrungsmodell und die für nutzerbezogene Verpflichtungen verantwortliche Einheit.

Fügen Sie in dieser Vorlage keine Produktionsgeheimnisse, Vollzugriffstoken, private Schlüssel oder ungeschwärzte Benutzerdaten hinzu.

Verwenden Sie die [Produktionsstart-Checkliste](/de/resources/production-launch-checklist) für die endgültige Genehmigung und die [Support-Anfrage-Vorlage](/de/resources/support-request-template) für die Eskalation von Themen.
