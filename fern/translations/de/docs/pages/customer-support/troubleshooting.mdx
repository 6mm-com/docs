## Konsolen- und Besucherunterstützung

| Symptom | Überprüfen Sie zuerst |
| --- | --- |
| Es fehlt ein Menü | Kontorolle und Mandantendienstverfügbarkeit |
| Widget öffnet sich nicht | Generiertes Skript URL, App-Schlüssel, zulässige Domänen- und Browserfehler |
| Bot verwendet nicht das große Modell | Tatsächlich abgestimmter Schritt, intelligente Serviceschalter und relevante Konfiguration |
| Eine Antwort verwendet alte Regeln | Quellartikel, Veröffentlichungsstatus, FAQ Text, Übersetzung und Abrufstatus |
| Übersetzung fehlt | Zielsprache, Übersetzungswechsel, gespeicherte Übersetzung und Service-/Balance-Verfügbarkeit |
| Die Vektorgenerierung schlägt fehl | Serviceverfügbarkeit und Abrufstatus; Vermeiden Sie wiederholte Wiederherstellungen, ohne den Fehler zu identifizieren |
| Ein Kontaktfeld ist leer | Ob dieses Feld tatsächlich gesammelt wurde; Unterscheiden Sie zwischen Kontakt- und Eintritts-E-Mail |

## MCP Verbindung und Anrufe

| Symptom | Nächster Schritt |
| --- | --- |
| Beim Öffnen des Endpunkts in einem Browser wird ein Fehler zurückgegeben | Es handelt sich um einen Protokollendpunkt, nicht um eine Anmeldeseite. Fügen Sie es einem kompatiblen MCP-Client hinzu |
| Die Autorisierung kann nicht gestartet werden | Überprüfen Sie den genauen Endpunkt, die Unterstützung für Streamable HTTP/OAuth des Clients und den Browser-Anmeldeablauf |
| Nicht autorisierte oder abgelaufene Verbindung | Widerruf und Ablauf prüfen; Stellen Sie die Verbindung über die Anwendung wieder her |
| Ein Werkzeug fehlt oder der Zugriff ist verweigert | Überprüfen Sie die Autorisierungskontorolle und den Datensatzbereich. Aktualisieren Sie die Werkzeugliste |
| Warten auf Genehmigung | Öffnen Sie den zurückgegebenen Genehmigungslink und überprüfen Sie ihn im Backend |
| Inhalt geändert | Lesen Sie den neuesten Datensatz, zeigen Sie ihn erneut in der Vorschau an und übermitteln Sie einen neuen geplanten Vorgang |
| Zeitüberschreitung bei der Anfrage | Fragen Sie den Vorgangsstatus ab, bevor Sie es erneut versuchen oder einen Fehler annehmen |
| Kein Schreibprotokoll | Unterscheiden Sie zwischen einem Lesevorgang, einer ausstehenden Genehmigung und einem abgeschlossenen Schreibvorgang. Überprüfen Sie die Filter in den Betriebsprotokollen |

<span id="before-contacting-support" data-sixmm-canonical-anchor="before-contacting-support" aria-hidden="true"></span>

## Bevor Sie den Support kontaktieren

Erfassen Sie die Uhrzeit und Zeitzone, den betroffenen Mandanten/das betroffene Konto, den Namen der Seite oder des Tools, die Vorgangs-ID (sofern verfügbar) und den genauen Fehler. Fügen Sie einen geschwärzten Screenshot oder Schritte zur Reproduktion bei. Senden Sie keine Passwörter, Bestätigungscodes, Inhabertokens oder Signaturgeheimnisse.

Versuchen Sie bei der Diagnose von Schreibvorgängen einen kleinen Testdatensatz. Überprüfen Sie das Ergebnis und bereinigen Sie nur die von Ihnen erstellten Testdaten, wobei Sie bei Bedarf den normalen Bestätigungsablauf verwenden.
