## Verfolgen Sie einen Vorgang

Öffnen Sie **Vorgangsprotokolle**. Filtern Sie mithilfe der verfügbaren Steuerelemente nach Schlüsselwort, Kategorie, Aktion, Akteurstyp, Zieltyp und Datum. Lesen Sie die Details, um herauszufinden, wer gehandelt hat, welcher Datensatz geändert wurde und welches Ergebnis das Ergebnis ist.

MCP Vorgänge werden mit ihrem Anwendungs-/Quellen- und Ausführungsstatus angezeigt. Je nach Vorgang können sowohl eine Geschäftsänderung als auch ihr MCP Ausführungsdatensatz angezeigt werden; Zwei Prüfeinträge allein bedeuten nicht, dass die Aktion zweimal ausgeführt wurde.

<span id="distinguish-authorization-from-execution" data-sixmm-canonical-anchor="distinguish-authorization-from-execution" aria-hidden="true"></span>

## Unterscheiden Sie zwischen Autorisierung und Ausführung

Eine Anwendungsverbindung weist lediglich die Autorisierung nach. Ein vorgeschlagener Schreibvorgang, eine ausstehende Genehmigung und ein abgeschlossener Schreibvorgang sind unterschiedliche Zustände. Das Protokoll ist keine vollständige Abschrift aller Aussagen zur externen KI, und es sollte nicht davon ausgegangen werden, dass eine schreibgeschützte Abfrage einen geschäftlichen Schreibdatensatz erstellt.

Behalten Sie bei der Untersuchung eines fehlgeschlagenen MCP-Anrufs dessen Vorgangs-ID, Uhrzeit und Fehlermeldung bei. Fragen Sie das Operationsergebnis ab, bevor Sie es erneut versuchen. Betriebsprotokolle sind bis MCP schreibgeschützt.
