Verwenden Sie Tickets, um Arbeiten zu verfolgen, die nicht in einem Gespräch erledigt werden können. Halten Sie den Datensatztyp, die verantwortliche Person und den aktuellen Fortschritt klar, damit der nächste Agent fortfahren kann.

<div className="sixmm-support-flow">

1. **Identifizieren Sie den Datensatz** – Wählen Sie ein Agententicket, ein Benutzerticket oder ein Feedback.
2. **Untersuchen und zuweisen** – Lesen Sie die Beschreibung und bestätigen Sie, wer sich darum kümmert.
3. **Aktualisieren Sie das Ergebnis** – Zeichnen Sie den Fortschritt auf und überprüfen Sie den gespeicherten Status.

</div>


<span id="choose-the-correct-record" data-sixmm-canonical-anchor="choose-the-correct-record" aria-hidden="true"></span>

## Wählen Sie den richtigen Datensatz

Öffnen Sie **Ticketverwaltung** und wählen Sie die entsprechende Registerkarte aus.

| Aufzeichnen | Zweck |
| --- | --- |
| Agententicket | Vom Support-Team erstellte und gepflegte Arbeit |
| Benutzerticket | Eine von einem Besucher zur Nachbearbeitung eingereichte Frage |
| Benutzer-Feedback | Ein Vorschlag oder ein Problem, das über einen Feedback-Eintrag eingereicht wurde |

<span id="handle-a-case" data-sixmm-canonical-anchor="handle-a-case" aria-hidden="true"></span>

## Behandeln Sie einen Fall

Lesen Sie die in der Akte verfügbare Beschreibung, Kontaktdaten, entsprechende Gespräche und Anhänge. Weisen Sie es dem entsprechenden Bearbeiter zu und aktualisieren Sie den Status im Verlauf der Arbeit. Verwenden Sie die unterstützten Bearbeitungssteuerelemente für Agententickets. Für Benutzertickets und Feedback stehen eigene Aktionen zur Verfügung.

Das Aktualisieren eines Status allein beweist nicht, dass der Besucher eine E-Mail- oder Chat-Antwort erhalten hat. Senden Sie bei Bedarf eine Antwort über einen verfügbaren Kommunikationskanal und überprüfen Sie das Ergebnis. Bewahren Sie persönliche Daten innerhalb des autorisierten Mieter-Workflows auf.

<span id="use-mcp-for-triage" data-sixmm-canonical-anchor="use-mcp-for-triage" aria-hidden="true"></span>

## Verwenden Sie MCP für die Triage

Bitten Sie die vernetzte KI, ungelöste Fälle aufzulisten, sie nach Problem zu gruppieren und einen Antwortvorschlag vorzubereiten. Überprüfen Sie Zuweisungen und Statusänderungen, bevor Sie sie auf reale Fälle anwenden. Die Erstellung von Agententickets und die Übermittlung von Benutzertickets sind unterschiedliche Arbeitsabläufe. Ein Werkzeug für den einen bedeutet nicht, dass es den anderen unterstützt. Das Löschen eines Tickets über MCP erfordert eine Bestätigung.


<span id="use-status-and-priority-deliberately" data-sixmm-canonical-anchor="use-status-and-priority-deliberately" aria-hidden="true"></span>

## Setzen Sie Status und Priorität bewusst ein

Agententickets unterstützen die Status „Ausstehend“, „Bearbeitet“, „Gelöst“ und „Geschlossen“. Benutzertickets und Feedback legen ihre eigenen Statuskontrollen offen; Gehen Sie nicht davon aus, dass jede Registerkarte genau die gleichen Aktionen hat.

| Detail | Wie es hilft |
| --- | --- |
| Losnummer | Suchen Sie den genauen Datensatz, wenn Sie Arbeit an einen anderen Agenten übergeben. |
| Beschreibung und zugehörige Sitzung | Verstehen Sie, was passiert ist und was bereits besprochen wurde. |
| Beauftragter oder Bearbeiter | Identifizieren Sie die Person, die für die nächste Aktion verantwortlich ist. |
| Vorrang bei Agententickets | Trennen Sie die Dringlichkeit vom Workflow-Status. Ein Ticket mit hoher Priorität wird nicht automatisch gelöst. |
| Mal erstellt und gelöst | Überprüfen Sie die Zeitleiste anhand der ausgewählten Datumsbasis. |

<span id="example-an-issue-needs-technical-investigation" data-sixmm-canonical-anchor="example-an-issue-needs-technical-investigation" aria-hidden="true"></span>

### Beispiel: Ein Problem erfordert eine technische Untersuchung

1. Öffnen Sie den Originaldatensatz und erfassen Sie die Zeit, die betroffene Seite und reproduzierbare Schritte aus den bereitgestellten Informationen.
2. Überprüfen Sie die verknüpfte Konversation, sofern verfügbar. Bitten Sie den Besucher nicht, bereits aufgezeichnete Informationen zu wiederholen.
3. Weisen Sie einen geeigneten Bearbeiter zu und aktualisieren Sie den Status im Verlauf der Arbeit. Halten Sie interne Notizen sachlich.
4. Wenn das Problem überprüft wurde, aktualisieren Sie das Ergebnis und kontaktieren Sie den Besucher über einen verfügbaren Kanal. Überprüfen Sie den gespeicherten Datensatz, bevor Sie die Seite verlassen.

<span id="common-questions" data-sixmm-canonical-anchor="common-questions" aria-hidden="true"></span>

## Häufige Fragen

<AccordionGroup>

<Accordion title="Wird der Besucher durch die Lösung eines Tickets automatisch benachrichtigt?">
Eine Statusänderung allein beweist nicht, dass eine E-Mail oder Chat-Nachricht gesendet wurde. Überprüfen Sie den Kommunikationskanal und das Lieferergebnis separat.
</Accordion>

<Accordion title="Warum kann ich das Ticket nicht finden?">
Überprüfen Sie die Registerkarte „Datensatz“, die Datumsbasis, den Datumsbereich, den Status und die Beauftragtenfilter. Löschen Sie unnötige Filter, bevor Sie erneut suchen.
</Accordion>

</AccordionGroup>
