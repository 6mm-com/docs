Ein klares Verantwortungsmodell reduziert das operative Risiko und hilft Support-Teams, schneller zu reagieren.

<h2 id="responsibility-split">Verantwortlichkeitsaufteilung</h2>

| Gebiet | 6MM | Partner |
| --- | --- | --- |
| Handelsinfrastruktur | Matching, Risiko, Handels-, API - und SDK -Fähigkeiten | Korrekte Integration und Produktionsüberwachung |
| Endbenutzerbeziehung | Keine direkte Kundenbeziehung, es sei denn, sie werden separat vereinbart | Benutzer-Onboarding, Support, Offenlegungen und Kontolebenszyklus |
| Geheimnisse und Qualifikationen | Bietet Credential-Modell und Signierungsanforderungen | Speichert Geheimnisse sicher und schränkt den internen Zugriff ein |
| Webhooks | Sendet signierte Lebenszyklusereignisse | Verifiziert Signaturen und verarbeitet Ereignisse idempotent |
| Compliance-Operationen | Stellt compliance-orientierte Technologien und Unterstützungsmaterialien bereit | Bestätigt lokale Verpflichtungen und benutzerorientierte Anforderungen |
| Integrationsveröffentlichungen | Verwaltet dokumentierte Plattform- und Integrationsfähigkeiten | Testet Partnercode, Konfiguration und Nutzerreisen vor der Veröffentlichung |
| Incident-Handling | Untersucht relevante 6MM Infrastruktur und stellt Partnerunterstützungskanäle bereit | Erkennt nutzerbezogene Auswirkungen, bewahrt Beweise, enthält Partnersysteme und eskaliert |

<h2 id="responsibilities-by-lifecycle">Verantwortlichkeiten nach Lebenszyklus</h2>

| Bühne | Partneraktion |
| --- | --- |
| Konstruktion | Definieren Sie Benutzereigentum, Asset-Flow, Datenfluss, Support-Modell und Zieljurisdiktionen. |
| Bau | Bewahre Geheimnisse im Backend, implementiere unterstützte Authentifizierung und bewahre Geschäftskennungen. |
| Test | Üben Sie Timeout-, Retry-, Duplicate-Webhook-, Expired-Token- und Fehlerszenarien. |
| Stapellauf | Vollständige Bereitschaftsprüfung, Einrichtung von Überwachung und Dokumentierung der Eskalation der Unterstützung. |
| Operieren | Überprüfen Sie Warnungen, gleichen abnormale Abläufe ab, wechseln Sie die Referenzdaten und bewahren Sie Prüfungsnachweise auf. |
| Vorfall | Enthalten Sie von Partnern kontrollierte Systeme, schützen Sie Zugangsdaten, bewahren Sie UTC Zeitlinien und kontaktieren Sie den richtigen 6MM Kanal. |

<h2 id="handoff-checklist">Checkliste für die operative Übergabe</h2>

- Benennen Sie den Eigentümer für Integrationsgesundheit, Sicherheit, Compliance und Endnutzersupport.
- Dokumentproduktionsbasis-URLs, Berechtigungsinhaber und Rotationsverfahren.
- Bestätigen von Dashboards und Warnungen bei Authentifizierung, Bestellungen, Übertragungen und Webhook-Fehlern.
- Speichere Anfrage-IDs, Partner-Bestellnummern und Ereignis-IDs in durchsuchbaren Logs.
- Definieren, welche Ereignisse eine sofortige Eskalation erfordern.
- Halten Sie die [Support Request Template](/de/resources/support-request-template) dem Betriebsteam zur Verfügung.
