Un modelo claro de responsabilidad reduce el riesgo operativo y ayuda a los equipos de soporte a responder más rápido.

<h2 id="responsibility-split">División de responsabilidades</h2>

| Área | 6MM | Socio |
| --- | --- | --- |
| Infraestructura de negociación | Capacidades de emparejamiento, riesgo, motor de trading, API y SDK | Integración correcta y monitorización de producción |
| Relación con el usuario final | No hay relación directa con el cliente a menos que se acuerde por separado | Incorporación de usuarios, soporte, divulgaciones y ciclo de vida de la cuenta |
| Secretos y credenciales | Proporciona modelo de credenciales y requisitos de firma | Almacena secretos de forma segura y restringe el acceso interno |
| Ganchos de red | Envía eventos de ciclo de vida firmados | Verifica firmas y procesa eventos idempotentes |
| Operaciones de cumplimiento | Proporciona tecnología orientada al cumplimiento y materiales de soporte | Confirma las obligaciones locales y los requisitos de atención al usuario |
| Versiones de integración | Mantiene capacidades documentadas de plataforma e integración | Prueba el código del socio, la configuración y los recorridos del usuario antes del lanzamiento |
| Gestión de incidentes | Investiga la infraestructura 6MM relevante y proporciona canales de soporte a socios | Detecta el impacto directo al usuario, preserva pruebas, contiene sistemas asociados y escala |

<h2 id="responsibilities-by-lifecycle">Responsabilidades por ciclo de vida</h2>

| Escenario | Acción de la pareja |
| --- | --- |
| Diseño | Define la propiedad del usuario, el flujo de activos, el flujo de datos, el modelo de soporte y las jurisdicciones objetivo. |
| Construcción | Guarda secretos en el backend, implementa autenticación compatible y preserva los identificadores empresariales. |
| Test | Escenarios de tiempo límite, reintento, duplicado-webhook, token expirado y fallo. |
| Lanzamiento | Revisión completa de la preparación, establecimiento de monitorización y documentación de apoyo a la escalada. |
| Funcionamiento | Revisa alertas, reconcilia operaciones anormales, rota las credenciales y mantén pruebas de auditoría. |
| Incidente | Contener sistemas controlados por socios, proteger las credenciales, preservar UTC plazos y contactar con el canal de 6MM correcto. |

<h2 id="handoff-checklist">Lista de verificación de transferencia operativa</h2>

- Nombrar al propietario para la integración, la salud, la seguridad, el cumplimiento y el soporte para el usuario final.
- Documentar las URLs de la base de producción, los propietarios de credenciales y los procedimientos de rotación.
- Confirmar paneles y alertas para fallos de autenticación, pedido, transferencia y webhook.
- Almacenar IDs de solicitudes, números de pedido de socios e IDs de eventos en registros consultables.
- Definir qué eventos requieren una escalada inmediata.
- Mantener la [Plantilla de Solicitud de Soporte](/es-ES/resources/support-request-template) disponible para el equipo de operaciones.
