El 6MM Agent SDK es para servicios backend de socios que necesitan llamar al Agente privilegiado APIs sin implementar la firma y el manejo de solicitudes desde cero. No debe ejecutarse en código de navegador, móvil o escritorio público porque la integración utiliza un secreto de socio API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Cuándo utilizar el Agent SDK

Utiliza el Agent SDK cuando tu backend necesite vincular a un usuario socio, transferir activos mediante un flujo aprobado, consultar registros de trading, crear una URL de acceso al trading integrado o verificar notificaciones de Webhook. Utiliza el [Trading Widget SDK](/es-ES/sdk/trading-widget/overview) por separado cuando el frontend del socio necesite mostrar la interfaz de trading.

## Configuración común

| Llave | Ejemplo | Descripción |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agente API servicio URL sin barra diagonal. |
| agentCode | AGENT001 | Código de agente asociado. |
| apiSecret | tu-api-secreto | API secreto de firma almacenado solo en el backend. |
| defaultCurrency | USDT | Moneda predeterminada para transferencia y cuenta APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Punto final del socio para notificaciones 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Flujo de integración típico

1. La interfaz del socio autentica al usuario a través del propio sistema de cuentas del socio.
2. El backend del socio asigna al usuario a un identificador estable del lado del socio.
3. El backend llama al Agent SDK con `agentCode` y el secreto protegido API.
4. El SDK firma y envía la solicitud del Agente API.
5. El backend almacena el identificador comercial devuelto y lo procesa posteriormente webhooks de forma idempotente.
6. La interfaz recibe solo el resultado de corta duración o la credencial de entrada que necesita.

<span id="production-checklist" data-sixmm-canonical-anchor="production-checklist" aria-hidden="true"></span>

## Lista de verificación de producción

- Cargue `apiSecret` desde un administrador secreto de backend, no desde el código fuente.
- Mantenga separadas las credenciales de desarrollo, puesta en escena y producción.
- Utilice un mapeo de usuarios de socios estable e identificadores de pedidos comerciales únicos.
- Conserve el identificador original al verificar el estado de una solicitud caducada.
- Verifique las firmas webhook y almacene los ID de eventos procesados.
- Redacte secretos y firmas de los registros y al mismo tiempo conserve los ID de las solicitudes de soporte.
