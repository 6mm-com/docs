Las excepciones pueden incluir interrupción de precios, evidencia de precios inconsistente, discrepancias en las probabilidades o procesamiento de liquidación fallido. Una excepción requiere una resolución registrada; no es automáticamente un resultado perdedor.

## Situaciones comunes

| Situación | que hacer |
| --- | --- |
| Falta alimentación de cuadrícula durante la ventana válida | Verificar el procesamiento de excepciones/reembolsos; una muestra ausente no puede probar un error |
| Se agotó el tiempo de respuesta del pedido | Busque el pedido y la reserva originales antes de volver a enviarlos. |
| La visualización y el resultado registrado no están de acuerdo | Compare la fuente de precios, las marcas de tiempo, los términos aceptados y la evidencia de resultados |
| El acuerdo parece retrasado | Verifique el estado final y la transacción por separado |
| Registro reembolsado o anulado | Revise el motivo, el movimiento real de fondos y la reserva restante. |

## El reembolso y la anulación son distintos

Un reembolso describe el tratamiento del fondo. Una anulación describe la invalidación de un pedido. No infiera el monto exacto del reembolso o la fecha límite de procesamiento únicamente de la etiqueta; utilizar la resolución y las transacciones registradas.

Los pedidos reembolsados ​​y anulados están excluidos de la participación válida en los informes. Los reembolsos no deben contarse como ganancias ganadoras al evaluar el rendimiento del juego.

## evidencia de apoyo

Proporcione el número de pedido, el número de ronda, si corresponde, el símbolo, las marcas de tiempo relevantes, el multiplicador de pago registrado, el resultado/estado y el número de transacción de liquidación. Para disputas sobre la red, incluya el intervalo de precios aceptado y el período de tiempo válido. Nunca incluya contraseñas, API secretos ni tokens de acceso completo.
