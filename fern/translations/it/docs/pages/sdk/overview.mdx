## Combinazione consigliata

| Obiettivo del partner | Frontend | Backend | Perché è importante |
| --- | --- | --- | --- |
| Aggiungere un terminale di trading embedded | Trading Widget SDK | Agent SDK | Il widget gestisce l'interfaccia di trading mentre il backend partner emette i token e mantiene i segreti privati. |
| Crea un punto di ingresso nativo per l'app | Ingresso nativo o H5 | Agent SDK | L'app apre una 6MM URL di voce dopo che il partner ha validato la sessione utente. |
| Crea un flusso di trading personalizzato | Interfaccia Partner | Sviluppatore API + flussi SDK selezionati | Usa API per i dati di conto, ordini, posizione e mercato mantenendo i controlli operativi lato server. |

<span id="reference-architecture" data-sixmm-canonical-anchor="reference-architecture" aria-hidden="true"></span>

## Architettura di riferimento

```text
Partner Web App
  -> TradingWidget.create()
  -> tokenProvider()
  -> Partner Backend
  -> 6MM Agent SDK
  -> 6MM Agent API
  -> 6MM Trading iframe
```

> **Tieni segreti lato server**
>
> Il codice del browser dovrebbe chiamare solo endpoint di proprietà del partner. L'Agente API segreto non deve mai essere inviato al codice frontend.

<span id="production-checklist" data-sixmm-canonical-anchor="production-checklist" aria-hidden="true"></span>

## Elenco di controllo della produzione

- Memorizza apiSecret solo nell'infrastruttura backend.
- Usare HTTPS per le richieste di API Agent e gli URL dei webhook.
- Persistere agentUserId, platformUserIde agentOrderNo mappamenti.
- Rappresentare importi monetari come stringhe decimali invece che come valori in virgola mobile.
- Gestire PROCESSING come in attesa, non come successo o fallimento.
- Elaborare i webhook idempotentemente perché ci sono previsti retentativi.
