Inizia con l'ambiente, il timestamp e l'identificatore aziendale per l'operazione non riuscita. Un controllo strutturato solitamente separa i problemi di configurazione dai problemi di autenticazione, rete ed elaborazione asincrona.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Ordine diagnostico consigliato

1. Conferma l'ambiente e la base interessati URL.
2. Registra l'intervallo di tempo UTC e la prima richiesta non riuscita.
3. Identificare il modulo: Trading Widget, Agent SDK, REST API, WebSocket o webhook.
4. Acquisisci l'ID richiesta, l'ID utente partner, `agentOrderNo`, l'ID ordine o l'ID evento webhook.
5. Controlla il codice recente, le credenziali, la whitelist IP o le modifiche alla distribuzione.
6. Riproduci con il caso di test sicuro più piccolo.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget problemi

| Sintomo | Probabile causa | Aggiustare |
| --- | --- | --- |
| iframe richiede il dominio locale del partner | Manca baseUrl | Passa baseUrl: 'https://app.6mm.com'. |
| iframe è invisibile o molto breve | Il contenitore principale non ha altezza | Imposta l'altezza del contenitore o l'altezza del passaggio. |
| token_provider_missing | La modalità partner-token non ha provider | Aggiungi autenticazionetokenProvider. |
| auth_exchange_failed | Token di incorporamento non valido, scaduto o non corrispondente | Controlla la risposta del token backend e channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK problemi

| Sintomo | Probabile causa | Aggiustare |
| --- | --- | --- |
| Firma rifiutata | Segreto errato, deriva dell'orologio o campi firmati modificati manualmente | Lascia che SDK generi i campi di firma e sincronizzi l'ora del server. |
| Rischio di movimento di fondi duplicati | Nuovo numero d'ordine utilizzato dopo il timeout | Interroga prima l'originale agentOrderNo. |
| PROCESSING trattato come un fallimento | Stato in sospeso frainteso | Attendi webhook o chiama queryOrder. |
| Webhook elaborato più volte | Riprovare il comportamento senza idempotenza | Aggiungi chiave di idempotenza e controlli dello stato finale. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Prove da catturare

| Integrazione | Prove utili |
| --- | --- |
| Trading Widget | Pagina URL, percorso della versione SDK, console del browser, richieste di rete non riuscite, payload `onError` e dimensioni del contenitore. |
| Agent SDK | Lingua/versione SDK, base URL, timestamp UTC, ID richiesta, `agentOrderNo`, codice di risposta e log ripuliti. |
| Webhook | Tempi di consegna, chiave aziendale o evento, risultato della convalida della firma, stato di elaborazione e hash del corpo grezzo ripulito. |
| REST API | Metodo, percorso, ambiente, ID richiesta, codice di risposta e parametri ripuliti. |

Non includere mai password, token di accesso, API segreti, firme complete, chiavi private o dati personali non oscurati nella diagnostica.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Prima di intensificare

- Riprovare solo quando l'operazione è documentata come sicura da riprovare.
- Dopo un timeout, esegui una query sull'identificatore aziendale originale invece di crearne uno nuovo.
- Confermare l'orologio di sistema e l'ambiente delle credenziali per eventuali errori di firma.
- Conservare il primo errore e tutti i risultati dei tentativi successivi.
- Usa il [Modello di richiesta di supporto](/it/resources/support-request-template) inviare un rapporto completo e redatto.

## Java diagnostica v0.3.0

| Sintomo | Controllo e ripristino |
| --- | --- |
| La richiesta di finanziamento ha un risultato sconosciuto | Conserva l'originale `agentOrderNo`; chiama `queryWalletTransfer` con l'ambiente originale. Non utilizzare `queryOrder`. |
| L'interfaccia utente di simulazione mostra fondi imprevisti | Controllare il frontend `tradingMode` separatamente dal backend `environment`; l'account `isSimulatedUser` non instrada le richieste. |
| Errore di query `6905` | Tornare indietro utilizzando la quota del partner condiviso, quindi riprovare con lo stesso cursore e filtrare attraverso SDK. |
| Errore di query `6904` | Ridurre le query simultanee e restringere la finestra temporale; contattare l'assistenza se persistente. |
| Cursore non valido o scaduto | Riavvia la stessa finestra della cronologia fissa e deduplica i record salvati. |
| Manca il nuovo metodo Java. | Confronta l'artefatto Maven risolto con il tag pubblico `v0.3.0`; rimuovere le dipendenze in conflitto in base alla policy degli artefatti. |
