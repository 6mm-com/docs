Il 6MM Agent SDK riguarda i servizi backend partner che devono chiamare un Agent API privilegiato senza implementare la gestione della firma e delle richieste da zero. Non deve funzionare in codice browser, mobile o desktop pubblico perché l'integrazione utilizza un partner API segreto.

<h2 id="when-to-use-the-agent-sdk">Quando usare il Agent SDK</h2>

Usa l’Agent SDK quando il backend deve associare un utente partner, trasferire asset tramite un flusso approvato, consultare i registri di trading, creare un URL di accesso al trading integrato o verificare le notifiche Webhook. Usa separatamente il [Trading Widget SDK](/it/sdk/trading-widget/overview) quando il frontend del partner deve mostrare l’interfaccia di trading.

<h2 id="common-configuration">Configurazione comune</h2>

| Chiave | Esempio | Descrizione |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agent API servizio URL senza slash di seguimento. |
| agentCode | AGENT001 | Codice agente partner. |
| apiSecret | your-api-secret | API segreto di firma memorizzato solo nel backend. |
| defaultCurrency | USDT | Valuta predefinita per trasferimenti e API conto. |
| webhookUrl | https://partner.example.com/6mm/webhook | Partner endpoint per notifiche 6MM webhook. |

<h2 id="typical-integration-flow">Flusso tipico di integrazione</h2>

1. Il frontend del partner autentica l'utente tramite il sistema account del partner.
2. Il backend partner mappa l'utente a un identificatore stabile lato partner.
3. Il backend chiama il Agent SDK con `agentCode` e il API protetto segreto.
4. Il SDK firma e invia l'Agente API richiesta.
5. Il backend memorizza l'identificativo di business restituito e processa ipotentemente i webhook successivi.
6. Il frontend riceve solo il risultato di breve durata o la credenziali di ingresso necessaria.

<h2 id="production-checklist">Elenco di controllo della produzione</h2>

- Carica `apiSecret` da un gestore di segreti backend, non dal codice sorgente.
- Mantenere separati le credenziali di sviluppo, staging e produzione.
- Utilizzare una mappatura utente partner stabile e identificatori unici.
- Preservare l'identificatore originale quando si verifica lo stato di una richiesta con timeout.
- Verifica le firme dei webhook e memorizza gli ID degli eventi processati.
- Oscurare segreti e firme dai log mantenendo gli ID delle richieste per il supporto.
