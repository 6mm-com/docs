Il 6MM Agent SDK è destinato ai servizi backend dei partner che devono chiamare l'agente privilegiato APIs senza implementare la firma e la gestione delle richieste da zero. Non deve essere eseguito nel codice del browser, del dispositivo mobile o del desktop pubblico perché l'integrazione utilizza un segreto API del partner.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Quando utilizzare il Agent SDK

Usa l’Agent SDK quando il backend deve associare un utente partner, trasferire asset tramite un flusso approvato, consultare i registri di trading, creare un URL di accesso al trading integrato o verificare le notifiche Webhook. Usa separatamente il [Trading Widget SDK](/it/sdk/trading-widget/overview) quando il frontend del partner deve mostrare l’interfaccia di trading.

<span id="common-configuration" data-sixmm-canonical-anchor="common-configuration" aria-hidden="true"></span>

## Configurazione comune

| Chiave | Esempio | Descrizione |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agente API servizio URL senza barra finale. |
| agentCode | AGENT001 | Codice agente partner. |
| apiSecret | il tuo segreto API | API segreto di firma memorizzato solo sul backend. |
| defaultCurrency | USDT | Valuta predefinita per trasferimento e conto APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Endpoint partner per le notifiche 6MM webhook |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Flusso di integrazione tipico

1. Il frontend del partner autentica l'utente tramite il sistema di account del partner.
2. Il backend del partner associa l'utente a un identificatore lato partner stabile.
3. Il backend chiama il Agent SDK con `agentCode` e il segreto protetto API.
4. Il SDK firma e invia la richiesta dell'Agente API.
5. Il backend memorizza l'identificatore aziendale restituito ed elabora successivamente webhooks in modo idempotente.
6. Il frontend riceve solo il risultato di breve durata o le credenziali di ingresso di cui ha bisogno.

<span id="production-checklist" data-sixmm-canonical-anchor="production-checklist" aria-hidden="true"></span>

## Lista di controllo della produzione

- Carica `apiSecret` da un gestore di segreti backend, non dal codice sorgente.
- Mantieni separate le credenziali di sviluppo, gestione temporanea e produzione.
- Utilizza una mappatura utente partner stabile e identificatori univoci degli ordini commerciali.
- Conserva l'identificatore originale quando controlli lo stato di una richiesta scaduta.
- Verifica le firme webhook e memorizza gli ID evento elaborati.
- Oscura i segreti e le firme dai log conservando gli ID delle richieste di supporto.
