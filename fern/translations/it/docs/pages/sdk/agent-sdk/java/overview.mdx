Questa guida è rivolta a **Agent Java SDK `v0.3.0`**, Java 8+ e agli appalti pubblici contrassegnati. Gli esempi vengono eseguiti nel backend di un partner dopo aver inizializzato `client` in [Avvio rapido](/it/sdk/agent-sdk/java/quick-start).

Base della documentazione: SDK `v0.3.0`, commit `54aa3c1`.

| Trasferimenti | Ordine inverso | `reverse` | Annulla un trasferimento riuscito quando il backend supporta un flusso di compensazione |
| Trasferimenti | Ordine delle interrogazioni | `queryOrder` | Interroga un ordine di trasferimento in base al numero dell'ordine del partner |
| Trasferimenti | Elenca gli ordini | `listOrders` | Sfogliare gli ordini di trasferimento per la riconciliazione |
| Trasferimenti | Webhook verifica | `WebhookVerifier.verify` | Verifica il trasferimento delle richiamate dello stato finale da 6MM |
| Portafoglio di finanziamento | Trasferimento fondi | `walletTransfer` | Partner ↔ Finanziamento o Finanziamento ↔ Contratto; confermare lo stato restituito |
| Portafoglio di finanziamento | Stato del trasferimento dei fondi | `queryWalletTransfer` | Recupera un'operazione di finanziamento utilizzando il numero d'ordine del partner originale |

| Dati perpetui | Ordini perpetui attuali | `listCurrentPerpetualOrders` | Interroga gli ordini attuali NORMAL o CONDITIONAL |

| Dati perpetui | Commerci perpetui | `listPerpetualTrades` | Interroga i riempimenti commerciali per un elenco esplicito di giocatori pubblici |

## Configurazione

Ottenere i seguenti valori da 6MM prima
integrando.

| Articolo | Esempio | Descrizione |
| --- | --- | --- |
| `baseUrl` | `https://agent-api.6mm.com` | Agente API base URL, senza barra finale |
| `agentCode` | `AGENT001` | Codice partner |
| `apiSecret` | `your-api-secret` | API segreto di firma. Tienilo solo sul backend |
| `defaultCurrency` | `USDT` | Valuta predefinita, solitamente `USDT` |
| `webhookUrl` | `https://partner.example.com/6mm/webhook` | Endpoint partner per callback 6MM. |

Raccomandazioni per la produzione:

- Utilizzare HTTPS per gli endpoint dell'agente API e webhook.
- Archivia `apiSecret` in un gestore segreto, un centro di configurazione o una variabile di ambiente.
- Mantieni l'ora del server sincronizzata, preferibilmente con NTP.
- Conserva tutti i numeri d'ordine dei partner e mantienili univoci a livello globale.
- Non inviare mai `apiSecret` a browser, app, mini programmi o codice sorgente frontend.

## Campi per la firma automatica

Per le chiamate dell'agente API firmate, il SDK inserisce automaticamente:

| Campo | Fonte | Descrizione |
| --- | --- | --- |
| `agentCode` | `AgentClientConfig.agentCode` | Codice partner |
| `timestamp` | Attuale UTC Timestamp Unix | Secondi |
| `nonce` | Generatore casuale sicuro | Protezione dalla riproduzione |
| `sign` | HMAC-SHA256 | Richiedi la firma |
| `currency` | `defaultCurrency` | Compilato quando le richieste di trasferimento/account omettono la valuta |

Regole per la firma:

1. Escludi `sign`.
2. Escludi valori vuoti.
3. Ordina le chiavi in ​​base all'ordine ASCII.
4. Iscriviti come `k=v&k2=v2`.
5. Calcola HMAC-SHA256 esadecimale con `apiSecret`.

I valori dell'array vengono serializzati come compatti JSON prima di unirsi al payload della firma. Ad esempio, `platformUserIds` viene indicato come `["1188041528"]`, fornendo `platformUserIds=["1188041528"]` nel payload `k=v`. Conserva l'ordine degli elementi dell'array, le virgolette doppie e gli ID delle stringhe; non inserire spazi di formattazione né utilizzare Java `List.toString()` (ad esempio `[1188041528]`). Il SDK gestisce questa serializzazione automaticamente.

Il normale codice aziendale non deve calcolare le firme o impostarle manualmente
`agentCode`, `timestamp`, `nonce` o `sign`.
