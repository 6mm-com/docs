<span id="runtime" data-sixmm-canonical-anchor="runtime" aria-hidden="true"></span>

## Durata

| Voce | Valore |
| --- | --- |
| Versione Java minima | Java 8+ |
| Strumento di build consigliato | Maven 3.9+ |
| Gruppo Maven | `com.sixmm.exchange.sdk` |
| Artefatto Maven | `agent` |
| Etichetta sorgente documentata | `v0.1.1` |

Il repository pubblico di GitHub è un source hosting, non un repository di dipendenza Maven. Compila e installa localmente il codice sorgente taggato oppure pubblica l'artefatto approvato nel repository Maven privato della tua organizzazione prima di usarlo nelle build di squadra.

<span id="typical-backend-responsibilities" data-sixmm-canonical-anchor="typical-backend-responsibilities" aria-hidden="true"></span>

## Responsabilità tipiche di backend

- Convalidare la sessione utente partner.
- Mappare l'utente partner a agentUserId.
- Binding di chiamata prima della prima negoziazione o dei flussi di trasferimento.
- Chiama createEntryUrl per un SSOunico in sede completa.
- Chiama createEmbedToken per Trading Widget modalità partner-token.
- Verificare i webhook di trasferimento e processarli idempotentemente.

<span id="security-and-operational-rules" data-sixmm-canonical-anchor="security-and-operational-rules" aria-hidden="true"></span>

## Regole di sicurezza e operative

- Memorizzare `apiSecret` solo in un gestore di segreti backend o in una variabile di ambiente protetto.
- Mantenere sincronizzato l'ora del server perché le richieste firmate contengono timestamp.
- Tratta `agentOrderNo` come una chiave di idempotenza resistente e mantenerla unica a livello globale.
- Memorizzare `platformUserId` come stringa e persistere la sua relazione con `agentUserId`.
- Interrogare il trasferimento originale prima di riprovare dopo un timeout o un risultato di rete incerto.
