Gamitin ang checklist na ito bago ipakita ang mga kakayahan sa trading na pinapagana ng 6MMsa mga totoong gumagamit.

<h2 id="integration-readiness">Kahandaan sa Integrasyon</h2>

- Kinukumpirma ang mga production domain at redirect paths.
- Trading Widget, Agent SDK, API, o WebSocket daloy ang nasubukan nang end-to-end.
- Ang partner backend ay nag-iimbak ng lahat ng lihim sa server-side.
- Naka-enable ang Webhook receiving, signature verification, retry handling, at idempotency.
- Kasama sa mga log ang request IDs, user mapping IDs, order IDs, at timestamps.

<h2 id="product-and-resource-readiness">Kahandaan ng produkto at mga yaman</h2>

- Ang mga entry point, banner, at card asset ay gumagamit ng aprubadong bersyon ng wika.
- Ang mga white-label na asset ay ginagamit lamang kapag pinapayagan ito ng kasunduan sa kooperasyon.
- Sinusuri ng partner team ang mga risk prompt na nakaharap sa user at trading entry copy.
- Itinalaga ang mga may-ari ng suporta at eskalasyon.

<h2 id="operational-readiness">Kahandaan sa operasyon</h2>

- Saklaw ng monitoring ang mga error ng API , pag-isyu ng token, pag-initialize ng widget, pagkabigo ng webhook, at mga event sa lifecycle ng order.
- Nakumpirma na ang mga emergency contact path.
- Inihahanda ang rollback o pansamantalang plano para sa pagpasok sa kalakalan.

<h2 id="security-and-compliance-readiness">Kahandaan sa seguridad at pagsunod</h2>

- Ang API keys ay gumagamit ng minimum na pahintulot at aprubadong IP restrictions kung naaangkop.
- Nasubukan na ang pag-ikot at pagbawi ng kredensyal.
- Ang mga Webhook signature ay sinusuri laban sa raw request bodies.
- Kumpleto na ang mga user disclosure, risk notices, liability boundaries, at target-market review.
- Maaaring makuha ang ebidensya ng insidente, pagkakasundo, at suporta nang hindi inilalantad ang mga lihim.
