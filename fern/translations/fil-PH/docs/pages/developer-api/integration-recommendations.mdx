Gamitin ang mga rekomendasyong ito bilang baseline para sa kahandaan sa produksyon. Pinapalawak nila ang endpoint reference at tumutulong sa mga integrasyon na ligtas na makabawi mula sa timeouts, reconnects, duplicate requests, at credential incidents.

<h2 id="authentication-and-secrets">Pagpapatunay at mga lihim</h2>

- Mas gusto ang [API Key signing](/fil-PH/developer-api/authentication) para sa server-side trading programs at JWT para sa user-driven frontend actions.
- Panatilihin `apiSecret` sa backend secret management. Ipinapakita ito nang isang beses lamang at hindi dapat ipadala sa browser o mobile client.
- I-apply ang minimum na kinakailangang API Key permissions at limitahan ang source IPs kapag sinusuportahan ng integration environment ang stable egress addresses.
- I-disable o tanggalin agad ang leaked key, pagkatapos ay suriin ang request logs bago magbigay ng kapalit.

<h2 id="request-validation-and-idempotency">Humiling ng beripikasyon at idempotency</h2>

- Bago maglagay ng order, i-query `/v1/public/market/symbols` at i-validate ang `tickSize`, `stepSize`, minimum na notional value, at maximum na dami sa lokal na lugar.
- Gumawa ng natatanging `clientOrderId` para sa bawat order write upang ma-reconcile ang mga request pagkatapos ng disconnect.
- Panatilihin ang orihinal na identifier kapag hindi tiyak ang HTTP resulta. I-query ang umiiral na order bago gumawa ng kapalit na kahilingan.
- Ituring ang decimal na halaga at presyo bilang mga string o decimal na uri, hindi bilang binary floating-point values.

<h2 id="order-and-websocket-state">Kaayusan at WebSocket estado</h2>

- Tukuyin ang panghuling estado pagkatapos ng cancel, cancel-all, o amendment operations mula sa [private WebSocket events](/fil-PH/developer-api/websocket/private-user-channel) o isang REST query.
- Ituring ang bawat reconnect bilang bagong WebSocket session at ibalik ang lahat ng kinakailangang subscription.
- Suriin ang order-book continuity gamit ang `endVersion`. Kung may lumabas na puwang sa bersyon, itapon ang lokal na libro at mag-subscribe muli para sa bagong snapshot.
- I-deduplicate ang mga pribadong order at account events bago ito ilapat sa balanse, posisyon, o partner records.

<h2 id="logging-monitoring-and-retries">Logging, monitoring, at retries</h2>

- I-record ang request ID, client order ID, HTTP status, API business code, latency, at bilang ng retry nang hindi naglo-log ng mga lihim o buong token.
- Muling subukan lamang ang mga operasyon na naitala bilang ligtas, gamit ang bounded exponential backoff at jitter.
- Mag-alerto sa mga pagkabigo sa authentication, mga error sa pirma, mga tugon sa rate-limit, WebSocket reconnect loops, sequence gaps, at pagkakaiba sa pagkakasundo ng order.
- Panatilihing naka-synchronize ang server clocks dahil nakadepende ang authentication at signing sa timestamps.

<h2 id="before-production">Bago ang produksyon</h2>

- Mag-ehersisyo ng timeout, duplicate request, reconnect, key rotation, at webhook retry na mga senaryo sa isang non-production na kapaligiran.
- Magtalaga ng mga may-ari para sa credential rotation, trading incidents, webhook failures, at reconciliation.
- Kumpletuhin ang [production launch checklist](/fil-PH/resources/production-launch-checklist) at gamitin ang [support request template](/fil-PH/resources/support-request-template) kapag kinakailangan ang escalation.
