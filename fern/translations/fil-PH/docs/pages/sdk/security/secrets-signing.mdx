Agent SDK mga kahilingan ay pinapatunayan gamit ang isang partner API lihim. Itago ang lihim na iyon sa isang trusted backend service at hayaan ang SDK na gumawa ng signing fields hangga't maaari.

> **Dalawang signing protocol**
>
> Agent SDK signing ay gumagamit ng nakaayos na request fields, isang timestamp na batay sa segundo, at isang nonce. Ang Direct Developer API requests ay gumagamit ng hiwalay na proseso na inilalarawan sa [Request Signing](/fil-PH/developer-api/request-signing). Huwag muling gamitin ang isang payload format para sa isa pa.

<h2 id="signing-rule">Patakaran sa pagpirma</h2>

Para sa Agent SDK mga kahilingan:

1. I-exclude ang `sign` field.
2. Tanggalin ang mga field na walang laman ang mga halaga.
3. Ayusin ang natitirang mga pangalan ng field ayon sa ASCII pagkakasunod-sunod.
4. I-join ang mga field bilang `k=v&k2=v2`.
5. Kalkulahin ang HMAC-SHA256 hexadecimal signature gamit ang `apiSecret`.

Dapat bumuo ang SDK ng value na ito mula sa parehong data na ipinapadala nito. Ang pagbabago ng signed field pagkatapos ng signature generation ay nagdudulot ng pagkabigo sa beripikasyon.

<h2 id="sdk-managed-fields">SDK-pinamamahalaang mga patlang</h2>

| Larangan | Pinagmulan | Paglalarawan |
| --- | --- | --- |
| agentCode | SDK config | Code ng partner agent. |
| timestamp | Kasalukuyang oras ng server | Unix timestamp sa ilang segundo. |
| nonce | Siguraduhin ang random na halaga | Replay-protection random string. |
| palatandaan | HMAC-SHA256 | Humiling ng pirma. |
| pera | Default na pera | Ginagamit kapag naglilipat o nag- APIs ng account na hindi gumagamit ng pera. |

<h2 id="secret-storage">Lihim na imbakan</h2>

- I-load ang `apiSecret` mula sa backend secret manager o protected runtime configuration.
- Huwag kailanman ilagay ang lihim sa frontend bundles, mobile apps, desktop clients, screenshots, o support tickets.
- Panatilihing hiwalay ang mga kredensyal para sa development, staging, at production.
- Limitahan ang access sa mga serbisyo at operator na nangangailangan nito.
- I-redact ang mga pirma ng kahilingan, mga halaga ng awtorisasyon, at mga lihim mula sa mga log.
- Bawiin at palitan ang mga kredensyal kapag pinaghihinalaan ang exposure.

<h2 id="clock-and-replay-protection">Proteksyon sa orasan at replay</h2>

Kasama sa SDK ang `timestamp` at `nonce` upang mabawasan ang panganib ng replay. Panatilihing naka-synchronize ang backend clocks at huwag gamitin muli ang manu-manong ginawa na nonce. Kung mabigo ang signature validation, kumpirmahin ang naka-configure na secret, server time, serialized fields, at environment bago muling subukan.

<h2 id="integration-checklist">Checklist ng integrasyon</h2>

| Suriin | Inaasahang resulta |
| --- | --- |
| Lihim na lokasyon | Backend-only na lihim na imbakan. |
| Kapaligiran | Ang base URL at credential ay kabilang sa iisang kapaligiran. |
| Paghawak sa Field | SDK bumubuo ng `timestamp`, `nonce`, at `sign`. |
| Pagtotroso | Nananatiling nakikita ang mga Business ID habang tinatanggal ang mga kredensyal. |
| Pag-ikot | Ang may-ari ng kredensyal at proseso ng pagpapalit ay dokumentado. |
