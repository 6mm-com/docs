A negociação embutida é normalmente introduzida num produto existente, não lançada como um destino independente. O melhor caminho de integração depende de onde os utilizadores já gastam tempo e de qual sistema detém a identidade, fundos e operações.

<h2 id="common-scenarios">Cenários comuns</h2>

| Cenário | Melhor ponto de partida | Notas |
| --- | --- | --- |
| A aplicação ou carteira quer uma entrada de trading | Trading Widget SDK | Use um ponto de entrada nativo ou H5 e abra a experiência de negociação embutida após a autorização do utilizador. |
| Corretor ou plataforma de canal quer acesso a derivados | Agent SDK + Trading Widget SDK | Mantém a relação com o cliente e a validação de backend no sistema de parceiros. |
| A plataforma quer um fluxo de negociação guiado | API + módulos SDK selecionados | Use APIs backend para fluxos de trabalho de conta, transferência e encomendas, expondo apenas a entrada frontend necessária. |
| A bolsa existente quer mercados adicionais | Integração Liquidez + API | Combine profundidade de mercado, fluxos de trabalho de contas e monitorização operacional. |

<h2 id="product-decisions-before-integration">Decisões de produto antes da integração</h2>

- Decidir se os utilizadores entram a partir de um cartão de página inicial, página de ativos, página de campanha ou centro de contas.
- Decidir qual o sistema que detém o estado de login, a elegibilidade do utilizador e a disponibilidade de país ou região.
- Decidir como as transferências, registos de liquidação e tickets de apoio ao cliente são apresentados aos utilizadores.
- Decidir quais os eventos que devem ser encaminhados para análises internas, CRMou operações de risco.
