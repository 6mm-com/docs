> **Planeado – ainda não lançado**
> O AI Hub é um recurso planeado. As características, terminais, comandos e definições do cliente nesta página descrevem o design proposto e não estão atualmente disponíveis. A disponibilidade final e as instruções de configuração serão anunciadas no lançamento.


6MM O Agentic AI Hub é a AI-interface nativa para 6MM dados de mercado, fluxos de trabalho de contas e futuras operações de negociação controladas.

Em vez de alternar entre painéis, API documentos e scripts, os utilizadores podem pedir a um cliente de IA para consultar 6MM, explicar as condições do mercado, rever o risco da conta ou preparar uma visualização do pedido. O cliente AI não substitui o modelo de segurança 6MM API; chama ferramentas 6MM estruturadas através de CLI, MCP ou modelos de workflow.

<span id="what-you-can-ask-an-ai-client" data-sixmm-canonical-anchor="what-you-can-ask-an-ai-client" aria-hidden="true"></span>

## O que pode perguntar a um cliente de IA

Utilize o AI Hub quando quiser colocar questões como:

```text
Show me the BTC-USDT-PERP order book and explain current liquidity.
```

```text
Compare BTC and ETH funding rates over the last 24 hours.
```

```text
Check my testnet positions and explain liquidation risk. Do not place orders.
```

```text
Preview a small BTC long order and explain fees, margin impact, and risk checks.
```

<span id="why-ai-agents-need-a-dedicated-access-layer" data-sixmm-canonical-anchor="why-ai-agents-need-a-dedicated-access-layer" aria-hidden="true"></span>

## Porque é que os agentes de IA precisam de uma camada de acesso dedicada

Os agentes de IA funcionam melhor quando possuem ferramentas estruturadas em vez de páginas web em bruto ou texto copiado não estruturado. O AI Hub oferece-lhes:

| Exigência | Abordagem 6MM |
| --- | --- |
| Contexto do mercado em direto | Ferramentas e recursos de dados públicos de mercado para símbolos, carteiras de encomendas, negociações, financiamento, taxas e regras. |
| Limpar permissões | Dados públicos separados, leitura de conta, visualização e escopos de negociação controlados. |
| Execução mais segura | Visualização do fluxo do primeiro pedido, confirmação explícita, idempotência, limites e registos de auditoria. |
| Flexibilidade do cliente | Alojado MCP, local MCP, CLI, remoto MCP e competências de agente para diferentes ambientes de IA. |

## Caminhos de configuração

| Percurso | Melhor para | O utilizador deve saber |
| --- | --- | --- |
| Alojado MCP | Acesso rápido a dados públicos de mercado | Sem instalação e sem chave de utilizador API para dados públicos. Negociar não é o objetivo do primeiro lançamento. |
| Localização MCP | Clientes de IA que necessitam de contexto de conta privada | O servidor MCP é executado localmente e as credenciais permanecem na máquina do utilizador. |
| CLI | Agentes de codificação, scripts e utilizadores de terminal | Produz saída de comando amigável para o agente e pode ser utilizado sem servidor MCP. |
| Remoto MCP | Instituições e equipas que desejam o seu próprio endpoint | O utilizador ou instituição controla o alojamento, as credenciais, o acesso à rede e os registos. |
| Habilidades Agentes | Fluxos de trabalho repetíveis | As competências guiam a IA através de etapas de análise e risco, utilizando ferramentas aprovadas. |

## O que está disponível em primeiro lugar

O AI Hub deve começar com dados públicos de mercado e características de regras de negociação:

- Mercados.
- Relógios.
- Encomende livros.
- Negociações.
- Klines.
- Taxas de financiamento.
- Estado do sistema.
- Taxas, especificações de contrato, regras de margem e características de regras de risco.

O acesso à conta privada e a negociação devem ser realizados:

- As ferramentas de leitura de contas exigem credenciais explícitas de leitura apenas.
- A visualização do pedido deve vir antes de qualquer criação real do pedido.
- A negociação controlada requer escopos de permissão, verificações de risco do lado do serviço, confirmação do utilizador, idempotência e registos de auditoria.
