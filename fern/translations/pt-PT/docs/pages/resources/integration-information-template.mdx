Use este modelo ao preparar uma nova integração ou ao transferir uma integração existente para produção.

<span id="partner-information" data-sixmm-canonical-anchor="partner-information" aria-hidden="true"></span>

## Informação sobre parceiros

| Campo | Descrição |
| --- | --- |
| Nome do parceiro | Nome legal ou de projeto usado para a integração. |
| Tipo de produto | App, carteira, portal de corretores, exchange white-label, plataforma institucional ou outra. |
| Contactos primários | Contactos de negócios, técnicos, operações e emergências. |
| Regiões de lançamento | Países ou regiões onde a integração será exposta. |

<span id="technical-information" data-sixmm-canonical-anchor="technical-information" aria-hidden="true"></span>

## Informação técnica

| Campo | Descrição |
| --- | --- |
| Domínios frontend | Domínios que carregam o widget ou as páginas de entrada. |
| Domínios backend | Domínios de servidor usados para chamadas Agent SDK ou API . |
| Webhook URL | Endpoint do webhook de produção e requisitos esperados IP da lista de permissões. |
| Âmbito da integração | Trading Widget, Agent SDK, REST API, WebSocket, sistema white-label ou integração de liquidez. |

<span id="operational-information" data-sixmm-canonical-anchor="operational-information" aria-hidden="true"></span>

## Informação operacional

- Data prevista de lançamento.
- Tráfego esperado ou intervalo de utilizadores ativos.
- Responsável pelas horas de suporte e escalonamento.
- Monitorizar o proprietário e o contacto do incidente.

<span id="security-and-review-information" data-sixmm-canonical-anchor="security-and-review-information" aria-hidden="true"></span>

## Informação de segurança e revisão

- Método de autenticação e API Key escopo de permissões.
- Armazenamento secreto, proprietário da rotação e IPs de origem aprovados.
- Verificação de assinatura Webhook e design de idempotência.
- Proprietários de registo, monitorização, reconciliação, rollback e resposta a incidentes.
- Mercados-alvo, tipo de utilizador, modelo de custódia e a entidade responsável pelas obrigações de contacto com o utilizador.

Não inclua segredos de produção, tokens de acesso completo, chaves privadas ou dados de utilizador não censurados neste modelo.

Use a [lista de verificação de lançamento em produção](/pt-PT/resources/production-launch-checklist) para aprovação final e o [modelo de pedido de suporte](/pt-PT/resources/support-request-template) para escalonar problemas.
