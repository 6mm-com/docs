O 6MM Agent SDK é para serviços de back-end de parceiros que precisam de chamar o agente privilegiado APIs sem implementar a assinatura e a manipulação de pedidos de raiz. Não deve ser executado em código de browser, telemóvel ou desktop público porque a integração utiliza um segredo de parceiro API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Quando utilizar o Agent SDK

Utilize o Agent SDK quando o backend precisar de associar um utilizador parceiro, transferir ativos através de um fluxo aprovado, consultar registos de negociação, criar um URL de acesso à negociação incorporada ou verificar notificações de webhook. Utilize o [Trading Widget SDK](/pt-PT/sdk/trading-widget/overview) separadamente quando o frontend do parceiro tiver de apresentar a interface de negociação.

## Configuração comum

| Chave | Exemplo | Descrição |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agente API serviço URL sem barra final. |
| agentCode | AGENT001 | Código do agente parceiro. |
| apiSecret | seu-api-secret | API segredo de assinatura apenas armazenado no back-end. |
| defaultCurrency | USDT | Moeda padrão para transferência e conta APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Endpoint do parceiro para notificações 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Fluxo de integração típico

1. O frontend do parceiro autentica o utilizador através do sistema de conta do próprio parceiro.
2. O back-end do parceiro mapeia o utilizador para um identificador estável do lado do parceiro.
3. O back-end chama o Agent SDK com `agentCode` e o segredo protegido API.
4. O SDK assina e envia o pedido do Agente API.
5. O back-end armazena o identificador comercial devolvido e processa posteriormente webhooks de forma idempotente.
6. O frontend recebe apenas o resultado de curta duração ou a credencial de entrada necessária.

## Lista de verificação de produção

- Carregue `apiSecret` a partir de um gestor de segredos de back-end, e não do código-fonte.
- Mantenha as credenciais de desenvolvimento, preparação e produção separadas.
- Utilize um mapeamento estável de utilizadores parceiros e identificadores únicos de ordem comercial.
- Preserve o identificador original ao verificar o estado de um pedido que expirou.
- Verifique as assinaturas webhook e armazene os IDs dos eventos processados.
- Edite segredos e assinaturas de registos, mantendo os IDs de pedido de suporte.

## Java SDK recursos v0.3.0

Java SDK inclui agora carteiras de financiamento, ambientes de fundos explícitos, seis consultas de dados perpétuos e taxas de referência fiduciárias.
