Este guia é dirigido a **Agent Java SDK `v0.3.0`** e Java 8+.

<span id="decide-what-needs-upgrading" data-sixmm-canonical-anchor="decide-what-needs-upgrading" aria-hidden="true"></span>

## Decida o que precisa de atualização

| Integração existente | Ação |
| --- | --- |
| Funções de produção existentes com ambiente omitido | As formas de resposta existentes mantêm-se compatíveis; as novas consultas não obrigam a uma atualização. |
| Autenticação incorporada genérica existente para negociação de segundos | Reutilizar a autenticação e renovação; selecione a página do produto necessária. |
| Saldos de financiamento, transferências e recuperação | Utilize os modelos que contêm `withFunding`, `walletTransfer` e `queryWalletTransfer`. |
| Fundos simulados explícitos | Utilize modelos de pedido/resposta suportados por `environment`. |
| Seis consultas de dados perpétuos | Utilize public Java SDK `v0.3.0`, incluindo os seis métodos e suporte para assinatura de arrays. |

Preserve as suas `baseUrl`, `agentCode`, `apiSecret` atuais, as ligações de utilizador e as ordens comerciais originais.

<span id="install-the-stable-public-tag" data-sixmm-canonical-anchor="install-the-stable-public-tag" aria-hidden="true"></span>

## Instale a etiqueta pública estável

Fonte de hosts GitHub. A publicação de uma etiqueta GitHub não publica as coordenadas do Maven no Maven Central. Instale a fonte marcada localmente ou publique o seu JAR/POM verificado no repositório de artefactos da sua organização.

```bash
git clone --branch v0.3.0 --single-branch https://github.com/6mm-com/agent-java-sdk.git agent-java-sdk-v0.3.0
cd agent-java-sdk-v0.3.0
git rev-parse HEAD
git rev-parse 'v0.3.0^{commit}'
mvn install
```

Os dois IDs de confirmação devem corresponder. Declare a dependência no projeto parceiro:

```xml
<dependency>
    <groupId>com.sixmm.exchange.sdk</groupId>
    <artifactId>agent</artifactId>
    <version>0.3.0</version>
</dependency>
```

Verifique a dependência resolvida:

```bash
mvn dependency:tree -Dincludes=com.sixmm.exchange.sdk:agent
```

Uma instalação local apenas disponibiliza o artefacto nessa máquina. CI e outros programadores necessitam da mesma instalação marcada ou do seu repositório de artefactos verificado. Se já possui um artefacto privado chamado `0.3.0`, verifique a sua origem e métodos; não substitua silenciosamente um artefacto partilhado.

## Mudanças de integração necessárias

1. Atualize os modelos de pedido e resposta para `environment` explícito. Modelos de resposta mais antigos e rigorosos podem rejeitar o campo adicional.
2. Utilize `withFunding()` antes de ler `funding`. Os saldos dos contratos não são saldos de segunda negociação.
3. Utilize `/v1/agent/wallet-transfer` e `/v1/agent/wallet-transfer-status` para financiamento. O antigo `queryOrder` não pode recuperar uma operação de financiamento.
4. As seis consultas utilizam `platformUserIds` como um array de strings. Subscrever arrays como compactos JSON; Java `List.toString()` não é compatível.
5. Armazene as ordens de transferência, as ordens de negociação ordinárias, as ordens condicionais e os preenchimentos como entidades distintas. Analise `orderStatus` ou `status` de acordo com a operação.
6. Verifique o corpo original webhook antes de analisar. As notificações simuladas explícitas incluem `environment`; compare-o com o pedido guardado.
7. Faça a gestão das versões do Java e do widget de forma independente. Uma atualização de back-end não altera a página de front-end ou o modo de negociação, e a negociação de segundos não requer um novo tipo de token.

<span id="verify-the-upgrade" data-sixmm-canonical-anchor="verify-the-upgrade" aria-hidden="true"></span>

## Verifique a atualização

Execute o build do projeto parceiro e inspecione a sua árvore de dependências. Ligação de testes, fluxo de produção original, saldos simulados explícitos, recuperação de resultados de financiamento, todas as seis consultas, paginação de janela fixa, tratamento de erros e callbacks idempotentes.

Para um cliente HTTP personalizado, siga o pedido marcado e o contrato de subscrição em vez de assumir que os modelos antigos cobrem novos campos. Ver [Visão geral da consulta](/pt-PT/sdk/agent-sdk/java/perpetual-queries) e [Guia ambiental](/pt-PT/sdk/agent-sdk/java/environments).
