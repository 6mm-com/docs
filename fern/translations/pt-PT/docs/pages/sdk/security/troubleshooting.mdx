Comece pelo ambiente, o carimbo de data/hora e o identificador comercial da operação com falha. Uma verificação estruturada separa frequentemente os problemas de configuração dos problemas de autenticação, de rede e de processamento assíncrono.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Ordem de diagnóstico recomendada

1. Confirme o ambiente afetado e a base URL.
2. Registe o intervalo de tempo UTC e o primeiro pedido com falha.
3. Identifique o módulo: Trading Widget, Agent SDK, REST API, WebSocket ou webhook.
4. Capte o ID do pedido, o ID do utilizador parceiro, `agentOrderNo`, o ID do pedido ou o ID do evento webhook.
5. Verifique o código recente, a credencial, a lista de permissões IP ou as alterações de implementação.
6. Reproduza com o mais pequeno caso de teste seguro.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget problemas

| Sintoma | Causa provável | Corrigir |
| --- | --- | --- |
| iframe solicita domínio local do parceiro | baseUrl está em falta | Passe baseUrl: 'https://app.6mm.com'. |
| iframe é invisível ou demasiado curto | O contentor pai não tem altura | Defina a altura do recipiente ou a altura da passagem. |
| token_provider_missing | modo de token de parceiro não tem fornecedor | Adicionar autenticação.tokenProvider. |
| auth_exchange_failed | Token incorporado inválido, expirado ou incompatível | Verifique a resposta do token de backend e channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK problemas

| Sintoma | Causa provável | Corrigir |
| --- | --- | --- |
| Assinatura rejeitada | Segredo errado, desvio de relógio ou campos assinados alterados manualmente | Deixe SDK gerar campos de assinatura e sincronizar a hora do servidor. |
| Risco de movimentação de fundos duplicados | Novo número de encomenda utilizado após o tempo limite | Consulte primeiro pelo agentOrderNo original. |
| PROCESSING tratado como falha | Estado pendente mal compreendido | Aguarde webhook ou ligue para queryOrder. |
| Webhook processado várias vezes | Tentar novamente o comportamento sem idempotência | Adicione chave de idempotência e verificações de estado final. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Evidências para captar

| Integração | Evidência útil |
| --- | --- |
| Trading Widget | Página URL, caminho da versão SDK, consola do browser, pedidos de rede com falha, carga útil `onError` e dimensões do contentor. |
| Agent SDK | SDK idioma/versão, base URL, UTC carimbo de data/hora, ID do pedido, `agentOrderNo`, código de resposta e registos limpos. |
| Webhook | Prazo de entrega, evento ou chave de negócio, resultado da validação da assinatura, estado de processamento e hash do corpo bruto higienizado. |
| REST API | Método, caminho, ambiente, ID de pedido, código de resposta e parâmetros higienizados. |

Nunca inclua palavras-passe, tokens de acesso, API segredos, assinaturas completas, chaves privadas ou dados pessoais não editados nos diagnósticos.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Antes de escalar

- Tente novamente apenas quando a operação estiver documentada como segura para tentar novamente.
- Após um tempo limite, consulte o identificador comercial original em vez de criar um novo.
- Confirme o relógio do sistema e o ambiente de credenciais para erros de assinatura.
- Preserve a primeira falha e quaisquer resultados de novas tentativas posteriores.
- Use o [Modelo de pedido de suporte](/pt-PT/resources/support-request-template) para enviar um relatório completo e redigido.

## Diagnóstico Java v0.3.0

| Sintoma | Verificação e recuperação |
| --- | --- |
| A solicitação de financiamento tem um resultado desconhecido | Mantenha o original `agentOrderNo`; chame `queryWalletTransfer` com o ambiente original. Não utilize `queryOrder`. |
| UI de simulação mostra fundos inesperados | Verifique o frontend `tradingMode` separadamente do backend `environment`; a conta `isSimulatedUser` não encaminha pedidos. |
| Erro de consulta `6905` | Recue utilizando a quota de parceiro partilhado, tente novamente o mesmo cursor e filtre por SDK. |
| Erro de consulta `6904` | Reduza as consultas simultâneas e restrinja a janela de tempo; contacte o suporte se persistir. |
| Cursor inválido ou expirado | Reinicie a mesma janela de histórico fixa e desduplique os registos guardados. |
| Novo método Java em falta | Verifique o artefacto Maven resolvido em relação à etiqueta pública `v0.3.0`; remova as dependências conflituantes de acordo com a sua política de artefactos. |
