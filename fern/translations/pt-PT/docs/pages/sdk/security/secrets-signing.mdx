Os pedidos Agent SDK são autenticados com um segredo do parceiro API. Mantenha este segredo dentro de um serviço de back-end fiável e deixe que o SDK gere campos de subscrição sempre que possível.

> **Dois protocolos de assinatura**
>
> A assinatura Agent SDK utiliza campos de pedido classificados, um carimbo de data/hora baseado em segundos e um nonce. Os pedidos diretos Developer API utilizam o processo separado descrito em [Solicitar assinatura](/pt-PT/developer-api/request-signing). Não reutilize um formato de carga útil para o outro.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## Regra de assinatura

Para pedidos Agent SDK:

1. Apague o campo `sign`.
2. Omita campos com valores vazios.
3. Ordene os restantes nomes dos campos pela ordem ASCII.
4. Junte os campos como `k=v&k2=v2`.
5. Calcule a assinatura hexadecimal HMAC-SHA256 com `apiSecret`.

Os valores da matriz são serializados como compactos JSON antes de se juntarem à carga útil de assinatura. Por exemplo, `platformUserIds` assina como `["1188041528"]`, fornecendo `platformUserIds=["1188041528"]` na carga útil `k=v`. Preservar a ordem dos elementos do array, as aspas duplas e os IDs de string; não introduza espaços de formatação nem utilize Java `List.toString()` (como `[1188041528]`). O SDK trata esta serialização automaticamente.

O SDK deve construir este valor a partir dos mesmos dados que envia. A alteração de um campo assinado após a geração da assinatura provoca a falha da verificação.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## Campos geridos por SDK

| Campo | Fonte | Descrição |
| --- | --- | --- |
| agentCode | Configuração SDK | Código do agente parceiro. |
| carimbo de data/hora | Hora atual do servidor | Carimbo de data/hora Unix em segundos. |
| agora | Valor aleatório seguro | Sequência aleatória de proteção de repetição. |
| assinar | HMAC-SHA256 | Solicite assinatura. |
| moeda | Moeda padrão | Utilizado quando a transferência/conta APIs omite a moeda. |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## Armazenamento secreto

- Carregue `apiSecret` a partir de um gestor de segredos de back-end ou de uma configuração de tempo de execução protegida.
- Nunca coloque o segredo em pacotes de front-end, aplicações móveis, clientes de desktop, capturas de ecrã ou tickets de suporte.
- Mantenha as credenciais de desenvolvimento, preparação e produção separadas.
- Limite o acesso aos serviços e operadores que dele necessitem.
- Edite as assinaturas de pedidos, os valores de autorização e os segredos dos registos.
- Revogar e substituir as credenciais quando haja suspeita de exposição.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Proteção de relógio e replay

O SDK inclui `timestamp` e `nonce` para reduzir o risco de repetição. Mantenha os relógios de back-end sincronizados e não reutilize um nonce construído manualmente. Se a validação da assinatura falhar, confirme o segredo configurado, a hora do servidor, os campos serializados e o ambiente antes de tentar novamente.

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## Lista de verificação de integração

| Verificação | Resultado esperado |
| --- | --- |
| Localização secreta | Armazenamento secreto apenas de back-end. |
| Ambiente | Base URL e credencial pertencem ao mesmo ambiente. |
| Manipulação de campo | SDK gera `timestamp`, `nonce` e `sign`. |
| Registo | Os IDs comerciais permanecem visíveis enquanto as credenciais são editadas. |
| Rotação | O proprietário da credencial e o processo de substituição são documentados. |
