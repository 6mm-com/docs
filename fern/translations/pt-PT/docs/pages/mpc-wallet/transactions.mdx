Uma retirada é uma operação comercial assíncrona. Uma resposta HTTP bem-sucedida significa que o pedido foi tratado; não estabelece que os fundos chegaram à rede.

<span id="persist-one-business-identifier" data-sixmm-canonical-anchor="persist-one-business-identifier" aria-hidden="true"></span>

## Persistir um identificador comercial

Gere e armazene `client_request_id` antes de enviar um saque. Reutilize-o para novas tentativas da mesma operação pretendida, incluindo após o reinício do processo. Mantenha os campos da transação consistentes; a implementação atual rejeita um identificador repetido com parâmetros de negócio conflituantes.

Não confie apenas num cabeçalho `Idempotency-Key`. O SDK fornecido pode adicionar este cabeçalho, mas o contrato de desduplicação de levantamento atual é baseado no campo de corpo `client_request_id`.

<span id="understand-request-data" data-sixmm-canonical-anchor="understand-request-data" aria-hidden="true"></span>

## Entenda os dados da solicitação

| Campo | Significado |
| --- | --- |
| `chain_id`, `asset_id` | Identificadores no ambiente acordado |
| `to_address`, `amount` | Destino e um valor decimal positivo representado como uma string |
| `client_request_id` | Identificador de pedido comercial estável |
| `dest_memo_type`, `dest_memo` | Detalhes do memorando de destino onde a rede os exige |
| `client_authorization` | Autorização de transação do cliente para levantamentos iniciados pela chave API |
| `end_user_id` | Identificador de utilizador empresarial opcional no fluxo empresarial API |

Esta tabela destaca os campos principais, e não um esquema de pedido completo. Confirme a visualização, a confirmação das taxas e os requisitos específicos de custódia em relação à versão de integração. Evite valores binários de ponto flutuante e não copie exemplos de cadeias ou números de ativos entre ambientes.

<span id="follow-the-result" data-sixmm-canonical-anchor="follow-the-result" aria-hidden="true"></span>

## Acompanhe o resultado

| Exemplos de estado | Interpretação |
| --- | --- |
| `pending_approval`, `pending_platform_review` | Uma aprovação ou revisão comercial está pendente |
| `approved`, `pending_sign` | A aprovação e a assinatura são etapas separadas |
| `broadcasting`, `pending_chain` | A transmissão ou confirmação da cadeia está em curso |
| `broadcast_unverified`, `recovering` | O resultado é ainda incerto; não crie outra transferência |
| `awaiting_reauthorization` | Pode ser necessária uma nova autorização do cliente para a mesma solicitação |
| `confirmed` | O sistema registou a confirmação da cadeia |

A lista é ilustrativa e pode evoluir. Preserve os estados desconhecidos para investigação em vez de os mapear para o sucesso ou fracasso. Uma etiqueta falhada ou rejeitada por si só não é prova suficiente de que nada foi assinado ou transmitido.

<span id="recover-after-a-timeout" data-sixmm-canonical-anchor="recover-after-a-timeout" aria-hidden="true"></span>

## Recuperar após um tempo limite

Consulte `GET /api/v1/withdrawals/by-request` utilizando o parâmetro de consulta original `client_request_id`. Continue a sondar ou a reconciliar a operação original enquanto o seu resultado for incerto. Se for necessária a renovação da autorização, utilize o mesmo identificador e o procedimento de renovação acordado.

O cancelamento depende da fase real de subscrição e das verificações do servidor. Só inicie uma operação comercial de substituição depois de o original ter sido estabelecido como não transferido e incapaz de ser transferido. Receba eventos através [webhooks](/pt-PT/mpc-wallet/webhooks-and-sdks)e reter as consultas API como um caminho de reconciliação.
