<h2 id="orders">Encomendas</h2>

| Enum                 | Valores                                                                                                    |
| -------------------- | --------------------------------------------------------------------------------------------------------- |
| Lado da ordem           | `BUY` / `SELL`                                                                                            |
| Lado da posição        | `BOTH` / `LONG` / `SHORT`                                                                                 |
| Tipo de ordem normal    | `LIMIT` / `MARKET`                                                                                        |
| Tipo de ordem de condição | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| Período em vigor        | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| Tipo de preço de gatilho   | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| Estado da ordem         | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` significa que o pedido de encomenda foi aceite e devolvido. `PENDING` significa que a ordem entrou no estado pendente ou de ordem aberta.

<h2 id="positions">Cargos</h2>

| Enum                      | Valores                                                      |
| ------------------------- | ----------------------------------------------------------- |
| Valor do pedido em modo margem | `1` cruz, `2` isolado                                     |
| Cadeia em modo margem        | `ISOLATED` / `CROSS`                                        |
| Modo de gatilho fechado        | `1` manual, `2` obter lucro, `3` stop loss `4` liquidação |

<h2 id="integration-rules">Regras de integração</h2>

- Tratar valores de enum como valores de fio sensíveis a maiúsculas minúsculas.
- Preservar valores desconhecidos nos registos e falhar em segurança em vez de os mapear silenciosamente para um estado conhecido.
- Não inferir que todo estado de ordem não final é seguro para tentar novamente. Questione a ordem ou reconcilie-a com um evento WebSocket privado.
- Armazenar tanto o valor API original como a etiqueta de exibição voltada para o parceiro para que novos valores possam ser suportados sem alterar registos históricos.

<h2 id="order-state-handling">Tratamento do estado da ordem</h2>

| Grupo estadual | Valores | Manuseamento recomendado |
| --- | --- | --- |
| Aceite ou aberto | `NEW`, `PENDING`, `PARTIALLY_FILLED` | Mantenha a ordem ativa e reconcilie com WebSocket ou atualizações REST . |
| Concluído | `FILLED` | Aplica a quantidade final preenchida e os registos de execução. |
| Encerrado sem preenchimento completo | `CANCELED`, `REJECTED`, `PARTIALLY_FILLED_CANCELED` | Pare o processamento ativo e preserve a razão e qualquer quantidade executada. |
