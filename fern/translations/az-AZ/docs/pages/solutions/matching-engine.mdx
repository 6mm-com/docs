Ağ etiketli mübadilə yalnız ön hissə qabığı tələb etmir. İstifadəçi təcrübəsi ticarət, hesablar, risk və hesablaşma arxasında etibarlı əsas modullara əsaslanır.

<h2 id="core-modules">Əsas modullar</h2>

| Modul | Rolu |
| --- | --- |
| Uyğunluq və sıra həyat dövrü | Sifariş göndərilməsi, uyğun vəziyyət, ləğv və icra qeydlərini idarə edir. |
| Hesab və mövqe sistemi | Balansları, marja vəziyyətini, mövqeləri və ticarət əlçatanlığını saxlayır. |
| Risk nəzarəti | Leverage, marja, likvidasiya və anormal bazar davranışını koordinasiya edir. |
| Bazar məlumatları | Qiymətləri, dərinliyi, ticarətləri və qrafik məlumatlarını ticarət interfeyslərinə paylayır. |
| Məskunlaşma və qeydlər | Ticarət tarixini, balans dəyişikliklərini və əməliyyat qeydlərini uyğunlaşdırır. |

<h2 id="documentation-path">Sənədləşdirmə yolu</h2>

İnteqrasiyadan əvvəl ticarət qaydalarından API başlayın. Məhsul, əməliyyat və inkişaf komandaları sifariş növləri, marja davranışı, ödənişlər və likvidasiya məntiqi barədə eyni anlayışa sahib olmalıdırlar.

<h2 id="implementation-questions">Tətbiq sualları</h2>

- İstifadəçilərə hansı sifariş və şərt-sıra növləri açıqdır?
- Hansı xidmət simvol qaydalarına, dəqiq təsdiqləməyə və ticarətə mövcudluğa sahibdir?
- Sifariş, ticarət, mövqe, balans və hesablaşma qeydləri necə uzlaşdırılır?
- REST cavablar, WebSocket hadisələr və tərəfdaş qeydləri arasında hansı identifikatorlar sabit qalır?
- Uyğunluq, risk və ya bazar məlumatları əlçatan olmadıqda hansı monitorinq və geri dönüş yolu tətbiq olunur?

Bu suallara frontend inkişafından əvvəl cavab verin, beləliklə məhsul davranışı, API idarəetmə, əməliyyatlar və dəstək eyni ticarət modelindən istifadə etsin.
