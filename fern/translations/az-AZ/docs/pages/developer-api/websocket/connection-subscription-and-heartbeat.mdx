Bazar məlumatları və sorğu olmadan aktual qalmalı olan özəl istifadəçi vəziyyəti yeniləmələri üçün WebSocket axınlarından istifadə edin.

<h2 id="connection-url">Əlaqə URL</h2>

```text
wss://ws.6mm.com/ws
```

Özəl axınlar özəl kanal sənədlərində təsvir olunan listenKey və ya giriş tokeni kimi autentifikasiya konteksti tələb edir.

<h2 id="subscribe">Abunə olun</h2>

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

Uğurlu abunə təsdiqi:

```json
{
  "id": "1772007814666",
  "event": "subscribe",
  "success": true,
  "data": ["market.depth.BTCUSDT"]
}
```

<h2 id="unsubscribe">Abunəliyi ləğv et</h2>

```json
{ "id": "1772007814667", "op": "unsubscribe", "args": ["market.depth.BTCUSDT"] }
```

<h2 id="application-ping">Tətbiq pingi</h2>

```json
{ "id": "1772007814668", "op": "ping", "args": [] }
```

<h2 id="message-envelope">Mesaj zərfi</h2>

İctimai push-lar ardıcıl envelope istifadə edir:

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

<h2 id="operational-recommendations">Əməliyyat tövsiyələri</h2>

- Hər abunəlik, abunəlikdən çıxma və ping sorğusu üçün unikal müştəri tərəfi `id` yaratmaq.
- Reconnect-i yeni sessiya kimi qəbul edin və tələb olunan mövzulara yenidən abunə olun.
- Qaytarılan `topic` xidmətinizin gözlədiyi kanalla uyğun olduğunu təsdiqləyin.
- Şəxsi sifariş və ya hesab hadisələri olduqda mesaj emalını idempotent saxlayın.
- Log bağlantı vəziyyəti dəyişiklikləri, abunə təsdiqlənmələri və anormal bağlantı kəsilmələri.

<h2 id="reconnect-workflow">Reconnect iş axını</h2>

1. Əvvəlki soketi bağlayın və ya atın və yeni bağlantı yaradın.
2. Özəl axınları etibarlı listenKey və ya giriş tokeni ilə yenidən autentifikasiya edin.
3. Bütün tələb olunan mövzulara yenidən abunə olun və uğurlu təsdiqləri gözləyin.
4. Yerli sifariş kitabı vəziyyətini yeni snapshot ilə əvəz edin, sonra isə tədrici yeniləmələr tətbiq edin.
5. Açıq əmrləri, mövqeləri və balansları REST ərzində uzlaşdırın, əgər özəl tədbirlər qaçırılmış ola bilərsə.

Yenidən qoşulma cəhdləri üçün məhdudlaşdırılmış eksponensial geri çəkilmə və jitter istifadə edin. Davamlı yenidən qoşulan müştəri operatorları xəbərdar etməlidir, görünürlük olmadan sonsuz yenidən cəhd etmək əvəzinə.

<h2 id="heartbeat-and-stale-connections">Ürək döyüntüsü və köhnəlmiş əlaqələr</h2>

- Ən son gələn mesajı və uğurlu ping təsdiqləməsini izləyin.
- İstehsal mühiti üçün təsdiqlənmiş ürək döyüntüsü intervalı və boş həddən istifadə edin.
- Konfiqurasiya edilmiş hədd keçildikdə, TCP yuvası hələ açıq görünsə belə, bağlantını köhnəlmiş kimi qəbul edin.
- Köhnə socket-dən abunəlikləri təkrar istifadə etməyin; hər yenidən qoşulmadan sonra açıq şəkildə yenidən abunə olun.
