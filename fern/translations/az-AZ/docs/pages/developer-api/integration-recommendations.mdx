Bu tövsiyələri istehsal hazırlığı üçün əsas kimi istifadə edin. Onlar son nöqtə referansını tamamlayır və inteqrasiyaların timeout, yenidən qoşulmalar, təkrarlanan sorğular və etinad hadisələrindən təhlükəsiz şəkildə bərpa olunmasına kömək edir.

<h2 id="authentication-and-secrets">Autentifikasiya və sirlər</h2>

- Server tərəfi ticarət proqramları üçün [API Key signing](/az-AZ/developer-api/authentication) və istifadəçi tərəfindən idarə olunan frontend əməliyyatları üçün JWT üstün tutulur.
- `apiSecret` arxa planda gizli idarəetmədə saxla. Bu yalnız bir dəfə göstərilir və heç vaxt brauzerə və ya mobil müştəriyə göndərilməməlidir.
- İnteqrasiya mühiti sabit çıxış ünvanlarını dəstəklədikdə minimum tələb olunan API Key icazələrini tətbiq etmək və mənbə IP-ləri məhdudlaşdırmaq.
- Sızdırılmış açarı dərhal deaktiv etmək və ya silmək, sonra əvəzləmə verməzdən əvvəl sorğu qeydlərini nəzərdən keçirmək.

<h2 id="request-validation-and-idempotency">Doğrulama və idempotensiya sorğusu</h2>

- Sifariş verməzdən əvvəl `/v1/public/market/symbols` sorğu alın və `tickSize`, `stepSize`, minimum nominal dəyər və maksimum miqdarı yerli olaraq təsdiqləyin.
- Hər sifariş yazısı üçün unikal `clientOrderId` yaradın ki, sorğular ayrıldıqdan sonra uzlaşdırıla bilsin.
- HTTP nəticə qeyri-müəyyən olduqda orijinal identifikatoru qoruyun. Əvəzləmə sorğusu yaratmadan əvvəl mövcud sifarişi sorğulayın.
- Onluq ədədləri və qiymətləri sətirlər və ya onluq tiplər kimi qəbul edin, ikili onluq nöqtəli dəyərlər kimi yox.

<h2 id="order-and-websocket-state">Nizam və WebSocket vəziyyəti</h2>

- [özəl WebSocket hadisələri](/az-AZ/developer-api/websocket/private-user-channel) və ya REST sorğusundan ləğv edilən, hamısını ləğv edən və ya dəyişdirmə əməliyyatlarından sonra son vəziyyəti müəyyən etmək.
- Hər yenidən birləşməni yeni WebSocket sessiyası kimi qəbul edin və bütün tələb olunan abunəlikləri bərpa edin.
- Sifariş kitabının ardıcıllığını `endVersion`ilə yoxlayın. Əgər versiya boşluğu yaranarsa, yerli kitabı atın və yeni bir görüntü üçün yenidən abunə olun.
- Özəl sifariş və hesab hadisələrini balanslara, mövqelərə və ya tərəfdaş qeydlərinə tətbiq etməzdən əvvəl duplikatdan çıxarın.

<h2 id="logging-monitoring-and-retries">Qeydiyyat, monitorinq və təkrar cəhdlər</h2>

- Qeyd sorğusu ID, müştəri sifariş ID, HTTP statusu, API biznes kodu, gecikmə və təkrar cəhd sayı, sirləri və tam tokenləri qeyd etmədən.
- Yalnız təhlükəsiz kimi sənədləşdirilmiş əməliyyatları təkrar cəhd etmək, məhdudlaşdırılmış eksponensial geri çəkilmə və jitter istifadə etməklə.
- Autentifikasiya uğursuzluqları, imza səhvləri, sürət məhdudiyyəti cavabları, WebSocket yenidən birləşmə dövrləri, ardıcıllıq boşluqları və sifariş uyğunlaşdırma fərqləri barədə xəbərdarlıq.
- Server saatlarını sinxronlaşdırmaq, çünki autentifikasiya və imzalama zaman möhürlərinə bağlıdır.

<h2 id="before-production">İstehsaldan əvvəl</h2>

- İstehsal olmayan mühitdə timeout, təkrarlanan sorğu, yenidən qoşulma, açar fırlanması və webhook yenidən cəhd ssenariləri.
- Sahibləri credential dövrü, ticarət hadisələri, webhook uğursuzluqları və uzlaşdırma üçün təyin edin.
- [istehsalın başlanğıc yoxlama siyahısı](/az-AZ/resources/production-launch-checklist) tamamlayın və eskalasiya lazım olduqda [dəstək sorğusu şablonu](/az-AZ/resources/support-request-template) istifadə edin.
