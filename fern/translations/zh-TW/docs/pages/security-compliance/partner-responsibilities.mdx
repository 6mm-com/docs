明確的責任模式能降低營運風險，並協助支援團隊更快回應。

<h2 id="responsibility-split">責任分工</h2>

| 面積 | 6MM | 夥伴 |
| --- | --- | --- |
| 貿易基礎設施 | 配對、風險、交易引擎、 API 與 SDK 能力 | 正確的整合與生產監控 |
| 終端使用者關係 | 除非另有協議，否則無法直接與客戶建立關係 | 使用者入職、支援、揭露與帳號生命週期 |
| 秘密與資歷 | 提供憑證模型與簽署要求 | 安全儲存機密並限制內部存取 |
| Webhook | 傳送有署名的生命週期事件 | 驗證簽名並以冪等方式處理事件 |
| 合規作業 | 提供符合法規的技術與支援資料 | 確認當地義務及面向使用者的需求 |
| 整合版本 | 維護有文件化的平台與整合能力 | 在發佈前測試合作夥伴程式碼、設定及使用者歷程 |
| 事件處理 | 調查相關 6MM 基礎設施並提供合作夥伴支援管道 | 偵測使用者相關影響、保存證據、包含合作夥伴系統，並升級處理 |

<h2 id="responsibilities-by-lifecycle">按生命週期劃分的職責</h2>

| 舞台 | 夥伴行動 |
| --- | --- |
| 設計 | 定義使用者所有權、資產流、資料流、支援模式及目標司法管轄區。 |
| 建造 | 後端保留機密，實作支援的認證，並保留商業識別碼。 |
| 測試 | 執行逾時、重試、重複 webhook、過期令牌及失敗情境。 |
| 發射 | 完成準備度審查、建立監控，並記錄支援升級。 |
| 操作 | 審查警示、核對異常操作、輪換憑證，並維護稽核證據。 |
| 事件 | 包含合作夥伴控制的系統、保護憑證、維護 UTC 時程，並聯絡正確的 6MM 管道。 |

<h2 id="handoff-checklist">操作交接檢查清單</h2>

- 指定整合健康、安全、合規及終端使用者支援的擁有者。
- 記錄生產基地網址、憑證擁有者及輪替程序。
- 確認認證、訂單、傳輸及 webhook 失敗的儀表板與警示。
- 將請求 ID、合作夥伴訂單號碼及事件 ID 儲存在可搜尋的日誌中。
- 定義哪些事件需要立即升級。
- 保留[支援請求模板]（/resources/support-request-template）供營運團隊使用。
