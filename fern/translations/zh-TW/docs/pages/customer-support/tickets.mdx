使用票證來追蹤無法在一次對話中完成的工作。保持記錄類型、負責人和當前進度清晰，以便下一個代理可以繼續。

<div className="sixmm-support-flow">

1. **識別記錄** — 選擇代理票證、使用者票證或回饋。
2. **調查並指派** — 閱讀說明並確認由誰處理。
3. **更新結果** — 記錄進度並驗證已儲存的狀態。

</div>


<span id="choose-the-correct-record" data-sixmm-canonical-anchor="choose-the-correct-record" aria-hidden="true"></span>

## 選擇正確的記錄

開啟**票證管理**並選擇適當的選項卡。

| 記錄 | 目的 |
| --- | --- |
| 代理票 | 由支援團隊創建和維護的工作 |
| 用戶票 | 訪客提交的問題以供後續跟進 |
| 使用者回饋 | 透過反饋條目提交的建議或問題 |

<span id="handle-a-case" data-sixmm-canonical-anchor="handle-a-case" aria-hidden="true"></span>

## 辦案

閱讀記錄中的描述、聯絡資訊、相關對話和附件。將其分配給適當的處理程序並隨著工作的進展更新狀態。使用支援的代理工單編輯控制項；使用者票證和回饋有其自己的可用操作。

更新狀態本身並不證明訪客收到了電子郵件或聊天回覆。需要時透過可用的通訊管道發送回應，並驗證結果。將個人資訊保留在授權租戶工作流程中。

<span id="use-mcp-for-triage" data-sixmm-canonical-anchor="use-mcp-for-triage" aria-hidden="true"></span>

## 使用 MCP 進行分類

要求連接的人工智慧列出未解決的案例，按問題分組並準備建議的回應。在將任務和狀態變更應用於實際案例之前，請先檢查它們。代理票證創建和使用者票證提交是不同的工作流程；一種工具適用於一種工具並不意味著它支援另一種工具。透過 MCP 刪除工單需要確認。


<span id="use-status-and-priority-deliberately" data-sixmm-canonical-anchor="use-status-and-priority-deliberately" aria-hidden="true"></span>

## 有意使用狀態和優先級

代理票證支援待定、處理、已解決和已關閉狀態。使用者票證和回饋暴露了他們自己的狀態控制；不要假設每個選項卡都有完全相同的操作。

| 細節 | 它有什麼幫助 |
| --- | --- |
| 票號 | 將工作交給其他代理商時找到準確的記錄。 |
| 描述和相關會話 | 了解發生了什麼事以及已經討論過的內容。 |
| 受讓人或處理人 | 確定負責下一步的人員。 |
| 優先購買代理票 | 將緊急程度與工作流程狀態分開；高優先票證不會自動解決。 |
| 創建和解決時間 | 使用選定的日期基準查看時間表。 |

<span id="example-an-issue-needs-technical-investigation" data-sixmm-canonical-anchor="example-an-issue-needs-technical-investigation" aria-hidden="true"></span>

### 例：問題需要技術調查

1. 開啟原始記錄並從提供的資訊中收集時間、受影響的頁面和可重現的步驟。
2. 查看可用的連結對話。避免要求訪客重複已記錄的資訊。
3. 分配適當的處理程序並隨著工作進度更新狀態。保持內部記錄真實。
4. 當問題得到驗證後，更新結果並透過可用管道聯繫訪客。離開頁面前請檢查已儲存的記錄。

## 常見問題

<AccordionGroup>

<Accordion title="解決票證是否會自動通知訪客？">
更改狀態本身並不能證明電子郵件或聊天訊息已發送。分別驗證通訊管道和傳遞結果。
</Accordion>

<Accordion title="為什麼我找不到票？">
檢查記錄標籤、日期基礎、日期範圍、狀態和受讓人過濾器。再次搜索之前清除不必要的过滤器。
</Accordion>
