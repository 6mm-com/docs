處理傳入對話從首次審核到移交的整個過程。使用此工作區來理解問題、協調人員支援並使對話保持在上下文中。

<div className="sixmm-support-flow">

1. **閱讀對話** — 查看問題和最近的訊息。
2. **選擇處理者** — 在加入或轉移之前檢查所有權。
3. **回覆並跟進** — 回答、邀請回饋或繼續在工單中。

</div>


<span id="work-from-one-conversation-workspace" data-sixmm-canonical-anchor="work-from-one-conversation-workspace" aria-hidden="true"></span>

## 在一個對話工作區工作

開啟**線上對話**。人員、監控和機器人標籤組織您帳戶可見的對話。監控存取和對話所有權仍然適用；代理商不會自動看到每個租戶的對話。

1. 選擇一個對話並閱讀其最近的訊息和可用的訪客資訊。
2. 使用您的角色允許的操作加入、接管、指派或轉移它。
3. 使用文字、支援的附件或快速回覆進行回覆。需要時使用語言辨識和翻譯。
4. 管理訪客上傳權限並邀請評分（如果有）。
5. 當需要進一步工作時，完成對話或建立/跟進票證。

<span id="understand-visitor-information" data-sixmm-canonical-anchor="understand-visitor-information" aria-hidden="true"></span>

## 了解訪客資訊

可讀的訪客姓名是顯示標籤，而不是經過驗證的交易帳戶的證明。區分登入使用者 ID、輸入電子郵件和支援期間提供的聯絡電子郵件。使用可用的會話詳細資訊來了解案例；不要假設具有相同電子郵件地址的兩個訪客是同一經過身份驗證的使用者。

發送前檢查當前對話。 AI-從外部MCP客戶端產生的文字不會僅僅因為出現在您的AI聊天中而被發送；透過MCP發送需要平台的確認流程。

<span id="when-human-support-is-unavailable" data-sixmm-canonical-anchor="when-human-support-is-unavailable" aria-hidden="true"></span>

## 當無法獲得人力支持時

訪客條目遵循配置的可用性和回退行為。票證可以保留問題以供以後處理。保持顯示的說明與您的實際人員配置和回應政策一致；避免承諾不支援的回應時間。

## 知道要使用哪個工作區

| 工作空間 | 在這裡做什麼 |
| --- | --- |
| 人類 | 查看您可以進行的對話並處理分配的工作。回覆前請檢查目前代理。 |
| 監控 | 在您的監控權限範圍內查看對話。查看會話和接管它是不同的操作。 |
| 機器人 | 在決定是否需要手動處理之前檢查問題和機器人的答案。 |

<span id="example-a-user-asks-about-exchange-integration" data-sixmm-canonical-anchor="example-a-user-asks-about-exchange-integration" aria-hidden="true"></span>

### 範例：用戶詢問交易所集成

1. 閱讀對話以區分文件請求和特定於帳戶的問題。
2. 使用經過審閱的知識答案或適當的快速回覆。發送前請檢查所有平台名稱、連結和金額。
3. 對於其他語言，請使用可用的識別和翻譯控制並在回復之前查看含義。
4. 如果同事必須繼續，請在您的權限範圍內調動或指派。如果問題需要稍後調查，請繼續執行相應的票證工作流程。

**結束前：**確認用戶收到回复，識別任何未完成的問題並保留相關對話號碼以供後續跟進。

## 常見問題

<AccordionGroup>

<Accordion title="為什麼我可以看到對話但看不到回應？">
檢查其目前所有者、您的帳戶權限以及您是否需要先加入或接管。監控不會自動授予處理權限。
</Accordion>

<Accordion title="帶有 AI- 標籤的回應是否總是來自大型模型？">
不會。已儲存的回覆和先前的比對階段也可以顯示為 AI 訊息。當您需要診斷回應路徑時，請使用機器人流測試。
</Accordion>

</AccordionGroup>
