將對話、票證和知識活動轉化為您的團隊可以採取行動的問題。從定義的報告期間開始，然後調查數字變化背後的記錄。

<div className="sixmm-support-flow">

1. **設定期限** — 保持日期和過濾器一致。
2. **比較指標** — 一起查看音量、操控性和回饋。
3. **檢查記錄** — 尋找範例並選擇特定的改進。

</div>


<span id="understand-support-activity" data-sixmm-canonical-anchor="understand-support-activity" aria-hidden="true"></span>

## 了解支持活動

開啟**統計**並選擇相關時間範圍和可用篩選器。查看即時概覽、對話、工單、滿意度、訊息、代理、回饋和知識統計。

一起使用多個指標。對話量顯示需求，票證狀態顯示後續工作，評級提供個人體驗的回饋。僅高知識視圖計數並不能證明問題已解決。

<span id="compare-like-for-like-data" data-sixmm-canonical-anchor="compare-like-for-like-data" aria-hidden="true"></span>

## 比較同類數據

比較結果時保持相同的時間範圍、時區、過濾器和模組範圍。檢查欄位標籤，而不是假設所有數字都算作唯一的人員。如果某個值與另一個螢幕不同，請先比較其定義和篩選。

MCP可以查詢統計數據並幫助總結趨勢。不能透過唯讀統計工具修改統計記錄。要求它在摘要中包含查詢的時間段和來源指標，以便可以在控制台中檢查結果。


<span id="choose-a-view-for-the-question" data-sixmm-canonical-anchor="choose-a-view-for-the-question" aria-hidden="true"></span>

## 選擇問題的視圖

| 問題 | 有用的觀點 |
| --- | --- |
| 支持需求發生了什麼變化？ | 訊息、人類對話、機器人活動和國家分佈。 |
| 後續工作是否有累積？ | 票證和回饋，與報告週期相同。 |
| 訪客如何評估服務？ | 滿意，然後回顧基本對話。 |
| 需要注意哪些幫助內容？ | FAQ 和知識統計，與真實會話中的重複問題進行比較。 |

<span id="example-prepare-a-weekly-review" data-sixmm-canonical-anchor="example-prepare-a-weekly-review" aria-hidden="true"></span>

### 範例：準備每週回顧

1. 選擇商定的一周並在審核中記錄日期範圍和活動過濾器。
2. 分別彙總需求、未完成的工作和訪客回饋。不要將不同的指標加在一起。
3. 打開一小組相關對話或票證以了解更改背後的原因。
4. 選擇具體的行動：修改不清楚的文章、更新快速回覆或檢視團隊的處理方式。使用相同的定義比較下一個時期。

您可以要求 MCP- 連接的 AI 總結所選的統計資料並確定要調查的問題。要求它說出該時期的名稱，並將觀察到的數字與建議的解釋區分開來。

## 常見問題

<AccordionGroup>

<Accordion title="一篇受歡迎的文章是否意味著它可以解決大多數問題？">
視圖和互動描述的是活動，而不是保證解決方案。在做出結論之前先閱讀訪客的問題和結果。
</Accordion>

<Accordion title="為什麼兩份報告顯示不同的總數？">
首先比較時間基礎、篩選器和指標定義。會話計數、訊息和獨立訪客數量不同。
</Accordion>

</AccordionGroup>
