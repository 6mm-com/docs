為每個代理提供一個單獨的帳戶，選擇一個角色並準備經過審核的快速回應。圍繞每個人執行的工作組織存取權限，然後使用該帳戶進行驗證。

<div className="sixmm-support-flow">

1. **建立帳戶** — 確定代理程式和帳戶狀態。
2. **指派角色** — 授予作業所需的模組和操作。
3. **驗證工作流程** — 測試訪問並準備快速回覆。

</div>


<span id="organize-the-support-team" data-sixmm-canonical-anchor="organize-the-support-team" aria-hidden="true"></span>

## 組織支援團隊

使用**代理管理**來維護代理帳戶、角色和快速回應。根據每個人實際需要的模組和操作分配角色。將帳戶憑證保留為個人訊息，而不是在整個團隊中共享一個管理員登入資訊。

更改角色後，使用受影響的帳戶進行驗證：可見選單、對話監控、內容編輯和設定存取可能會有所不同。除了選單之外，帳戶狀態、會話所有權和欄位層級檢查仍然適用。

<span id="mcp-inherits-the-same-identity" data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP 繼承相同的身份

MCP 連線綁定到授權租用戶和代理帳戶。 AI 沒有單獨的管理員角色。本服務會重新評估帳戶的通話權限；無法透過猜測其名稱或提供另一個租用戶 ID 來啟用不可用的工具。

在**系統設定 → MCP 連線**中管理連線的應用程式。撤銷不再需要的連線。註銷瀏覽器本身並不會撤銷外部人工智慧應用程式的授權。

透過 MCP 進行的角色和代理帳戶變更需要確認。透過MCP建立代理程式時，初始密碼由使用者在後端確認頁面輸入，而不是傳回給AI。

## 了解三個管理領域

| 區域 | 保養什麼 |
| --- | --- |
| 代理帳戶 | 頁面公開的姓名、登入電子郵件、角色、啟用狀態和接收控制。 |
| 角色管理 | 一組代理允許的模組和操作。在儲存變更之前檢查對現有成員的影響。 |
| 快速回覆 | 可重複使用的回應標題、內容、順序和啟用狀態。檢查該功能可用的翻譯。 |

<span id="prepare-an-agent-for-their-first-shift" data-sixmm-canonical-anchor="prepare-an-agent-for-their-first-shift" aria-hidden="true"></span>

### 為座席的第一班做好準備

1. 確認登入電子郵件和預期角色。不要將帳戶可用性、登入狀態和工作狀態視為同一件事。
2. 檢查配置的監控存取、接收優先權和最大並發會話數。這些控制項補充了角色權限。
3. 請客服人員登入並驗證其工作所需的選單和處理操作。
4. 準備常見問題的快速答复，然後檢查它們是否包含當前連結且不包含特定於訪問者的信息。

**移交例行程序：**在更改代理的存取權限之前審查未履行的職責。角色或帳戶變更後，請驗證有效權限，而不是僅依賴角色名稱。

## 常見問題

<AccordionGroup>

<Accordion title="管理員授權的AI是否充當普通代理？">
不可以。 MCP 連結使用授權它的帳戶。連接其存取權限適合預期工作的帳戶。
</Accordion>

<Accordion title="註銷會斷開外部 AI 的連接嗎？">
登出控制台與撤銷 MCP 連線是分開的。使用系統設定 → MCP 連線來撤銷應用程式。
</Accordion>
