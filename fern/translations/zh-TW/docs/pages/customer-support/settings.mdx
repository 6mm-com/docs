設定訪客如何獲得支援、他們看到的內容以及可用的智慧服務。將設定變更視為一個小版本：儲存它，測試實際條目並檢查結果。

<div className="sixmm-support-flow">

1. **選擇設定** — 找到您要變更的行為的標籤。
2. **儲存變更** — 查看受影響的條目或服務。
3. **以訪客身分測試** — 開啟真實網站並驗證結果。

</div>


<span id="configure-the-visitor-experience" data-sixmm-canonical-anchor="configure-the-visitor-experience" aria-hidden="true"></span>

## 配置訪客體驗

開啟**系統設定**。可用的控制取決於您的角色和啟用的租用戶服務。

| 選項卡 | 需要配置什麼 |
| --- | --- |
| 外觀與集成 | 可用的視覺和入口設置 |
| 主頁及副本 | 面向客戶的主頁文字和指導 |
| 會話和超時 | 對話行為與超時控制 |
| 訪客對話 | 訪客進入時收集的資訊和提示 |
| 智慧服務 | 向租戶開放的人工智慧、檢索和翻譯功能 |
| 網站整合 | 域白名單、嵌入程式碼、簽名身分和語言/主題集成 |
| MCP 連接 | 服務地址、授權申請及撤銷 |

保存設置，然後從訪客條目中驗證它們。預覽或成功儲存並不能確定單獨嵌入的網站已在使用最新設定。

<span id="keep-boundaries-clear" data-sixmm-canonical-anchor="keep-boundaries-clear" aria-hidden="true"></span>

## 保持界線清晰

租戶設定配置租戶的客戶支援。他們不授予對平台範圍內的提供者金鑰、其他租戶、儲值操作或交易所交易帳戶的存取權限。 MCP 僅公開目前角色允許的支援組態欄位。透過 MCP 進行的域白名單變更需要確認。


<span id="plan-the-initial-setup" data-sixmm-canonical-anchor="plan-the-initial-setup" aria-hidden="true"></span>

## 規劃初始設定

1. **外觀和文案：**檢查可見品牌、主頁指南和支援措辭。保持描述與您實際提供的換貨服務一致。
2. **訪客條目：**決定收集哪些資訊並查看可用的提示行為。在相關的情況下測試新訪問和回訪。
3. **接待行為：**與處理即時對話的團隊一起審查會話和超時控制。
4. **智慧型服務：**驗證啟用的租用戶功能，然後測試代表性問題或翻譯。單獨配置的交換器並不能證明上游要求成功。
5. **網站整合：** 檢查允許的網站網域並使用嵌入程式碼、登入身分、語言和主題的整合指南。
6. **MCP:**只有在驗證授權帳號和可用權限後才能連接外部AI。

<span id="example-a-saved-change-is-not-visible-on-your-website" data-sixmm-canonical-anchor="example-a-saved-change-is-not-visible-on-your-website" aria-hidden="true"></span>

### 範例：儲存的變更在您的網站上不可見

首先驗證正在測試的租戶和訪客條目。重新載入該條目，檢查嵌入網站是否傳遞自己的語言或主題，並確認已儲存預期配置。對於存取失敗，請在重複變更不相關的設定之前檢查允許的網域和整合配置。

## 常見問題

<AccordionGroup>

<Accordion title="為什麼我看不到設定選項卡？">
帳戶權限和啟用的租用戶服務決定了可用的內容。請租用戶管理員檢查相關存取權限，而不是更改其他租用戶或帳戶。
</Accordion>

<Accordion title="模型憑證和儲值在哪裡管理？">
提供者憑證和平台平衡調整不在租戶設定範圍內。使用與平台業者同意的服務安排。
</Accordion>

</AccordionGroup>
