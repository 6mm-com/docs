當應用程式需要持續更新價格、交易、蠟燭圖或訂單簿深度，且不需反覆輪詢 REST 端點時，請使用公開市場通道。這些串流可支援交易畫面、價格顯示、警示及市場監控。

<h2 id="connection-url">連結 URL</h2>

```
wss://ws.6mm.com/ws
```

公開 WebSocket 不需要驗證。

關於連線生命週期、取消訂閱、ping 及重新連線行為，請參見 [Connection， Subscription and Heartbeat]（/developer-api/websocket/connection-subscription-and-heartbeat）。

<h2 id="common-channels">共用頻道</h2>

| 頻道                            | 描述                                                        |
| ---------------------------------- | ------------------------------------------------------------------ |
| `market.depth.{symbol}`            | 訂購簿深度。先傳送快照，再進行增量更新 |
| `market.trade.{symbol}`            | 最新交易                                                      |
| `market.kline.{symbol}.{interval}` | 克萊恩                                                             |
| `market.ticker.{symbol}`           | 單符號行情摘要                                       |
| `market.tickers`                   | 全符號行情條摘要                                          |

<h2 id="choose-a-channel">選擇頻道</h2>

| 應用需求 | 頻道 |
| --- | --- |
| 建立或維護訂單簿 | `market.depth.{symbol}` |
| 顯示即時交易動態 | `market.trade.{symbol}` |
| 畫一張蠟燭圖 | `market.kline.{symbol}.{interval}` |
| 顯示一個市場摘要 | `market.ticker.{symbol}` |
| 保持市場概況 | `market.tickers` |

<h2 id="subscription-example">訂閱範例</h2>

```json
{ "id": "1772007814666", "op": "subscribe", "args": ["market.depth.BTCUSDT"] }
```

<h2 id="push-message-wrapper">推送訊息包裝器</h2>

```json
{
  "topic": "market.depth.BTCUSDT",
  "event": "data",
  "ts": 1772007815000,
  "data": {}
}
```

使用 `topic` 將每則訊息路由至正確的處理程序，並 `ts` 觀察傳送時序。 `data` 物件包含訂閱通道的有效載荷。

<h2 id="order-book-handling">訂單簿處理</h2>

深度通道先傳送快照，然後再進行增量更新。在套用更新前，先從快照初始化本地書籍。重新連線後，建立新工作階段，再次訂閱，從下一個快照重建本地書籍，而不是從記憶體過時狀態繼續。

<h2 id="production-recommendations">製作建議</h2>

- 為每個訂閱、取消訂閱及 ping 請求產生唯一 `id` 。
- 在將頻道視為活躍前，先確認訂閱確認。
- 重新連線後重新訂閱所有必讀主題。
- 將網路讀取與較慢的資料庫或使用者介面處理分開。
- 監控斷線頻率、訊息處理延遲及格式異常的有效載荷。
- 使用 [Private User Channel]（/developer-api/websocket/private-user-channel）進行認證帳號及訂單更新。
