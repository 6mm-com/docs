從當前空間的菜單與權限開始操作。個人和團隊錢包側重錢包資產與設備簽名，企業空間還提供業務審批和運營視圖。

<span id="receive-assets" data-sixmm-canonical-anchor="receive-assets" aria-hidden="true"></span>

## 接收資產

選擇目標網絡和資產，使用該錢包或業務用戶對應的收款信息。有些網絡除地址外還需要備註或標籤，應將這些信息一起保存，並在轉入前核對。

地址已分配不代表充值已經到賬。需要分別關注充值記錄、鏈上確認以及可能的風險凍結。鏈上能夠查到交易時，業務賬戶中的資金仍可能尚未變為可用。

<span id="transfer-assets" data-sixmm-canonical-anchor="transfer-assets" aria-hidden="true"></span>

## 轉出資產

1. 選擇來源錢包或餘額，填寫目標地址、金額和必要的備註。
2. 核對預覽、費用與地址檢查結果；按錢包模式準備相應的手續費資產。
3. 提交一次並保存請求編號，完成當前產品要求的審批或設備確認。
4. 跟蹤簽名、廣播和鏈上確認，直到最終結果明確。

審批通過不等於已完成簽名，廣播成功也不等於鏈上確認。個人與團隊的簽名流程，不能直接套用企業提現的網頁審批方式。

<span id="understand-enterprise-wallet-roles" data-sixmm-canonical-anchor="understand-enterprise-wallet-roles" aria-hidden="true"></span>

## 理解企業錢包分工

| 角色 | 用途 |
| --- | --- |
| 充值錢包 | 接收轉入資產，配合資金歸集 |
| 熱錢包或提現錢包 | 處理日常轉出 |
| 中轉錢包 | 銜接運營資金和儲備資金的調撥 |
| 儲備錢包 | 按適合儲備用途的簽名安排保管資產 |

部分產品還區分手續費資金或隔離資金。這些是資金運作中的角色，不代表所有產品都提供全部錢包類型。僅憑“儲備”這個名稱，也不能判斷設備是否離線。

<span id="reconcile-uncertain-results" data-sixmm-canonical-anchor="reconcile-uncertain-results" aria-hidden="true"></span>

## 核對不確定的結果

將業務請求、錢包記錄和鏈上交易對應起來，區分可用餘額、凍結餘額、賬本分錄與鏈上觀察結果。

遇到請求超時或交易仍在核對中，應查詢已有記錄。不要因為缺少成功頁面或通知就另發一筆。能否取消取決於真實的簽名階段；提交了取消請求，並不能證明資金不會轉出。開發人員可繼續閱讀[交易狀態與重試](/zh-TW/mpc-wallet/transactions)。
