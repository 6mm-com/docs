嵌入式交易通常是引入現有產品，而非作為獨立平台推出。最佳整合路徑取決於使用者已投入時間的地點，以及哪個系統擁有身份、資金與營運。

<h2 id="common-scenarios">常見情境</h2>

| 劇本 | 最佳起點 | 註釋 |
| --- | --- | --- |
| 應用程式或錢包需要交易輸入 | Trading Widget SDK | 使用原生或 H5 的入口點，並在用戶授權後開啟內嵌的交易體驗。 |
| 經紀商或通路平台希望取得衍生性商品的存取權 | Agent SDK + Trading Widget SDK | 客戶關係和後端驗證都放在合作夥伴系統中。 |
| 平台希望有引導的交易流程 | API + 選擇 SDK 模組 | 使用後端 APIs 處理帳戶、轉帳和訂單工作流程，同時只公開必要的前端條目。 |
| 現有交易所希望增加市場 | 流動性 + API 整合 | 結合市場深度、帳戶工作流程與營運監控。 |

<h2 id="product-decisions-before-integration">整合前的產品決策</h2>

- 決定使用者是從首頁卡片、資產頁、活動頁面或帳號中心輸入。
- 決定哪個系統擁有登入狀態、使用者資格及國家或地區可用性。
- 決定轉帳、結算紀錄及客戶支援工單如何向使用者展示。
- 決定哪些事件必須轉交內部分析、 CRM或風險作業。
