O trading embutido geralmente é introduzido em um produto existente, não lançado como um destino independente. O melhor caminho de integração depende de onde os usuários já gastam tempo e qual sistema detém identidade, fundos e operações.

<h2 id="common-scenarios">Cenários comuns</h2>

| Cenário | Melhor ponto de partida | Notas |
| --- | --- | --- |
| App ou carteira quer uma entrada de negociação | Trading Widget SDK | Use um ponto de entrada nativo ou H5 e abra a experiência de negociação embarcada após a autorização do usuário. |
| Corretor ou plataforma de canal quer acesso a derivativos | Agent SDK + Trading Widget SDK | Mantenha o relacionamento com o cliente e a validação de backend no sistema de parceiros. |
| A plataforma quer um fluxo de negociação guiado | API + módulos selecionados SDK | Use API backend para fluxos de trabalho de conta, transferência e pedidos, expondo apenas a entrada frontend necessária. |
| A bolsa existente quer mercados extras | Integração Liquidez + API | Combine profundidade de mercado, fluxos de trabalho de contas e monitoramento operacional. |

<h2 id="product-decisions-before-integration">Decisões de produto antes da integração</h2>

- Decidir se os usuários entram a partir de um cartão de página inicial, página de ativos, página de campanha ou centro de contas.
- Decidir qual sistema possui o estado de login, elegibilidade do usuário e disponibilidade de país ou região.
- Decidir como transferências, registros de liquidação e tickets de suporte ao cliente são mostrados aos usuários.
- Decidir quais eventos devem ser encaminhados para análises internas, CRMou operações de risco.
