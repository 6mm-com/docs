Comece com o ambiente, o carimbo de data/hora e o identificador comercial da operação com falha. Uma verificação estruturada geralmente separa problemas de configuração de problemas de autenticação, rede e processamento assíncrono.

<span id="diagnostic-order" data-sixmm-canonical-anchor="diagnostic-order" aria-hidden="true"></span>

## Ordem de diagnóstico recomendada

1. Confirme o ambiente afetado e a base URL.
2. Registre o intervalo de tempo UTC e a primeira solicitação com falha.
3. Identifique o módulo: Trading Widget, Agent SDK, REST API, WebSocket ou webhook.
4. Capture o ID da solicitação, o ID do usuário parceiro, `agentOrderNo`, o ID do pedido ou o ID do evento webhook.
5. Verifique código recente, credencial, lista de permissões IP ou alterações de implantação.
6. Reproduza com o menor caso de teste seguro.

<span id="trading-widget-issues" data-sixmm-canonical-anchor="trading-widget-issues" aria-hidden="true"></span>

## Trading Widget problemas

| Sintoma | Causa provável | Consertar |
| --- | --- | --- |
| iframe solicita domínio local do parceiro | baseUrl está faltando | Passe baseUrl: 'https://app.6mm.com'. |
| iframe é invisível ou muito curto | O contêiner pai não tem altura | Defina a altura do recipiente ou a altura da passagem. |
| token_provider_missing | modo de token de parceiro não tem provedor | Adicionar autenticação.tokenProvider. |
| auth_exchange_failed | Token incorporado inválido, expirado ou incompatível | Verifique a resposta do token de backend e channelId. |

<span id="agent-sdk-issues" data-sixmm-canonical-anchor="agent-sdk-issues" aria-hidden="true"></span>

## Agent SDK problemas

| Sintoma | Causa provável | Consertar |
| --- | --- | --- |
| Assinatura rejeitada | Segredo errado, desvio de relógio ou campos assinados alterados manualmente | Deixe SDK gerar campos de assinatura e sincronizar o horário do servidor. |
| Risco de movimentação de fundos duplicados | Novo número de pedido usado após o tempo limite | Consulte primeiro pelo agentOrderNo original. |
| PROCESSING tratado como falha | Estado pendente mal compreendido | Aguarde webhook ou ligue para queryOrder. |
| Webhook processado várias vezes | Tentar novamente o comportamento sem idempotência | Adicione chave de idempotência e verificações de estado final. |

<span id="evidence-to-capture" data-sixmm-canonical-anchor="evidence-to-capture" aria-hidden="true"></span>

## Evidências para capturar

| Integração | Evidência útil |
| --- | --- |
| Trading Widget | Página URL, caminho da versão SDK, console do navegador, solicitações de rede com falha, carga útil `onError` e dimensões do contêiner. |
| Agent SDK | SDK idioma/versão, base URL, UTC carimbo de data/hora, ID da solicitação, `agentOrderNo`, código de resposta e logs limpos. |
| Webhook | Prazo de entrega, evento ou chave de negócios, resultado da validação de assinatura, estado de processamento e hash de corpo bruto higienizado. |
| REST API | Método, caminho, ambiente, ID de solicitação, código de resposta e parâmetros higienizados. |

Nunca inclua senhas, tokens de acesso, API segredos, assinaturas completas, chaves privadas ou dados pessoais não editados em diagnósticos.

<span id="before-escalating" data-sixmm-canonical-anchor="before-escalating" aria-hidden="true"></span>

## Antes de escalar

- Tente novamente somente quando a operação estiver documentada como segura para tentar novamente.
- Após um tempo limite, consulte o identificador comercial original em vez de criar um novo.
- Confirme o relógio do sistema e o ambiente de credenciais para erros de assinatura.
- Preserve a primeira falha e quaisquer resultados de novas tentativas posteriores.
- Use o [Modelo de solicitação de suporte](/pt-BR/resources/support-request-template) para enviar um relatório completo e redigido.

## Diagnóstico Java v0.3.0

| Sintoma | Verificação e recuperação |
| --- | --- |
| A solicitação de financiamento tem um resultado desconhecido | Mantenha o original `agentOrderNo`; chame `queryWalletTransfer` com o ambiente original. Não use `queryOrder`. |
| UI de simulação mostra fundos inesperados | Verifique o frontend `tradingMode` separadamente do backend `environment`; a conta `isSimulatedUser` não encaminha solicitações. |
| Erro de consulta `6905` | Recue usando a cota de parceiro compartilhado, tente novamente o mesmo cursor e filtre por SDK. |
| Erro de consulta `6904` | Reduza consultas simultâneas e restrinja a janela de tempo; entre em contato com o suporte se persistir. |
| Cursor inválido ou expirado | Reinicie a mesma janela de histórico fixa e desduplicar os registros salvos. |
| Novo método Java ausente | Verifique o artefato Maven resolvido em relação à tag pública `v0.3.0`; remova dependências conflitantes de acordo com sua política de artefatos. |
