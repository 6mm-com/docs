As solicitações Agent SDK são autenticadas com um segredo do parceiro API. Mantenha esse segredo dentro de um serviço de back-end confiável e deixe o SDK gerar campos de assinatura sempre que possível.

> **Dois protocolos de assinatura**
>
> A assinatura Agent SDK usa campos de solicitação classificados, um carimbo de data/hora baseado em segundos e um nonce. Solicitações diretas Developer API usam o processo separado descrito em [Solicitar assinatura](/pt-BR/developer-api/request-signing). Não reutilize um formato de carga útil para o outro.

<span id="signing-rule" data-sixmm-canonical-anchor="signing-rule" aria-hidden="true"></span>

## Regra de assinatura

Para solicitações Agent SDK:

1. Exclua o campo `sign`.
2. Omita campos com valores vazios.
3. Classifique os nomes de campos restantes na ordem ASCII.
4. Junte os campos como `k=v&k2=v2`.
5. Calcule a assinatura hexadecimal HMAC-SHA256 com `apiSecret`.

Os valores da matriz são serializados como compactos JSON antes de ingressar na carga útil de assinatura. Por exemplo, `platformUserIds` assina como `["1188041528"]`, fornecendo `platformUserIds=["1188041528"]` na carga útil `k=v`. Preservar a ordem dos elementos do array, aspas duplas e IDs de string; não insira espaços de formatação nem use Java `List.toString()` (como `[1188041528]`). O SDK lida com essa serialização automaticamente.

O SDK deve construir esse valor a partir dos mesmos dados que envia. Alterar um campo assinado após a geração da assinatura causa falha na verificação.

<span id="sdk-managed-fields" data-sixmm-canonical-anchor="sdk-managed-fields" aria-hidden="true"></span>

## Campos gerenciados por SDK

| Campo | Fonte | Descrição |
| --- | --- | --- |
| agentCode | Configuração SDK | Código do agente parceiro. |
| carimbo de data/hora | Hora atual do servidor | Carimbo de data/hora Unix em segundos. |
| agora | Valor aleatório seguro | Sequência aleatória de proteção de repetição. |
| sinal | HMAC-SHA256 | Solicite assinatura. |
| moeda | Moeda padrão | Usado quando a transferência/conta APIs omite a moeda. |

<span id="secret-storage" data-sixmm-canonical-anchor="secret-storage" aria-hidden="true"></span>

## Armazenamento secreto

- Carregue `apiSecret` de um gerenciador de segredos de back-end ou de uma configuração de tempo de execução protegida.
- Nunca coloque o segredo em pacotes de front-end, aplicativos móveis, clientes de desktop, capturas de tela ou tíquetes de suporte.
- Mantenha as credenciais de desenvolvimento, preparação e produção separadas.
- Limite o acesso aos serviços e operadoras que o necessitam.
- Edite assinaturas de solicitação, valores de autorização e segredos dos logs.
- Revogar e substituir credenciais quando houver suspeita de exposição.

<span id="clock-and-replay-protection" data-sixmm-canonical-anchor="clock-and-replay-protection" aria-hidden="true"></span>

## Proteção de relógio e replay

O SDK inclui `timestamp` e `nonce` para reduzir o risco de repetição. Mantenha os relógios de back-end sincronizados e não reutilize um nonce construído manualmente. Se a validação da assinatura falhar, confirme o segredo configurado, a hora do servidor, os campos serializados e o ambiente antes de tentar novamente.

<span id="integration-checklist" data-sixmm-canonical-anchor="integration-checklist" aria-hidden="true"></span>

## Lista de verificação de integração

| Verificar | Resultado esperado |
| --- | --- |
| Localização secreta | Armazenamento secreto somente de back-end. |
| Ambiente | Base URL e credencial pertencem ao mesmo ambiente. |
| Manipulação de campo | SDK gera `timestamp`, `nonce` e `sign`. |
| Registro | Os IDs comerciais permanecem visíveis enquanto as credenciais são editadas. |
| Rotação | O proprietário da credencial e o processo de substituição são documentados. |
