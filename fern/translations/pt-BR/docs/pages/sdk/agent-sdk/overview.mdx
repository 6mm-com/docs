O 6MM Agent SDK é para serviços de back-end de parceiros que precisam chamar o agente privilegiado APIs sem implementar assinatura e manipulação de solicitações do zero. Ele não deve ser executado em código de navegador, celular ou desktop público porque a integração usa um segredo de parceiro API.

<span id="when-to-use-the-agent-sdk" data-sixmm-canonical-anchor="when-to-use-the-agent-sdk" aria-hidden="true"></span>

## Quando usar o Agent SDK

Use o Agent SDK quando o backend precisar vincular um usuário parceiro, transferir ativos por um fluxo aprovado, consultar registros de negociação, criar uma URL de acesso à negociação incorporada ou verificar notificações de webhook. Use o [Trading Widget SDK](/pt-BR/sdk/trading-widget/overview) separadamente quando o frontend do parceiro precisar exibir a interface de negociação.

<span id="common-configuration" data-sixmm-canonical-anchor="common-configuration" aria-hidden="true"></span>

## Configuração comum

| Chave | Exemplo | Descrição |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agente API serviço URL sem barra final. |
| agentCode | AGENT001 | Código do agente parceiro. |
| apiSecret | seu-api-secret | API segredo de assinatura armazenado apenas no back-end. |
| defaultCurrency | USDT | Moeda padrão para transferência e conta APIs. |
| webhookUrl | https://partner.example.com/6mm/webhook | Endpoint do parceiro para notificações 6MM webhook. |

<span id="typical-integration-flow" data-sixmm-canonical-anchor="typical-integration-flow" aria-hidden="true"></span>

## Fluxo de integração típico

1. O frontend do parceiro autentica o usuário por meio do sistema de conta do próprio parceiro.
2. O back-end do parceiro mapeia o usuário para um identificador estável do lado do parceiro.
3. O back-end chama o Agent SDK com `agentCode` e o segredo protegido API.
4. O SDK assina e envia a solicitação do Agente API.
5. O back-end armazena o identificador comercial retornado e processa posteriormente webhooks de forma idempotente.
6. O frontend recebe apenas o resultado de curta duração ou a credencial de entrada necessária.

## Lista de verificação de produção

- Carregue `apiSecret` de um gerenciador de segredos de back-end, não do código-fonte.
- Mantenha as credenciais de desenvolvimento, preparação e produção separadas.
- Use um mapeamento estável de usuários parceiros e identificadores exclusivos de ordem comercial.
- Preserve o identificador original ao verificar o status de uma solicitação que expirou.
- Verifique as assinaturas webhook e armazene IDs de eventos processados.
- Edite segredos e assinaturas de logs, mantendo IDs de solicitação de suporte.
