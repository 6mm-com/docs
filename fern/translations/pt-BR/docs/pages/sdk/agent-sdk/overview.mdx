A 6MM Agent SDK é para serviços backend parceiros que precisam chamar o Agente privilegiado API sem implementar assinatura e tratamento de requisições do zero. Não deve rodar em código de navegador, celular ou desktop público porque a integração usa um parceiro API segredo.

<h2 id="when-to-use-the-agent-sdk">Quando usar o Agent SDK</h2>

Use o Agent SDK quando o backend precisar vincular um usuário parceiro, transferir ativos por um fluxo aprovado, consultar registros de negociação, criar uma URL de acesso à negociação incorporada ou verificar notificações de webhook. Use o [Trading Widget SDK](/pt-BR/sdk/trading-widget/overview) separadamente quando o frontend do parceiro precisar exibir a interface de negociação.

<h2 id="common-configuration">Configuração comum</h2>

| Chave | Exemplo | Descrição |
| --- | --- | --- |
| baseUrl | `https://agent-api.6mm.com` | 6MM Agente API URL serviço sem slash de trança. |
| agentCode | AGENT001 | Código do agente parceiro. |
| apiSecret | Seu-API-Segredo | API segredo de assinatura armazenado apenas no backend. |
| defaultCurrency | USDT | Moeda padrão para transferências e API da conta. |
| webhookUrl | https://partner.example.com/6mm/webhook | Endpoint parceiro para notificações de webhook 6MM . |

<h2 id="typical-integration-flow">Fluxo típico de integração</h2>

1. A interface do parceiro autentica o usuário por meio do próprio sistema de conta do parceiro.
2. O backend parceiro mapeia o usuário para um identificador estável do lado do parceiro.
3. O backend chama o Agent SDK com `agentCode` e o API protegido como segredo.
4. O SDK assina e envia o Agente API pedido.
5. O backend armazena o identificador de negócio retornado e processa webhooks posteriores idempotentemente.
6. O frontend recebe apenas o resultado de curta duração ou credencial de entrada que precisa.

<h2 id="production-checklist">Checklist de produção</h2>

- Carregar `apiSecret` de um gerenciador de segredos backend, não do código-fonte.
- Mantenha as credenciais de desenvolvimento, encenação e produção separadas.
- Utilizar um mapeamento de usuário de parceiro estável e identificadores únicos de ordem de negócios.
- Preservar o identificador original ao verificar o status de uma solicitação com tempo de expiração.
- Verificar assinaturas de webhooks e armazenar IDs de eventos processados.
- Ocultar segredos e assinaturas dos logs enquanto retém IDs de solicitação para suporte.
