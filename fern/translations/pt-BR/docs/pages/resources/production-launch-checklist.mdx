Use este checklist antes de expor as capacidades de negociação baseadas em 6MMpara usuários reais.

<h2 id="integration-readiness">Prontidão para integração</h2>

- Domínios de produção e caminhos de redirecionamento são confirmados.
- Trading Widget, Agent SDK, API WebSocket ou fluxos foram testados de ponta a ponta.
- O backend parceiro armazena todos os segredos no lado do servidor.
- Recebimento de Webhook, verificação de assinatura, tratamento de retentativas e idempotência são ativados.
- Os logs incluem IDs de requisição, IDs de mapeamento de usuários, IDs de pedidos e carimbos de data.

<h2 id="product-and-resource-readiness">Prontidão para produtos e recursos</h2>

- Pontos de entrada, banners e ativos de cartões utilizam a versão aprovada em idioma.
- Ativos de marca branca são usados apenas quando o acordo de cooperação permite.
- Prompts de risco voltados para o usuário e cópias de entrada de negociação são revisados pela equipe parceira.
- Os donos de suporte e escalonamento são designados.

<h2 id="operational-readiness">Prontidão operacional</h2>

- O monitoramento cobre erros de API , emissão de tokens, inicialização de widgets, falhas de webhooks e eventos do ciclo de vida dos pedidos.
- Rotas de contato de emergência confirmadas.
- Um plano de rollback ou incapacidade temporária é preparado para a entrada na negociação.

<h2 id="security-and-compliance-readiness">Prontidão para segurança e conformidade</h2>

- API chaves usam permissões mínimas e restrições IP aprovadas quando aplicável.
- Rotação e revogação de credenciais foram testadas.
- Assinaturas Webhook são verificadas contra os órgãos brutos de solicitação.
- Divulgações de usuários, avisos de risco, limites de responsabilidade e revisão do mercado-alvo estão completos.
- Evidências de incidente, reconciliação e suporte podem ser recuperadas sem expor segredos.
