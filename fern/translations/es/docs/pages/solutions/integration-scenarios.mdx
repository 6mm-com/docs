El trading embebido suele introducirse en un producto existente, no lanzarse como un destino independiente. La mejor vía de integración depende de dónde los usuarios ya dediquen tiempo y qué sistema posee la identidad, los fondos y las operaciones.

<h2 id="common-scenarios">Escenarios comunes</h2>

| Escenario | El mejor punto de partida | Notas |
| --- | --- | --- |
| La app o cartera quiere una entrada de trading | Trading Widget SDK | Utiliza un punto de entrada nativo o H5 y abre la experiencia de trading embebida tras la autorización del usuario. |
| El broker o la plataforma de canales quiere acceso a derivados | Agent SDK + Trading Widget SDK | Mantén la relación con el cliente y la validación de backend en el sistema de socios. |
| La plataforma quiere un flujo de trading guiado | API + módulos SDK seleccionados | Utiliza APIs backend para los flujos de trabajo de cuenta, transferencia y pedidos, exponiendo solo la entrada necesaria en el frontend. |
| La bolsa existente quiere mercados adicionales | Integración de liquidez + API | Combina la profundidad del mercado, los flujos de trabajo de cuentas y la monitorización operativa. |

<h2 id="product-decisions-before-integration">Decisiones de producto antes de la integración</h2>

- Decidir si los usuarios acceden desde una tarjeta de página principal, página de activos, página de campaña o centro de cuentas.
- Decidir qué sistema posee el estado de inicio de sesión, la elegibilidad de usuario y la disponibilidad de país o región.
- Decidir cómo se muestran las transferencias, los registros de liquidación y los tickets de atención al cliente a los usuarios.
- Decidir qué eventos deben reenviarse a analítica interna, CRMu operaciones de riesgo.
