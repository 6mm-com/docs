<h2 id="error-response-format">Formato de respuesta a errores</h2>

```json
{
  "code": 1003,
  "message": "Invalid token",
  "requestId": "req-12345678"
}
```

Los errores de negocio suelen seguir devolviendo la estructura unificada de JSON . Los integradores deben comprobar `code` primero. Los fallos de autenticación pueden devolver HTTP `401`; la limitación de velocidad puede devolver HTTP `429`.

<h2 id="common-error-codes">Códigos de error comunes</h2>

| Código de error      | Descripción                                  |
| --------------- | -------------------------------------------- |
| `0`             | Éxito                                      |
| `1001`          | No se proporciona información de autenticación válida |
| `1002`          | Token expirado                                |
| `1003`          | Token inválido, API Keyo firma         |
| `1004`          | Token revocado                                |
| `1006`          | Fuente IP desajuste                           |
| `2001`          | Parámetro requerido faltante                   |
| `2002`          | Valor de parámetro inválido                      |
| `2003`          | Parámetro fuera de rango                       |
| `3001`          | Equilibrio insuficiente                         |
| `3003`          | Orden no encontrado                              |
| `3004`          | Solicitud duplicada                            |
| `3005`          | El pedido no puede ser cancelado                     |
| `3006`          | Permiso denegado                            |
| `3100` - `3112` | Error de validación de parámetros de orden de condición   |
| `5001`          | Error interno del servidor                        |
| `5002`          | Servicio temporalmente indisponible              |
| `5003`          | Límite de tasa activado                         |

<h2 id="troubleshooting">Resolución de problemas</h2>

| Problema                                     | Recomendación                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `1001` no hay información válida de autenticación  | Comprueba si `Authorization: Bearer <accessToken>` o `X-API-KEY` está incluido.                  |
| `1002` Token expirado                        | Actualiza el Token o vuelve a iniciar sesión antes de volver a intentarlo.                                                   |
| `1003` Token, API Keyo firma inválida | Comprueba API Key, carga útil de firma, cuerpo de la JSON cadena de solicitud y orden de los parámetros de consulta.           |
| `1006` fuente IP desajuste                   | Revisa la configuración API Key IP lista blanca.                                                    |
| `3004` solicitud de duplicado                    | No reutilices la misma firma para caminos relacionados con el orden. Regenera `timestamp` y `signature`. |
| `5003` límite de tasa activado                 | Reduce la frecuencia de las solicitudes y usa un retroceso exponencial si vuelves a intentarlo.                                |
| `Timestamp outside of tolerance window`     | Llama a `/v1/time` para calibrar el desfasamiento de tiempo y firma la solicitud de nuevo.                             |
