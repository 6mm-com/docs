Webhooklar hamkor backendga asinxron biznes holati o'zgarishlari haqida xabar beradi. Yetkazib berish qayta sinab ko'rilishi mumkinligi sababli, har bir qabul qiluvchi ishonchli ma'lumotlarni tahlil qilishdan oldin imzoni tekshirishi va voqeani idempotik tarzda qayta ishlashi kerak.

<h2 id="webhook-headers">Webhook sarlavhalari</h2>

| Sarlavha | Tavsif |
| --- | --- |
| X-Agent-Vaqt tamg'asi | Unix vaqt tamg'asi soniyalarda. |
| X-Agent-Nonce | Qayta ko'rsatishdan himoya qilish nonce. |
| X-Agent-Imzo | HMAC-SHA256 imzo. |

```text
timestamp + nonce + rawBody
```

Imzolangan qiymatni tiklashda HTTP dan ortiq qabul qilingan aniq xom so'rov tanasidan foydalaning. Avval JSON tahlil qilish va qayta seriyalashtirish bo'sh joy yoki maydon tartibini o'zgartirib, boshqa imzo hosil qilishi mumkin.

<h2 id="verification-flow">Verifikatsiya jarayoni</h2>

1. Vaqt tamg'asini, nonce va imzo sarlavhalarini o'qing.
2. O'zgartirilmagan xom so'rov tanasini qo'lga oling.
3. Qur `timestamp + nonce + rawBody`.
4. Hisoblab HMAC-SHA256 hamkor API sir.
5. Hisoblangan va qabul qilingan imzolarni doimiy vaqt taqqoslash orqali taqqoslang.
6. Tasdiqlangan vaqt tamg'asini yangilik va qayta ishlatmaslik tekshiruvlarini qo'llang.
7. Hodisani tahlil qilish va faqat tekshirish muvaffaqiyatli bo'lgandan keyin qayta ishlash.

Rasmiy Agent SDK tasdiqlovchi mavjud bo'lsa, mustaqil imzo kodini saqlash o'rniga undan foydalaning.

<h2 id="order-idempotency">Order idempotency</h2>

| Ish | Boshqaruv |
| --- | --- |
| Dastlabki transfer so'rovi | Dunyo miqyosida noyob bir agentOrderNoyarating. |
| HTTP tanaffus | Yangi agentOrderNo yaratishdan oldin asl  so'rang. |
| PROCESSING javob | Webhook yoki so'rov tartibi holatini kuting. |
| Takroriy webhook | Idempotency kaliti va yakuniy holat bo'yicha duplikat. |

<h2 id="recommended-idempotency-record">Tavsiya etilgan idempotensiya yozuvi</h2>

Takroriy yetkazib berishni aniqlash va xavfsiz tiklash uchun yetarli ma'lumotni saqlang:

| Maydon | Maqsad |
| --- | --- |
| Tadbir yoki biznes kaliti | Bildirishnoma yoki operatsiyani noyob tarzda aniqlaydi. |
| Hamkor buyurtma raqami | Tadbirni asl so'rovga ulaydi. |
| Yuklama xeshi | Takrorlanuvchi yuklarni aniqlashga yordam beradi. |
| Joriy ishlov berish holati | Qabul qilingan, qayta ishlangan, muvaffaqiyatli va muvaffaqiyatsiz ishlarni ajratib ko'rsatadi. |
| Yakuniy biznes holati | Terminal harakatning ikki marta qo'llanilishini oldini oladi. |
| Qayta ishlangan vaqt tamg'asi | Tergov va saqlash siyosatini qo'llab-quvvatlaydi. |

Biznes o'zgarishi va idempotentlik yozuvini imkon qadar bir xil tranzaksiyada amalga oshiring. Takrorlangan hodisa balans, buyruq yoki foydalanuvchi o'zgarishini qayta qo'llash o'rniga allaqachon ma'lum natijani qaytarishi kerak.

<h2 id="timeout-and-retry-rule">Tanaffus va qayta urinish qoidasi</h2>

HTTP tanaffus dastlabki so'rov muvaffaqiyatsiz bo'lganini isbotlamaydi. Operatsiyani asl `agentOrderNo`yordamida so'rov qiling yoki uning webhookini kuting, so'ngra yana bir harakat kerakmi, deb qaror qiling. Har bir timeoutdan so'ng yangi biznes buyurtma raqamini yaratish moliyaning takroriy harakatlariga sabab bo'lishi mumkin.

<h2 id="production-checklist">Ishlab chiqarish ro'yxati</h2>

- Parsing yoki biznes qayta ishlashdan oldin imzoni JSON tekshiring.
- Xom tanani tahlil qilingan yukdan mustaqil saqlash.
- Tasdiqlangan integratsiya siyosatiga muvofiq eskirgan yoki qayta ko'rilgan so'rovlarni rad etish.
- Tadbirlarni qayta ishlashni takroriy va tartibsiz yetkazib berish uchun xavfsiz qilish.
- Tadbir identifikatorlari, hamkor buyurtma raqamlari, ishlov berish natijalari va so'rov vaqtini qayd etish.
- Loglar va qo'llab-quvvatlovchi ilovalardan sirlar va imzo qiymatlarini yashirish.
