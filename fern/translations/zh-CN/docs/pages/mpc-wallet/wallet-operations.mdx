从当前空间的菜单与权限开始操作。个人和团队钱包侧重钱包资产与设备签名，企业空间还提供业务审批和运营视图。

<span id="receive-assets" data-sixmm-canonical-anchor="receive-assets" aria-hidden="true"></span>

## 接收资产

选择目标网络和资产，使用该钱包或业务用户对应的收款信息。有些网络除地址外还需要备注或标签，应将这些信息一起保存，并在转入前核对。

地址已分配不代表充值已经到账。需要分别关注充值记录、链上确认以及可能的风险冻结。链上能够查到交易时，业务账户中的资金仍可能尚未变为可用。

<span id="transfer-assets" data-sixmm-canonical-anchor="transfer-assets" aria-hidden="true"></span>

## 转出资产

1. 选择来源钱包或余额，填写目标地址、金额和必要的备注。
2. 核对预览、费用与地址检查结果；按钱包模式准备相应的手续费资产。
3. 提交一次并保存请求编号，完成当前产品要求的审批或设备确认。
4. 跟踪签名、广播和链上确认，直到最终结果明确。

审批通过不等于已完成签名，广播成功也不等于链上确认。个人与团队的签名流程，不能直接套用企业提现的网页审批方式。

<span id="understand-enterprise-wallet-roles" data-sixmm-canonical-anchor="understand-enterprise-wallet-roles" aria-hidden="true"></span>

## 理解企业钱包分工

| 角色 | 用途 |
| --- | --- |
| 充值钱包 | 接收转入资产，配合资金归集 |
| 热钱包或提现钱包 | 处理日常转出 |
| 中转钱包 | 衔接运营资金和储备资金的调拨 |
| 储备钱包 | 按适合储备用途的签名安排保管资产 |

部分产品还区分手续费资金或隔离资金。这些是资金运作中的角色，不代表所有产品都提供全部钱包类型。仅凭“储备”这个名称，也不能判断设备是否离线。

<span id="reconcile-uncertain-results" data-sixmm-canonical-anchor="reconcile-uncertain-results" aria-hidden="true"></span>

## 核对不确定的结果

将业务请求、钱包记录和链上交易对应起来，区分可用余额、冻结余额、账本分录与链上观察结果。

遇到请求超时或交易仍在核对中，应查询已有记录。不要因为缺少成功页面或通知就另发一笔。能否取消取决于真实的签名阶段；提交了取消请求，并不能证明资金不会转出。开发人员可继续阅读[交易状态与重试](/zh-CN/mpc-wallet/transactions)。
