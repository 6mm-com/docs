<h2 id="orders">订单</h2>

| 枚举     | 取值                                                                                                        |
| ------ | --------------------------------------------------------------------------------------------------------- |
| 订单方向   | `BUY` / `SELL`                                                                                            |
| 持仓方向   | `BOTH` / `LONG` / `SHORT`                                                                                 |
| 普通订单类型 | `LIMIT` / `MARKET`                                                                                        |
| 条件单类型  | `STOP_MARKET` / `STOP_LIMIT` / `TAKE_PROFIT_MARKET` / `TAKE_PROFIT_LIMIT` / `TRAILING_STOP`               |
| 有效方式   | `GTC` / `IOC` / `FOK` / `GTE_GTC`                                                                         |
| 触发价格类型 | `MARK_PRICE` / `CONTRACT_PRICE`                                                                           |
| 订单状态   | `NEW` / `PENDING` / `PARTIALLY_FILLED` / `FILLED` / `CANCELED` / `REJECTED` / `PARTIALLY_FILLED_CANCELED` |

`NEW` 表示下单请求已被接受并返回；`PENDING` 表示订单已进入待成交或挂单状态。

<h2 id="positions">仓位</h2>

| 枚举       | 取值                          |
| -------- | --------------------------- |
| 保证金模式请求值 | `1` 全仓，`2` 逐仓               |
| 保证金模式字符串 | `ISOLATED` / `CROSS`        |
| 平仓触发模式   | `1` 手动，`2` 止盈，`3` 止损，`4` 强平 |

<h2 id="integration-rules">接入规则</h2>

- 枚举值是区分大小写的接口传输值。
- 日志中保留未知值，并采用安全失败处理；不要静默映射为已知状态。
- 不要把所有非终态都理解为可以安全重试。应通过订单查询或私有 WebSocket 事件完成对账。
- 同时保存接口原始值和合作方展示文案，避免新增枚举值时破坏历史记录。

<h2 id="order-state-handling">订单状态处理</h2>

| 状态组 | 取值 | 建议处理 |
| --- | --- | --- |
| 已接受或进行中 | `NEW`、`PENDING`、`PARTIALLY_FILLED` | 保持订单活动状态，并通过 WebSocket 或 REST 更新对账。 |
| 已完成 | `FILLED` | 记录最终成交数量和成交明细。 |
| 未完全成交即关闭 | `CANCELED`、`REJECTED`、`PARTIALLY_FILLED_CANCELED` | 停止活动处理，同时保留原因和已成交数量。 |
