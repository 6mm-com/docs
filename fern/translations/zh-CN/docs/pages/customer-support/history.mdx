历史会话用于查找旧咨询、复盘接待质量和追踪具体问题。优先使用会话编号或明确的时间范围定位，减少逐条翻找。

<div className="sixmm-support-flow">

1. **定位会话** — 设置筛选和正确的日期口径。
2. **阅读上下文** — 核对消息、客服及访客资料。
3. **继续跟进** — 完善答案或处理尚未解决的问题。

</div>

## 查找历史咨询

进入 **历史会话**，使用用户或会话搜索、会话类型、评分、客服、分类、语言和时间等页面提供的筛选条件，打开详情阅读消息与会话信息。

列表中的用户邮箱优先显示联系邮箱，没有时显示访客邮箱；详情保留两个字段，便于区分来源。空值表示未收集到该字段，不代表用户没有邮箱。

<span id="review-service-quality" data-sixmm-canonical-anchor="review-service-quality" aria-hidden="true"></span>

## 复盘服务质量

结合会话内容、接待客服和评分分析问题。显示为 AI 助手的消息也可能来自配置文案或匹配阶段，并不一定调用了大模型。排查回复时，对照当前知识内容，并使用流程测试确认路径。

删除需要相应权限，单条或批量删除前阅读确认信息。MCP 查询同样受授权范围限制，删除需确认；不能假定普通客服可以读取所有历史会话。


<span id="read-the-fields-without-mixing-identities" data-sixmm-canonical-anchor="read-the-fields-without-mixing-identities" aria-hidden="true"></span>

## 这些字段分别代表什么

| 字段 | 如何理解 |
| --- | --- |
| 会话编号 | 定位当前复盘的这次咨询，避免把不同会话混在一起。 |
| 访客名称 | 便于阅读的显示名称，不等于已核验的交易所账号。 |
| 入口类型与用户 ID | 帮助区分匿名访问和对接的登录身份；没有身份数据时不要自行推断。 |
| 用户邮箱 | 优先联系邮箱，其次访客邮箱；详情中保留两个来源。 |
| 语言与 IP 归属地 | 为接待提供参考，不作为身份或精确地理位置的证明。 |
| 评分 | 用户对该会话已提交的反馈；未评分不等于差评。 |

<span id="example-review-a-low-rated-consultation" data-sixmm-canonical-anchor="example-review-a-low-rated-consultation" aria-hidden="true"></span>

### 示例：复盘一次低评分咨询

1. 按需要选择日期、客服和评分条件，打开完整会话记录。
2. 先看用户原始问题，再判断回复是否恰当；注意转接过程或语言理解是否影响了沟通。
3. 如果答案不完整，检查对应知识内容和机器配置，不能仅凭一次体验不好就认定是模型故障。
4. 在内部跟进时保留会话编号，让团队能够回到同一份记录继续核对。

## 常见问题

<AccordionGroup>

<Accordion title="为什么邮箱是空的？">
这次咨询可能没有收集联系邮箱，接入方也没有传入访客邮箱。先在详情中核对两个字段的来源。
</Accordion>

<Accordion title="为什么换个日期条件，结果就不同？">
页面可按开始时间或关闭时间查询。跨天结束的会话，在两种口径下会落入不同的日期范围。
</Accordion>

</AccordionGroup>
