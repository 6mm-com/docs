## 区分三类记录

进入 **工单管理**，选择对应标签。

| 记录 | 用途 |
| --- | --- |
| 客服工单 | 由客服团队创建和维护的处理任务 |
| 用户工单 | 访客提交、需要后续跟进的问题 |
| 用户反馈 | 通过反馈入口提交的建议或问题 |

<span id="handle-a-case" data-sixmm-canonical-anchor="handle-a-case" aria-hidden="true"></span>

## 处理一个问题

查看描述、联系方式、关联会话和记录提供的附件，分配合适的处理人，并随进展更新状态。客服工单使用对应的编辑功能，用户工单和反馈有各自的可操作范围。

修改状态本身不代表用户已经收到邮件或聊天回复。需要回复时，通过实际可用的沟通渠道联系用户，并确认发送结果。个人信息应保留在已授权的租户处理流程内。

<span id="use-mcp-for-triage" data-sixmm-canonical-anchor="use-mcp-for-triage" aria-hidden="true"></span>

## 使用 MCP 辅助分流

可以让连接的 AI 查询未解决事项、按问题类型整理并起草回复。正式修改处理人或状态前核对目标记录。创建客服工单与访客提交用户工单是不同流程，不能把一种工具理解成支持另一种操作。通过 MCP 删除工单需要确认。
