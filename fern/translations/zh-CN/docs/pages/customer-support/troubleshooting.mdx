## 后台与访客客服

| 现象 | 优先检查 |
| --- | --- |
| 看不到菜单 | 账号角色及租户服务是否可用 |
| 客服窗口打不开 | 后台生成的脚本地址、App Key、允许域名与浏览器错误 |
| 没有走大模型 | 实际命中步骤、智能服务开关与对应配置 |
| 回答仍使用旧规则 | 原文章、发布状态、FAQ 文案、译文与检索状态 |
| 没有翻译 | 目标语言、翻译开关、已保存译文、服务与余额是否可用 |
| 向量生成失败 | 服务可用性和检索状态，查明原因前避免反复重建 |
| 联系信息为空 | 对应字段是否确实收集，注意联系邮箱与入口邮箱的区别 |

## MCP 连接与调用

| 现象 | 处理方式 |
| --- | --- |
| 浏览器直接打开 MCP 地址报错 | 这是协议端点，不是登录页面，应添加到兼容的 MCP 客户端 |
| 无法发起授权 | 核对地址、客户端的 Streamable HTTP 与 OAuth 支持，以及浏览器登录流程 |
| 未授权或连接过期 | 检查撤销和到期状态，通过应用重新连接 |
| 缺少工具或提示无权限 | 检查授权账号角色与记录范围，刷新工具列表 |
| 等待确认 | 打开返回的确认链接，在后台核对并处理 |
| 内容已变化 | 读取最新记录，重新预览，提交新的操作 |
| 请求超时 | 先查询操作状态，再决定是否重试，不直接认定失败 |
| 没有写入日志 | 区分查询、待确认和执行完成，在操作日志核对筛选条件 |

## 联系支持前准备

记录时间与时区、涉及的租户和账号、页面或工具名、可用的操作 ID 以及准确错误信息，提供脱敏截图或复现步骤。不要发送密码、验证码、访问令牌或签名密钥。

排查写入可先使用少量测试记录，确认执行结果后只清理自己创建的测试数据，需要确认时遵循正常流程。
