从阅读用户问题到接待、转接和跟进，在一个工作台完成日常咨询处理。先了解上下文，再选择合适的处理方式。

<div className="sixmm-support-flow">

1. **阅读会话** — 先看问题和近期消息。
2. **确定接待人** — 确认归属后接入或转接。
3. **回复与跟进** — 答复、邀请评价或继续跟进工单。

</div>


<span id="work-from-one-conversation-workspace" data-sixmm-canonical-anchor="work-from-one-conversation-workspace" aria-hidden="true"></span>

## 在同一个工作台处理会话

进入 **在线会话**，通过人工、监控和机器人标签查看当前账号可见的会话。监控权限与会话归属仍然有效，并非每个客服都能查看全租户会话。

1. 选择会话，阅读近期消息与可用的访客资料。
2. 根据权限接入、接管、分配或转接会话。
3. 使用文字、支持的附件或快捷回复处理问题，必要时识别和翻译消息。
4. 按需要管理访客上传权限，邀请用户评价。
5. 完成会话；需要持续处理时，创建或跟进工单。

<span id="understand-visitor-information" data-sixmm-canonical-anchor="understand-visitor-information" aria-hidden="true"></span>

## 理解访客信息

可读的访客名称是显示标识，不代表已验证的交易所账户。区分登录用户 ID、入口提交的邮箱和咨询过程中提供的联系邮箱。使用会话中已有资料了解问题，不应仅凭相同邮箱认定两个访客是同一登录用户。

发送前确认当前会话。外部 MCP 客户端生成了回复，不等于消息已经发给访客；通过 MCP 发送仍需执行平台确认流程。

<span id="when-human-support-is-unavailable" data-sixmm-canonical-anchor="when-human-support-is-unavailable" aria-hidden="true"></span>

## 人工暂时不可用

访客入口遵循当前接待状态与替代处理配置，可以通过工单保留问题供后续处理。提示文案应与实际排班和处理政策一致，不承诺未经确认的响应时间。


<span id="know-which-workspace-to-use" data-sixmm-canonical-anchor="know-which-workspace-to-use" aria-hidden="true"></span>

## 先看哪个会话标签

| 标签 | 适合做什么 |
| --- | --- |
| 人工 | 处理当前账号可见的人工会话，回复前核对接待客服和会话归属。 |
| 监控 | 在已有监控权限内查看会话；查看内容与接管处理是不同操作。 |
| 机器人 | 查看用户问题和机器人回复，判断是否需要人工进一步接待。 |

<span id="example-a-user-asks-about-exchange-integration" data-sixmm-canonical-anchor="example-a-user-asks-about-exchange-integration" aria-hidden="true"></span>

### 示例：用户咨询交易所接入

1. 先阅读上下文，判断用户想了解接入文档，还是遇到了需要核实账号的具体问题。
2. 使用已核对的知识答案或合适的快捷回复，发送前检查平台名称、链接和金额。
3. 遇到其他语种时，使用页面提供的识别和翻译功能，理解原意后再回复。
4. 需要同事继续处理时，按权限转接或分配；需要后续调查时，使用对应工单流程跟进。

**结束前核对：** 用户是否收到回复、是否仍有未解决的问题、后续跟进需要保留哪个会话编号。

## 常见问题

<AccordionGroup>

<Accordion title="为什么能看到会话，却不能直接回复？">
先检查当前接待人、账号权限，以及是否需要先接入或接管。拥有监控权限不等于已经接待该会话。
</Accordion>

<Accordion title="标着 AI 助手的回复一定调用了大模型吗？">
不一定。固定文案和前面的匹配结果也可能显示为 AI 消息，排查时可结合机器配置中的流程测试。
</Accordion>

</AccordionGroup>
