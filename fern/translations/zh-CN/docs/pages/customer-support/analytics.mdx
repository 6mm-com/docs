把会话、工单和知识内容的数据转化成团队可以处理的问题。先确定统计周期，再回到具体记录核实变化原因。

<div className="sixmm-support-flow">

1. **确定周期** — 保持日期与筛选条件一致。
2. **结合指标** — 同时看咨询量、处理情况和反馈。
3. **回看记录** — 找出实例，确定具体改进动作。

</div>


<span id="understand-support-activity" data-sixmm-canonical-anchor="understand-support-activity" aria-hidden="true"></span>

## 了解服务情况

进入 **数据统计**，选择时间范围和页面提供的筛选条件，查看实时概况、会话、工单、满意度、消息、客服、反馈与知识库统计。

多个指标结合分析：会话量反映咨询需求，工单状态反映后续处理情况，评分帮助了解用户体验。知识内容被浏览较多，不直接等于用户问题已经解决。

<span id="compare-like-for-like-data" data-sixmm-canonical-anchor="compare-like-for-like-data" aria-hidden="true"></span>

## 使用一致的统计口径

对比时保持时间范围、时区、筛选条件和模块范围一致。阅读指标名称，不要假定所有数量都是去重用户数。与其他页面数字不同时，先核对定义和筛选条件。

MCP 可以查询统计并辅助总结趋势，不能通过只读统计工具修改数据。让 AI 在总结中说明查询周期和引用指标，方便回到后台核对。


<span id="choose-a-view-for-the-question" data-sixmm-canonical-anchor="choose-a-view-for-the-question" aria-hidden="true"></span>

## 按问题选择统计视图

| 想回答的问题 | 优先查看 |
| --- | --- |
| 咨询需求有什么变化？ | 消息、人工会话、机器人及国家分布等视图。 |
| 后续跟进是否积压？ | 相同统计周期下的工单与反馈。 |
| 用户如何评价服务？ | 满意度，并回到相关会话核对原因。 |
| 哪些帮助内容需要完善？ | FAQ 与知识库统计，再结合真实咨询中的重复问题。 |

<span id="example-prepare-a-weekly-review" data-sixmm-canonical-anchor="example-prepare-a-weekly-review" aria-hidden="true"></span>

### 示例：准备每周服务复盘

1. 选择约定的统计周，在复盘中写清日期范围和当前筛选条件。
2. 分别整理咨询需求、待跟进事项和用户反馈，不把含义不同的指标直接相加。
3. 抽查相关会话或工单，了解数字变化背后的具体原因。
4. 选择可执行的改进，例如完善一篇说明、更新一条快捷回复或调整团队处理方式；下一周期使用相同口径比较。

也可以让已连接 MCP 的 AI 汇总选定数据，但应要求它注明统计周期，并区分实际观察到的数据与推测的原因。

## 常见问题

<AccordionGroup>

<Accordion title="文章浏览多就说明解决问题最多吗？">
浏览和交互数据反映使用情况，不直接证明问题已经解决，需要结合用户提问和处理结果判断。
</Accordion>

<Accordion title="为什么两个报表的数量不同？">
先核对时间口径、筛选条件和指标定义。会话数、消息数和去重访客数不是同一种数量。
</Accordion>
