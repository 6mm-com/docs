为每位客服分配独立账号，选择合适的角色，并维护可复用的快捷回复。按实际岗位组织权限，最后使用对应账号验证。

<div className="sixmm-support-flow">

1. **建立账号** — 确认客服身份与账号状态。
2. **分配角色** — 配置岗位需要的模块和操作。
3. **验证接待** — 检查权限并准备常用回复。

</div>


<span id="organize-the-support-team" data-sixmm-canonical-anchor="organize-the-support-team" aria-hidden="true"></span>

## 组织客服团队

在 **客服管理** 维护客服账号、角色与快捷回复。根据岗位实际需要分配模块和操作权限，避免多人共享同一个管理员登录账号。

修改角色后，使用受影响的账号验证菜单、会话监控、内容编辑和设置权限。除了菜单权限，账号状态、会话归属和字段级校验也会继续生效。

<span id="mcp-inherits-the-same-identity" data-sixmm-canonical-anchor="mcp-inherits-the-same-identity" aria-hidden="true"></span>

## MCP 继承同一个账号身份

MCP 连接绑定授权的租户与客服账号，AI 不会额外获得管理员角色。服务在调用时重新检查权限，不能通过猜工具名或传入其他租户 ID 获得额外访问能力。

在 **系统设置 → MCP 连接** 管理已连接应用，不再使用时撤销连接。退出浏览器后台，不等于撤销外部 AI 应用的授权。

通过 MCP 管理角色与客服账号需要确认。通过 MCP 创建客服时，初始密码由用户在后台确认页填写，不返回给 AI。

## 了解三个管理区域

| 区域 | 维护哪些内容 |
| --- | --- |
| 客服账号 | 名称、登录邮箱、角色、启用状态，以及页面提供的接待配置。 |
| 角色管理 | 一组客服可使用的模块和操作；保存前确认对已有成员的影响。 |
| 快捷回复 | 常用回复的标题、正文、排序与启用状态；开放翻译时同时检查对应语言内容。 |

<span id="prepare-an-agent-for-their-first-shift" data-sixmm-canonical-anchor="prepare-an-agent-for-their-first-shift" aria-hidden="true"></span>

### 为新客服准备第一次接待

1. 核对登录邮箱与角色。账号是否启用、是否已登录、是否处于工作状态，是不同的信息。
2. 检查已配置的监控权限、接待优先级和最大并发接待数，这些设置与角色权限共同影响实际使用。
3. 让客服登录自己的账号，验证工作所需菜单和会话操作是否可用。
4. 准备常见问题的快捷回复，检查链接是否仍有效，避免把某位用户的个人信息写进通用模板。

**交接建议：** 调整账号权限前先核对未完成事项；修改角色或账号后，验证实际权限，不要只看角色名称。

## 常见问题

<AccordionGroup>

<Accordion title="管理员授权的 AI 会自动变成普通客服权限吗？">
不会。MCP 使用实际授权账号的权限，应选择与目标工作相匹配的账号进行连接。
</Accordion>

<Accordion title="退出后台就能断开外部 AI 吗？">
退出后台与撤销 MCP 授权是两件事，需要在系统设置 → MCP 连接中撤销对应应用。
</Accordion>

</AccordionGroup>
