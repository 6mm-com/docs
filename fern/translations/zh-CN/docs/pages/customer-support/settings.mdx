配置访客如何进入客服、看到什么内容，以及本租户可以使用哪些智能服务。每次调整都按“保存—实际访问—核对效果”的顺序验证。

<div className="sixmm-support-flow">

1. **找到配置** — 按目标行为选择设置标签。
2. **保存修改** — 确认影响的入口或服务。
3. **访客侧验证** — 打开真实网站核对效果。

</div>

## 配置访客体验

进入 **系统设置**。可用配置取决于账号角色和租户已开启的服务。

| 标签 | 配置内容 |
| --- | --- |
| 外观与接入 | 页面提供的外观及入口设置 |
| 首页与文案 | 面向用户的首页文字和引导说明 |
| 会话与超时 | 会话行为与超时控制 |
| 访客弹窗 | 访客入口收集的信息与提示 |
| 智能服务 | 本租户开放的 AI、智能检索和翻译能力 |
| 网站接入 | 域名白名单、嵌入代码、登录身份、语言与主题对接 |
| MCP 连接 | 服务地址、已授权应用和撤销连接 |

保存后，从真实访客入口验证效果。预览正常或保存成功，不代表另一个嵌入网站已经加载最新配置。

<span id="keep-boundaries-clear" data-sixmm-canonical-anchor="keep-boundaries-clear" aria-hidden="true"></span>

## 明确租户边界

租户设置只管理本租户客服，不提供平台供应商密钥、其他租户、余额充值或交易账户操作能力。MCP 只开放当前角色允许的配置字段，修改网站域名白名单需要确认。


<span id="plan-the-initial-setup" data-sixmm-canonical-anchor="plan-the-initial-setup" aria-hidden="true"></span>

## 首次配置推荐顺序

1. **外观与文案：** 核对品牌展示、首页引导和客服说明，确保与实际提供的交易所服务一致。
2. **访客入口：** 确定需要收集哪些信息，检查页面提供的弹窗行为；按实际场景验证首次访问和再次访问。
3. **接待行为：** 与接待团队一起检查会话及超时设置，确认符合工作安排。
4. **智能服务：** 确认本租户已开启的能力，再测试一个典型问题或一次翻译。开关已开启，不等于上游请求一定成功。
5. **网站接入：** 核对网站域名白名单，按接入指南配置嵌入代码、登录身份、语言和主题。
6. **MCP：** 在确认授权账号及权限范围后，再连接外部 AI 应用。

<span id="example-a-saved-change-is-not-visible-on-your-website" data-sixmm-canonical-anchor="example-a-saved-change-is-not-visible-on-your-website" aria-hidden="true"></span>

### 示例：保存后网站上没有变化

先确认测试的是哪个租户、哪个访客入口，再重新加载页面。检查嵌入网站是否另行指定了语言或主题，以及目标设置是否真正保存。若无法访问，优先核对域名白名单和接入配置，避免反复修改无关设置。

## 常见问题

<AccordionGroup>

<Accordion title="为什么看不到某个设置标签？">
页面可用范围受账号权限和租户已开放服务影响，应由租户管理员核对对应权限。
</Accordion>

<Accordion title="在哪里配置模型密钥或给租户充值？">
供应商密钥和平台余额调整不属于租户设置范围，需要按与平台运营方约定的方式处理。
</Accordion>

</AccordionGroup>
