先看余额概况，再用调用记录查服务消耗、用余额流水查资金变化。比较费用前，先确认服务类型和计量单位。

<div className="sixmm-support-flow">

1. **查看概况** — 了解余额与近期消费。
2. **定位调用** — 按服务和时间范围筛选。
3. **核对流水** — 对照最终费用与余额变化。

</div>


<span id="review-intelligent-service-usage" data-sixmm-canonical-anchor="review-intelligent-service-usage" aria-hidden="true"></span>

## 查看智能服务用量

进入 **用量账单**，查看余额、可用服务价格、调用记录和余额流水。AI 回复、翻译与向量操作可能按租户配置消耗共用的智能服务余额。

不同回复路径对应不同用量：返回已保存答案与请求大模型不是同一种调用。模型和价格可能变化，请以当前后台显示为准，本文不写死价格。

<span id="understand-settlement" data-sixmm-canonical-anchor="understand-settlement" aria-hidden="true"></span>

## 理解结算

计量请求可能先预扣估算金额。取得可靠上游用量时，沿用正常结算规则；有效结果已经返回、但缺少可靠用量时，可以保留原预扣金额作为保底费用，不会在预扣上再次增加缓冲。请求失败或结果无效时，按失败规则退回预扣。

预扣不是额外再收一笔费用。对照最终费用、初始预扣和余额调整记录理解账单，不能把保底使用的估算单位当成上游实际测量的 token。

<span id="mcp-and-costs" data-sixmm-canonical-anchor="mcp-and-costs" aria-hidden="true"></span>

## MCP 与费用

MCP 没有新增一套收费规则，但通过工具调用平台 AI、翻译或向量服务时，仍可能产生原有业务费用。外部 AI 提供方也可能独立收费。账单工具可以查看余额、用量、流水和价格，不能充值或修改账单。

## 三个账单视图怎么用

| 视图 | 主要回答什么问题 |
| --- | --- |
| 用量记录 | 什么时间调用了什么服务、适用的输入／输出用量、最终费用与状态。 |
| 余额流水 | 每次余额变化的类型和金额，以及变动前后的余额。 |
| 服务价格 | 当前可用服务的计价方式；以页面价格为准，不沿用旧文档中的单价。 |

<span id="example-investigate-an-unexpected-balance-change" data-sixmm-canonical-anchor="example-investigate-an-unexpected-balance-change" aria-hidden="true"></span>

### 示例：排查一次不理解的余额变化

1. 记录大致时间，选择对应范围；按服务类型区分 AI、翻译、语言识别和向量调用。
2. 查看调用状态与最终扣费，聊天页面出现一条消息本身不等于一条计费记录。
3. 对照同一时间段的余额流水，包括消费、退款和页面展示的其他调整。
4. 仍需核实时，保留时间范围、服务及相关记录信息，交由平台运营方确认；不要为了观察余额而反复执行收费操作。

**不同服务的单位不同。** AI 文本生成可以分别按输入和输出词元计价；向量服务按输入用量计价。翻译与语言识别应按页面显示的单位理解，不要把所有数字都当成 token。

## 常见问题

<AccordionGroup>

<Accordion title="初始预扣是额外再收一笔吗？">
不是。它属于上文说明的结算过程，应结合最终费用和余额调整理解，不能把预扣再加一次。
</Accordion>

<Accordion title="连接 MCP 后 AI 调用都免费吗？">
不是。调用原有平台服务仍可能消耗共用余额，外部 AI 应用也可能有自己的费用。
</Accordion>

</AccordionGroup>
