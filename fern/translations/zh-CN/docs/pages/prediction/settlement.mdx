结果判定用于确认订单条件是否满足，结算用于记录最终资金处理。计划开奖或到期时间，不一定等于所有关联流水处理完成的时间。

<span id="按玩法判定" data-sixmm-anchor-target="evaluation-by-game" aria-hidden="true"></span>
<h2 id="evaluation-by-game">按玩法判定</h2>

| 玩法 | 判定方式 |
| --- | --- |
| 涨跌预测 | 比较场次开盘价与结算价 |
| 自选预测 | 比较该笔订单开盘价与到期结算价 |
| 预测网格 | 检查已受理时间窗内是否有效触碰或穿过区间 |

方向玩法中的价格相等，以及恰好位于价格或时间边界的情况，需要按适用规则处理。网格命中本身也不代表资金立即可用，应继续检查结算进度。

<span id="结算依据" data-sixmm-anchor-target="settlement-evidence" aria-hidden="true"></span>
<h2 id="settlement-evidence">结算依据</h2>

保留订单号、已记录条件、价格证据、最终状态、实际返还、结算时间与流水号。涨跌场次记录还包含开奖信息及场次下注、返还汇总。

<span id="如何核对" data-sixmm-anchor-target="reconcile-the-result" aria-hidden="true"></span>
<h2 id="reconcile-the-result">如何核对</h2>

1. 确认记录对应正确的订单和账户。
2. 按正确的价格与时间条件检查结果。
3. 根据订单赔率、适用费用和舍入规则核对实际返还。
4. 将结算流水与资金账户变动对应起来。

<span id="延迟与异常" data-sixmm-anchor-target="delays-and-exceptions" aria-hidden="true"></span>
<h2 id="delays-and-exceptions">延迟与异常</h2>

结果延迟不应被理解为未中奖；结果已显示但余额尚未刷新时，不应重复提交请求。先检查订单与流水状态，持续不一致时携带证据联系支持。
